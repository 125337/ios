## 二、根因归纳：三个结构性缺陷

上面 11 个待修项不是 11 个独立 bug，是**三个架构缺陷**的投影：

```
缺陷一：数据层读错了层
  读 timelineMgr.getCache（原生页 UI 缓存，易空、有上限）
  应读 数据源对象/本地库层（m_timelineWithLocalDatas，冷启动有数、无上限）
  → 投影出 B6/B7；快照机制只是给这个错层打的创可贴

缺陷二：媒体资源的 key↔文件 映射没有生命周期
  key 进程内存态 + 计数器 + 无文件校验 + 无回落
  → 投影出 B1-B5

缺陷三：推送是"全量快照式"而非"增量协议式"
  全量序列化 + lastJson 比对 → 体积随 cache 线性涨，每推必变
  → 投影出 B8/B9；B10/B11 是推送触发器的边角
```

**结论：逐个修 B1-B11 = 在错误地基上砌墙。重构 = 换地基。**

### 3.1 数据层 `MioDualTimelineStore`（修 B6/B7/B8）

```objc
// MioDualTimelineStore.h
@interface MioDualTimelineStore : NSObject
+ (instancetype)shared;
- (NSArray<NSDictionary *> *)currentItems;      // 统一字段映射后的行数组（无 300 上限）
- (NSUInteger)approxCount;                      // 预估条数（exhausted 判定用）
- (void)refreshHead;                            // updateTimelineHead
- (void)loadTail;                               // updateTimelineTail
- (id)dataItemByID:(NSString *)objID;           // getDataItemByID:
- (NSString *)lastSnapshotJSON;                 // 上次会话快照（冷启动秒显）
@end
```

关键设计：
1. **双源读取**：先 `timelineMgr.getCache`；**为空或条数突降时回落 `m_timelineWithLocalDatas`**（KVC 直取 ivar，本地库支撑——冷启动有数、无 300 上限）。两源字段映射统一在这层做一次，上游永远拿干净 dict。
2. **字段映射收口**：username/nickname/createTime/content/comment 嵌套等全部大小写变体在这层 @try 消化，**上游不再写任何 @try**。
3. **快照同存同删**：快照 JSON 与媒体注册表用同一个版本号管理（见 3.2），不会出现"JSON 有 key、注册表没 key"的撕裂。
4. **上限改 LRU**：不做 300 截断；按 `createTime` 排序保留最近 500 条（内存 dict 上限），彻底移除硬上限。

### 3.2 媒体层 `MioDualMediaService`（修 B1-B5）

```objc
// MioDualMediaService.h
@interface MioDualMediaService : NSObject
+ (instancetype)shared;
- (NSString *)registerLocalPath:(NSString *)path;          // 返回稳定 key（路径 MD5）
- (NSString *)resolveKey:(NSString *)key;                  // 内存→持久→文件校验→nil
- (NSString *)cdnFallbackForKey:(NSString *)key;           // CDN 回落 URL
- (void)pruneExcept:(NSSet<NSString *> *)liveKeys;         // 快照修剪
@end
```

关键设计（合并此前已给的修复）：
1. **key = 路径 MD5**（稳定，跨启动同路径同 key，不撞车）
2. **双层存储**：内存 dict（会话内快）+ NSUserDefaults 持久 dict（跨启动）——lookup 顺序：内存→（文件校验）→持久→（文件校验）→nil
3. **文件校验**：每次 resolve 都 `fileExistsAtPath:`——微信清缓存后自动降级 CDN
4. **修剪**：快照保存时 `pruneExcept:` 只留快照引用的 key——NSUserDefaults 不膨胀
5. **@synchronized** 取代假锁（原 MioDualPathsLock 从不加解锁的 bug 一并消灭）
6. 视频同表：pathForData 注册进同一张表，快照里视频文件被清 → resolve nil → JS 显示封面 + "已过期"，不再黑屏

### 3.3 推送层 `MioDualFeedBridge`（修 B8/B9/B10/B11）

```objc
// 增量协议：JS 端维护 rowID→DOM map；native 只推三类操作
// __mioFeedPatch({ upsert: [ {id, ...row} ], remove: [id], order: [id...] })
```

关键设计：
1. **行级 diff**：native 持 `lastRowsByID`（rowID→行 JSON）；每次 store 更新后 diff 出 upsert/remove/order，只序列化变更行——296 条里通常变更 <10 条，JSON 从 300KB 降到 ~10KB
2. **尾沿防抖**：事件 → 0.5s 后推一次（推送时重读最新状态，窗口内变更全合并）——永不丢尾
3. **让位兜底**：onTimelineDataChanged 被他方插件占有时 → 启动 10s 慢轮询保底（实时性降级但不断供）
4. **快照协议**：冷启动 `__mioFeedSnapshot(json)` 一次性灌快照，JS 标记 `stale=true`（可显示"更新中"角标），新数据落地后自动切正常

### 3.4 UI 层（已达标）

面板常驻、手绘卡、分段/导航/刷新、每消息一 section——**全部保留**。唯一改动：cellForRow 从手工拼 dict 字段改为消费 `MioDualTimelineStore` 的干净 dict（字段映射已在上游完成，@try 全删）。
