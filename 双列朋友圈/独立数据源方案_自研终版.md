# 双列朋友圈 · 独立数据源方案（自研终版）

> 结论：依赖审计完成——Mio 数据层与 WCMoments **零代码关联**。唯一的外部类 `WCFacade` 是微信原生服务（8.0.78 头文件实证，665 方法），所有调用的方法均为原生声明。本文档固化自研终版架构，明确每层职责与"不抄清单"。

---

## 一、依赖审计结论

| 触点 | 性质 | 判定 |
|---|---|---|
| `objc_getClass("WCFacade")` | 微信原生类（WCFacade : MMUserService） | ✅ 原生 API |
| `timelineMgr` / `getCache` / `getAllMessages` / `updateTimelineHead/Tail` / `getDataItemByID:` / `beginTimeline` / `endTimeline` / `reloadTimelineDataItems` / `countOfTimelineDataItem` / `getTimelineDataItemOfIndex:` / `onTimelineDataChanged…` | WCFacade 原生方法（头文件 L357/415/421/422/426/435/437/485/563 实证） | ✅ 原生 API |
| 注释中的 "WCMoments 同款/同构" | 设计参考记录 | 非依赖 |
| WCMoments 的任何类/方法/状态/文件 | **未引用** | — |

**结论：Mio 数据层 = 微信原生 API 的自研薄封装。WCMoments 卸载/升级/消失，零影响。**

## 三、数据层职责终版（全部原生 API）

```
会话生命周期：
  beginSession  = beginTimeline + reloadTimelineDataItems   （开面板/预热时，一次）
  endSession    = endTimeline                                （关面板时）
拉新/翻页：
  refreshHead   = beginTimeline（重开会话）+ updateTimelineHead
  loadTail      = beginTimeline（重开会话）+ updateTimelineTail
数据直读：
  currentItems  = countOfTimelineDataItem → getTimelineDataItemOfIndex: 循环
                  → itemDict 统一字段映射 → 时间降序 → LRU 500
事件驱动：
  onTimelineDataChanged hook（原生回调）→ 尾沿防抖 0.5s → diff → patch
快照兜底：
  冷启动 count=0 期间 → 上次快照顶屏（stale 模式），数据落地自动换新
媒体：
  mediaSrc → 本地四级回落 → MioDualMediaService 注册（MD5 key）→ mioimg://
  未就绪/被清 → imgCdn 回落
```

## 四、明确不抄清单（WCMoments 有、我们刻意不做）

| WCMoments 机制 | 我们的做法 | 理由 |
|---|---|---|
| 会话状态机（session_begin/stop/unavailable、loggedIn/accepted、facadeAvailable 检查链） | begin/endTimeline 直调 + accepted 返回值检查 | 它的状态机是给它的多页面用的；我们单面板单数据流，直调更简单 |
| bridgeGeneration/bridgeBusy 推送节流 | lastJson 比对 + 0.5s 尾沿防抖 | 同目标，更简 |
| latestFeedSnapshot/pendingFeedSnapshot 快照体系 | NSUserDefaults 单 key JSON | 300-500 行规模够用 |
| mediaQueue/mediaProbeTimes/mediaRequestTimes/renderQualities 媒体管线 | 后台拷贝副本 + imgCdn 回落 | 副本方案已消除破图类问题，探测/质量是增强项 |
| pendingSeenIDs/lastSeenItemID/syncHiddenUsers | 不做（后续按需） | 角标已有 getSnsMessageCount 原生通道 |
| WCCommentListViewController 子控制器嵌入 | "查看原帖"跳回原生 | 成本/收益不匹配 |
| onFirstPageUpdated 重试循环（每秒 head 重发） | 单次 head + 事件驱动 + 用户下拉 | 原生页的循环是给它的首屏；我们面板常驻，事件驱动已覆盖 |
| Call: 动态分发接口 | 直接 msgSend 原生方法 | 少一层间接 |

## 五、验证基线（自研终版的完成定义）

1. 冷启动微信（不进原生朋友圈）→ beginSession 预热 → 点双列 → live 数据直显
2. 面板内下拉 → 新帖增量上屏（accepted 返回值检查 + 日志）
3. 滚底 → 旧帖翻页（tail）
4. 好友发新帖 → 不碰任何页面 → 30s 内自动上屏（事件驱动）
5. WCMoments 插件完全卸载 → 以上全部不受影响
6. 连续 10 次冷/热开零 crash
