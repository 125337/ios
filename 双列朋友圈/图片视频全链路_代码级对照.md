# 图片/视频全链路 · 他（WCMoments）vs 我们（Mio）· 代码级对照

> 证据等级：【反编译】= dylib 代码逐行 ｜【运行时】= GOLD trace ｜【dump】= class dump（有污染风险，仅作类名参考）
> 六段：媒体提取 → 后台导出 → scheme 服务 → 解码 → 大图浏览 → 视频链路

---

## 〇、全链路对照总图

```
【微信原生】SNS 同步落库（WCDataItem + 媒体 URL）
    ↓ 缩略图按需下载到本地缓存（原生页渲染时）
【② 媒体提取】nativePath 由 pathFor* 系列 duck-typing 取得
    （pathForSightData=视频 / pathForData/HdData/UhdData=gallery 质量 2/3/4）
【③ 后台导出】读源 → 魔数嗅探（jpg/png/heic 原字节直存，异格式才 JPEG 0.999）
    → 写自有存储 root/<sha256(mediaKey)>.<ext>
    ↓ renderKeys 就绪门槛：就绪的 key 才进 JS 行
【④ scheme 服务】<img src="wcm-cache://<accountToken>/<sha256>.<ext>">
    → host==accountToken 校验 + 白名单校验 → decodeQueue 异步读 → ImageIO 缩放服务
    ↓ 缺失 → NSURLError -1100 didFail → JS onerror → assetMiss 消息 → native 补拉
【⑤ 大图浏览】WCMYBImageBrowser → WCMYYImageDecoder 全格式解码
【⑥ 视频】extractVideoCover（AVAsset 抽帧）+ WCDownloadVideoCDNMgr 回调 → 原生播放环境
```

## 一、② 媒体提取（nativePath 从哪来）

**他**：【反编译】feed 条目处理的媒体提取未在 start 中（mediaRequestTimes 在 start，媒体读取在渲染链）。
**dylib 全量 selector 索引中不存在 getMediaWraps/getThumbImagePath/attachThumbUrl/mediaItem**——那是微信本体 WCMediaItem 的方法（我们 Mio 的 duck-typing 链），不是他的代码路径。
他实际用 `_Call` + CFString 常量 duck-typing：`pathForSightData`（视频）/ `pathForData`/`pathForHdData`/`pathForUhdData`（galleryRawPath:quality:，quality 2/3/4，size+mtime 文件签名去重）→ nativePath 传入 exportImage。

**我们（MioDualTimelineStore.itemDict 现状）**：
```objc
if ([item respondsToSelector:@selector(getMediaWraps)]) {
    NSArray *wraps = getMediaWraps(item);
    for (id wrap in wraps) {
        id mi = [wrap respondsToSelector:@selector(mediaItem)] ? mediaItem(wrap) : nil;
        NSString *src = [self mediaSrc:mi itemID:itemID];   // 四级路径回落
        if (!src && _lastMediaPending) mediaPending = YES;  // 有图未就绪（等补图）
        ...
    }
}
// 分享帖标题回落（WCMediaItem L25-26 同款）：
if (!content.length && firstMi) content = firstMi.title ?: firstMi.desc;
// 分享帖封面：attachThumbUrl 直连（四件套路径拿不到）✓ 已实现
```
判定：✅ 同构。

## 二、③ 后台导出（exportImage 管线）

**他**【反编译】exportImage 本体 @0x32700 选择器序列：
```
pendingExports → containsObject:（去重：同图不重复导出）
pendingOriginalExports → count（quality>1 原图通道独立去重）
assetHandler → accountToken（CDN 鉴权）
previewQueue / mediaQueue → addOperationWithBlock:（后台入队）
cf_quality（质量参数）
```

**导出块** @0x32ff4（真正干活的部分）：
```
dataWithContentsOfFile_options_error_(1)       ← 读源（微信缩略图）
魔数嗅探                                        ← FF D8=jpg / PNG 签名 / ftyp heic|heix|mif1|msf1=heic
  → jpg/png/heic：原字节直存（只定扩展名，不转码）
  → 其余格式：UIImageJPEGRepresentation(0x3fef5c28f5c28f5c)  ← JPEG 0.999（条件式转码）
_Digest(mediaKey) = CC_SHA256 → 64 位 hex      ← key 算法（非 base62）
FileManager fileExistsAtPath_                  ← 查目标
writeToFile_options_error_(0x40000001)         ← 写自有存储（原子+保护）
dispatch_async(main, block_invoke_2)           ← 完成回调回主线程（更新 renderKeys + 推 JS）
```

**我们（MioDualMediaService 现状）**：
```objc
- (void)registerLocalPath:p itemID:cdnURL:completion: {
    NSString *dst = stablePathForKey(key);                // Caches/mio_dual_media/<key>.jpg
    if (isReady(dst)) { cb(key, YES); return; }           // 副本已在（_ready 缓存命中免 stat）
    if (fileSize(path) < 1024) {                          // ★ 占位闸门（<1KB = 未下载完）
        recordEntry({p,iid,cdn}); cb(key, NO); return;    // 只登记，cb(NO)，本轮文本卡
    }
    [_exportQueue addOperationWithBlock:^{                // ★ 后台导出（NSOperationQueue，2 并发）
        jpg/png 直拷；heic/gif 等异格式解码 → JPEG 0.999;  // 格式归一（WKWebView 不支持 HEIC）
        markReady(key); gMediaEpoch++;                    // 就绪标记 + 补图重映射触发
        notifyDataChanged;                                // 触发 diff 补图
        cb(key, YES);
    }];
}
```
判定：✅ **同构**（后台队列/去重/就绪门槛/转码全有；我们多占位闸门，他多原图通道）。

## 三、④ scheme 服务（WebView 图片请求的响应）

**他**【反编译】@0x41e0 选择器序列：
```
lastPathComponent          ← key 提取（URL 尾段）
URL.host + accountToken    ← host 段校验（accountToken = SHA256 摘要，非 CDN 鉴权）
characterSet + invertedSet + rangeOfCharacterFromSet_  ← key 字符校验（[A-Za-z0-9_] 白名单，
                                                          另禁止 "_" 前缀，防路径穿越）
root                       ← 自有存储根目录
mainScreen.bounds + scale  ← 屏幕适配（target = (w-40)*scale/2 + 64，min 512——我们逐字同款）
decodeQueue                ← 异步解码/读取队列
didFailWithError_          ← 校验失败/文件缺失失败路径（不挂起；缺失 = NSURLErrorDomain -1100）
```
解码块 @0x4968：displayCache（URL → {data, mime}，cost=length）→ **ImageIO 管线**
（CGImageSource 属性/方向翻转/thumbnail max pixel [1024,2048] clamp/CGImageDestination 重编码）。
assetMiss = **JS→native script message**（img onerror 上报 → native 补拉），与 fail-fast 组成闭环。

**我们（MioDualSchemeHandler 现状）**：mioimg:// **异步 serve**——resolveKey（稳定副本优先 → 原路径回落 + 自动补拷）→ displayCache(240) 命中直返 → 专属串行 decodeQueue（QOS UTILITY）后台读+解码+缩放+JPEG 0.8 → 主线程交付；activeTasks 去重（滚过去的图不解码）+ cancelledTasks 对已停 task 防崩。缺失路径：1x1 透明 PNG HTTP 200（永不 didFail，no-store）+ 渲染层 ensureMediaForKey → WCMediaDownloader（微信管线 CDN+解密+落盘）→ mediaReadyForKey 精准重载对应 img。
判定：✅ **同构**（异步 decodeQueue 已落地）。差异点：他 fail-fast（错误回调 + assetMiss 被动补拉），我们 zero-fail（占位 200 + 视口主动备图）。

## 四、⑤ 解码（WCMYYImageDecoder——YYImage fork）

【dump】WCMYYImageDecoder：initWithData:scale:decodeDecision: / frameAtIndex:decodeForDisplay: / initWithCGImage:scale_orientation:。
【反编译】@0x695a8：decoderWithData_scale_ → frameAtIndex_decodeForDisplay_（首帧解码）→ initWithCGImage_scale_orientation_（方向校正）。
动图：WCMYYAnimatedImageView + blendFromIndex/isFullSize（帧混合）。
**判定**：⚪ 我们无此层——大图浏览器/原图通道均未实现（无 YB fork，panel.js 无图片点击处理）；WebP/GIF 仅靠 WKWebView 系统解码顺带支持（iOS 14+ WebP），卡片场景够用，非对齐。
