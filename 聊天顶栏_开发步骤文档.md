## 一、v18 修复为何失败

### 1.1 `view.window` 阻断聊天顶栏

`viewDidLoad` 在 UIKit 生命周期中的调用时机是**view 加载完成后**，此时 view 还**未加入 window**。view 加入 window 发生在后续的布局/呈现阶段（present/push 动画中）。

```objc
// v18 添加的检查——在 viewDidLoad 中 view.window 永远为 nil！
if (![self isViewLoaded] || ![self view].window) return;
```

结果：**所有 VC（包括用户真正进入的聊天页）都被跳过**，聊天顶栏完全不显示。

### 1.2 仍是闪退——说明根因不是我们业务逻辑

即使 hook 代码变成几乎空操作（`view.window` 检查后立即 return），闪退依然发生。这证明：

> 闪退的根因**不是**我们的 hook 在预加载 VC 上做 GetContact / 修改 navigationItem / 访问 MMServiceCenter 这些业务操作。

根因在更底层。

### 3.2 Objective-C 运行时类名冲突机制

```
两个 dylib 加载顺序（从 crash log usedImages 表确认）：
  Mio_arm64-1.dylib       base=4792762368  ← 先加载
  微信优化1.6.5.dylib     base=4798218240  ← 后加载

运行时行为：
  Step 1: Mio_arm64-1 加载 → objc_registerClass("CSChatAvatarTitleView") ✓
  Step 2: 微信优化 加载 → objc_registerClass("CSChatAvatarTitleView") ✗ 被拒绝！
          → 运行时打印警告：Class CSChatAvatarTitleView is implemented in both
            Mio_arm64-1.dylib and 微信优化1.6.5.dylib. One of the two will be used.
          → 微信优化的 objc::class_t::CSChatAvatarTitleView 引用通过 dyld 绑定
            解析到 Mio_arm64-1 的类对象
```

### 3.3 类名冲突导致的崩溃链路

```
阶段 1：微信优化 hook_viewDidLoad 执行
  └→ [[CSChatAvatarTitleView alloc] initWithFrame:...]  ← 创建的是 Mio_arm64-1 的类实例！
    └→ 调用 Mio_arm64-1 的 initWithFrame: 实现
    └→ 调用 Mio_arm64-1 的 setupSubviews  ← 创建 5 个子视图（Mio_arm64-1 的 ivar 布局）
    └→ Mio_arm64-1 的 ivars: leftAvatarView, rightAvatarView, separatorView, titleLabel, subtitleLabel, ...

阶段 2：微信优化 hook_viewDidLoad 继续
  └→ [view setChatController:self]  ← Mio_arm64-1 的实现（assign 属性）
  └→ [view layoutSubviews]  ← Mio_arm64-1 的实现
    └→ 访问 Mio_arm64-1 的 ivar 布局
    └→ 调用 PluginConfig.shared（Mio_arm64-1 的配置读取逻辑）
    └→ 微信优化的代码预期走自己的 CSChatAvatarTitleView::layoutSubviews

阶段 3：微信优化 hook_viewWillAppear 执行
  └→ [titleView updateAvatars]  ← 实际执行 Mio_arm64-1 的 updateAvatars！
    └→ Mio_arm64-1 的 updateAvatars 调用：
      - [self.chatController GetContact]  ← 微信优化创建的 VC，通过 KVC 访问
      - loadAvatarWithPriorityForWxid: → MMServiceCenter → MMHeadImageMgr
      - getSelfWxid → MMServiceCenter → CContactMgr → getSelfContact
      - 设置 leftAvatarView.image = ...
      - 设置 titleLabel.text = ...
    └→ 这些操作使用了 Mio_arm64-1 的 ivar 和逻辑，但执行时机/顺序是微信优化决定的

阶段 4：冲突爆发
  └→ Mio_arm64-1 的 CSChatAvatarTitleView 方法在微信优化的执行上下文中运行
  └→ ivar 布局可能不同 → 访问到错误内存 → 数据损坏
  └→ PluginConfig 被两个 dylib 同时访问 → 共享 NSUserDefaults（这个相对安全）
  └→ 但 navigationItem.titleView 被替换为 Mio_arm64-1 的类实例
  └→ 微信优化后续在 NewMainFrameViewController::tableView:cellForRowAtIndexPath: 中
      可能通过导航栈引用到这个对象
  └→ 微信优化的 cell 渲染 dispatch_async 块中捕获了损坏的引用
  └→ dispatch_async 内部尝试处理 → EXC_BAD_ACCESS at 0x54
```

### 3.4 为什么单独注入不崩溃

| 场景 | CSChatAvatarTitleView 来源 | 冲突？ |
|------|--------------------------|--------|
| 只有 Mio_arm64-1 | Mio_arm64-1 自己的类 | 无冲突，类的创建和使用在同一个 dylib |
| 只有微信优化 | 微信优化自己的类 | 无冲突，类的创建和使用在同一个 dylib |
| **两个同时注入** | Mio_arm64-1 的类（先注册），微信优化的代码也在用 | **冲突：两个 dylib 共享同一个类对象，但预期不同的实现** |

### 3.5 为什么 `0x54` 崩溃

`dispatch_async(queue, block)` 内部的崩溃发生在 `0x54`（84 字节偏移）：

- 微信优化在 `NewMainFrameViewController` 的 cell 渲染中，通过某个 block 捕获了 `CSChatAvatarTitleView` 实例的引用
- 该实例实际是 Mio_arm64-1 的类对象，但微信优化的代码按自己的 ivar 布局访问了错误偏移
- 被损坏的内存最终表现为一个块内捕获的 dispatch queue 指针损坏
- `dispatch_async` 尝试访问该 queue → 读取地址 `0x54` → SIGSEGV

### 4.4 关键新增：`UINavigationController::pushViewController:animated:` hook

这是微信优化在第 L36413 行做的 hook，作用是在每次导航跳转时**统一拦截和注入**，而非仅依赖 VC 自身的 `viewDidLoad`。

```objc
// ============================================================
// Hook: UINavigationController::pushViewController:animated:
// ============================================================
static IMP _orig_UINavigationController_pushViewController = NULL;

static void hook_pushViewController(id self, SEL _cmd, id viewController, BOOL animated) {
    // 调用原始实现
    ((void (*)(id, SEL, id, BOOL))_orig_UINavigationController_pushViewController)
        (self, _cmd, viewController, animated);

    // 检查是否为 BaseMsgContentViewController（聊天页）
    Class msgCls = objc_getClass("BaseMsgContentViewController");
    if (!msgCls || ![viewController isKindOfClass:msgCls]) return;

    PluginConfig *config = [PluginConfig shared];
    if (!config.showChatAvatar) return;

    // 获取 contact（KVC）
    id contact = ((id (*)(id, SEL))objc_msgSend)(viewController,
        NSSelectorFromString(@"GetContact"));
    if (!contact) return;

    NSString *username = ((id (*)(id, SEL))objc_msgSend)(contact,
        NSSelectorFromString(@"m_nsUsrName"));
    if (isContactInBlacklist(username)) return;

    // 创建 MioChatAvatarTitleView（类名已改为唯一名）
    CGFloat width = config.chatTitleViewWidth > 0 ? config.chatTitleViewWidth : 210.0;
    MioChatAvatarTitleView *view = [[MioChatAvatarTitleView alloc]
                                     initWithFrame:CGRectMake(0, 0, width, 45)];
    [view setChatController:(BaseMsgContentViewController *)viewController];

    [[viewController navigationItem].titleView removeFromSuperview];
    [[viewController navigationItem] setTitleView:view];
    [view layoutSubviews];
    [view release];
}

// 在 +install 中注册
+ (void)install {
    // ... 原有 BaseMsgContentViewController hooks ...
    
    // 新增：UINavigationController hook（对齐微信优化 L36413）
    Class navCls = objc_getClass("UINavigationController");
    if (navCls) {
        MSHookMessageEx(navCls, @selector(pushViewController:animated:),
                        (IMP)hook_pushViewController,
                        &_orig_UINavigationController_pushViewController);
        WPLog(@"ChatTopBar", @"[Hook] ✓ UINavigationController::pushViewController:animated:");
    }
}
```

### 4.5 关键删除：移除 v18 的 `view.window` 检查

v18 在 `hook_viewDidLoad` 和 `hook_viewWillAppear` 中添加的以下代码**必须删除**：


## 五、Hook 时序与冲突避免机制

### 5.1 两个 dylib 同时注入时的 Hook 链

```
用户打开聊天页：

UINavigationController::pushViewController:animated: 被调用
  ├── 我们的 hook_pushViewController 执行
  │     └── [viewController isKindOfClass:BaseMsgContentViewController]? YES
  │     └── 创建 MioChatAvatarTitleView（唯一类名，不冲突）
  │     └── [[viewController navigationItem] setTitleView:view]
  │
  ├── 微信优化的 hook_pushViewController 执行（L36413）
  │     └── 微信优化的内部处理（期望 CSChatAvatarTitleView 自己做它的 titleView）
  │     └── 因为类名不同，不干扰我们的 MioChatAvatarTitleView
  │
  └── 原始 pushViewController:animated: 执行

随后 BaseMsgContentViewController::viewDidLoad 被调用：
  ├── 我们的 hook_viewDidLoad 执行
  │     └── 检查是否已有 MioChatAvatarTitleView 作为 titleView
  │     └── 如果 pushViewController hook 已经创建 → skip
  │     └── 如果还没创建（回退到聊天页） → 创建
  │
  └── 微信优化的 hook_viewDidLoad 执行（L13285）
        └── 创建 CSChatAvatarTitleView（微信优化自己的类）
        └── 因为类名不同，与我们的 MioChatAvatarTitleView 并存
```

### 5.2 关键防冲突策略

1. **类名唯一化**：`MioChatAvatarTitleView` ≠ `CSChatAvatarTitleView`，两个类在运行时完全独立
2. **`isKindOfClass` 检查**：hook 中检查当前 titleView 的类型，避免重复替换
3. **关联对象隔离**：每个 dylib 使用自己的 key 保存原始 titleView
4. **Hook 位置对齐**：hook 微信优化 hook 过的类，保证执行顺序可预测

## 七、修改后的 ChatTopBarHook.m 完整代码

```objc
#import "ChatTopBarHook.h"
#import "MioChatAvatarTitleView.h"
#import "../../Config/PluginConfig.h"
#import "../../Config/Constants.h"
#import "../../Core/LogManager.h"
#import <substrate.h>
#import <objc/runtime.h>
#import <objc/message.h>

// Original IMPs
static IMP _orig_BaseMsgContentVC_viewDidLoad    = NULL;
static IMP _orig_BaseMsgContentVC_viewWillAppear  = NULL;
static IMP _orig_UINavigationController_push       = NULL;

// associatedObject key
static const void *kOriginalTitleViewKey = &kOriginalTitleViewKey;

// ============================================================
// 黑名单匹配
// ============================================================
static BOOL isContactInBlacklist(NSString *contactID) {
    if (!contactID.length) return NO;
    NSString *blacklist = [[NSUserDefaults standardUserDefaults]
        stringForKey:[kPluginPrefix stringByAppendingString:@"ChatAvatarBlacklist"]];
    if (!blacklist.length) return NO;

    NSArray *lines = [blacklist componentsSeparatedByString:@"\n"];
    BOOL isGroup = [contactID containsString:@"@chatroom"];

    for (NSString *line in lines) {
        NSString *t = [line stringByTrimmingCharactersInSet:
                        [NSCharacterSet whitespaceCharacterSet]];
        if (!t.length) continue;
        if (isGroup && [t isEqualToString:@"@"]) return YES;
        if ([contactID hasPrefix:@"gh_"] && [t hasPrefix:@"gh_"]) return YES;
        if ([t isEqualToString:contactID]) return YES;
        if (isGroup && [contactID containsString:t]) return YES;
    }
    return NO;
}

// ============================================================
// Hook: viewDidLoad
// ============================================================

                                     originalTitleView,
                                     OBJC_ASSOCIATION_RETAIN_NONATOMIC);

    id currentTitle = [[self navigationItem] titleView];

    // 获取 contact
    id contact = ((id (*)(id, SEL))objc_msgSend)(self, NSSelectorFromString(@"GetContact"));
    if (!contact) return;

    NSString *username = ((id (*)(id, SEL))objc_msgSend)(contact, NSSelectorFromString(@"m_nsUsrName"));
    if (isContactInBlacklist(username)) return;

    // 创建 MioChatAvatarTitleView（已改名）
    CGFloat width = config.chatTitleViewWidth > 0 ? config.chatTitleViewWidth : 210.0;
    MioChatAvatarTitleView *view = [[MioChatAvatarTitleView alloc]

    [view setChatController:(BaseMsgContentViewController *)self];

    [[self navigationItem].titleView removeFromSuperview];
    [[self navigationItem] setTitleView:view];
    [view layoutSubviews];
    [view release];
}

            [[self navigationItem] setTitleView:originalTitle];

    [currentTitle layoutIfNeeded];
```

## 八、MRC 内存管理要点

1. **`MioChatAvatarTitleView` 与 `CSChatAvatarTitleView` 完全独立**：不再有类名冲突
2. **关联对象用 `OBJC_ASSOCIATION_RETAIN_NONATOMIC`**：宿主 dealloc 自动 release
3. **`chatController` 用 `assign`**：VC 生命周期 ≥ titleView 生命周期
4. **`alloc init` → `[view release]`**：setTitleView 会 retain
5. **`pushViewController:animated:` hook 中：push 先于 titleView 设置**（微信优化同样如此），确保 VC 的导航环境已就绪
