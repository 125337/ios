## 一、两个 Crash 深度分析

### 1.1 Crash 1：`WeChat-2026-05-27-115239(1).ips` — 会话列表滑动闪退

| 项目 | 值 |
|------|-----|
| 异常 | `EXC_BAD_ACCESS` (SIGSEGV) at `0x54` |
| 触发 | 会话列表页上下滑动 |
| 崩溃位置 | UIKit `_updateVisibleCellsForRanges:` → `_createPreparedCellForGlobalRow:` → `_notifyWillDisplayCell:` |

**根因：微信优化 1.6.5 的 `NewMainFrameViewController` hook**

123456.c L30218-30220：
```c
uVar1 = _objc_getClass("NewMainFrameViewController");
_MSHookMessageEx(uVar1, "tableView:cellForRowAtIndexPath:", FUN_000323f0, &DAT_0013ad20);
```

`NewMainFrameViewController` 就是微信的**会话列表页**！微信优化 hook 了它的 `tableView:cellForRowAtIndexPath:` 方法。这个全局 hook 在 cell 创建/复用过程中，如果遇到数据状态不一致（比如 `_sections` 数组被其他插件修改），就会产生野指针。

**与项目的关系**：项目 hook 的是 `BaseMsgContentViewController`（聊天对话页），不是 `NewMainFrameViewController`（会话列表页）。但两者操作的是**同一套微信内部 cell 体系**（`CSSettingTableViewCell`、`CContact` 数据模型等）。当项目修改导航栏 titleView 时可能间接触发 view 层级刷新，与微信优化的 cell hook 产生竞态。

**解决方案**：在 ChatTopBarHook 中增加保护——仅当 `self` 确实是 `BaseMsgContentViewController` 且不在会话列表时才执行 hook 逻辑。

### 1.2 Crash 2：`WeChat-2026-05-27-115246(1).ips` — 点击进入详情页闪退（项目 bug！）

```
exceptionReason:
"-[ContactInfoViewController setContact:]: unrecognized selector sent to instance 0x13b865600"
```

**这是项目自己的 bug！** crasn 调用栈明确显示在 `Mio_arm64-1.dylib`（`imageOffset:41720, imageIndex:17`），即 `onHomepageTapped` 方法中。

**根因**：`ContactInfoViewController` 类**存在**，但它**没有 `setContact:` 方法**。

123456.c 的做法（L118375-118386）：
```c
auVar7 = _objc_alloc_init();                              // [[ContactInfoViewController alloc] init]
uVar6 = auVar7._0_8_;
FUN_000ce560(uVar6, auVar7._8_8_, lVar4, &cf_m_contact);  // [vc setValue:contact forKey:@"m_contact"]
```

`FUN_000ce560` 是 `setValue:forKey:` ——用 **KVC** 直接设置 ivar `m_contact`，而不是调 `setContact:`。

**修复**：将 `setContact:` 改为 KVC `setValue:forKey:@"m_contact"`。

#### 差异 3：圆角卡片

## 六、MRC 注意事项

1. `[[UITableViewCell alloc] initWithStyle:reuseIdentifier:]` 返回 retain count +1 — cell 赋值后由 tableView 管理，**不需要手动 release**（table view 在 cell 移除时会 release）
2. KVC `setValue:forKey:` 的 value 参数如果是 `self.contact`（retain 属性），MRC 下 pass 的是 retained 对象，无需额外 retain
3. `dispatch_once` 中的 `[@[...] retain]` — `s_infoItems()` 静态数组需在 dylib 卸载时 release
4. Auto Layout 约束在 MRC 下正常工作，`translatesAutoresizingMaskIntoConstraints = NO` 是 BOOL 赋值，不需要内存管理
5. `onHomepageTapped` 的 dismiss completion block 中 `[vc release]` — 对应 `alloc] init]` 的 retain，必须在 push 或 block 结束前 release
