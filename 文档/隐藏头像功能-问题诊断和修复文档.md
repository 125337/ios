# 隐藏头像功能 - 问题诊断和修复文档 (修正版)

## 一、诊断结论

**真正根因：KVC (`valueForKey:`) 无法正确获取微信的内部属性，必须改用 `objc_msgSend` 直接方法调用。**

### 反编译代码中的关键证据

| 反编译函数 | 行号 | 实际调用 | 我们之前的实现 | 问题 |
|---|---|---|---|---|
| `FUN_000c2420` | L127435 | `[self GetContact]` (objc_msgSend) | `[self valueForKey:@"m_contact"]` (KVC) | ❌ KVC 与 `GetContact` 方法不是同一路径 |
| `FUN_000c7b40` | L133728 | `[contact m_nsUsrName]` (objc_msgSend) | `[contact valueForKey:@"m_nsUsrName"]` (KVC) | ⚠️ 可能因为#1失败而从未执行到 |
| `FUN_000c6f20` | L132854 | `[viewModel isSender]` (objc_msgSend) | `[[self valueForKey:@"isSender"] boolValue]` (KVC) | ⚠️ 同上 |

### 故障链路

```
进入聊天页
  → viewDidLoad Hook 触发 ✓ (反编译代码确认类名正确)
  → updateChatContext 被调用 ✓
  → [self valueForKey:@"m_contact"] ★ KVC 失败 ★
  → @catch 捕获异常, _currentChatType = MOChatTypeUnknown
  → 静默返回 (无日志)

消息渲染
  → isShowHeadImage Hook 触发 ✓ (反编译代码确认类名正确)
  → _currentChatType == MOChatTypeUnknown → 直接返回原始值
  → 静默返回 (无日志)
  → 头像正常显示 (配置未被使用)
```

### KVC vs objc_msgSend 的本质差异

```objc
// KVC 的搜索顺序 (valueForKey:@"m_contact"):
//  ① getM_contact (方法)
//  ② m_contact (方法)
//  ③ isM_contact (方法)
//  ④ _m_contact (ivar)
//  ⑤ _isM_contact (ivar)
//  ⑥ m_contact (ivar)
//  ⑦ isM_contact (ivar)

// 微信实际暴露的是:
//  [self GetContact]    ← 方法, 但大小写不匹配 KVC 规则
//  KVC 找不到这个属性 → 抛异常

// 正确做法 (对齐反编译):
//  ((id (*)(id, SEL))objc_msgSend)(self, @selector(GetContact))
//  直接调用方法, 不经过 KVC 搜索
```

## 二、修复方案

### 唯一修改文件：`HideAvatarHook.m`

替换三处 KVC 调用为 `objc_msgSend` 直接方法调用：

| 位置 | 修改前 (KVC) | 修改后 (objc_msgSend) |
|------|-------------|---------------------|
| 获取联系人 | `[self valueForKey:@"m_contact"]` | `((id (*)(id, SEL))objc_msgSend)(self, NSSelectorFromString(@"GetContact"))` |
| 获取用户名 | `[contact valueForKey:@"m_nsUsrName"]` | `((id (*)(id, SEL))objc_msgSend)(contact, NSSelectorFromString(@"m_nsUsrName"))` |
| 获取isSender | `[[self valueForKey:@"isSender"] boolValue]` | `((BOOL (*)(id, SEL))objc_msgSend)(self, NSSelectorFromString(@"isSender"))` |

### 完整修复代码

```objc
// updateChatContext - 获取联系人
contact = ((id (*)(id, SEL))objc_msgSend)(self, NSSelectorFromString(@"GetContact"));

// updateChatContext - 获取用户名  
username = ((id (*)(id, SEL))objc_msgSend)(contact, NSSelectorFromString(@"m_nsUsrName"));

// hook_isShowHeadImage - 获取isSender
isSender = ((BOOL (*)(id, SEL))objc_msgSend)(self, NSSelectorFromString(@"isSender"));
```

### 注意：`GetContact` 方法名的大小写

微信优化反编译代码 L127435 显示方法是 `GetContact`（大写 G），不是 `getContact`（小写 g）。这是微信内部的命名风格，`NSSelectorFromString(@"GetContact")` 必须精确匹配。

## 三、验证方法

编译安装后，日志应出现：

```
[HideAvatar] viewDidLoad triggered
[HideAvatar] updateChatContext: username=wxid_xxx chatType=1
[HideAvatar] isShowHeadImage called: chatType=1 isSender=0 hide=1 orig=1
```

如果仍不出现 `viewDidLoad triggered`，先检查日志中是否有 `[HideAvatar] [Hook] ✓ BaseMsgContentViewController` 确认 Hook 安装成功。

## 四、之前的错误诊断（已废弃）

之前错误地认为 `BaseMsgContentViewController` 和 `CommonMessageViewModel` 类在当前微信版本中不存在。这个诊断是错误的，证据如下：

1. 微信优化在当前版本依旧可用 → 说明这些类存在
2. 反编译代码中的类名是直接嵌入二进制字符串，不经过 cfstring 表转换 → 类名是精确的
3. `MSHookMessageEx` 日志显示 Hook 全部安装成功 → `objc_getClass` 返回了有效类

错误根因是 KVC vs 方法调用路径的差异，而非类/方法不存在。

## 五、经验教训

在 iOS Tweaks 开发中，获取微信内部属性时：

- ❌ **不要用 `valueForKey:`** — KVC 有固定的搜索顺序，微信的内部方法/ivar 命名不一定符合 KVC 规则
- ✅ **用 `objc_msgSend` 调用实际方法** — 与反编译代码一致，直接调用方法不经过 KVC 搜索
- ✅ **方法名必须精确匹配反编译代码** — 注意大小写（如 `GetContact` vs `getContact`）
