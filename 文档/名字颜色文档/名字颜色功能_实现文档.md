# 微信优化插件 - 名字颜色功能实现文档

## 一、功能概述

名字颜色功能用于自定义微信聊天界面和朋友圈中用户昵称的显示颜色。该功能通过 **Hook 微信原生消息 Cell 的渲染流程**，在消息文本布局时动态替换昵称部分的文字颜色，支持浅色/深色模式双配色，以及字体大小调整。

### 涉及的能力维度
| 维度 | 聊天界面 | 朋友圈 |
|------|---------|--------|
| 名字颜色自定义 | 已完成 Hook | 仅 UI 配置（未实现 Hook） |
| 名字字体大小 | 已完成 Hook | 仅 UI 配置（未实现 Hook） |

### 4.2 TintHook - 核心名字颜色 Hook

**文件**：[TintHook.m](file:///www/wwwroot/ios/WeChatPlugin/Modules/Layout/TintHook.m)

#### 4.2.1 install 方法

```objc
+ (void)install {
    for (NSString *cls in @[@"SystemMessageCellView",
                             @"TextMessageCellView",
                             @"CommonMessageCellView",
                             @"BaseMessageCellView"]) {
        hookCellColor(cls);
    }
}
```

Hook 的目标类是微信的 **四种消息 Cell 视图**：
- `SystemMessageCellView` - 系统消息（如"XX撤回了一条消息"）
- `TextMessageCellView` - 文本消息
- `CommonMessageCellView` - 通用消息
- `BaseMessageCellView` - 基类消息

对每个类的 `updateStatus` 和 `layoutContentView` 方法进行 Method Swizzling。

#### 4.2.2 hookCellColor 实现

```objc
static void hookCellColor(NSString *className) {
    Class cls = objc_getClass(className.UTF8String);
    if (!cls) return;

    for (NSString *methodName in @[@"updateStatus", @"layoutContentView"]) {
        SEL sel = NSSelectorFromString(methodName);
        Method m = class_getInstanceMethod(cls, sel);
        if (!m) continue;

        // 保存原始 IMP
        IMP origIMP = method_getImplementation(m);
        [gTintOrigIMPs setObject:[NSValue valueWithPointer:origIMP] forKey:key];

        // 替换为新的 Block IMP
        IMP newIMP = imp_implementationWithBlock(^void(id self) {
            // 先调用原始实现
            IMP orig = [impValue pointerValue];
            ((void (*)(id, SEL))orig)(self, sel);

            // 再执行自定义颜色处理
            tintRevokeCell(self);
        });

        method_setImplementation(m, newIMP);
    }
}
```

**关键机制**：
1. 通过 `imp_implementationWithBlock` 创建替换 IMP
2. Block 内先调用原始实现确保 Cell 正常布局
3. 然后在原始布局基础上修改 AttributedText 的颜色属性
4. 全局字典 `gTintOrigIMPs` 保存原始 IMP 指针以便调用

#### 4.2.3 tintRevokeCell - 颜色替换核心逻辑

```objc
static void tintRevokeCell(id cell) {
    // 1. 获取消息包装对象 CMessageWrap
    // 2. 检查是否为撤回消息（content 包含"撤回"）
    // 3. 解析消息内容格式：
    //    "HH:mm:ss\n「名字」撤回了一条消息"
    //    \____←time____/  \_____←content area______/
    //
    // 4. 获取 RichTextView
    // 5. 基于 existing AttributedText 创建 NSMutableAttributedString
    // 6. 设置三个颜色区域：
    //    - 时间行 → [config timeColor]
    //    - 「名字」→ [config nameColor]  ★名字颜色核心
    //    - 其余文本保持原色
    // 7. setAttributedText + setNeedsDisplay
}
```

**名字解析逻辑**（[TintHook.m:40-48](file:///www/wwwroot/ios/WeChatPlugin/Modules/Layout/TintHook.m#L40-L48)）：

```objc
// 在正文区域（\n 之后）搜索双引号包裹的名字
NSRange nameSearch = [ma.string rangeOfString:@"\"" options:0 range:contentStart];
if (nameSearch.location != NSNotFound) {
    // 找到结束的引号
    NSRange nameEnd = [ma.string rangeOfString:@"\"" options:0 
        range:NSMakeRange(nameSearch.location + 1, ma.length - nameSearch.location - 1)];
    if (nameEnd.location != NSNotFound) {
        NSRange nameRange = NSMakeRange(nameSearch.location, 
            nameEnd.location - nameSearch.location + 1);
        // ★ 核心：用 [config nameColor] 设置引号内名字的颜色
        [ma addAttribute:NSForegroundColorAttributeName 
                   value:[config nameColor] 
                   range:nameRange];
    }
}
```

#### 4.3.3 nameColor 方法 - 颜色获取入口

[PluginConfig.m](file:///www/wwwroot/ios/WeChatPlugin/Config/PluginConfig.m#L630-L636)：

```objc
- (UIColor *)nameColor {
    if (!_customColorsEnabled) {
        // 用户未启用自定义颜色 → 返回默认红色
        return [UIColor colorWithRed:250.0/255.0 
                               green:81.0/255.0 
                                blue:81.0/255.0 
                               alpha:1.0];  // #FA5151
    }
    // 根据深色/浅色模式选择对应颜色 hex
    return [self colorFromHex:[self isDarkMode] ? _darkNameColorHex : _nameColorHex]
        ?: [UIColor colorWithRed:250.0/255.0 green:81.0/255.0 blue:81.0/255.0 alpha:1.0];
}
```

**逻辑**：
1. 检查 `customColorsEnabled` 是否启用
2. 判断当前系统是否为深色模式 (`UITraitCollection.current.userInterfaceStyle`)
3. 从对应 hex 字符串解析颜色
4. 解析失败则 fallback 到默认红色 `#FA5151`

#### 4.3.4 颜色工具方法

```objc
- (UIColor *)colorFromHex:(NSString *)hex;  // "#FA5151" → UIColor
- (NSString *)hexFromColor:(UIColor *)color; // UIColor → "#RRGGBB"
- (BOOL)isDarkMode;                          // 检测系统深色模式
```

#### 4.3.5 持久化

所有配置通过 `NSUserDefaults` 持久化，键名前缀 `WCP_`（kPluginPrefix）。核心流程：

```
loadDefaults() → 从 NSUserDefaults 读取 → 填充属性
save()         → 将属性写入 NSUserDefaults → synchronize
resetAllConfig() → 清除所有 WCP_ 前缀的配置 → reloadDefaults
```

## 七、关键设计决策

### 7.1 为什么 Hook `updateStatus` 和 `layoutContentView`？

| 方法 | 用途 | 触发时机 |
|------|------|---------|
| `updateStatus` | 更新消息状态（发送中/已送达/已读） | 状态变化时 |
| `layoutContentView` | 布局消息内容视图 | Cell 创建和复用阶段 |

Hook 这两个方法可以覆盖消息 Cell 的**初始化布局**和**运行时更新**两个场景，确保名字颜色在各种情况下都能正确应用。

### 7.2 为什么通过 AttributedText 而非直接设置 Label 颜色？

微信的消息 Cell 使用 `RichTextView`（富文本组件），内容已经是 `NSAttributedString` 格式。直接修改 AttributedText 的 `NSForegroundColorAttributeName` 属性：
- 不需要重新计算布局
- 避免与微信自身的样式冲突
- 兼容各种消息类型

### 7.3 为什么使用 `imp_implementationWithBlock` 而非 MSHookMessageEx？

[libsubstrate](file:///www/wwwroot/ios/WeChatPlugin/libs/substrate.h) 是 Cydia Substrate 的标准 hook 库。TintHook 选择直接使用 Objective-C Runtime 的 Method Swizzling：
- 不需要额外依赖 Cydia Substrate
- 性能开销更小
- 足够应对本功能的简单场景

### 7.4 深色/浅色模式双配色

```
                              ┌── isDarkMode? ──→ YES → darkNameColorHex (#FF6B6B)
nameColor() → customColorsEnabled?
                              └── isDarkMode? ──→ NO  → nameColorHex    (#FA5151)
```

系统深色模式切换时，`UITraitCollection.currentTraitCollection.userInterfaceStyle` 会实时反映当前模式，确保颜色跟随切换。

## 八、当前限制与已知问题

### 8.1 朋友圈 Hook 未实现

`SettingNameColorController` 中提供了朋友圈的名字颜色和字体大小设置 UI，但在 `TintHook` 的 `install` 方法中只 Hook 了聊天消息 Cell：

```objc
// 仅 Hook 消息 Cell
@[@"SystemMessageCellView", @"TextMessageCellView", 
  @"CommonMessageCellView", @"BaseMessageCellView"]
```

**朋友圈（Moments/Timeline）的名字颜色配置已经就绪但缺少对应的 Hook 实现**。需要额外 Hook 朋友圈的昵称显示视图（通常是 `WCFinderFeedContentTextView` 或 `SnsTimelineLabel`）。

### 8.2 仅处理撤回类系统消息

`tintRevokeCell` 中有 `if (![content containsString:@"撤回"]) return;` 判断，意味着：
- 当前只对**撤回消息**（系统提示）应用颜色定制
- 普通消息中发件人昵称的颜色不受影响

### 8.3 名字解析依赖引号格式

名字解析依赖于微信的特定格式（`"名字"` 被双引号包裹），如果微信改变了消息格式，解析逻辑可能需要适配。

### 8.4 颜色设置 key 命名规范

`addColorRowInGroup` 的 `key` 参数应使用 PluginConfig 的**真实属性名**（如 `nameColorHex`、`darkNameColorHex`），与消息时间功能中 `senderTextColorHex` 等 key 保持一致。命名不当会导致颜色选择器保存时 KVC `setValue:forKey:` 写入失败。
