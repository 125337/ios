### 1.2 发现的重要修正

**修正 1：FUN_0002c284 同时处理了圆角和边框**

原分析文档说 `FUN_0002c284` 只处理文本/颜色/字体，`FUN_0002c830` 处理圆角/边框。但反编译代码 L26808-L26858 显示，`FUN_0002c284` **也在 `MMGrowTextView` 上应用了 `roundedCorners`、`cornerRadius`、`border.enabled`、`border.width`、`border.color`**。

即：**两个 Hook 函数都处理圆角和边框** — `FUN_0002c284` 应用于 `MMGrowTextView`（输入框本体），`FUN_0002c830` 应用于 `MMTransparentButton`（附属按钮）。当前项目 UI 层暂未实现圆角和边框设置项，后续可按需扩展。

**修正 2：宽度检查方向**

反编译代码 L26694 显示 `if (50.0 < in_d3) return;`（宽度 > 50 时跳过），但分析文档解读为 `width <= 50` 时跳过。这是 ARM64 浮点比较的反编译歧义。功能上分析文档的解读更合理（宽视图才需要应用样式），Hook 实现采纳分析文档的解读。

**修正 3：`inputText.bold` 键未被 Hook 使用**

反编译代码中 `cf_com.wechat.enhance.inputText.bold`（L2590）仅作为常量字符串定义，`FUN_0002c284` 中字体始终使用 `systemFontOfSize:` 创建，未读取 bold 键。bold 键仅用于设置界面。当前项目 Hook 实现中**增加了粗体支持**，因为 UI 层已提供粗体开关。

### 3.2 PlaceholderTextHook.m

**路径**: `WeChatPlugin/Modules/PlaceholderText/PlaceholderTextHook.m`

Hook 实现，对齐反编译代码 `FUN_0002c284`：

#### 执行流程

```
1. 调用原始 layoutSubviews
2. 宽度安全检查 (width <= 50 → 跳过)
3. Responder Chain 向上查找 UIViewController
4. 验证 VC 是否为 BaseMsgContentViewController 子类 (对齐 FUN_0002cbfc)
5. 检查 PlaceholderTextEnabled 开关
6. 读取 PlaceholderText_Text → 调用 setPlaceHolder:
7. 读取 PlaceholderText_ColorHex + PlaceholderText_Alpha → 调用 setPlaceHolderColor:
8. 读取 PlaceholderText_FontSize + PlaceholderText_Bold → 调用 setPlaceholderFont:
9. 调用 setPlaceHolderMultiLine:YES
```

#### 关键对齐点

| 反编译代码位置 | 功能 | Hook 实现 |
|-------------|------|----------|
| L26692 | 调用原始 layoutSubviews | `_orig_MMGrowTextView_layoutSubviews(self, _cmd)` |
| L26693-L26696 | 宽度检查 | `if (frame.size.width <= 50.0) return` |
| L26697-L26716 | Responder Chain 查找 VC | `findParentViewController()` |
| L26718 (FUN_0002cbfc) | VC 类型验证 | `isBaseMsgContentVC()` |
| L26723 | 读取 enabled 开关 | `[d boolForKey:kEnabled]` |
| L26726-L26733 | 占位文本内容 | `setPlaceHolder:` |
| L26734-L26783 | 颜色 + Alpha | `setPlaceHolderColor:` → 通过 `PluginConfig.colorFromHex:` 转换 |
| L26785-L26800 | 字体大小 + 粗体 | `setPlaceholderFont:` |
| L26801 | 多行占位 | `setPlaceHolderMultiLine:YES` |

#### UI 配置 Key → Hook 使用对照

| UI Key | 类型 | Hook 处理 |
|--------|------|----------|
| `PlaceholderTextEnabled` | BOOL | 总开关 |
| `PlaceholderText_Text` | NSString | `[self setPlaceHolder:content]` |
| `PlaceholderText_Bold` | BOOL | 选择 `systemFontOfSize:` / `boldSystemFontOfSize:` |
| `PlaceholderText_FontSize` | NSString | `safeFloat()` 解析 → `setPlaceholderFont:` |
| `PlaceholderText_ColorHex` | NSString (#RRGGBB) | `PluginConfig.colorFromHex:` → `setPlaceHolderColor:` |
| `PlaceholderText_Alpha` | NSString | `safeFloat()` 解析 → `colorWithAlphaComponent:` |

## 7. 验证测试要点

### 7.1 基础功能验证

1. 进入微信 → Mio助手 → 界面定制 → 文本占位
2. 打开「显示占位文本」开关
3. 设置占位文本内容（如 "请输入消息..."）
4. 设置字体颜色、大小、透明度
5. 进入任意聊天页面，观察输入框占位文本是否按设置显示

### 7.2 边界场景验证

| 场景 | 预期结果 |
|------|---------|
| 开关关闭 | 占位文本恢复微信默认样式 |
| 文本内容为空 | 保留微信默认占位文本 |
| 字体大小设为 0 或空 | 使用默认值 15.0 |
| 透明度设为 0 或空 | 使用默认值 0.6 |
| 颜色未设置 | 使用默认灰色 (#808080) |
| 进入非聊天页面（如发现页） | 不影响（BaseMsgContentViewController 验证过滤） |
| 多个聊天页面切换 | 每个页面的输入框都应用设置 |
