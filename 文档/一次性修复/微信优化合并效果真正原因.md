# 微信优化合并效果的真正原因

## 一句话总结

微信优化做了**两件事**，少一件都不能实现"合并"效果：

> **① 透明化 Section Header + ② 边界 cell 去圆角 = 视觉合并**

---

## 微信优化的完整算法（通讯录 section <= 3 时）

```
section = [indexPath section]
totalSections = [tableView numberOfSections]

if (section > 3) → 标准 per-section（回车）

// section 0-3 的处理：
rowCounts = [section0行数, section1行数, section2行数, section3行数]

// 条件：Section 0 必须恰好 3 或 4 行
if (rowCounts[0] > 4) → 标准 per-section（回车）

// bVar2：当前 section 是否是单行

// bVar1：section 1/2/3 是否都是 1 行
bVar1 = (rowCounts[1] == 1 && rowCounts[2] == 1 && rowCounts[3] == 1)

if (bVar1) {
    // ★ 半合并模式
    if (section == 0) {
        // per-section（首行顶角，末行底角）
    } else if (section == lastOneRowSection) {
        // 底角（最后一个单行 section）
    } else {
        // 无角（中间单行 section）
    }

}
```

**关键**：即使 bVar1=false 走 per-section，Section Header 已经被透明化了，所以 per-section 之间也没有视觉分隔！

## 为什么反编译代码看起来"> 3 section 就降级 per-section"？

这是对的，但有两层含义：

| 条件 | 行为 |
|:---|:---|
| **整体 section 数** | 不检查！不管总共有 30 个还是 5 个 section |
| **当前 cell 的 section 索引** | section ≤ 3 → 特殊算法；section > 3 → per-section |

也就是说，如果你的通讯录有 30 个 section：
- Section 0 的 cell → 进入特殊算法（合并处理）
- Section 1 的 cell → 进入特殊算法
- Section 2 的 cell → 进入特殊算法
- Section 3 的 cell → 进入特殊算法
- Section 4-29 的 cell → per-section

**每种 cell 各自走各自的分支**，不是整体判断！

## 结论

**微信优化的"合并效果" = 透明 Header + 边界去角 + per-section，三管齐下。**

MioPlugin 只做了 per-section，没做 Header 透明化和边界去角，所以看起来是分离的。
