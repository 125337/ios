# Mio助手 开发注意规范

> 最后更新: 2026-05-30
> 本文档记录项目开发中的关键规范，新增功能时务必遵守。

---

## 一、配置架构（两层设计）

```
┌─────────────────────────────────────────────────┐
│  UI 层 (KVC 访问)                                │
│  key: camelCase  →  PluginConfig.propertyName    │
│  例如: @"autoRedEnvelop"  →  .autoRedEnvelop     │
├─────────────────────────────────────────────────┤
│  存储层 (NSUserDefaults)                         │
│  key: "MioPlugin_" + PascalCase                  │
│  例如: @"MioPlugin_AutoRedEnvelop"               │
└─────────────────────────────────────────────────┘
```

**两层是独立的**：
- UI 层用 camelCase key 通过 KVC 读写 PluginConfig 属性
- 存储层用 `kPluginPrefix + PascalCase` 做 NSUserDefaults 持久化
- 两层 key 名称已经不同（2026-05-30 重构后），不需要再建映射字典

## 二、新增功能的检查清单

### 1. 在 PluginConfig.h 声明属性

```objc
// PluginConfig.h
@property (nonatomic, assign) BOOL myNewFeature;         // 开关
@property (nonatomic, assign) unsigned int myFeatureDelay; // 数值
@property (nonatomic, copy)   NSString *myFeatureText;    // 文本
```

### 2. 在 PluginConfig.m 添加持久化

**loadDefaults**:
```objc
_myNewFeature = [d boolForKey:[kPluginPrefix stringByAppendingString:@"MyNewFeature"]];
_myFeatureDelay = (unsigned int)[d integerForKey:[kPluginPrefix stringByAppendingString:@"MyFeatureDelay"]];
NSString *v = [d stringForKey:[kPluginPrefix stringByAppendingString:@"MyFeatureText"]];
_myFeatureText = v.length > 0 ? [v copy] : @"默认值";
```

**save**:
```objc
[d setBool:_myNewFeature forKey:[kPluginPrefix stringByAppendingString:@"MyNewFeature"]];
[d setInteger:(NSInteger)_myFeatureDelay forKey:[kPluginPrefix stringByAppendingString:@"MyFeatureDelay"]];
if (_myFeatureText) [d setObject:_myFeatureText forKey:[kPluginPrefix stringByAppendingString:@"MyFeatureText"]];
```

**注意**: 存储层的 key 用 PascalCase（首字母大写），这是持久化约定，与 UI 层无关。

### 3. 在控制器中创建 UI row

```objc
// ✅ 正确: key 使用 camelCase，与 PluginConfig 属性名完全一致
cy = [self addSwitchRowInGroup:group
                          title:@"启用新功能"
                           desc:nil
                            key:@"myNewFeature"      // ← 必须与属性名一致
                           isOn:config.myNewFeature
                             cy:cy
                          width:w];

*ecy = [self addInputRowInGroup:expand
                          title:@"延迟时间"
                            key:@"myFeatureDelay"    // ← 必须与属性名一致
                          value:[NSString stringWithFormat:@"%u", config.myFeatureDelay]
                           hint:@"秒"
                             cy:*ecy
                          width:w];

// ❌ 错误: 用 PascalCase key
// key:@"MyNewFeature"  ← KVC 找不到 PluginConfig 属性，永远读不到值
```

### 4. Hook 文件中读取配置

```objc
// ✅ 正确: 直接访问 PluginConfig 属性
PluginConfig *config = [PluginConfig shared];
if (!config.myNewFeature) return;

// ❌ 错误: 用 NSUserDefaults 直接读
// if (![[NSUserDefaults standardUserDefaults] boolForKey:@"MioPlugin_MyNewFeature"]) return;
// ❌ 错误: 用 KVC + PascalCase
// if (![[PluginConfig shared] valueForKey:@"MyNewFeature"]) return;
```

## 三、命名规范对照表

| 层级 | 命名风格 | 示例 | 用途 |
|------|---------|------|------|
| PluginConfig 属性 | camelCase | `autoRedEnvelop` | OC 属性声明 |
| UI row key | camelCase | `@"autoRedEnvelop"` | KVC 访问 key |
| NSUserDefaults 存储 key | MioPlugin_ + PascalCase | `@"MioPlugin_AutoRedEnvelop"` | 持久化 key |

**关键规则**: UI key 必须和 PluginConfig 属性名**完全一致**，都是 camelCase。

## 四、典型错误模式（禁止）

### 错误 1: UI key 用 PascalCase
```objc
// ❌ 错误
key:@"AutoRedEnvelop"
// 后果: KVC 找不到 PluginConfig.autoRedEnvelop，配置永远读不到

// ✅ 正确
key:@"autoRedEnvelop"
```

### 错误 2: 添加 key→property 映射字典（已废弃）
```objc
// ❌ 已删除的旧模式 - 不要再用
NSDictionary *mapping = @{@"AutoRedEnvelop": @"autoRedEnvelop"};
NSString *prop = mapping[key];
[config setValue:value forKey:prop];

// ✅ 新模式 - 直接用 key
[config setValue:value forKey:key];
```

### 错误 3: 在 Hook 中直接访问 NSUserDefaults
```objc
// ❌ 错误
BOOL enabled = [[NSUserDefaults standardUserDefaults] boolForKey:@"MioPlugin_AutoRedEnvelop"];

// ✅ 正确
BOOL enabled = [PluginConfig shared].autoRedEnvelop;
```

### 错误 4: 在 Hook 中使用 PluginConfig 的 KVC
```objc
// ❌ 不推荐 (虽然能工作，但不如直接属性访问安全)
[[PluginConfig shared] valueForKey:@"autoRedEnvelop"]

// ✅ 推荐 (编译期类型检查)
[PluginConfig shared].autoRedEnvelop
```

## 五、控制器类型说明

项目中有两类控制器，各自的 key 使用方式不同：

### A. 标准 Setting 控制器（继承 SettingCategoryController）
- 使用 `addSwitchRowInGroup`, `addInputRowInGroup`, `addColorRowInGroup` 等方法
- key 走 KVC 通路 → 必须 camelCase
- 开关变化由 `switchChanged:` (SettingEntryHook.m) 和 `switchChanged:` (SettingCategoryController.m) 处理
- 输入弹窗由 `onEditRowTap:` (SettingEntryHook.m) 处理

**涉及文件**: SettingRedEnvelopController, SettingMessageTimeController, SettingRevokeController, SettingAvatarHideController, SettingGeneralFunctionController, SettingChatTopBarController, SettingNameColorController, WPUIPurifyVC, WPOtherVC, WPUIAttachmentLayoutVC, WPUIPlaceholderTextVC

### B. 自定义逻辑控制器
- 有自己的 `onNumericRowTap:` 或 `buttonClicked:` 方法
- 内部使用 if/else 链进行 key 分发（非 KVC）
- 这些内部路由 key 可以保持 PascalCase，因为它们不经过 KVC

**涉及文件**:
- SettingChatTopBarController 的 `keyForTag:` 和 `subtitleForKey:` 中的 key（如 `@"AvatarCornerRadius"`, `@"AvatarSize"`）
- SettingNameColorController 的 `onNumericRowTap:` 中的 key（如 `@"ChatNameFontSize"`, `@"MomentsNameFontSize"`）

## 六、关联对象 key 约定

项目中用 Associated Objects 在 sender/cell 上存储元数据，key 字符串必须全局一致：

| Key | 存储位置 | 读取位置 | 用途 |
|-----|---------|---------|------|
| `"key"` | SettingCategoryController (创建行时) | switchChanged, colorButtonTapped | 配置 key |
| `"editConfigKey"` | SettingCategoryController (didSelectRow) | onEditRowTap | 输入行配置 key |
| `"editTitle"` | SettingCategoryController, WPCommonUI | onEditRowTap | 输入弹窗标题 |
| `"editValueLabel"` | SettingCategoryController, WPCommonUI | onEditRowTap, onNumericRowTap | 值标签(更新用) |
| `"editConfigHint"` | SettingCategoryController | onEditRowTap | 输入占位提示 |
| `"action"` | WPCommonUI | onNavigate | 导航 selector 名 |
