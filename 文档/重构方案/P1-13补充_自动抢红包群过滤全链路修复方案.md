# 自动抢红包群过滤全链路修复方案（重写版）

> 基于 [红包功能深度分析报告](file:///www/wwwroot/ios/文档/红包功能分析/红包功能深度分析报告.md) 与锤子助手实现对比，发现我们的群过滤存在 **双重复设计 + 数据提取错误 + 过滤范围缺失** 三重问题。本文档提供根本性改造方案。

---

## 一、问题总览

### 1.1 用户反馈

```
已选择不抢的群 → 群列表保存成功 → 实际收到红包 → 仍然自动抢
```

### 1.2 当前代码的三大问题

| # | 问题 | 严重程度 | 来源 |
|---|------|---------|------|
| 1 | `getSelectedGroupIds` 返回 `allKeys`，可能为 `CContact*` 而非 `NSString*`，NSUserDefaults 静默失败 | **阻断** | 保存链路 |
| 2 | 群组过滤 `redEnvelopGroupFilterList` 仅对 `isGroupReceiver` 生效，遗漏 `isGroupSender` | **功能缺失** | 过滤链路 |
| 3 | `redEnvelopBlackList` 与 `redEnvelopGroupFilterList` 功能完全重叠，但黑名单无 UI 入口 | **设计冗余** | 架构层 |

---

## 二、与锤子助手的对比分析

### 2.1 架构对比

```
┌─────────────────────────────────────────────────────────────────┐
│                      锤子助手（反编译）                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  isRedEnvelopGroupFiter (NSArray)  ← 唯一的数据源                 │
│       │                                                           │
│       ├── UI入口: showBlackList → 群组多选控制器                  │
│       │                                                           │
│       └── 过滤逻辑: 对所有群消息生效                               │
│            + [fromUsr containsString:item]                        │
│                                                                   │
│  ★ 一个功能，一个数据源，一个入口                                  │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│                      MioPlugin（当前）                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  redEnvelopGroupFilterList (NSArray)  ← 群过滤数据源              │
│       │                                                           │
│       ├── UI入口: 「选择群聊」按钮 → MioTweakGroupSelectsController│
│       │                                                           │
│       └── 过滤逻辑: 仅对 isGroupReceiver 生效                     │
│            + [fromUsr containsString:item]                        │
│                                                                   │
│  redEnvelopBlackList (NSArray)  ← 黑名单数据源（重复！）          │
│       │                                                           │
│       ├── UI入口: 无（死功能，用户无法配置）                      │
│       │                                                           │
│       └── 过滤逻辑: 对所有群消息生效                              │
│            + [fromUsr containsString:item]                        │
│                                                                   │
│  ★ 两个数据源，功能完全重复，一个无入口，一个有入口但实现有bug     │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 关键问题定位

分析报告 4.3 节明确指出：
> "源码中的 `redEnvelopGroupFilterEnabled` + `redEnvelopGroupFilterList` 与反编译中的 `isRedEnvelopGroupFiter`（getter）相对应。从 `showBlackList` 的调用来看，黑名单和群组过滤共享同一个数据源。"

**结论**：锤子助手压根就没有分成两个功能，这是同一个功能。我们的 `redEnvelopBlackList` 是多余的拆分，且没有 UI 入口，属于**废弃代码**。

### 3.3 步骤二：修复保存链路 — `getSelectedGroupIds`

#### 文件：[MioTweakGroupSelectsController.m](file:///www/wwwroot/ios/MioPlugin/Settings/Controllers/MioTweakGroupSelectsController.m)

**根因分析**：`m_dicMultiSelect` 是微信 `ContactSelectView` 的内部属性，其 **values 一定是 `CContact*` 对象**。key 的类型随微信版本变化（可能是 `NSString*` 或 `CContact*`）。直接调用 `allKeys` 返回的元素类型不确定，若为 `CContact*` 则 NSUserDefaults 保存静默失败。

**改前代码**（第 183-186 行）：

```objc
- (NSArray<NSString *> *)getSelectedGroupIds {
    if (!self.selectView) return @[];
    return [self.selectView.m_dicMultiSelect allKeys];
}
```

**改后代码**：

```objc
- (NSArray<NSString *> *)getSelectedGroupIds {
    if (!self.selectView) return @[];
    
    NSMutableArray<NSString *> *groupIds = [NSMutableArray array];
    
    // ★ 主方案：从 allValues（CContact*）提取 m_nsUsrName
    // CContact 是微信联系人模型，m_nsUsrName 是其用户名（群ID）
    // allValues 的类型由 ContactSelectView 内部保证为 CContact*
    for (id contact in [self.selectView.m_dicMultiSelect allValues]) {
        if ([contact respondsToSelector:NSSelectorFromString(@"m_nsUsrName")]) {
            NSString *usrName = ((NSString *(*)(id, SEL))objc_msgSend)(
                contact, NSSelectorFromString(@"m_nsUsrName"));
            if (usrName.length > 0) {
                [groupIds addObject:usrName];
            }
        }
    }
    
    // ★ 降级方案：如果 values 方式取不到，退回到 keys 方式
    // 此时必须做 isKindOfClass: 检查确保只取 NSString
    if (groupIds.count == 0) {
        for (id key in [self.selectView.m_dicMultiSelect allKeys]) {
            if ([key isKindOfClass:[NSString class]]) {
                [groupIds addObject:(NSString *)key];
            }
        }
    }
    
    return [groupIds copy];
}
```

**与锤子助手的对比**：锤子助手的 `onMultiSelectGroupReturn:` 同样需要从选择控制器中提取群 ID。虽然其具体提取方式未知，但**显式提取联系人属性**是唯一能保证类型正确的方法。

### 3.4 步骤三：统一过滤链路 — `RedEnvelopHook.m`

#### 文件：[RedEnvelopHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/RedEnvelop/RedEnvelopHook.m) 第 125-139 行

**改造要点**：

| 改动用 | 原因 |
|--------|------|
| 删除 `redEnvelopBlackList` 过滤块 | 数据源已合并，功能由 groupFilterList 统一承担 |
| 群过滤改为对**所有群消息**生效 | 锤子助手设计如此，`isGroupReceiver` + `isGroupSender` 都应被过滤 |
| `isEqualToString:` 替代 `containsString:` | 精确匹配群 ID，消除模糊匹配 |
| 根据消息方向选择正确比较字段 | `isGroupReceiver → fromUsr`，`isGroupSender → toUsr` |

**改前代码**（第 125-139 行）：

```objc
if (config.redEnvelopBlackList.count > 0) {
    for (NSString *blackItem in config.redEnvelopBlackList) {
        if ([fromUsr containsString:blackItem]) { shouldReceive = NO; break; }
    }
}

if (config.redEnvelopGroupFilterEnabled && config.redEnvelopGroupFilterList.count > 0 && isGroupReceiver) {
    for (NSString *groupItem in config.redEnvelopGroupFilterList) {
        if ([fromUsr containsString:groupItem] || [toUsr containsString:groupItem]) {
            shouldReceive = NO;
            WPLog(@"RedEnv", @"[FILTER] 群过滤命中: %@ 匹配 %@", fromUsr, groupItem);
            break;
        }
    }
}
```

**改后代码**（替换第 125-139 行）：

```objc
// ★★★ 统一群黑名单过滤 ★★★
// 合并自原来的 redEnvelopBlackList + redEnvelopGroupFilterList
// 设计参考：锤子助手 isRedEnvelopGroupFiter（同一个数据源，对所有群消息生效）
//
// 匹配策略（根据消息方向自动选择正确字段）：
//   isGroupReceiver → 匹配 fromUsr（群 ID）
//   isGroupSender   → 匹配 toUsr（群 ID）
//   非群消息 → 不执行此过滤
//
if (config.redEnvelopGroupFilterEnabled && config.redEnvelopGroupFilterList.count > 0) {
    NSString *sessionToCheck = nil;
    NSString *directionTag = nil;
    if (isGroupReceiver) {
        sessionToCheck = fromUsr;
        directionTag = @"RECV";
    } else if (isGroupSender) {
        sessionToCheck = toUsr;
        directionTag = @"SEND";
    }
    
    if (sessionToCheck.length > 0) {
        WPLog(@"RedEnv", @"[FILTER] [%@] 检查会话: %@ | 过滤列表(%lu项): %@",
              directionTag, sessionToCheck,
              (unsigned long)config.redEnvelopGroupFilterList.count,
              config.redEnvelopGroupFilterList);
        
        BOOL matched = NO;
        for (id groupItem in config.redEnvelopGroupFilterList) {
            // 防御性检查：确保过滤列表元素是 NSString
            if (![groupItem isKindOfClass:[NSString class]]) {
                WPLog(@"RedEnv", @"[FILTER] ⚠ 过滤列表元素非 NSString: %@ (type=%@)",
                      groupItem, NSStringFromClass([groupItem class]));
                continue;
            }
            if ([sessionToCheck isEqualToString:(NSString *)groupItem]) {
                shouldReceive = NO;
                matched = YES;
                WPLog(@"RedEnv", @"[FILTER] ✅ [%@] 群黑名单命中: %@ == %@",
                      directionTag, sessionToCheck, groupItem);
                break;
            }
        }
        
        if (!matched) {
            WPLog(@"RedEnv", @"[FILTER] ❌ [%@] 未命中黑名单: %@", directionTag, sessionToCheck);
        }
    }
}
```

**为什么这是最佳方案**：

| 对比项 | 当前代码 | 改造后 |
|--------|---------|--------|
| 数据源数量 | 2 个（冗余） | 1 个（统一） |
| 覆盖方向 | 仅 `isGroupReceiver` | `isGroupReceiver` + `isGroupSender` |
| 比较方式 | `containsString:` 模糊匹配 | `isEqualToString:` 精确匹配 |
| 比较字段 | `fromUsr` 和 `toUsr` 同时比（含无效比较） | 根据方向选择正确字段 |
| 类型安全 | 无检查 | `isKindOfClass:` 防御 |
| 运行时诊断 | 仅命中时有日志 | 全链路：检查→命中/未命中 |
| 与锤子助手一致性 | ❌ 偏离 | ✅ 一致 |

### 3.5 步骤四：`onDone` 添加保存验证日志

#### 文件：[MioTweakGroupSelectsController.m](file:///www/wwwroot/ios/MioPlugin/Settings/Controllers/MioTweakGroupSelectsController.m)

```objc
- (void)onDone {
    NSArray<NSString *> *groupIds = [self getSelectedGroupIds];
    
    // 日志：保存确认 + 类型验证
    WPLog(@"RedEnv", @"[DONE] 群黑名单保存: %lu 个群", (unsigned long)groupIds.count);
    if (groupIds.count > 0) {
        WPLog(@"RedEnv", @"[DONE] items: %@", groupIds);
        BOOL allString = YES;
        for (id item in groupIds) {
            if (![item isKindOfClass:[NSString class]]) {
                allString = NO;
                WPLog(@"RedEnv", @"[DONE] ⚠ 发现非 NSString 元素: %@", item);
                break;
            }
        }
        WPLog(@"RedEnv", @"[DONE] 类型验证: %@", allString ? @"✅ 全部为 NSString" : @"❌ 存在非 NSString");
    }
    
    if ([self.delegate respondsToSelector:@selector(onGroupSelectReturn:)]) {
        [self.delegate onGroupSelectReturn:groupIds];
    }
    [self.navigationController popViewControllerAnimated:YES];
}
```

## 四、完整数据流重构前后对比

### 4.1 重构前（当前）

```
用户选择群 → onDone()
  → getSelectedGroupIds()          [← allKeys，可能返回 CContact*]
  → onGroupSelectReturn:groupIds
  → config.redEnvelopGroupFilterList = groupIds
  → [ConfigManager saveAll]        [← CContact* 存入 NSUserDefaults → 静默失败]

收到群红包 → processRedEnvelopMessage()
  → redEnvelopBlackList 过滤       [← 有逻辑但无 UI 入口，死代码]
  → redEnvelopGroupFilterList 过滤  [← 仅 isGroupReceiver]
    → 数据为空（因保存失败）       [← 过滤不执行]
  → 自动抢该群红包                 [← 功能异常]
```

### 4.2 重构后

```
用户选择群 → onDone()
  → getSelectedGroupIds()          [← 从 CContact* 显式提取 m_nsUsrName → NSString*]
  → onGroupSelectReturn:groupIds
  → config.redEnvelopGroupFilterList = groupIds
  → [ConfigManager saveAll]        [← NSString* 存入 NSUserDefaults → ✅ 成功]

收到群红包 → processRedEnvelopMessage()
  → redEnvelopGroupFilterList 过滤  [← 统一数据源，isGroupReceiver + isGroupSender]
    → isEqualToString: 精确匹配     [← 确认命中]
  → shouldReceive = NO              [← 过滤生效]
  → 跳过该红包                     [✅ 功能正常]
```

## 七、方案效果总结
