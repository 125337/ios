# P1-11: 暗黑模式圆角边框与资料卡背景渲染问题修复方案

## 问题概述

| 问题 | 现象 | 严重度 |
|------|------|:------:|
| **问题1**: 圆角美化边框渲染异常 | 开启深色模式后，列表圆角的边框颜色未随模式切换而更新，仍使用浅色模式下的边框颜色 | **高** |
| **问题2**: 资料卡背景色切换错误 | 开启深色模式后，资料卡背景色先正确变为深色（~0.5秒），然后 2-3 秒后又恢复为浅色 | **高** |

---

## 问题1：圆角美化暗黑模式边框渲染异常

### 涉及文件

- [ListCornerRadiusHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ListCornerRadius/ListCornerRadiusHook.m)

### 根因分析

核心问题在 `wp_applyBorderAndBg:radius:position:isFTSHome:` 方法的**缓存键（cache key）没有包含暗黑模式状态**。

```objc
// 第639-645行 — 缓存键不包含 isDark！
static NSString *kBorderCacheKey = @"com.mio.cornerBorderCache";

NSString *existingCacheKey = objc_getAssociatedObject(cell, (__bridge const void *)kBorderCacheKey);
NSString *cacheKey = [NSString stringWithFormat:@"r%ld-p%ld-f%d-b%.1f",
                      (long)radius, (long)position, isFTSHome,
                      config.listCellBorderWidth];
if ([existingCacheKey isEqualToString:cacheKey]) return;  // ← 缓存命中直接返回
```

#### 产生过程

1. **浅色模式下**，Cell 首次 `layoutSubviews`：
   - `cacheKey` = `r18-p0-f0-b1.0`（假设: radius=18, position=0, isFTSHome=NO, borderWidth=1.0）
   - `isDark` = NO → `borderColor` = 浅色边框色
   - 创建 `CAShapeLayer` 边框，颜色为浅色
   - 缓存 key 绑定到 Cell：`@"r18-p0-f0-b1.0"` ✅

2. **切换到深色模式**，Cell 再次 `layoutSubviews`：
   - `cacheKey` = `r18-p0-f0-b1.0`（**和浅色模式完全一样！**）
   - `existingCacheKey` = `r18-p0-f0-b1.0`（和缓存 key 匹配）
   - `[existingCacheKey isEqualToString:cacheKey]` = **YES**
   - **直接 return，跳过边框更新** ❌
   - 旧的浅色 `CAShapeLayer` 边框保留，颜色未更新为深色

3. **结果**：边框颜色永远停留在第一次渲染时的颜色，不随暗黑模式切换而更新。

#### 本质原因

`cacheKey` 只包含 4 个维度：`radius`、`position`、`isFTSHome`、`borderWidth`，**缺少第 5 个关键维度：`isDark`**。由于边框颜色完全由 `isDark` 决定（第 665 行），当模式切换时，这 5 个维度中的 `isDark` 变化了，但缓存键检测不到，导致错误地走了 early-return 路径。

#### 代码路径追溯

```
replaced_MMTableViewCell_layoutSubviews (第106行)
  → wp_applyStandardCorner: (第503行)
    → wp_applyBorderAndBg:radius:position:isFTSHome: (第633行)
      → 第645行: 缓存键检查 ← ★ BUG ★
      → 第663行: BOOL isDark = [WPUtility isDarkModeForView:cell];
      → 第665行: borderColor = isDark ? darkHex : lightHex;
      → 第674-721行: 创建 CAShapeLayer 并添加到 cell.layer
```

### 修复方案

**方案：在缓存键中增加暗黑模式维度**

将第 642-644 行的缓存键构造改为：

```objc
// 修改前（缺少 isDark 维度）
NSString *cacheKey = [NSString stringWithFormat:@"r%ld-p%ld-f%d-b%.1f",
                      (long)radius, (long)position, isFTSHome,
                      config.listCellBorderWidth];

// 修改后（增加 isDark 维度）
BOOL isDark = [WPUtility isDarkModeForView:cell];
NSString *cacheKey = [NSString stringWithFormat:@"r%ld-p%ld-f%d-b%.1f-d%d",
                      (long)radius, (long)position, isFTSHome,
                      config.listCellBorderWidth, isDark];
```

同时需注意：`isDark` 的获取要放在缓存检查**之前**，因为边框颜色由 `isDark` 决定。把第 663 行的 `isDark` 计算提前即可。

**修改后流程**：

```
1. 浅色模式 → cacheKey = "r18-p0-f0-b1.0-d0" → borderColor = 浅色 ✅
2. 切换到深色模式 → cacheKey = "r18-p0-f0-b1.0-d1" → 缓存不匹配 ✅
   → 移除旧 CAShapeLayer → 创建新深色 CAShapeLayer → 更新缓存 ✅
3. 切回浅色模式 → cacheKey = "r18-p0-f0-b1.0-d0" → 缓存不匹配 ✅
   → 同上更新 ✅
```

### 影响范围

- 仅影响 `wp_applyBorderAndBg:` 方法中的边框颜色更新逻辑
- 不影响圆角半径、背景色等其他功能
- 不影响浅色模式下的行为（浅色模式的缓存键不变）

### 用户测试方法

| 步骤 | 操作 | 预期结果 |
|:----:|------|----------|
| 1 | 在浅色模式下打开微信，进入聊天列表 | 列表圆角边框为浅灰色 |
| 2 | 开启系统深色模式（iOS 控制中心或设置） | 列表圆角边框立即变为深灰色 |
| 3 | 滚动列表，检查所有 Cell | 所有 Cell 的边框颜色统一为深灰色 |
| 4 | 关闭深色模式，切回浅色模式 | 边框颜色立即恢复为浅灰色 |
| 5 | 杀掉微信进程，在深色模式下重新打开微信 | 列表圆角边框直接显示为深灰色（无需手动触发） |
| 6 | 进入「我」页面，检查圆角边框 | 边框颜色与当前模式一致 |
| 7 | 进入「通讯录」页面，检查圆角边框 | 边框颜色与当前模式一致 |
| 8 | 在插件设置中修改边框宽度/颜色/圆角半径 | 修改后立即刷新，边框正常显示 |

## 问题2：资料卡暗黑模式背景色切换错误

### 涉及文件

- [ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m)

### 根因分析

核心问题：**MMUIButton 的 `traitCollectionDidChange:` 原生实现会主动恢复浅色模式背景色**，而我们只 Hook 了 `layoutSubviews`，拦截不住这条路径。

#### 产生过程

假设用户配置：
- 浅色模式背景色 = `#FFFFFF`（白色）
- 深色模式背景色 = `#000000`（黑色）

切换到深色模式的实际时序：

```
切换暗黑模式
  ↓
① MMUIButton.layoutSubviews 触发
    → WeChat 原生 layoutSubviews 执行
    → 我们的 Hook 执行 → handleButtonLayout:
      → applyProfileCardCorner:isDark:
        → isDark = YES → bgColor = #000000 ✅ 变黑了
  ↓
② MMUIButton.traitCollectionDidChange: 触发（WeChat 原生方法）
    → WeChat 内部重新读取自己缓存的浅色背景色值
    → 把 MMUIButton.backgroundColor 设回 #FFFFFF ❌ 变回浅色
    → 我们没有 Hook 此方法，拦截不住！
  ↓
③ 用户看到的结果：闪了一下黑色 → 又变回浅色了
```

关键点：**第②步是 WeChat 自己主动执行的**，不是异步回调也不是数据绑定。`MMUIButton` 作为 WeChat 的基础 UI 组件，它自己的 `traitCollectionDidChange:` 实现会在暗黑模式切换时主动把颜色重置为 WeChat 的默认值（即你配置的浅色背景色）。这与是否使用背景图片完全无关——仅使用背景色时，问题同样存在，因为 WeChat 直接通过 `setBackgroundColor:` 覆盖。

#### 根本原因对比

| 因素 | 详细说明 |
|------|----------|
| **触发时机** | `traitCollectionDidChange:` 在暗黑模式切换时由 iOS 自动发送给所有 View |
| **覆盖路径** | WeChat 的 `MMUIButton` 原生 `traitCollectionDidChange:` 实现中主动恢复背景色 |
| **我们的缺失** | 只 Hook 了 `layoutSubviews`，没有 Hook `traitCollectionDidChange:`，拦截不住 WeChat 的覆盖操作 |
| **与背景图片关系** | 无关。即使只使用纯背景色，WeChat 仍会通过此路径覆盖 |

#### 代码路径追溯

```
暗黑模式切换
  ↓
【阶段1】layoutSubviews
  → replaced_MMUIButton_layoutSubviews (第40行)
    → orig_MMUIButton_layoutSubviews (WeChat原始layoutSubviews)
    → handleButtonLayout: (第502行)
      → isDark = [WPUtility isDarkModeForViewController:vc] (第518行) ✅ 正确
      → handleCornerAndQR: (第529行)
        → applyProfileCardCorner:isDark: (第596-602行)
          → cell.backgroundColor = darkBgColor ✅ 深色设置正确
  ↓
【阶段2】traitCollectionDidChange:（WeChat 原生覆盖）
  → MMUIButton 原生 traitCollectionDidChange: 运行
    → WeChat 读取自己缓存的背景色（浅色模式的值）
    → button.backgroundColor = lightBgColor ❌ 覆盖为我们设的深色
    → 我们没有 Hook traitCollectionDidChange: → 无法阻止
```

### 修复方案

**方案：Hook `traitCollectionDidChange:` 并在此处重新应用暗黑模式颜色**

在 `initProfileCardHook` 中增加对 `MMUIButton` 的 `traitCollectionDidChange:` Hook：

```objc
// 新增: traitCollectionDidChange hook
static IMP orig_MMUIButton_traitCollectionDidChange = NULL;
static void replaced_MMUIButton_traitCollectionDidChange(id self, SEL _cmd, UITraitCollection *previousTraitCollection) {
    if (orig_MMUIButton_traitCollectionDidChange) {
        ((void (*)(id, SEL, UITraitCollection *))orig_MMUIButton_traitCollectionDidChange)(self, _cmd, previousTraitCollection);
    }

    if (@available(iOS 13.0, *)) {
        if (previousTraitCollection && self) {
            // ★ 关键：检测暗黑模式是否发生了变化
            UITraitCollection *current = ((UIView *)self).traitCollection;
            if (previousTraitCollection.userInterfaceStyle != current.userInterfaceStyle) {
                // 暗黑模式状态发生了变化 → 重新应用颜色
                [ProfileCardBgHook handleButtonLayout:(UIView *)self];
            }
        }
    }
}
```

在 `initProfileCardHook` 中注册此 Hook：

```objc
+ (void)initProfileCardHook {
    Class cls = objc_getClass("MMUIButton");
    if (cls) {
        MSHookMessageEx(cls, @selector(layoutSubviews),
            (IMP)replaced_MMUIButton_layoutSubviews,
            (IMP *)&orig_MMUIButton_layoutSubviews);

        // ★ 新增: traitCollectionDidChange hook
        MSHookMessageEx(cls, @selector(traitCollectionDidChange:),
            (IMP)replaced_MMUIButton_traitCollectionDidChange,
            (IMP *)&orig_MMUIButton_traitCollectionDidChange);
    }
}
```

**为什么这个方案能解决问题？**

关键差异：**Hook 的执行顺序**

```
修复前（只 Hook layoutSubviews）:
  暗黑模式切换
    → layoutSubviews → 我们的Hook设深色 ✅
    → traitCollectionDidChange: → WeChat 原生覆盖回浅色 ❌

修复后（同时 Hook traitCollectionDidChange:）:
  暗黑模式切换
    → layoutSubviews → 我们的Hook设深色 ✅
    → traitCollectionDidChange: → 先调 orig（WeChat原生覆盖回浅色 ❌）
                              → 再调我们的代码 → 重新设回深色 ✅
```

我们的 Hook 在 `orig` 之后执行，所以：

1. WeChat 原生 `traitCollectionDidChange:` 把颜色恢复为浅色
2. **紧接着**我们的 Hook 运行，又把颜色设回深色
3. 用户视觉上**看不到"闪回"**，因为两次操作都在同一帧内完成
4. 颜色最终锁定在我们设置的值

**额外加固：在 `applyProfileCardCorner:` 中使用系统动态颜色**

如果想更彻底地解决，还可以将 `applyProfileCardCorner:isDark:` 中的颜色创建方式改为 iOS 13+ 的**动态颜色**（`UIColor` 的 `initWithDynamicProvider:`），让颜色自动跟随模式切换：

```objc
// 在 applyProfileCardCorner:isDark: 中，将静态颜色改为动态颜色
UIColor *bgColor = [UIColor colorWithDynamicProvider:^UIColor * _Nonnull(UITraitCollection * _Nonnull traitCollection) {
    BOOL isDark = (traitCollection.userInterfaceStyle == UIUserInterfaceStyleDark);
    return [WPColorUtil colorFromHexString:isDark
        ? config.cardBgCornerDarkBgColor : config.cardBgCornerBgColor]
        ?: [UIColor clearColor];
}];
cell.backgroundColor = bgColor;
```

这样做的好处是：即使 WeChat 原生代码在 `layoutSubviews` 之后又去读 `backgroundColor`，系统动态颜色会自动返回正确的颜色值，不需要我们的 Hook 介入。

### 影响范围

- 仅影响资料卡（`MMUIButton`）的暗黑模式颜色切换
- 不影响其他功能模块
- 不影响浅色模式行为

| 2 | 插件设置中设置资料卡深色背景色为深色（如黑色 `#000000`） | 无变化（当前为浅色模式） |

## 对比总结

| 维度 | 问题1：边框渲染 | 问题2：资料卡背景 |
|------|:---------------:|:-----------------:|
| **根因** | 缓存键缺少 `isDark` 维度 | 未 Hook `traitCollectionDidChange:`，拦截不住 WeChat 原生方法主动恢复浅色背景 |
| **触发条件** | 任何有圆角边框的列表 Cell | 资料卡（`MMUIButton`） |
| **修复复杂度** | 低（改 1 行缓存键） | 中（新增 1 个 Hook） |
| **验证方式** | 切换暗黑模式观察列表边框 | 切换暗黑模式观察资料卡背景 |
| **是否影响浅色模式** | 否 | 否 |
| **风险** | 极低（仅缓存键范围变化） | 低（仅新增方法，不改现有逻辑） |
| **修复后效果** | 边框颜色实时跟随模式切换 | 背景色实时跟随模式切换，不被覆盖 |

## 注意事项

1. **问题1 的修复是最小改动**：只修改缓存键格式，不改任何逻辑。必须确保 `isDark` 在缓存检查前已计算好。
2. **问题2 的 `traitCollectionDidChange:` Hook**：需要做 `previousTraitCollection` 的 nil 保护，以及 `userInterfaceStyle` 前后变化的判断，避免不必要的布局刷新。
3. **`traitCollectionDidChange:` 可能被频繁调用**：即使 `userInterfaceStyle` 没有变化，系统也可能因其他 trait 变化而调用此方法。所以一定要加 `if (previousTraitCollection.userInterfaceStyle != current.userInterfaceStyle)` 判断。
4. **iOS 版本兼容**：`traitCollectionDidChange:` 和 `UITraitCollection.userInterfaceStyle` 均需 `@available(iOS 13.0, *)` 保护。低于 iOS 13 的设备没有暗黑模式，不需要处理。
5. **两个修复可独立部署**：互不依赖，可以各自独立验证。
