# P1-1: 暗黑模式检测统一改造方案

> **当前状态**: 未修复 | **优先级**: P1（建议修复）
>
> **关联文件**:
> - `Core/WPUtility.h` / `Core/WPUtility.m` — 已有 `isDarkMode` + `isDarkModeForViewController:` 两个方法
> - `Modules/MessageTime/MessageTimeHook.m` — 使用 `[WPUtility isDarkMode]`
> - `Modules/ListCornerRadius/ListCornerRadiusHook.m` — 混用 `[WPUtility isDarkMode]`（1处）和 `[WPUtility isDarkModeForViewController:vc]`（4处）
> - `Modules/ProfileCardBg/ProfileCardBgHook.m` — 自定义 `isDarkModeForVc:` 包装器（仅转发到 `[WPUtility isDarkModeForViewController:vc]`）

## 1. 问题分析

### 1.1 当前状态总览

目前全项目有 **3 种不同的暗黑模式检测路径**：

| 编号 | 实现 | 所在文件 | 调用模式 | 准确度 |
|:----:|------|---------|---------|:------:|
| A | `[WPUtility isDarkMode]` | `WPUtility.m:30-35` | 全局 `UITraitCollection.currentTraitCollection` | ❌ 可能不准确 |
| B | `[WPUtility isDarkModeForViewController:vc]` | `WPUtility.m:37-42` | 传入 VC 的 `traitCollection` | ✅ 准确 |
| C | `[ProfileCardBgHook isDarkModeForVc:vc]` | `ProfileCardBgHook.m:280-282` | 直接转发到 B | ✅ 同 B，但多余包装 |

### 1.2 精确问题：全局 `isDarkMode` 的不可靠性

```objc
// WPUtility.m:30-35 — 全局检测
+ (BOOL)isDarkMode {
    if (@available(iOS 13.0, *)) {
        return UITraitCollection.currentTraitCollection.userInterfaceStyle == UIUserInterfaceStyleDark;
    }
    return NO;
}
```

`UITraitCollection.currentTraitCollection` 返回的是**当前线程的当前 trait collection**，存在以下问题：

| 场景 | 问题 |
|------|------|
| **非主线程调用** | `currentTraitCollection` 可能返回过时的缓存值，甚至与 UI 的实际 trait collection 不同 |
| **多窗口环境（iPad）** | 不同窗口可能处于不同外观模式（分屏多任务时），全局检测无法区分 |
| **ViewController 尚未加载** | 在 `viewDidLoad` 之前，当前 trait collection 可能没有反映窗口的最终状态 |
| **动画过渡期间** | UITraitCollection 在 `traitCollectionDidChange:` 回调期间过渡，`currentTraitCollection` 可能处在中间状态 |

### 1.3 当前各调用点的准确度分析

#### 调用点 A：`MessageTimeHook.m` — 3 处使用 `[WPUtility isDarkMode]`

```objc
// MessageTimeHook.m:18 — autoDarkColor() 辅助函数
static UIColor *autoDarkColor(UIColor *lightColor) {
    if ([WPUtility isDarkMode]) { ... }  // ← 全局检测
}

// MessageTimeHook.m:31 — colorInLightMode() 辅助函数
return [WPUtility isDarkMode] ? ... : ...;  // ← 全局检测

// MessageTimeHook.m:367 — formatMessageTime() 被调用处
[WPUtility isDarkMode]  // ← 全局检测
```

**影响**: 这些函数被调用的上下文都有可用的 ViewController 或 UIView。`autoDarkColor` 和 `colorInLightMode` 被消息时间标签绘制时调用，此时必定在某个 VC 的视图层级中，有可用的 VC 引用。

#### 调用点 B：`ListCornerRadiusHook.m` — 1 处使用 `[WPUtility isDarkMode]`

```objc
// ListCornerRadiusHook.m:663
BOOL isDark = [WPUtility isDarkMode];  // ← 全局检测
```

**影响**: 此处在 `wp_applyBorderAndBg:radius:position:isFTSHome:` 方法中，被 layoutSubviews Hook 调用。调用方（`replaced_MMTableViewCell_layoutSubviews`）在被 Hook 的 UIView 上下文中执行，可以通过 `[WPUtility findParentViewController:]` 获取 ViewController。

**其余 4 处已使用 `isDarkModeForViewController:vc`（第 186、254、279、341 行），无需改动。**

#### 调用点 C：`ProfileCardBgHook.m` — 自定义包装器

```objc
// ProfileCardBgHook.m:280-282 — 仅转发到 WPUtility
+ (BOOL)isDarkModeForVc:(UIViewController *)vc {
    return [WPUtility isDarkModeForViewController:vc];
}
```

**影响**: 纯包装器，无实际价值。全文件有 4 处调用（第 280 行定义，第 522 行调用）。每次调用者都已持有 VC 引用，直接调 `[WPUtility isDarkModeForViewController:vc]` 即可。

### 1.4 现状总结

```
                            WPUtility
                    ┌─────────────────────┐
                    │  isDarkMode() ❌    │ ← 全局检测，不可靠
                    │  isDarkModeForVC()✅│ ← VC 检测，推荐使用
                    └─────────┬───────────┘
                              │
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
   MessageTimeHook     ListCornerRadiusHook  ProfileCardBgHook
   ┌──────────────┐   ┌──────────────┐     ┌──────────────┐
   │ autoDarkColor│   │  isDarkMode  │←全局│ isDarkModeForVc│
   │ colorInLight │   │  (1处) ❌   │     │ (4处，实际   │
   │ formatMsgTime│   │              │     │  就是包装器) │
   │ (3处) ❌    │   │ isDarkForVC  │     └──────────────┘
   └──────────────┘   │ (4处) ✅    │
                      └──────────────┘
```

## 2. 改造方案

### 2.1 设计目标

1. **统一入口**: 所有模块调用同一个方法，不再各搞各的
2. **默认精确**: 无 VC 引用时禁止静默降级到全局检测，强迫调用方提供 VC 或做出明确选择
3. **定位便利**: 需要全局检测的调用点可以通过明确的命名知道自己在做什么
4. **删除重复**: 移除 `ProfileCardBgHook` 的自定义包装器
5. **零耦合**: 不修改其他功能的业务逻辑

### 2.2 API 设计

```objc
// WPUtility.h — 改造后

/// 检测指定 ViewController 是否为暗黑模式
/// ⚠️ 所有 UI 相关检测都应优先使用此方法。
/// @param vc 非空的 UIViewController 实例
/// @return YES 表示暗黑模式
+ (BOOL)isDarkModeForViewController:(UIViewController *)vc;

/// 检测当前环境是否为暗黑模式（仅用于非 UI 场景）
/// ⚠️ 仅推荐在以下场景使用：
///   - AppDelegate / 后台计算 / 非 UI 线程
///   - 确实无法获取任何 VC 引用的纯工具方法
/// @return YES 表示暗黑模式
+ (BOOL)isDarkModeForCurrentEnvironment;

/// 从 UIView 推断所属 ViewController 并检测暗黑模式
/// 简便方法：先查找 VC，再调用 isDarkModeForViewController:
/// @param view 任意 UIView
/// @return YES 表示暗黑模式，无法找到 VC 时返回 NO
+ (BOOL)isDarkModeForView:(UIView *)view;
```

| 文件 | 改动内容 | 改动量 |
|------|---------|:------:|
| **`Core/WPUtility.h`** | `isDarkMode` → `isDarkModeForCurrentEnvironment`；新增 `isDarkModeForView:` | +2 行声明 |
| **`Core/WPUtility.m`** | 方法改名；新增 `isDarkModeForView:` 实现 | +10 行 |
| **`MessageTimeHook.m`** | `[WPUtility isDarkMode]` 3 处调用 → `[WPUtility isDarkModeForViewController:vc]`（需确保 vc 可达） | 3 行，每行 1 个参数 |

#### 2.3.1 `MessageTimeHook.m` 的 3 处改造详解

这 3 处改造最关键，因为这 3 处当前没有 ViewController 参数，需要找到或传入 VC。

**改造点 1: `autoDarkColor`（第 16-28 行）**

```objc
// 改造前 — 全局检测
static UIColor *autoDarkColor(UIColor *lightColor) {
    if (!lightColor) return nil;
    if ([WPUtility isDarkMode]) { ... }  // ← 无 VC 上下文
    return lightColor;
}
```

`autoDarkColor` 被 `colorInLightMode` 调用，`colorInLightMode` 又被 `replaced_CommonMessageCellView_updateNodeStatus` 调用。在这个 Hook 函数中，`self` 就是 cell，可以通过 `findParentViewController:` 获取 VC。

改造方案：**向 `autoDarkColor` 和 `colorInLightMode` 增加 `BOOL isDark` 参数**，由调用方传入。

```objc
// 改造后
static UIColor *autoDarkColor(UIColor *lightColor, BOOL isDark) {
    if (!lightColor) return nil;
    if (isDark) {
        CGFloat r, g, b, a;
        if ([lightColor getRed:&r green:&g blue:&b alpha:&a]) {
            return [UIColor colorWithRed:MIN(r + 0.15, 1.0)
                                   green:MIN(g + 0.15, 1.0)
                                    blue:MIN(b + 0.15, 1.0)
                                   alpha:a];
        }
    }
    return lightColor;
}
```

**改造点 2: `colorInLightMode`（第 30-32 行）**

```objc
// 改造前
static UIColor *colorInLightMode(UIColor *lightColor, UIColor *darkColor) {
    return [WPUtility isDarkMode] ? (darkColor ?: autoDarkColor(lightColor)) : lightColor;
}

// 改造后 — 增加 isDark 参数，透传给 autoDarkColor
static UIColor *colorInLightMode(UIColor *lightColor, UIColor *darkColor, BOOL isDark) {
    return isDark ? (darkColor ?: autoDarkColor(lightColor, isDark)) : lightColor;
}
```

**改造点 3: `repl_CommonMessageCellView_updateNodeStatus` 中的第 367 行调用**

`repl_CommonMessageCellView_updateNodeStatus` 的 hook 函数中，有以下上下文：

```objc
// 当前 Hook 函数签名
static void repl_CommonMessageCellView_updateNodeStatus(id self, SEL _cmd, id arg1, ...) {
    // self 就是 CommonMessageCellView，是 UIView 的子类
    // 在函数开始处，通过 [WPUtility findParentViewController:self] 获取 VC
}
```

**改造方案**：在 `repl_CommonMessageCellView_updateNodeStatus` 函数顶部获取一次 VC，将 `isDark` 作为局部变量传入各处调用：

```objc
// 改造后 — 函数顶部获取一次 VC
UIViewController *vc = [WPUtility findParentViewController:(UIView *)self];
BOOL isDark = [WPUtility isDarkModeForViewController:vc];

NSString *timeText = formatMessageTime(date, config.messageTimeCustomFormat, isDark, isSender, statusCode);
// autoDarkColor / colorInLightMode 也使用同一个 isDark 变量
```

`autoDarkColor` 和 `colorInLightMode` 同样增加 `isDark` 参数，调用方传入同一个局部变量。

#### 2.3.2 `ListCornerRadiusHook.m` 第 663 行改造

```objc
// 改造前
BOOL isDark = [WPUtility isDarkMode];

// 改造后 — cell 参数已存在，直接用 isDarkModeForView:
BOOL isDark = [WPUtility isDarkModeForView:cell];
```

`wp_applyBorderAndBg:radius:position:isFTSHome:` 方法签名是：

```objc
+ (void)wp_applyBorderAndBg:(UIView *)cell
                     radius:(NSInteger)radius
                   position:(NSInteger)position
                  isFTSHome:(BOOL)isFTSHome;
```

已经有了 `(UIView *)cell` 参数，所以可以直接用 `isDarkModeForView:cell`。

#### 2.3.3 `ProfileCardBgHook.m` 改造

删除自定义包装器：

```objc
// ProfileCardBgHook.h — 移除声明
// + (BOOL)isDarkModeForVc:(UIViewController *)vc;  ← 删除

// ProfileCardBgHook.m — 移除实现
// + (BOOL)isDarkModeForVc:(UIViewController *)vc {
//     return [WPUtility isDarkModeForViewController:vc];
// }  ← 删除
```

将 4 处调用 `[ProfileCardBgHook isDarkModeForVc:vc]` 改为 `[WPUtility isDarkModeForViewController:vc]`。

### 2.4 `isDarkModeForView:` 的实现

```objc
// WPUtility.m — 新增方法
+ (BOOL)isDarkModeForView:(UIView *)view {
    if (!view) return NO;
    UIViewController *vc = [self findParentViewController:view];
    return vc ? [self isDarkModeForViewController:vc] : NO;
}
```

### 2.5 最终调用链总览（改造后）

```
                     WPUtility
             ┌────────────────────────┐
             │ isDarkModeForVC(vc) ✅ │ ← 主要入口，全部 UI 场景使用
             │ isDarkModeForView(v) ✅│ ← 便捷方法（内部调 VC 版）
             │ isDarkEnv() ✅ (改名)  │ ← 仅非 UI 场景
             └────────────────────────┘
                       │
         ┌─────────────┼─────────────┐
         ▼             ▼             ▼
  MessageTimeHook  ListCornerHook  ProfileCardHook
  ┌────────────┐  ┌────────────┐  ┌────────────┐
  │全部调用改成│  │全部调用改成│  │删除包装器  │
  │isDarkForVC │  │isDarkForVC │  │直接调WPU   │
  └────────────┘  └────────────┘  └────────────┘
```

## 4. 用户测试方法

### 4.1 准备工作

需要一台 **支持 iOS 13+ 的真机或模拟器**（所有暗黑模式 API 仅在 iOS 13+ 生效）。

### 4.2 测试流程

#### 测试 1：消息时间标签暗黑模式适配 —— MessageTimeHook.m

| 步骤 | 操作 | 预期结果 |
|:----:|------|---------|
| 1 | 开启微信 → 进入任意聊天 → 开启插件"消息时间"功能 | 消息上方显示自定义时间标签 |
| 2 | 打开控制中心 → 长按亮度条 → 开启**深色模式** | 时间标签文字颜色自动变亮（暗黑模式自动亮度补偿） |
| 3 | 在深色模式下横竖屏切换 3 次 | 时间标签颜色在切换过程中不变白/不变黑 |
| 4 | 返回到聊天列表 → 再进入同一个聊天 | 时间标签颜色仍然正确适配暗黑模式 |
| 5 | 关闭深色模式 → 返回普通模式 | 时间标签恢复普通颜色 |
| 6 | 重复步骤 2-5 共 3 轮 | 每次切换颜色都正确变化，没有卡住不切换或切换错误的情况 |

**测试说明**：消息时间颜色的暗黑模式判断依赖 `autoDarkColor` 和 `colorInLightMode`，这两者当前使用了全局 `isDarkMode`。改后通过传入当前 VC 的 traitCollection 检测，精度更高。此测试确保过渡后行为完全正确。

#### 测试 2：聊天列表圆角暗黑模式适配 —— ListCornerRadiusHook.m

| 步骤 | 操作 | 预期结果 |
|:----:|------|---------|

**测试说明**：`wp_applyBorderAndBg` 方法中第 663 行使用了全局 `isDarkMode`，改后通过 `isDarkModeForView:cell` 检测。此测试确保 cell 边界颜色的暗黑模式切换精度不变或更高。

#### 测试 3：资料卡背景暗黑模式适配 —— ProfileCardBgHook.m

| 步骤 | 操作 | 预期结果 |

**测试说明**：`handleButtonLayout:` 中的 `isDarkModeForVc:` 包装器删除后，调用改为直接 `[WPUtility isDarkModeForViewController:vc]`。行为完全一致，此测试验证功能无退化。

### 4.3 异常场景测试

| 场景 | 操作 | 预期结果 |
|------|------|---------|
| **快速切换** | 在 3 秒内连续切换深色模式 5 次 | 不应崩溃，最终颜色应与当前模式一致 |
| **低内存** | 开启深色模式后，使用 Xcode 的 Memory 模拟低内存警告 | 不崩溃，颜色正确 |
| **多窗口 (iPad)** | 分屏模式下，左侧窗口深色 + 右侧窗口普通 | 各窗口正确显示对应的颜色模式 |
| **iOS 12** | 在 iOS 12 设备上运行（如果支持的话） | 暗黑模式 API 不会调用，`isDarkModeForCurrentEnvironment` 返回 NO |

### 4.4 测试通过标准

- 所有测试步骤中，应用不崩溃
- 颜色切换无延迟、无闪白/闪黑
- 多次切换后颜色状态与模式一致，不残留
- 所有 `isDarkMode` 全局调用的删除均不影响功能表现
