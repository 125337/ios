# P1-12 补充修复：混合动态颜色方案导致「我的」页面崩溃修复方案

## 概述

执行 P1-12 混合动态颜色改造方案后，点击「我的」页面（`MoreViewController`）出现 **EXC_BAD_ACCESS (SIGSEGV)** 崩溃。崩溃类型为 **STACK GUARD 保护触发**，即**栈溢出**。

---

## 崩溃分析

### 崩溃特征

| 项目 | 内容 |
|------|------|
| **异常类型** | `EXC_BAD_ACCESS` / `KERN_PROTECTION_FAILURE` |
| **崩溃地址** | `0x000000016fa7bfe0`（STACK GUARD 区域：`16fa78000-16fa7c000`） |
| **崩溃本质** | **栈溢出（Stack Overflow）** — 线程 0 的栈增长到 guard 页 |
| **崩溃模块** | `Mio_arm64-1-2.dylib` offset `0x23E80`，重复帧在 offset `0x23E88` |
| **触发操作** | 点击微信「我」的页面（`MoreViewController`） |
| **崩溃线程** | `com.apple.main-thread`（主线程） |

### 崩溃机制：无限递归

崩溃日志中 frames 显示 **21+ 帧全部集中在同一偏移量 `0x23E88`**，这是典型的**无限递归**特征。同一函数被反复调用，最终栈空间耗尽，写入 STACK GUARD 保护区触发 `KERN_PROTECTION_FAILURE`。

### 递归调用链分析

```
MMUIButton.layoutSubviews
    ↓ (hooked)
replaced_MMUIButton_layoutSubviews
    ↓
handleButtonLayout:
    ↓
├── handleHiddenPath:isDark: / handleVisiblePath:isDark:
│   └── button.backgroundColor = clearColor (触发 setNeedsLayout)
│   └── button.frame = ... (触发 layoutSubviews)
│   └── button.layer.masksToBounds = ... (触发布局变更)
│
├── handleMarginAdjustment:
│   └── button.frame = bf  ★★★ 直接触发 layoutSubviews ★★★
│
└── handleCornerAndQR:isDark:
    └── applyProfileCardCorner:isDark:
        └── cell.backgroundColor = dynamicColor  (新增)
        └── cell.layer.masksToBounds = YES
        └── cell.layer.cornerRadius = radius
              ↓ (这些属性变更可能触发重新布局)
        MMUIButton.layoutSubviews (递归)
              ↓
        ...无限循环直至栈溢出...
```

### 根因分析

#### 根本原因1：`handleMarginAdjustment:` 设置 frame 后缺少递归防护

```objc
// ProfileCardBgHook.m 第588-592行
if (fabs(currentX - targetX) > 0.5 || fabs(currentW - targetW) > 0.5) {
    CGRect bf = button.frame;
    bf.origin.x = targetX;
    bf.size.width = targetW;
    button.frame = bf;  // ← 设置 frame 立即触发 layoutSubviews
```

设置 `button.frame` 会触发 `MMUIButton.layoutSubviews`，而 `layoutSubviews` 又被 `replaced_MMUIButton_layoutSubviews` 拦截，再次调用 `handleButtonLayout:`，形成递归循环。

虽然浮点比较守卫 `fabs(currentX - targetX) > 0.5` 理论上能阻断二次进入，但存在以下隐患：

1. **浮点精度问题**：某些设备/布局场景下，实际渲染的 frame 可能与目标值有微小偏差（< 0.5），导致每次都能通过守卫
2. **调用链中其他代码**（如 `handleVisiblePath/discoverPath` 中的 `setupBackgroundMaterialInButton:`）也会修改 frame，改变 currentX/currentW 值

#### 根本原因2：WPUtility 动态颜色方法缺少 nil 安全防护

```objc
+ (UIColor *)dynamicColorWithLightHex:(NSString *)lightHex
                             darkHex:(NSString *)darkHex {
    ...
    NSString *hex = isDark ? darkHex : lightHex;  // ← 如果 darkHex 为 nil
    UIColor *color = [WPColorUtil colorFromHexString:hex];  // ← 传入 nil
    ...
    if (isDark) {
        UIColor *light = [WPColorUtil colorFromHexString:lightHex];
        if (light) {
            CGFloat r=0, g=0, b=0, a=0;
            if ([light getRed:&r green:&g blue:&b alpha:&a]) {  // ← light 可能不是 UIColor
                return [UIColor colorWithRed:r*0.3 green:g*0.3 blue:b*0.3 alpha:a];
            }
        }
    }
```

当配置中的 `listCellDarkBgColor` 或 `cardBgCornerDarkBgColor` 为空字符串或 nil 时：

1. `hex = darkHex = nil` → `[WPColorUtil colorFromHexString:nil]` 可能返回 nil
2. 进入 fallback 路径 → `[WPColorUtil colorFromHexString:lightHex]` 也可能失败
3. 返回 `[UIColor clearColor]` → `cell.backgroundColor = [UIColor clearColor]`
4. 在某些 iOS 版本中，设置 clearColor 到 `MMTableViewCell` 或特定 Cell 上，会触发 iOS 原生代码的布局变更，意外调用 `layoutSubviews` → 递归

#### 根本原因3：handleButtonLayout: 整体缺少重入锁

```objc
+ (void)handleButtonLayout:(UIView *)button {
    ...
    [ProfileCardBgHook handleMarginAdjustment:button];  // 可能触发 layoutSubviews
    [ProfileCardBgHook handleCornerAndQR:button isDark:isDark];  // 设置颜色/圆角
}
```

整个 `handleButtonLayout:` 方法没有防止重入的机制。当其中任一操作触发 `layoutSubviews` 时，会再次进入此方法，形成递归。

## 修复方案

### 修复1：WPUtility.m — dynamicColorWithLightHex:darkHex: 添加 nil 安全防护

**改动位置**：`/www/wwwroot/ios/MioPlugin/Core/WPUtility.m` 第51-73行

**改动内容**：

```objc
+ (UIColor *)dynamicColorWithLightHex:(NSString *)lightHex
                             darkHex:(NSString *)darkHex {
    // ★★★ 新增：nil 防护 ★★★
    if (!lightHex.length && !darkHex.length) {
        return [UIColor clearColor];
    }
    if (!lightHex.length) lightHex = @"#FFFFFF";   // 浅色默认白色
    if (!darkHex.length) darkHex = @"#1C1C1E";     // 深色默认黑色（iOS 标准暗色背景）

    if (@available(iOS 13.0, *)) {
        return [UIColor colorWithDynamicProvider:^UIColor * _Nonnull(UITraitCollection * _Nonnull traitCollection) {
            BOOL isDark = (traitCollection.userInterfaceStyle == UIUserInterfaceStyleDark);
            NSString *hex = isDark ? darkHex : lightHex;
            UIColor *color = [WPColorUtil colorFromHexString:hex];
            if (color) return color;
            // fallback：暗黑模式自动变暗
            if (isDark) {
                UIColor *light = [WPColorUtil colorFromHexString:lightHex];
                if (light) {
                    CGFloat r=0, g=0, b=0, a=0;
                    if ([light getRed:&r green:&g blue:&b alpha:&a]) {
                        return [UIColor colorWithRed:r*0.3 green:g*0.3 blue:b*0.3 alpha:a];
                    }
                }
            }
            return [UIColor clearColor];
        }];
    }
    return [WPColorUtil colorFromHexString:lightHex] ?: [UIColor clearColor];
}
```

**改动说明**：
- 在方法开头判定 `lightHex` 和 `darkHex` 是否为空
- 两者都为空时直接返回 `clearColor`，避免创建动态颜色
- 单个为空时设置安全的默认值，确保 `colorFromHexString:` 总能成功解析
- 消除了 provider block 内部的 nil 处理路径

### 修复2：ProfileCardBgHook.m — handleButtonLayout: 添加重入锁

**改动位置**：`/www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m`

**改动1：添加静态重入标识变量**

在文件 `@implementation` 上方或内部添加：

```objc
@implementation ProfileCardBgHook

// ★★★ 新增：重入锁，防止 handleButtonLayout 递归调用 ★★★
static BOOL _wp_isHandlingButtonLayout = NO;
```

**改动2：handleButtonLayout: 入口/出口加锁**

```objc
+ (void)handleButtonLayout:(UIView *)button {
    // ★★★ 重入守卫：如果在处理中则直接返回 ★★★
    if (_wp_isHandlingButtonLayout) return;
    _wp_isHandlingButtonLayout = YES;

    CardBgConfig *config = [CardBgConfig shared];

    // ☆ 独立功能：状态隐藏
    [ProfileCardBgHook hideStateElementsInCell:button
                                   shouldHide:config.cardBgHideStateEnabled];

    // ☆ 独立功能：箭码隐藏
    [ProfileCardBgHook hideArrowQRInCell:button
                              shouldHide:[CardBgConfig shared].cardBgHideArrow];

    // 通用守卫
    UIViewController *vc = [ProfileCardBgHook findMoreViewController:button];
    if (!vc) { _wp_isHandlingButtonLayout = NO; return; }
    if (![ProfileCardBgHook hasHeadImageViewInView:button]) { _wp_isHandlingButtonLayout = NO; return; }
    if (button.frame.size.height <= 50.0) { _wp_isHandlingButtonLayout = NO; return; }
    BOOL isDark = [WPUtility isDarkModeForViewController:vc];

    // ★ 场景路由：隐藏 vs 可见
    if (config.cardBgHidden) {
        [ProfileCardBgHook handleHiddenPath:button isDark:isDark];
    } else if (config.cardBgMaterialEnabled || config.cardBgCornerEnabled) {
        [ProfileCardBgHook handleVisiblePath:button isDark:isDark];
    }

    // 独立功能
    [ProfileCardBgHook handleMarginAdjustment:button];
    [ProfileCardBgHook handleCornerAndQR:button isDark:isDark];

    // ★★★ 释放重入锁 ★★★
    _wp_isHandlingButtonLayout = NO;
}
```

**改动说明**：
- 使用 `static BOOL` 作为重入锁
- 入口处检查锁状态，已处理则直接返回
- 所有 return 路径前必须释放锁
- 正常处理完成也释放锁

> **注意**：`_wp_isHandlingButtonLayout` 是静态变量而非属性或 ivar，线程安全方面：`handleButtonLayout:` 始终在主线程调用（`layoutSubviews` 在主线程），因此不需要 `@synchronized` 或其他线程同步机制。

### 修复3：ProfileCardBgHook.m — handleMarginAdjustment: 增强精度守卫

**改动位置**：`/www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m` 第570-608行

**改动内容**：

```objc
+ (void)handleMarginAdjustment:(UIView *)button {
    CardBgConfig *config = [CardBgConfig shared];

    if (!config.cardBgCornerEnabled) return;

    CGFloat margin = 0;
    ListCornerRadiusConfig *listConfig = [ListCornerRadiusConfig shared];
    if (config.cardBgCornerUseGlobal) {
        margin = listConfig.listCellMargin;
    } else if (config.cardBgCornerMargin > 0) {
        margin = config.cardBgCornerMargin;
    }

    if (margin <= 0) return;

    CGFloat currentX = button.frame.origin.x;
    CGFloat currentW = button.frame.size.width;
    UIView *superview = button.superview;
    CGFloat containerW = superview ? superview.bounds.size.width
                                   : [UIScreen mainScreen].bounds.size.width;
    CGFloat targetX = margin;
    CGFloat targetW = containerW - margin * 2;

    // ★★★ 改动：提高精度阈值到 1.0，且记录上次值防止振荡 ★★★
    static CGFloat lastSetX = 0;
    static CGFloat lastSetW = 0;

    if (fabs(currentX - targetX) > 1.0 || fabs(currentW - targetW) > 1.0) {
        // ★★★ 额外判断：与上次设的值比较，如果已经设过了就不再设 ★★★
        if (fabs(currentX - lastSetX) < 0.5 && fabs(currentW - lastSetW) < 0.5) {
            return;  // frame 已经是我们设的值，阻止递归
        }

        CGRect bf = button.frame;
        bf.origin.x = targetX;
        bf.size.width = targetW;
        button.frame = bf;

        // ★★★ 记录本次设置的值 ★★★
        lastSetX = targetX;
        lastSetW = targetW;

        // ── Label sizeToFit ──
        for (UIView *sub in button.subviews) {
            if ([sub isKindOfClass:[UILabel class]]) {
                UILabel *label = (UILabel *)sub;
                if (label.text.length > 0) {
                    [label sizeToFit];
                }
            }
        }
    } else {
        // frame 已匹配，重置记录
        lastSetX = 0;
        lastSetW = 0;
    }
}
```

> **注意**：用了 `static` 变量记录上次设置值。由于 `handleButtonLayout:` 添加了重入锁，这里的 `static` 不会产生并发问题。

### 修复4：ProfileCardBgHook.m — traitCollectionDidChange: 防止多次触发

**改动位置**：`/www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m` 第47-64行

**改动内容**：

```objc
// ★★★ P1-11 问题2 + P1-12 补充：traitCollectionDidChange Hook + 防重入 ★★★
static IMP orig_MMUIButton_traitCollectionDidChange = NULL;
static void replaced_MMUIButton_traitCollectionDidChange(id self, SEL _cmd, UITraitCollection *previousTraitCollection) {
    if (orig_MMUIButton_traitCollectionDidChange) {
        ((void (*)(id, SEL, UITraitCollection *))orig_MMUIButton_traitCollectionDidChange)(self, _cmd, previousTraitCollection);
    }

    if (@available(iOS 13.0, *)) {
        if (previousTraitCollection && self) {
            UITraitCollection *current = ((UIView *)self).traitCollection;
            if (previousTraitCollection.userInterfaceStyle != current.userInterfaceStyle) {
                // ★★★ 暗黑模式变化 → handleButtonLayout 内部有重入锁 ★★★
                // 但这里额外判断：避免在 initWithDynamicProvider block 执行期间触发
                if (!_wp_isHandlingButtonLayout) {
                    [ProfileCardBgHook handleButtonLayout:(UIView *)self];
                }
            }
        }
    }
}
```
