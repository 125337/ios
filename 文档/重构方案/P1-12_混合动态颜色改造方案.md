# P1-12: 暗黑模式颜色方案重构 — 混合动态颜色改造方案

## 概述

将项目中所有 **UIView 级别**的颜色属性（`backgroundColor`、`textColor`）从手动 `isDark` 判断切换改为 iOS 13+ **动态颜色**（`colorWithDynamicProvider:`），**CALayer/CAShapeLayer 的 CGColor 属性**保留手动模式。

### 为什么是"混合"策略？

| 层级 | 属性 | 动态颜色效果 | 改造方式 |
|------|------|:-----------:|----------|
| **UIView** | `backgroundColor` | ✅ 自动跟随暗黑模式切换 | 改为动态颜色 |
| **UILabel** | `textColor` | ✅ 自动跟随暗黑模式切换 | 改为动态颜色 |
| **CALayer** | `borderColor`（CGColor） | ❌ 不支持自动更新 | 保留手动模式 |
| **CAShapeLayer** | `strokeColor`（CGColor） | ❌ 不支持自动更新 | 保留手动模式 |

## 第1步：WPUtility 新增动态颜色工厂方法

### WPUtility.h

在 `@interface` 中新增方法声明：

```objc
/// 创建动态颜色（iOS 13+），自动跟随暗黑模式切换
/// 适用于 UIView.backgroundColor、UILabel.textColor 等属性
/// 不适用于 CALayer.borderColor、CAShapeLayer.strokeColor（CGColor 属性）
/// @param lightColor 浅色模式颜色字符串（#RRGGBB 或 #RRGGBBAA）
/// @param darkColor  深色模式颜色字符串（#RRGGBB 或 #RRGGBBAA），传 nil 则自动变暗
/// @return 动态 UIColor 对象
+ (UIColor *)dynamicColorWithLightHex:(NSString *)lightColor
                             darkHex:(NSString *)darkColor;
```

### WPUtility.m

```objc
+ (UIColor *)dynamicColorWithLightHex:(NSString *)lightHex
                             darkHex:(NSString *)darkHex {
    if (@available(iOS 13.0, *)) {
        return [UIColor colorWithDynamicProvider:^UIColor * _Nonnull(UITraitCollection * _Nonnull traitCollection) {
            BOOL isDark = (traitCollection.userInterfaceStyle == UIUserInterfaceStyleDark);
            NSString *hex = isDark ? darkHex : lightHex;
            UIColor *color = [WPColorUtil colorFromHexString:hex];
            if (color) return color;
            // fallback：暗黑模式自动变暗
            if (isDark) {
                UIColor *light = [WPColorUtil colorFromHexString:lightHex];
                if (light) {
                    CGFloat r=0, g=0, b=0, a=0;
                    if ([light getRed:&r green:&g blue:&b alpha:&a]) {
                        return [UIColor colorWithRed:r*0.3 green:g*0.3 blue:b*0.3 alpha:a];
                    }
                }
            }
            return [UIColor clearColor];
        }];
    }
    return [WPColorUtil colorFromHexString:lightHex] ?: [UIColor clearColor];
}
```

## 改造前后对比

### 改前：手动 isDark 模式

```
暗黑模式切换
  ↓
① layoutSubviews 触发
  → 计算 isDark = [WPUtility isDarkModeForViewController:vc]
  → isDark ? darkColor : lightColor
  → cell.backgroundColor = 手动选择的颜色
  ↓
② traitCollectionDidChange: 触发
  → WeChat 原生覆盖颜色
  → 我们没有 Hook → 颜色错误
```

### 改后：动态颜色 + 手动 CGColor 混合模式

```
暗黑模式切换
  ↓
① layoutSubviews 触发
  → cell.backgroundColor = 动态颜色（自动响应模式切换）
  → cell.layer.borderColor = isDark ? darkCGColor : lightCGColor（手动）
  ↓
② traitCollectionDidChange: 触发
  → WeChat 原生覆盖 backgroundColor
  → 动态颜色自动返回正确值（因为 UIColor 本身感知 trait）
  → WeChat 覆盖无效 ✅
  ↓
③ cell.backgroundColor ✅ 自动正确
   cell.layer.borderColor ❌ 仍需 Hook traitCollectionDidChange: 手动更新
```

## 配套修复（必须同步实施）

由于动态颜色对 **CALayer/CAShapeLayer 的 CGColor** 无效，以下修复仍需按 P1-11 文档实施：

1. **P1-11 问题1的缓存键修复**：`wp_applyBorderAndBg:` 的缓存键增加 `-d%d`（isDark 维度）
2. **P1-11 问题2的 `traitCollectionDidChange:` Hook**：虽然 backgroundColor 改用动态颜色后不再需要，但 `cell.layer.borderColor` 仍需此 Hook 来更新

这两个修复互不冲突，混合策略实施后 P1-11 问题2 的 backgroundColor 部分自动解决，但 borderColor 部分仍需要 `traitCollectionDidChange:`。
