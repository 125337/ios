# 列表圆角 + 卡片背景同时开启 — 改造方案

## 问题总览

| 问题 | 触发条件 | 原因 |
|------|----------|------|
| **卡死**（0x8BADF00D） | 同时开启列表圆角 + 卡片背景，进入"我的"页面 | Cell Hook 和 Button Hook 同时修改 frame，`==` 比较永不收敛 |
| **资料卡无边距** | 改造后卡死修复，但资料卡无左右边距 | 改造 C 删除了缩窄 button 的 margin 块，但 Cell Hook 缩窄 cell frame 对资料卡 button 无效 |

## 根因链

```
Cell Hook:  cell.frame = (9, y, 375, H)   → cell 变窄 ✅
    但 MMUIButton.frame = (0, 0, 393, H)  → button 固定全宽 ❌
    且 cell.clipsToBounds = NO            → button 冲出 cell 边界 ❌
    视觉上：button 占满屏幕 → 无边距
```

Key insight：资料卡的 `MMUIButton` 使用**绝对定位**（固定全宽 frame），不会随 cell frame 缩窄而自动缩小。视觉边距只能通过**缩窄 button 本身**来实现。

## 当前状态

| 改造 | 做的事 | 状态 |
|------|--------|------|
| **A** | `==` → `fabs > 0.5` | ✅ 保留 |
| **B** | 跳过资料卡 cell 的 Cell Hook margin | ❌ 被删除 → **需恢复** |
| **C** | margin 移到 bg 创建分支 + 删独立 margin 块 | ⚠️ 需补充 button 缩窄 |

## 修正步骤

### 步骤 1：恢复改造 B（跳过资料卡 cell）

在 [ListCornerRadiusHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ListCornerRadius/ListCornerRadiusHook.m#L210-231) 的 margin 代码前插入：

```objc
// ★ 改造 B：跳过含 MMUIButton 的资料卡 cell margin（由 Button Hook 统一处理）
if ([className isEqualToString:@"MoreViewController"]) {
    __block BOOL isProfileCardCell = NO;
    [cellView.subviews enumerateObjectsUsingBlock:^(__kindof UIView *sub,
                                                     NSUInteger idx, BOOL *stop) {
        if ([sub isKindOfClass:NSClassFromString(@"MMUIButton")]) {
            isProfileCardCell = YES;
            *stop = YES;
        }
    }];
    if (isProfileCardCell) {
        goto AFTER_MARGIN;
    }
}
```

### 步骤 2：补充改造 C（创建时也缩窄 button）

在 [ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L476-479) 的 `newBg.frame` 设置之后追加：

```objc
// ★ 新增：创建 bg 时同时缩窄 button（只执行 1 次，匹配微信优化）
if (bgMargin > 0) {
    CGRect bf = button.frame;
    bf.origin.x += bgMargin;
    bf.size.width -= bgMargin * 2;
    button.frame = bf;
}
```
