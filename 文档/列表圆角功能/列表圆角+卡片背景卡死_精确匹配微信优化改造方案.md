# 列表圆角 + 卡片背景同时开启卡死 — 改造方案

## 问题 1：卡死

**列表圆角 + 卡片背景同时开启**，进入"我的"页面 → **看门狗超时**（0x8BADF00D）。

**根因**：两个 Hook 在 layoutSubviews 中多重修改 frame，形成永不收敛的布局循环。

## 问题 2：资料卡无边距

**改造后卡死修复，但资料卡 cell 没有左右边距**。

### 根因分析

当前三个改造之间的**逻辑冲突**：

```
改造 B：Cell Hook 跳过资料卡 cell 的 margin  → 资料卡 cell 保持全宽 ✅
改造 C：Button Hook 只调整 bg 图片的 frame   → MMUIButton 本身保持全宽 ✅
                       ↓
              两者都跳过了"改 button/cell 宽度" → 无视觉边距 ❌
```

**改造 C 删掉的独立 margin 块**本来在做的事：
```objc
// 被删之前（原来的独立 margin 块）
CGRect bf = button.frame;
bf.origin.x += margin;        // ← 缩窄 button
bf.size.width -= margin * 2;  // ← 缩窄 button
button.frame = bf;
```

**改造 C 替换后的代码**只做了：
```objc
newBg.frame = CGRectMake(..., adjustedW, ...);  // ← 只缩窄 bg 图片
```

### 修复方案

**删除改造 B**（去掉资料卡 cell 跳过逻辑），让 Cell Hook 统一管理所有 cell 的 margin。有了改造 A（fabs 守卫），不会产生布局循环。

具体改动：`ListCornerRadiusHook.m` 删除 L214-227 的整个 `if ([className isEqualToString:@"MoreViewController"]) { ... }` 块。

改动后保留：
| 改造 | 作用 |
|------|------|
| A：fabs 比较 | 防止 Cell Hook 因浮点精度永远重设 frame |
| C：margin 在 bg 创建时 | Button Hook 不再每轮改 button 宽度，消除循环放大因素 |
| **删除 B** | 资料卡 cell 的 margin 由 Cell Hook 统一管理 |

### 微信优化参照

微信优化的行为也是如此：
- **Cell Hook**（FUN_0000b4cc）调整所有 cell 的 frame（含资料卡 cell）
- **Button Hook**（FUN_00007b4c）只在创建时设置 bg 较窄的 frame，`layoutSubviews` 不再改 button 宽度
