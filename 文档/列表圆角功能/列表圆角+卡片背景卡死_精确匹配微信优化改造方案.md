# 列表圆角 + 卡片背景同时开启 — 改造方案

## 问题总览

| 问题 | 触发条件 | 原因 |
|------|----------|------|
| **卡死**（0x8BADF00D） | 同时开启列表圆角 + 卡片背景，进入"我的"页面 | Cell Hook 和 Button Hook 同时修改 frame，`==` 比较永不收敛 |
| **资料卡无边距（仅开列表圆角）** | 只开列表圆角，不开卡片背景 | button margin 代码在 `if (needsFullCardBg)` 内部，cardBg 关闭时永不执行 |
| **资料卡有边距（两者都开）** | 列表圆角 + 卡片背景同时开启 | 两个条件都满足，button margin 代码在 bg 创建时执行 ✅ |

## 根因链

### 问题 1：卡死（已修复）

CardBg+Cell 双重 frame 修改 + `==` 浮点比较 → 永不收敛 → watchdog 超时。

### 问题 2：只开列表圆角时资料卡无边距

```
资料卡的边距来源只有「Button Hook 缩窄 button.frame」这一个途径。
    因为：
      Cell Hook（改造 B）跳过资料卡 cell → cell 保持全宽 ✅
      资料卡 MMUIButton 绝对定位，不随 cell frame 变化 ✅

当前 button margin 代码在 ProfileCardBgHook.m L481-487：
  if (bgMargin > 0) {  ← 只在 needsFullCardBg 内部有效
      button.frame = ...;
  }

执行路径：
  cardBgEnabled=YES → needsFullCardBg=YES → 进入 if 块 → 创建 bg → 缩窄 button → 有边距 ✅
  cardBgEnabled=NO  → needsFullCardBg=NO  → 跳过 if 块 → 不缩窄 button → 无边距 ❌

结论：button margin 代码被「卡片背景开关」错误地控制了。
     它应该由「列表圆角开关」独立控制。
```

## 修复方案

### 改动：把 button margin 移到 `needsFullCardBg` 外部

删除 [L481-487](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L481-487) 的 button margin 代码，在 `needsFullCardBg` 闭合 `}` **之后**，新增独立 margin 块：

```objc
// ══════════════════════════════════════════
// }  ← needsFullCardBg 的闭合大括号
// ══════════════════════════════════════════

// ★ 独立 margin 调整（由 listCornerRadiusEnabled 控制，而非 cardBgEnabled）
if (config.listCornerRadiusEnabled) {
    CGFloat margin = config.listCellMargin;
    if (margin > 0) {
        CGFloat containerW = button.superview ? button.superview.bounds.size.width
                                               : [UIScreen mainScreen].bounds.size.width;
        CGFloat newX = margin;
        CGFloat newW = containerW - margin * 2;
        // 使用绝对值比较，防止每轮 layout 无意义触发
        if (fabs(button.frame.origin.x - newX) > 0.5 ||
            fabs(button.frame.size.width - newW) > 0.5) {
            CGRect bf = button.frame;
            bf.origin.x = newX;
            bf.size.width = newW;
            button.frame = bf;
        }
    }
}
```

**关键点**：
- **使用绝对值赋值**（`=` 而非 `+=`），杜绝累加
- **不加 fabs 守卫** → 首次改变 button.frame → 触发 button 下一轮 layout → 再次进来时 frame 已到位 → fabs 收敛
- **containerW 取 superview 宽度**，与 Cell Hook 的 margin 逻辑一致
