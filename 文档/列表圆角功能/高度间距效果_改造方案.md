# 高度/间距效果 — 改造方案

> 基于对微信优化反编译代码的深度分析。包含 3 个步骤的完整代码级改造。

---

## 背景

[高度间距效果_对比分析.md](file:///www/wwwroot/ios/文档/列表圆角功能/高度间距效果_对比分析.md) 已证实两个差异：

| # | 差异 | 表现 |
|---|------|------|
| **①** | `_hooked_heightForHeader` 强制执行 `max(original, 144)` | Section 总高度多出 `144-original` px |
| **②** | `handleButtonLayout:` 的 margin 绑定在高度调整块内 | 高度 ≥ 144 时 margin 跳过不执行 |

---

## Step 1：修正 heightForHeader — 删除最小值强制

### 当前代码（ProfileCardBgHook.m L33-37）

```objc
// ★ ① 保证空间 ≥ 自定义高度（防止 button 被截断或覆盖其他 cell）
CGFloat customHeight = config.cardBgHeight;
if (customHeight > 0 && result < customHeight) {
    result = customHeight;
}
```

微信优化不做这个。这行代码会导致：
- Section 总高度变成 `max(original, 144) + 9`
- 当 `original < 144`，button 被 section 撑到 ≥ 144
- 后续 `button.frame.size.height >= targetH` 条件成立 → 高度调整块跳过

### 改后代码

```objc
// ★ ★ ★ 删除以下整个最小值强制块 ★ ★ ★
// CGFloat customHeight = config.cardBgHeight;
// if (customHeight > 0 && result < customHeight) {
//     result = customHeight;
// }
```

**只保留间距追加**：

```objc
// ★ 只追加间距（微信优化一致）
CGFloat spacing = config.cardBgListSpacing;
if (spacing > 0) {
    result += spacing;
}
```

### 改造后公式

```
改造前：result = max(original, 144) + 9
改造后：result = original + 9             // 与微信优化一致
```

### 风险分析

**问题**：删除最小值强制后，如果 `original < 144`，Button Hook 中的高度调整（Step 2 的"设高度为 targetH"）会负责把 button 高度升到 144。由于这是同一个 `layoutSubviews` 周期内修改 frame，不会触发额外的布局循环。

**结论**：安全。button 的高度由两部分保证：
1. Section 高度 = `original + 9`（仅保证底部空间）
2. Button 实际高度 = 在 Button Hook 中独立调整到 `targetH`（不受 section 限制）

## Step 2：将 margin 应用从高度调整块中解耦

### 当前代码（ProfileCardBgHook.m L650-704）

```objc
// ── 方案 H：通过视图层级链修改 button 高度 ──
{
    CGFloat targetH = config.cardBgHeight;
    if (targetH <= 0 || button.frame.size.height >= targetH) {
        WPLog(..., @"[HEIGHT-SKIP] ...");
        goto DO_CORNER;   // ★ 高度满足时整个块跳过，margin 也不执行
    }

    // ... 向上找 tableView、container ...

    CGRect bf = button.frame;
    CGFloat oldH = bf.size.height;
    bf.size.height = targetH;

    // ★ margin 绑定在高度调整块内
    CGFloat margin = config.listCellMargin;
    if (margin > 0) {
        bf.origin.x += margin;      // ★ 高度 ≥ 144 时不执行
        bf.size.width -= margin * 2; // ★ 高度 ≥ 144 时不执行
    }
    button.frame = bf;

    // ... sizeToFit ...
}
```

**问题**：margin 应用和高度调整不应该绑定在同一条件下。微信优化的 Button Hook 中，高度调整和宽度调整是两个独立段。

### 改造后代码

**改动 2A**：从高度调整块中 **移除 margin 相关代码**（L679-684）

```objc
{
    CGFloat targetH = config.cardBgHeight;
    if (targetH <= 0 || button.frame.size.height >= targetH) {
        WPLog(..., @"[HEIGHT-SKIP] ...");
        goto DO_CORNER;
    }

    // ... 向上找 tableView、container ...

    CGRect bf = button.frame;
    CGFloat oldH = bf.size.height;
    bf.size.height = targetH;

    // ★ 删除 margin 相关代码（移到 bg 生命周期段末尾）

    button.frame = bf;
    // ... sizeToFit ...
}
```

**改动 2B**：在 bg 生命周期段末尾（FIX-WHITE 之前），新增 **独立** 的 width/margin 调整：

```objc
        // ── ★ 新增：独立 width/margin 调整（与高度调整解耦）──
        // 条件与微信优化一致：列表圆角开启 && 非特殊模式
        if (config.listCornerRadiusEnabled &&
            !(config.cardBgFillMode == 3 && config.cardBgEnabled)) {
            CGFloat margin = config.listCellMargin;
            if (margin > 0) {
                CGRect bf = button.frame;
                bf.origin.x += margin;
                bf.size.width -= margin * 2;
                button.frame = bf;

                WPLog(@"CardBg-Diag", @"[WIDTH-MARGIN] margin=%.0f, newWidth=%.0f",
                      margin, bf.size.width);
            }
        }
```

## Step 3：高度调整块中保留 height-only 逻辑（可选做）

### 当前结构（改造后 L650+，已删除 margin）

```objc
    // ── 方案 H：通过视图层级链修改 button 高度 ──
    {
        CGFloat targetH = config.cardBgHeight;
        if (targetH <= 0 || button.frame.size.height >= targetH) {
            WPLog(..., @"[HEIGHT-SKIP] ...");
            goto DO_CORNER;
        }

        // 向上找 TextStateProfileTableView
        UIView *tableView = button.superview;
        if (!tableView || ...) { goto DO_CORNER; }

        // 继续向上找 MMUIButton 容器
        UIView *container = tableView.superview;
        if (!container || ...) { goto DO_CORNER; }

        CGRect bf = button.frame;
        bf.size.height = targetH;
        button.frame = bf;

        // ... sizeToFit ...
    }
```

**注意**：当前代码假设 button → TextStateProfileTableView → container MMUIButton 这个层级链。在 bg 切换到 Button 层后，这个层级链假设仍然是正确的。

**可优化点**：如果微信优化只用 `FUN_000cb900(param_5)`（即 `setFrame:` 直接设 button 高度）而不走层级链，可以简化。但当前代码的层级链已经验证过可行（HEIGHT-SET 日志正常）。

**建议**：保持当前代码不变。安全为主。

## 风险与注意事项

1. **删除最小值强制后**，section 高度变小了。button 在 `layoutSubviews` 时可能尺寸更小。这不是问题——Button Hook 中会主动设高度。

2. **Margin 默认值**：当前 `listCellMargin = 0`。如果想和微信优化一致（内置默认 9），应在 `PluginConfig` 中改默认值，或新增独立配置 `cardBgHorizontalMargin`。当前步骤不修改默认值，只改变 margin 的执行条件。

3. **Cell Hook margin 不变**：`ListCornerRadiusHook.m` L215-231 对 cell frame 应用 margin 的逻辑不受影响。微信优化也在 Cell 和 Button 两级都做 margin 调整。

4. **Step 2 的独立 margin 块放在了 bg 生命周期段末尾**（`needsFullCardBg` 块内），因为微信优化的 margin 调整也在 bg 创建段中。如果 `cardBgEnabled = NO`，margin 不执行——这和微信优化的条件 `MoreDiscoverListRoundCornerEnabled && (fillMode==3 && bgEnabled)` 的逻辑一致（bg 关闭时 margin 也不执行的条件不同，但 MioPlugin 的 `listCornerRadiusEnabled` 本身就是独立开关，边界一致）。
