# 隐藏信息卡片功能 — 反编译版 vs MioPlugin 实现对比

> 专注分析微信「我」页面中"隐藏信息卡片"(ProfileCardHideCard / cardBgHidden) 功能的完整实现链路。
>
> 对比基准：反编译版 `wxyh1.6.5.dylib.c`（Ghidra 反编译） / MioPlugin 版 `ProfileCardBgHook.m` + `ListCornerRadiusHook.m`
>
> 文档日期：2026-06-04

---

## 零、核心发现：反编译版不在 Cell Hook 中处理资料卡逻辑

**反编译版有两个 Hook 涉及 `MMTableViewCell::layoutSubviews` 相关功能**，但分工完全不同：

| Hook | 类 | 方法 | 处理内容 |
|------|-----|------|---------|
| `FUN_0000b4cc` | `MMTableViewCell` | `layoutSubviews` | **仅**处理列表圆角（边距、圆角、背景色、边框） |
| `FUN_00007b4c` | `MMUIButton` | `layoutSubviews` | 处理**所有**资料卡逻辑（背景图、高度、隐藏卡片、图层管理） |

> ⚠️ **关键纠正**：之前文档错误地认为反编译版的 `FUN_0000b4cc`（Cell Hook）也处理资料卡背景/隐藏/高度。实际反编译代码分析确认：
> 
> `FUN_0000b4cc` 在调用 `orig` 后，仅读取 `MoreDiscoverListRoundCornerEnabled`，通过 responder 链找到 VC 后检查是否属于约 20 个指定 VC（WCTimeLineViewController, WCAccountLoginUsersViewController 等），然后计算圆角/边距。**整个过程不涉及 MoreViewController、MMHeadImageView 或 ProfileCard 相关配置**。
>
> 所有资料卡逻辑（包括隐藏卡片）全部在 **Button Hook `FUN_00007b4c`** 中处理。

## 一、Hook 架构对比

### 1.1 反编译版：隐藏卡片涉及的 Hook 链

反编译版的隐藏卡片逻辑**全部在 Button Hook 中完成**，Cell Hook 不参与：

```
触发顺序：
① MMUIButton::layoutSubviews → FUN_00007b4c（Button 层 cardBg 路径，line 9550-9551）← ★ 主要隐藏逻辑
    ├─ Step 1: 检测 MoreViewController + MMHeadImageView + height > 50 确认资料卡
    ├─ Step 2: 高度调整
    ├─ Step 3: HideCard 分支
    │   ├─ button.backgroundColor = clearColor
    │   ├─ button.layer.backgroundColor = clearColor
    │   └─ subviews[0] 背景色清理
    ├─ Step 4: 子视图管理 + bg 生命周期（HideCard 时保留 bg，非 HideCard 时显示全部）
    └─ Step 5: 图层管理（masksToBounds = NO 等）

② MMUIButton::layoutSubviews → FUN_0000d898（Button 层 listCorner 路径，line 11548-11549）
    └─ HideCard 补充：跳过背景色设置

③ MMTableViewCell::layoutSubviews → FUN_0000b4cc（Cell 层，line 11533-11534）
    └─ 仅处理列表圆角，完全**不参与**隐藏卡片逻辑
```

### 1.2 MioPlugin：隐藏卡片涉及的 Hook 链

```
触发顺序：
① MMTableViewCell::layoutSubviews → replaced_MMTableViewCell_layoutSubviews
   （ListCornerRadiusHook.m:325-330，列表圆角 Cell Hook）
    └─ 不处理 HideCard，仅处理列表圆角

② MMUIButton::layoutSubviews → replaced_MMUIButton_layoutSubviews（薄分发）
   （ListCornerRadiusHook.m:352-360）
    └─ 分发给 [ProfileCardBgHook handleButtonLayout:]

   handleButtonLayout: 内部：
     ├─ HideCard 分支（cardBgHidden == YES）← ★ 主要隐藏逻辑
     │   ├─ button.backgroundColor = clearColor
     │   ├─ 清除 m_bgImageView
     │   ├─ 遍历 button.subviews → sub.hidden = YES
     │   └─ return 提前退出
     └─ 背景图分支（cardBgHidden == NO）

③ MMTableViewCell::layoutSubviews → handleCellLayout:（ProfileCardBgHook.m:774-830）
    └─ 透明化 Cell 全部四层 ← ★ Cell 层清理
       ├─ cell.backgroundColor = clearColor
       ├─ cell.contentView.backgroundColor = clearColor
       ├─ cell.backgroundView.backgroundColor = clearColor
       ├─ cell.backgroundView.hidden = YES
       └─ cell.selectedBackgroundView.backgroundColor = clearColor
```

## 三、逐行实现对比

### 3.1 Cell 层处理对比

| 步骤 | 作用说明 | 反编译版（Button Hook FUN_00007b4c） | MioPlugin（handleCellLayout:） | 谁更好 | 性能谁更好 |
|------|---------|--------------------------------------|-------------------------------|--------|-----------|
| **Cell.backgroundColor** | 清除 Cell 自身白色背景，避免遮挡下层内容 | ❌ 未处理（反编译版不在 Cell 层操作） | `clearColor` | **MioPlugin** | **反编译版**（未处理，零开销） |
| **contentView** | Cell 的内容容器，不清除时白色背景会遮挡自定义背景 | ❌ 未处理 | ✅ `clearColor` + `masksToBounds = NO` | **MioPlugin** | **反编译版**（未处理，零开销） |
| **backgroundView** | Cell 背景视图（微信可能设置背景图或颜色） | ❌ 未处理 | ✅ `clearColor` + `hidden = YES` | **MioPlugin** | **反编译版**（未处理，零开销） |
| **selectedBackgroundView** | 选中态背景视图，不清除时选中 Cell 会闪白色 | ❌ 未处理 | ✅ `clearColor` | **MioPlugin** | **反编译版**（未处理，零开销） |
| **layer.borderWidth** | 清除 Cell 层可能残留的边框（如微信默认分隔线） | ❌ 未处理 | ✅ 设为 0 | **MioPlugin** | **反编译版**（未处理，零开销） |
| **layer.masksToBounds** | 关闭 Cell 层裁剪，确保圆角或阴影不被裁切 | ❌ 未处理 | ✅ 设为 NO | **MioPlugin** | **反编译版**（未处理，零开销） |
| **隐藏子视图** | 隐藏 Cell/Button 上的子视图 | ✅ 在 Button Hook 中：遍历全部 subviews，非 UIImageView→hidden，UIImageView 检查 tag，仅 tag=9998/9999 保留可见（bg 豁免），其他 UIImageView 也 hidden | ✅ 在 Button Hook 中：遍历**全部** button.subviews → hidden=YES | **反编译版**（更精细，能保留 bg） | **MioPlugin**（遍历全部设 hidden，更简单直接） |
| **渐变色遮罩** | 对残留的 UIImageView 设 CardBackgroundColor 遮罩，统一视觉 | ✅ 在 Button Hook 中，对 ImageView 设 CardBackgroundColor 作为遮罩 | ❌ 无（MioPlugin 不保留 ImageView） | **反编译版**（独有） | **MioPlugin**（反编译版多一次完整子视图遍历 + UIColor 创建） |
| **调用位置** | 隐藏逻辑的触发时机 | 在 Button Hook 中：检查 HideCard→YES 时执行清除操作 | 独立 Hook，每次 layoutSubviews 都执行（不论是否隐藏） | **MioPlugin**（防御式） | **反编译版**（仅在 HideCard==YES 时执行，MioPlugin 每次 layoutSubviews 都执行） |

### 5.1 为什么反编译版不需要 Cell 层透明化？

反编译版没有 Cell 层透明化处理，原因在于它的架构设计：

| 维度 | 反编译版 | MioPlugin |
|------|---------|-----------|
| **背景图位置** | **Button 层**（`button.subviews`，tag=9998/9999） | Cell 层（`cell.subviews`，改造方案） |
| **Button 背景色** | 非 HideCard 时：有实色背景覆盖 Cell；HideCard 时：清除背景色；bg 始终在 Button 层可见 | HideCard 时：清除背景色 + hidden=YES；非 HideCard 时：有背景色；bg 在 Cell 层不受影响 |
| **Cell 是否需要透明** | **不需要**——按钮的实色背景覆盖 Cell，Cell 的背景色被遮挡且不影响视觉 | **需要**——改造前背景在 Button 层，改造后已移至 Cell 层（MioPlugin 方案） |
| **Hook 职责** | Cell Hook（FUN_0000b4cc）仅做列表圆角；Button Hook（FUN_00007b4c）做资料卡逻辑（含 bg 管理 + 子视图可见性控制） | Cell Hook（handleCellLayout:）做 Cell 透明化 + bg 生命周期；Button Hook（handleButtonLayout:）做子视图隐藏 |

### 5.2 核心架构差异

```
反编译版：
  FUN_0000b4cc (MMTableViewCell::layoutSubviews)
  └─ 仅处理列表圆角：边距/圆角/背景色/边框 ← 不涉及资料卡

  FUN_00007b4c (MMUIButton::layoutSubviews, cardBg 路径)

  └─ 仅处理列表圆角

  handleCellLayout: (ProfileCardBgHook, 也是 MMTableViewCell::layoutSubviews Hook)
  └─ 仅处理资料卡 Cell 透明化 + bg 生命周期
```

## 六、HideCard + 背景图的交互对比

### 6.1 反编译版：HideCard 模式保留背景图

当 `ProfileCardHideCard == YES` 且 `ProfileCardBackgroundEnabled == YES` 时：

```
┌──────────────────────────────────────────┐
│  Cell                                       │
│  ├── Cell.contentView                       │
│  └── MMUIButton (backgroundColor=clearColor)│
│       ├── UIImageView (背景图) ← tag=9998/9999，唯一可见
│       ├── MMHeadImageView (hidden=YES)      │
│       ├── MMCPLabel (hidden=YES)            │
│       ├── MMUILabel (hidden=YES)            │
│       ├── 其他 UIImageView (hidden=YES)      │
│       └── 其他非 UIImageView (hidden=YES)    │
└──────────────────────────────────────────┘
```

> **注意**：bg UIImageView 是 **button 的直接子视图**（tag=9998/9999），**不是 Cell 层的子视图**。反编译版在 HideCard 模式下遍历 button.subviews，对非 UIImageView 子视图设 hidden=YES，而对 UIImageView 检查 tag，只有 tag=9998/9999 的保留可见，其他 UIImageView 也隐藏。因此用户只看到背景图，卡片内容（头像/昵称/微信号）被隐藏。

### 6.2 MioPlugin：HideCard 模式提前退出

当 `cardBgHidden == YES` 时，`handleButtonLayout:` 在 HideCard 分支中 `return`，**不创建/加载背景图**：

```
┌──────────────────────────────────────────┐
│  Cell (backgroundColor = clearColor)       │
│  ├── Cell.contentView (backgroundColor = clearColor)
│  ├── Cell.backgroundView (hidden = YES)
│  ├── Cell.selectedBackgroundView (backgroundColor = clearColor)
│  └── MMUIButton (backgroundColor = clearColor)
│       └── 全部子视图 (hidden = YES)
└──────────────────────────────────────────┘
```

### 6.3 行为差异表

| 场景 | 作用说明 | 反编译版 | MioPlugin | 谁更好 | 性能谁更好 |
|------|---------|---------|-----------|--------|-----------|
| **HideCard=YES, 背景图=有** | 开启隐藏卡片 + 启用了背景图时，最终用户看到什么 | 显示背景图，隐藏卡片内容 | ❌ 全部隐藏（背景图也不显示） | **反编译版**（背景图可做装饰） | 平局（行为差异，非性能差异） |
| **HideCard=YES, 背景图=无** | 开启隐藏卡片 + 未启用背景图 | 背景透明，卡片内容隐藏 | 全部透明隐藏 | 平局 | 平局 |
| **HideCard=NO, 背景图=有** | 不隐藏卡片 + 启用了背景图 | 背景图 + 卡片内容都显示 | 背景图 + 卡片内容都显示 | 平局 | 平局 |
| **HideCard=NO, 背景图=无** | 不隐藏卡片 + 未启用背景图（仅纯色背景） | 纯色背景 + 卡片内容 | 纯色背景 + 卡片内容 | 平局 | 平局 |

## 七、代码示例对比

### 7.1 反编译版 HideCard 核心代码

反编译版的 HideCard 逻辑全部在 **Button Hook** 中，Cell Hook 不参与。HideCard 不是简单的 return，而是**选择性隐藏子视图**并**继续执行 bg 生命周期**：

```objc
// FUN_00007b4c（Button Hook cardBg 路径）- HideCard 分支（≈line 9724-9797）
if ([config boolForKey:@"ProfileCardHideCard"]) {
    // 1. 清除 button 背景色
    [button setBackgroundColor:[UIColor clearColor]];
    [button.layer setBackgroundColor:[UIColor clearColor].CGColor];

    // 2. 检查 subviews[0] frame 是否与 button 近似
    UIView *first = button.subviews.firstObject;
    if (first &&
        fabs(first.frame.size.width - button.frame.size.width) < 10.0 &&
        fabs(first.frame.size.height - button.frame.size.height) < 10.0) {
        [first setBackgroundColor:[UIColor clearColor]];
        [first.layer setBackgroundColor:[UIColor clearColor].CGColor];
    }

    // 3. ★ 不退出！继续执行下方的子视图管理 + bg 生命周期
}

// ★ HideCard 和 非 HideCard 都会执行到这里：
// 子视图管理（选择性隐藏/显示）
for (UIView *sub in button.subviews) {
    if ([sub isKindOfClass:[UIImageView class]]) {
        NSInteger tag = sub.tag;
        if (tag == 9998 || tag == 9999) {
            // bg 图片 → 保留可见（不隐藏）
            continue;
        }
    }
    // 非 UIImageView 或非 bg 标签 → 根据 HideCard 状态控制
    if ([config boolForKey:@"ProfileCardHideCard"]) {
        sub.hidden = YES;           // 隐藏
    } else {
        sub.hidden = NO;            // 显示
    }
}

// bg 生命周期（始终执行，不依赖 HideCard 状态）
UIImageView *existingBg = [self findBgImageViewInButton:button mode:isDark];
if (!existingBg) {
    existingBg = [self createNewBgImageViewForButton:button mode:isDark];
    [button insertSubview:existingBg atIndex:(button.subviews.count - 8)];
    // dispatch_async → 异步加载图片
}
// ...

// FUN_0000d898（Button Hook listCorner 路径）- HideCard 分支
if ([config boolForKey:@"ProfileCardHideCard"]) {
    // 跳过 backgroundColor 设置（让 button 保持透明）
} else {
    UIColor *color = FUN_0000e02c(config, 1);  // CardBackgroundColor
    [button setBackgroundColor:color];
}
```

> **关键**：反编译版在 HideCard 检测后**没有 return**，而是继续执行子视图管理和 bg 生命周期。bg UIImageView（tag=9998/9999）被豁免隐藏，始终可见。

### 7.2 MioPlugin HideCard 核心代码

```objc
// handleButtonLayout: HideCard 分支
if (config.cardBgHidden) {
    button.backgroundColor = [UIColor clearColor];
    button.layer.masksToBounds = NO;
    button.layer.cornerRadius = 0;
    button.layer.borderWidth = 0;

    // 清除微信原生背景图
    Ivar bgIvar = class_getInstanceVariable([button class], "m_bgImageView");
    if (bgIvar) {
        id bgImgView = object_getIvar(button, bgIvar);
        if (bgImgView && [bgImgView isKindOfClass:[UIImageView class]]) {
            [(UIImageView *)bgImgView setImage:nil];
            [(UIImageView *)bgImgView setBackgroundColor:[UIColor clearColor]];
            [(UIImageView *)bgImgView setHidden:YES];
        }
        object_setIvar(button, bgIvar, nil);
    }

    // 隐藏全部子视图
    for (UIView *sub in button.subviews) { sub.hidden = YES; }

    if (config.listHideRightQRCode) {
        [ProfileCardBgHook hideQRButtonInCell:button];
    }
    return;
}

// handleCellLayout: Cell 透明化
cellView.backgroundColor = [UIColor clearColor];
cellView.layer.borderWidth = 0;
cellView.layer.masksToBounds = NO;

cell.contentView.backgroundColor = [UIColor clearColor];
cell.contentView.layer.masksToBounds = NO;

cell.backgroundView.backgroundColor = [UIColor clearColor];
cell.backgroundView.hidden = YES;

cell.selectedBackgroundView.backgroundColor = [UIColor clearColor];
```

## 九、改进建议

### MioPlugin 可借鉴的反编译版 HideCard 设计

1. **HideCard 模式下保留背景图**：当前 MioPlugin 在 `cardBgHidden == YES` 时 `return` 跳过背景图加载。反编译版的做法是：**不在 HideCard 时 return**，而是先创建/管理 bg，再通过选择性隐藏子视图来实现。MioPlugin 可参考此方式，在 HideCard 分支中**不直接 return**，而是在 bg 创建完成后，再对 button.subviews 做选择性隐藏（保留 bg）。

2. **Tag 标签系统（9998/9999）**：反编译版使用 tag=9998（浅色模式）/9999（深色模式）标记 bg UIImageView，在子视图遍历时通过 tag 豁免隐藏。MioPlugin 可以使用类似机制，在遍历子视图时跳过特定 tag 的 UIImageView。

3. **渐变色遮罩**：反编译版在隐藏子视图后对 ImageView 设置 `CardBackgroundColor` 作为遮罩。MioPlugin 可考虑在隐藏子视图前，对希望保留的子视图额外处理。

### 反编译版可借鉴 MioPlugin 的 HideCard 设计

1. **Cell 透明化 4 层全清理**：反编译版不做 Cell 透明化（因为 bg 在 Button 层），但 MioPlugin 如果采用 Cell 层 bg 方案，4 层透明化是必要的防御措施。

2. **Runtime 清除 m_bgImageView**：通过 class_getInstanceVariable 清除微信原生背景图 ivar，避免原生背景图在隐藏状态下仍然显示。

3. **全量 layer 属性重置**：将 cornerRadius / masksToBounds / borderWidth 全部重置，避免隐藏状态下残留圆角或边框视觉效果。
