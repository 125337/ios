# 职责分离改造方案 — 边距全归 Cell Hook，Button Hook 零间距

## 新架构

```
┌──────────────────────────────────────────────────────────────┐
│ 列表圆角模块 (ListCornerRadiusHook.m)                         │
│                                                              │
│ ● 受 listCornerRadiusEnabled 控制                            │
│                                                              │
│ Cell Hook (MMTableViewCell layoutSubviews):                  │
│   ├─ 所有 cell 的 margin（缩窄 cell.frame）                   │
│   ├─ 资料卡 cell → 额外缩窄 MMUIButton.frame                 │
│   ├─ 所有 cell 的 cornerRadius + masksToBounds               │
│   ├─ 所有 cell 的 bgColor（listCellLightBgColor/DarkBgColor） │
│   ├─ 资料卡 button 的背景色（「卡片背景色」配置项             │
│   │  即 listCardLightBgColor/DarkBgColor，在列表圆角设置页)  │
│   └─ 所有 cell 的 border                                     │
│                                                              │
│ Button Hook (MMUIButton layoutSubviews):                     │
│   └─ 调用 ProfileCardBgHook.handleButtonLayout               │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│ 卡片背景模块 (ProfileCardBgHook.m)                            │
│                                                              │
│ ● 受 cardBgEnabled 控制                                      │
│                                                              │
│ handleButtonLayout:                                           │
│   ├─ bg 生命周期（创建/更新 bg image）                       │
│   ├─ 卡片高度调整（方案 H）                                   │
│   ├─ HideCard 分支                                           │
│   ├─ FIX-WHITE                                               │
│   ├─ ✅ 资料卡独立圆角 + 边框（DO_CORNER，仅当 cardBg 开）   │
│   └─ ❌ 不设 backgroundColor（由列表圆角管）                  │
│                                                              │
│ initCellHeightHook:                                           │
│   └─ heightForHeaderInSection:（上下间距）                   │
└──────────────────────────────────────────────────────────────┘
```

> **术语澄清**：
> - **「卡片背景色」** = 列表圆角模块的配置项 `listCardLightBgColor`/`listCardDarkBgColor`，位于列表圆角设置页，控制资料卡 button 的纯色背景
> - **「卡片背景」** = 卡片背景模块的开关 `cardBgEnabled`，控制资料卡上的背景**图片**
> - 两者是完全不同的功能，分属不同模块，互不冲突

## 改动 1：Cell Hook 新增资料卡 button 缩窄

**文件**：[ListCornerRadiusHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ListCornerRadius/ListCornerRadiusHook.m)

**位置**：L236 orig 调用之后，bgColor 之前

```objc
    // ★ orig ★
    if (_orig_MMTableViewCell_layoutSubviews) {
        ((void (*)(id, SEL))_orig_MMTableViewCell_layoutSubviews)(self, _cmd);
    }

    // ★ 新增：资料卡 cell → 缩窄 MMUIButton.frame 匹配 cell 边距 ★
    if (margin > 0 && [className isEqualToString:@"MoreViewController"]) {
        [cellView.subviews enumerateObjectsUsingBlock:^(__kindof UIView *sub,
                                                         NSUInteger idx, BOOL *stop) {
            if ([sub isKindOfClass:NSClassFromString(@"MMUIButton")]) {
                CGRect sf = sub.frame;
                CGFloat targetW = cellView.bounds.size.width;
                // button 起点对齐 cell content（0=cell 内部，cell 自己已在边距位置）
                if (fabs(sf.origin.x) > 0.5 || fabs(sf.size.width - targetW) > 0.5) {
                    sf.origin.x = 0;
                    sf.size.width = targetW;
                    sub.frame = sf;
                }
                *stop = YES;
            }
        }];
    }
```

**布局计算**：

```
cell.frame = (9, y, 375, H)          ← 在 table view 中
button.frame = (0, 0, 375, H')       ← 在 cell 内部 = 与 cell 同宽

视觉上：
  button.left = 0(table) + 9(cell) + 0(button) = 9px   → 9px 左边距 ✅
  button.right = 9 + 375 = 384                          → 9px 右边距 ✅
```

**不用 `AFTER_MARGIN:` 标签了**。改造 B 的跳转逻辑已完全删除，由这个统一代码替代。

### 验证：布局循环不会复现

- Cell Hook 首次设 button.frame → 触发 button 下一轮 layoutSubviews
  - ListCornerRadiusHook 的 MMUIButton hook → 只调 handleButtonLayout（height/corner，不碰宽度）
  - handleButtonLayout 不设 button 宽度 → button 宽度不变 → 无新触发
  - Cell Hook 再次进入 → fabs 比较 → within 0.5px → 跳过 → 收敛

## 改动 4：Cell Hook 新增资料卡 button 的背景色（卡片背景色）

**文件**：[ListCornerRadiusHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ListCornerRadius/ListCornerRadiusHook.m)

**位置**：bgColor 设置段落后、corner 设置之前

**背景**：「卡片背景色」（`listCardLightBgColor`/`listCardDarkBgColor`）是列表圆角模块的配置项，在列表圆角设置页中配置。当 `listCornerRadiusEnabled=YES` 时，Cell Hook 应当给资料卡 button 设置此背景色。

**注意**：此背景色是纯色背景，和卡片背景模块的**背景图片**无关。当同时开启卡片背景模块时，背景图片会覆盖在纯色背景之上，所以设置纯色背景不会产生视觉冲突。

```objc
    // ★ 新增：资料卡 button 的背景色（卡片背景色配置项）★
    if ([className isEqualToString:@"MoreViewController"]) {
        [cellView.subviews enumerateObjectsUsingBlock:^(__kindof UIView *sub,
                                                         NSUInteger idx, BOOL *stop) {
            if ([sub isKindOfClass:NSClassFromString(@"MMUIButton")]) {
                UIColor *cardBg = [config colorFromHex:isDark
                    ? config.listCardDarkBgColor : config.listCardLightBgColor];
                if (cardBg) {
                    sub.backgroundColor = cardBg;
                }
                *stop = YES;
            }
        }];
    }
```

### 与卡片背景模块的交互

| 场景 | 列表圆角设 button bgColor | 卡片背景模块行为 | 最终效果 |
|------|--------------------------|-----------------|---------|
| 只开列表圆角 | ✅ 设置 `listCardLightBgColor`/`listCardDarkBgColor` | 不介入 | 纯色背景 ✅ |
| 两者都开 | ✅ 设置（被背景图片覆盖） | 添加背景图片 subview | 背景图片可见 ✅ |
| 只开卡片背景 | ❌ Cell Hook 不执行 | `applyProfileCardCorner` 设置 bgColor 作为兜底 | 无图时显示纯色 ✅ |

> **说明**：当 cardBgEnabled=YES 且图片加载成功后，UIImageView 覆盖在 button 上方，button.backgroundColor 被遮盖，不影响视觉。
> 当 cardBgEnabled=YES 且图片加载失败时，卡片背景模块的 `handleButtonLayout` 已有兜底逻辑（L548-554）回退到 `listCardLightBgColor`/`listCardDarkBgColor`，不会出现空白。

### 需要清理：applyProfileCardCorner 中的旧逻辑

当前 `applyProfileCardCorner`（[ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m) L57-64）中有一段背景色设置：

```objc

        ? config.listCardDarkBgColor : config.listCardLightBgColor];

```

改造后，当 `listCornerRadiusEnabled=YES` 时由 Cell Hook 统一设置 button 背景色，所以这段代码的作用域缩小为：
- **仅当** `listCornerRadiusEnabled=NO && cardBgEnabled=YES` 时作为兜底
- Cell Hook 不进入（listCornerRadiusEnabled=NO），但 DO_CORNER 执行，此时需要设置背景色

可修改为：
```diff
-    if (!config.cardBgEnabled) {
+    if (!config.listCornerRadiusEnabled) {
         UIColor *cardBg = [config colorFromHex:isDark
             ? config.listCardDarkBgColor : config.listCardLightBgColor];
         if (cardBg) {
             cell.backgroundColor = cardBg;
         }
     }
```

即：当 `listCornerRadiusEnabled=NO` 时才由这边兜底设置背景色；当 `listCornerRadiusEnabled=YES` 时由 Cell Hook 统一处理。

## 改动 5：修复资料卡内容压缩回归（改造误删 label 修复）

**背景**：改造 改动 2 删除 `handleButtonLayout` 中的 margin 代码时，连带删除了 label 宽度调整 + `numberOfLines=0` 的修复代码。导致资料卡的昵称/微信号等 label 因 `numberOfLines=1` + `lineBreakMode=NSLineBreakByTruncatingTail` 而被截断为"...", 和改造前一模一样的 bug。

**分析文档**：[资料卡内容压缩Bug分析.md](file:///www/wwwroot/ios/文档/列表圆角功能/资料卡内容压缩Bug分析.md)

### 根因

| 层 | 改造前 | 改造后 |
|----|-------|-------|
| Cell Hook (cell.frame) | ✅ 缩窄 | ✅ 缩窄（未变） |
| Cell Hook (button.frame) | ❌ 无（由 handleButtonLayout 做） | ❌ **改动 1 未实现** |
| handleButtonLayout (button.frame) | ✅ 缩窄 + ✅ label 修复 | ❌ 全部删除 |
| 结果 | label 正常 | label 截断 |

### 修复方案

在 **改动 1** 的 button 缩窄代码中**追加** label 安全处理：对超出的 UILabel 设置 `numberOfLines=0` + `sizeToFit`，**不显式缩小 label 宽度**。

**文件**：[ListCornerRadiusHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ListCornerRadius/ListCornerRadiusHook.m)

**位置**：改动 1 的 button.frame 缩窄 block 内，框架调整之后

```objc
    // ★ 新增：资料卡 cell → 缩窄 MMUIButton.frame 匹配 cell 边距 ★
    if (margin > 0 && [className isEqualToString:@"MoreViewController"]) {
        [cellView.subviews enumerateObjectsUsingBlock:^(__kindof UIView *sub,
                                                         NSUInteger idx, BOOL *stop) {
            if ([sub isKindOfClass:NSClassFromString(@"MMUIButton")]) {
                CGRect sf = sub.frame;
                CGFloat targetW = cellView.bounds.size.width;
                if (fabs(sf.origin.x) > 0.5 || fabs(sf.size.width - targetW) > 0.5) {
                    sf.origin.x = 0;
                    sf.size.width = targetW;
                    sub.frame = sf;
                }

                // ★ 修复：label 内容压缩（改造误删）★
                for (UIView *sv in sub.subviews) {
                    if ([sv isKindOfClass:[UILabel class]]) {
                        UILabel *label = (UILabel *)sv;
                        // 只有超出 button 边界的 label 才需要修复，避免无谓触发
                        if (CGRectGetMaxX(label.frame) > sub.bounds.size.width) {
                            label.numberOfLines = 0;
                            [label sizeToFit];
                        }
                    }
                }

                *stop = YES;
            }
        }];
    }
```

### 与反编译版的对比

| 维度 | 反编译版 (wxyh1.6.5) | MioPlugin（改造后） |
|------|---------------------|-------------------|
| Label 宽度 | 不显式修改，依赖 autoresizing | **不显式修改** ✅（和反编译版一致） |
| 修复手段 | `[label sizeToFit]`（仅触发高度重算） | `numberOfLines=0` + `[label sizeToFit]` |
| 触发条件 | 无条件，每次 layout 都调 | 仅当 label 超出 button 边界 |
| 布局循环风险 | 无（仅调 sizeToFit，不碰 width） | 极低（有边界判断守卫） |

### 验证：无布局循环

- Label frame 变化由 `sizeToFit` 触发 → 不影响 button.frame → 不会触发 Cell Hook 的 button 缩窄
- 下次 Cell Hook 进入时：button.frame 已匹配 → fabs 比较跳过 → 不再进入 label 修复
- 即使 label 调整导致 button 内部重排，button.frame.width 不变 → 布局收敛
