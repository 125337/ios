#### 1.2.1 目标类和方法

| `VoiceMessageCellView` | `layoutSubviews` | 直接 `MSHookMessageEx` |

#### 1.2.2 实现逻辑

```objc
// layoutSubviews — 先调用原始布局，再隐藏红点和转文字
static void (*orig_VoiceMsgCell_layoutSubviews)(id, SEL) = NULL;
static void hook_VoiceMsgCell_layoutSubviews(id self, SEL _cmd) {
    orig_VoiceMsgCell_layoutSubviews(self, _cmd);
    if ([UIPurifyConfig shared].hideVoiceRedDot) {
        // 隐藏未读红点
        UIView *unreadView = [self valueForKey:@"m_unreadImageView"];
        [unreadView setHidden:YES];
        // 隐藏"转文字"快捷按钮
        UIView *transBtn = [self valueForKey:@"m_quickTransTipButton"];
        [transBtn setHidden:YES];
    }
}
```

#### 1.2.3 install 安装代码

```objc
// ── 语音红点和转文字 ──
Class voiceCellClass = objc_getClass("VoiceMessageCellView");
if (voiceCellClass) {
    MSHookMessageEx(voiceCellClass, @selector(layoutSubviews),
                    (IMP)hook_VoiceMsgCell_layoutSubviews,
                    (IMP *)&orig_VoiceMsgCell_layoutSubviews);
    WPLog(@"UIPurify", @"[+] VoiceMessageCellView layoutSubviews hooked");
} else {
    WPLog(@"UIPurify", @"[-] VoiceMessageCellView not found");
}
```

**说明**：`VoiceMessageCellView` 的 `layoutSubviews` 使用 `MSHookMessageEx` 而不是 `purifySafeHook`。原因是 `layoutSubviews` 来自 `UIView`（系统类），项目中的 Hook 模块不会 Hook `UIView` 的 `layoutSubviews`，不存在父子类 Hook 冲突。

| Hook 逻辑 | [UIPurifyHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/Layout/UIPurifyHook.m) | ❌ |

### 2.2 实现方案

#### 2.2.1 目标类和方法

| 类 | 方法 | 方式 |
|---|------|:----:|
| `YYAsyncImageView` | `layoutSubviews` | 直接 `MSHookMessageEx` |

#### 2.2.2 实现逻辑

```objc
// layoutSubviews — 遍历 superview 链，找到 CommonMessageCellView 后精确透明化
static void (*orig_YYAsyncImg_layoutSubviews)(id, SEL) = NULL;
static void hook_YYAsyncImg_layoutSubviews(id self, SEL _cmd) {
    orig_YYAsyncImg_layoutSubviews(self, _cmd);
    if ([UIPurifyConfig shared].hideBubbleBackground) {
        // 沿 superview 链向上查找 CommonMessageCellView
        UIView *current = self;
        while (true) {
            UIView *superview = [current superview];
            if (superview == nil) break;

            if ([superview isKindOfClass:NSClassFromString(@"CommonMessageCellView")]) {
                // 获取 cell 的背景图片视图
                UIImageView *bgImgView = [superview getBgImageView];
                if (bgImgView != nil) {
                    // 确认 self 是 bgImgView 的后代视图
                    if ([self isDescendantOfView:bgImgView]) {
                        [self setAlpha:0.0]; // 透明
                        break;
                    }
                }
            }
            current = superview;
        }
    }
}
```

> **说明**：使用 `getBgImageView` + `isDescendantOfView:` 组合而非简单 `subviews containsObject`，是因为 `CommonMessageCellView` 中可能包含多个 `YYAsyncImageView`（背景图、封面图等）。只有精确定位到气泡背景图的后代视图才设为透明，确保不影响其他图片。详见 [实现分析文档 §2.4](file:///www/wwwroot/ios/文档/微信优化分析/界面净化_语音红点_气泡背景_禁用听写_实现分析.md#24-为什么需要-getbgimageview--isdescendantofview)。

## 六、验证方法

### 6.1 隐藏语音红点和转文字

1. 发送一条语音消息
2. 开启开关 → 语音消息的红点消失，"转文字"按钮不显示
3. 关闭开关 → 恢复正常

### 6.2 隐藏聊天气泡背景

1. 开启开关 → 聊天界面中所有聊天气泡背景变为透明
2. 关闭开关 → 恢复正常
3. 注：气泡内的文字/图片内容不受影响

### 6.3 禁用输入框听写

1. 开启开关 → 输入框键盘上方的听写按钮不可用或消失
2. 关闭开关 → 恢复正常

### 6.4 组合测试

1. 三个功能同时开启 → 各自生效，不冲突
2. 快速开关 + 快速聊天 → 无 crash、无布局错乱
