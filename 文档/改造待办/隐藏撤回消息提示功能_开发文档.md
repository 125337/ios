# 隐藏撤回消息提示 — 功能开发文档

> 基于项目当前状态编写 | 独立于隐藏拍一拍功能
> 核验日期：2026-06-11 | 仅含当前未实现部分

## 一、功能描述

隐藏聊天界面中"xx 撤回了一条消息"的系统提示消息。让撤回提示完全不显示，不留空白占位。

### 功能边界

| 项目 | 内容 |
|------|------|
| 功能 | 隐藏撤回消息提示 |
| 配置 Key | `hideRevokeHint` |
| 持久化 Key | `WCP_UIPurify_hideRevokeHint` |
| 设置页面 | 界面净化 → 消息显示 → 隐藏撤回消息提示 |
| 当前状态 | **配置 ✅ / UI ✅ / Hook ❌** |

### 与防撤回（RevokeHook）的区别

| 功能 | 层级 | Hook 目标 | 行为 |
|------|:----:|----------|------|
| **防撤回**（已实现） | 消息层 | `CMessageMgr.onNewSyncNotAddDBMessage:` | 阻止撤回指令执行，消息不被删除 |
| **隐藏撤回提示**（本文档） | UI 层 | `SystemMessageCellView` × 4 + `SystemMessageViewModel` × 1 | 撤回提示 Cell 不显示 |

两者完全独立，互不依赖：
- 防撤回开启 → 消息不被撤回 → 没有撤回提示产生
- 隐藏撤回提示开启 → 撤回后产生的提示消息被隐藏

## 三、微信目标类分析

撤回提示消息在微信中的 Cell/ViewModel 类层次：

```
BaseMessageCellView                    ← 微信原生基类
  └── SystemMessageCellView            ← 撤回提示（目标类）
        └── AppPatMessageCellView      ← 拍一拍

BaseMessageViewModel
  └── SystemMessageViewModel           ← 撤回提示 ViewModel（目标类）
        └── AppPatMessageViewModel     ← 拍一拍
```

需要 Hook 的类：`SystemMessageCellView`（4 个方法） + `SystemMessageViewModel`（1 个方法）

| 方法 | 所属类 | 功能开启时行为 | 作用 |
|------|--------|---------------|------|
| `initWithViewModel:` | `SystemMessageCellView` | setHidden:YES + setFrame: | 创建时立即隐藏 |
| `layoutInternal` | `SystemMessageCellView` | 直接 return（跳过） | 阻止布局计算 |
| `canBeReused` | `SystemMessageCellView` | 返回 YES | 标记 Cell 可复用 |
| `shouldLayoutIfNeeded` | `SystemMessageCellView` | 返回 NO | 告知 TableView 不需要重新布局 |
| `measure:` | `SystemMessageViewModel` | 返回 CGSizeZero | 返回零高度，占位消失 |

## 四、独立性分析

### 4.1 与 hidePatHint 的关系

`hideRevokeHint` 和 `hidePatHint` 虽然共享同一个 `UIPurifyHook.m` 文件和同一个 `purifySafeHook` 工具函数（代码复用），但**功能完全独立**：

| 维度 | `hideRevokeHint` | `hidePatHint` |
|------|:----------------:|:-------------:|
| **Hook 目标类** | `SystemMessageCellView`（父类） | `AppPatMessageCellView`（子类） |
| **Hook 目标 ViewModel** | `SystemMessageViewModel`（父类） | `AppPatMessageViewModel`（子类） |
| **配置 Key** | `WCP_UIPurify_hideRevokeHint` | `WCP_UIPurify_hidePatHint` |
| **`_orig` 指针** | `_orig_SysMsgCell_*`（独立，不共用） | `_orig_AppPatCell_*`（独立，不共用） |
| **Hook 函数** | `hook_SysMsgCell_*` | `hook_AppPatCell_*` |
| **UI 开关** | 独立列表项 | 独立列表项 |

删除其中一个功能，不会影响另一个的正常运行。

### 4.2 `purifySafeHook` 隔离验证

两者是父子类关系，`purifySafeHook` 确保相互隔离：

```
SystemMessageCellView 方法表      AppPatMessageCellView 方法表
┌─────────────────────┐          ┌─────────────────────┐
│ initWithViewModel:  │          │ initWithViewModel:  │ (独立副本)
│   → hook_SysMsgCell │          │   → hook_AppPatCell │
│ _orig = Base 原始   │          │ _orig = SysMsg 原始 │
└─────────────────────┘          └─────────────────────┘
      ↑ 互不影响                      ↑ 互不影响
```

即使同时开启两个功能，各自 Hook 各自的方法表，`_orig` 指针不交叉。

### 4.3 与 RevokeHook（防撤回）的关系

| 维度 | RevokeHook（防撤回） | hideRevokeHint（隐藏撤回提示） |
|------|:-------------------:|:----------------------------:|
| **Hook 目标** | `CMessageMgr.onNewSyncNotAddDBMessage:` | `SystemMessageCellView` × 4 + `SystemMessageViewModel` × 1 |
| **作用层级** | 消息接收层 | UI 渲染层 |
| **功能** | 阻止撤回指令执行 | 隐藏撤回提示 UI |

**完全正交，互不影响。**

### 4.4 冲突扫描

| 扫描项 | 结果 |
|--------|:----:|
| 项目中是否有其他代码 Hook `SystemMessageCellView`？ | ✅ 无 |
| 项目中是否有其他代码 Hook `SystemMessageViewModel`？ | ✅ 无 |
| 项目中是否有其他代码 Hook `BaseMessageCellView`？ | ✅ 无 |
| 项目中是否有其他代码 Hook `setFrame:`？ | ✅ 无 |
| `SystemMessageCellView.layoutSubviews` 被其他模块 Hook？ | ✅ 无 |
| `objc_getClass` 返回 nil 安全？ | ✅ `+install` 有 `if (cls)` 保护 |

## 五、Hook 实现方案

### 5.1 文件修改范围

| 文件 | 操作 |
|------|:----:|
| [UIPurifyHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/Layout/UIPurifyHook.m) | 新增撤回提示 Hook 代码 |

**无需修改的文件：** `UIPurifyConfig.h`、`UIPurifyConfig.m`、`WPUIPurifyVC.m`、`UIPurifyHook.h`、`FeatureModuleRegistry.m`

### 5.2 新增内容

在 `UIPurifyHook.m` 的 `#pragma mark - 拍一拍 Hook 函数` 之后（或之前），新增撤回提示相关代码：

#### 5.2.1 `_orig` 指针（5 个）

```objc
#pragma mark - 撤回提示 Hook 函数

// ★ 撤回提示 _orig 指针
static IMP _orig_SysMsgCell_initWithViewModel = NULL;
static IMP _orig_SysMsgCell_layoutInternal = NULL;
static IMP _orig_SysMsgCell_canBeReused = NULL;
static IMP _orig_SysMsgCell_shouldLayoutIfNeeded = NULL;
static IMP _orig_SysMsgVM_measure = NULL;
```

#### 5.2.2 Hook 函数（5 个）

```objc
/// initWithViewModel: — 创建时隐藏
static id hook_SysMsgCell_initWithViewModel(id self, SEL _cmd, id viewModel) {
    id result = ((id (*)(id, SEL, id))_orig_SysMsgCell_initWithViewModel)(self, _cmd, viewModel);
    if (result && [UIPurifyConfig shared].hideRevokeHint) {
        [result setHidden:YES];
        [result setFrame:[result frame]];
    }
    return result;
}

/// layoutInternal — 跳过布局
static void hook_SysMsgCell_layoutInternal(id self, SEL _cmd) {
    if ([UIPurifyConfig shared].hideRevokeHint) return;
    ((void (*)(id, SEL))_orig_SysMsgCell_layoutInternal)(self, _cmd);
}

/// canBeReused — 可复用
static BOOL hook_SysMsgCell_canBeReused(id self, SEL _cmd) {
    if ([UIPurifyConfig shared].hideRevokeHint) return YES;
    return ((BOOL (*)(id, SEL))_orig_SysMsgCell_canBeReused)(self, _cmd);
}

/// shouldLayoutIfNeeded — 不需要布局
static BOOL hook_SysMsgCell_shouldLayoutIfNeeded(id self, SEL _cmd) {
    if ([UIPurifyConfig shared].hideRevokeHint) return NO;
    return ((BOOL (*)(id, SEL))_orig_SysMsgCell_shouldLayoutIfNeeded)(self, _cmd);
}

/// measure: — 返回零高度
static CGSize hook_SysMsgVM_measure(id self, SEL _cmd, CGSize size) {
    if ([UIPurifyConfig shared].hideRevokeHint) return CGSizeZero;
    return ((CGSize (*)(id, SEL, CGSize))_orig_SysMsgVM_measure)(self, _cmd, size);
}
```

#### 5.2.3 在 `+install` 中新增安装代码

```objc
// ── 撤回提示 ──
Class sysMsgCellClass = objc_getClass("SystemMessageCellView");
Class sysMsgVMClass = objc_getClass("SystemMessageViewModel");
if (sysMsgCellClass && sysMsgVMClass) {
    purifySafeHook(sysMsgCellClass, @selector(initWithViewModel:),
                   (IMP)hook_SysMsgCell_initWithViewModel,
                   &_orig_SysMsgCell_initWithViewModel);
    purifySafeHook(sysMsgCellClass, @selector(layoutInternal),
                   (IMP)hook_SysMsgCell_layoutInternal,
                   &_orig_SysMsgCell_layoutInternal);
    purifySafeHook(sysMsgCellClass, @selector(canBeReused),
                   (IMP)hook_SysMsgCell_canBeReused,
                   &_orig_SysMsgCell_canBeReused);
    purifySafeHook(sysMsgCellClass, @selector(shouldLayoutIfNeeded),
                   (IMP)hook_SysMsgCell_shouldLayoutIfNeeded,
                   &_orig_SysMsgCell_shouldLayoutIfNeeded);
    purifySafeHook(sysMsgVMClass, @selector(measure:),
                   (IMP)hook_SysMsgVM_measure,
                   &_orig_SysMsgVM_measure);
    WPLog(@"UIPurify", @"[+] SystemMessageCellView/ViewModel hooked (5 methods, purifySafeHook)");
} else {
    WPLog(@"UIPurify", @"[-] SystemMessageCellView/ViewModel not found");
}
```

## 七、验证方法

1. **独立生效测试：**
   - 只开启"隐藏撤回消息提示"，关闭其他净化功能
   - 发一条消息 → 让对方撤回
   - 预期：撤回提示不显示，拍一拍和分隔线不受影响

2. **与 hidePatHint 同时开启测试：**
   - 同时开启隐藏撤回 + 隐藏拍一拍
   - 预期：两个功能各自生效，互不干扰

3. **与防撤回同时开启测试：**
   - 开启防撤回 → 对方撤回消息 → 消息不被撤回，撤回提示不产生
   - 关闭防撤回，开启隐藏撤回提示 → 对方撤回消息 → 撤回提示被隐藏

4. **开关动态生效测试：**
   - 开启后发撤回 → 不显示
   - 关闭后再发撤回 → 正常显示

5. **无闪退测试：**
   - 快速开关 + 快速滑动聊天列表
   - 预期：无 crash、无布局错乱
