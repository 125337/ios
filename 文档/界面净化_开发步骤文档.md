### 1.2 与反编译「微信优化」的差异对照

| 功能 | 我们的实现方案 | 微信优化方案 | 差异评估 |
|---|---|---|---|
| 隐藏分割线 | Hook `ChatTimeCellView.layoutSubviews`，仅隐藏时间分隔线 | Hook `UIView.layoutSubviews`（全局），智能识别所有水平分割线 | 策略不同，我们的更精准但覆盖面窄，微信优化更全面但可能有误伤 |
| 隐藏撤回/拍一拍 | Hook `SystemMessageCellView.updateStatus`，通过文本内容匹配判断 | Hook `initWithViewModel:` + `layoutInternal` + `canBeReused` + `shouldLayoutIfNeeded` + `measure:`（5 连 Hook） | 微信优化的方案更彻底 — 从 Cell 创建阶段就阻止显示，我们的方案在渲染后隐藏 |
| 隐藏语音提示 | Hook `VoiceMessageCellView.layoutContentView`，KVC 多 key 尝试 | Hook `VoiceMessageCellView.layoutSubviews`，精确 KV 键 | 相似，我们更健壮（多 key 容错） |
| 气泡透明 | Hook `BaseMessageCellView.layoutContentView`，KVC 获取背景视图 setAlpha | Hook `YYAsyncImageView.layoutSubviews`，双重验证后 setAlpha | 不同目标类，微信优化有 `getBgImageView` + `isDescendantOfView` 双重验证 |
| 禁用听写 | Hook `BaseMsgContentViewController.viewDidLoad`，递归遍历子视图 | Hook `MMGrowTextViewExtConfig.enableDictation`，直接返回 NO | 微信优化更直接高效；我们的方案更动 |

### 步骤 2：编写 UIPurifyHook（Hook 核心层）

**文件：** `Modules/Layout/UIPurifyHook.m`

这是最核心的开发工作。每个功能需要：声明原始 IMP 指针 → 编写替换函数 → 在 install 中注册 Hook。

#### 2.1 框架模板

```objc
#import "UIPurifyHook.h"
#import "../../Config/PluginConfig.h"
#import <objc/runtime.h>
#import <objc/message.h>
#import <substrate.h>
#import "../../Core/LogManager.h"

// ============================================================
// 原始 IMP 指针声明区
// ============================================================
static IMP _orig_XXX = NULL;

// ============================================================
// Hook 函数实现区
// ============================================================
static void hook_XXX(id self, SEL _cmd) {
    // 1. 先调用原始实现
    if (_orig_XXX) { ((void (*)(id, SEL))_orig_XXX)(self, _cmd); }
    
    // 2. 读取配置
    if (![PluginConfig shared].某属性) return;
    
    // 3. 执行净化逻辑
    // ...
}

// ============================================================
// +install 入口
// ============================================================
@implementation UIPurifyHook

+ (void)install {
    WPLog(@"UIPurify", @"UIPurifyHook install start");
    
    // 逐个注册 Hook
    Class cls = objc_getClass("微信类名");
    if (cls) {
        MSHookMessageEx(cls, @selector(方法名), (IMP)hook_XXX, &_orig_XXX);
        WPLog(@"UIPurify", @"[Hook] ✓ 类名.方法名");
    } else {
        WPLog(@"UIPurify", @"[Hook] - 类名 not found");
    }
    
    WPLog(@"UIPurify", @"UIPurifyHook install complete");
}

@end
```

#### 2.2 功能 1：隐藏水平分割线

**目标微信类：** `ChatTimeCellView`
**Hook 方法：** `layoutSubviews`

**实现逻辑：**
1. 调用原始 `layoutSubviews`
2. 若 `hideSeparatorLine` 启用 → `setAlpha:0`

**现有关键代码（已完成）：**

```objc
static IMP _orig_ChatTimeCell_layoutSubviews = NULL;

static void hook_ChatTimeCell_layoutSubviews(id self, SEL _cmd) {
    if (_orig_ChatTimeCell_layoutSubviews) {
        ((void (*)(id, SEL))_orig_ChatTimeCell_layoutSubviews)(self, _cmd);
    }
    if ([PluginConfig shared].hideSeparatorLine) {
        ((void (*)(id, SEL, CGFloat))objc_msgSend)(self, sel_registerName("setAlpha:"), 0.0);
    }
}
```

**注册代码：**

```objc
Class cls = objc_getClass("ChatTimeCellView");
if (cls) {
```

**改进建议（参照微信优化）：** 若想实现全局分隔线隐藏（而非仅聊天时间线），可额外 Hook `UIView.layoutSubviews`，添加智能识别逻辑——检测 frame 高度 ≤ 1px 的视图，排除特定页面（朋友圈/订阅号），跳过 UILabel/UIImageView，然后 setHidden 或 setAlpha。

#### 2.3 功能 2 & 3：隐藏撤回和拍一拍消息

**目标微信类：** `SystemMessageCellView`
**Hook 方法：** `updateStatus`

**实现逻辑：**
1. 调用原始 `updateStatus`
2. 若 `hideRevokeHint` 或 `hidePatHint` 启用
3. 通过 `getCurrentMessageWrap` / `messageWrap` 获取消息包装对象
4. 读取 `m_nsContent` 文本
5. 文本包含 "撤回" → `setAlpha:0`
6. 文本包含 "拍了拍" → `setAlpha:0`

**现有关键代码（已完成）：**

```objc
static IMP _orig_SystemMsgCell_updateStatus = NULL;

static void hook_SystemMsgCell_updateStatus(id self, SEL _cmd) {
    if (_orig_SystemMsgCell_updateStatus) {
        ((void (*)(id, SEL))_orig_SystemMsgCell_updateStatus)(self, _cmd);
    }
    PluginConfig *cfg = [PluginConfig shared];
    if (!cfg.hideRevokeHint && !cfg.hidePatHint) return;

    NSString *content = nil;
    @try {
        id wrap = nil;
        for (NSString *sel in @[@"getCurrentMessageWrap", @"messageWrap"]) {
            SEL s = NSSelectorFromString(sel);
            if ([self respondsToSelector:s]) {
                wrap = ((id (*)(id, SEL))objc_msgSend)(self, s);
                break;
            }
        }
        if (wrap && [wrap respondsToSelector:@selector(m_nsContent)]) {
            content = ((id (*)(id, SEL, ...))objc_msgSend)(wrap, @selector(m_nsContent));
        }
    } @catch (NSException *e) {}

    if (content) {
        if (cfg.hideRevokeHint && [content containsString:@"撤回"]) {
            ((void (*)(id, SEL, CGFloat))objc_msgSend)(self, sel_registerName("setAlpha:"), 0.0);
        }
        if (cfg.hidePatHint && [content containsString:@"拍了拍"]) {
            ((void (*)(id, SEL, CGFloat))objc_msgSend)(self, sel_registerName("setAlpha:"), 0.0);
        }
    }
}
```

:white_check_mark: **状态：已完成。**

**改进建议：**
当前方案依赖文本内容匹配（`containsString:@"撤回"` / `containsString:@"拍了拍"`），缺点是：
- 英文版微信或未来 UI 变动可能失效
- 仅隐藏而不阻止渲染，Cell 仍然占用布局空间

微信优化方案更彻底——在 `initWithViewModel:` 阶段就将 Cell 标记为隐藏并零尺寸化，同时劫持 `canBeReused`、`shouldLayoutIfNeeded`、`layoutInternal` 和 ViewModel 的 `measure:`。如需升级，可参考文档 `微信优化_界面净化功能深度分析.md` 第二章 1、2 节。

#### 2.4 功能 4：隐藏语音红点和转文字

**目标微信类：** `VoiceMessageCellView`
**Hook 方法：** `layoutContentView`

**实现逻辑：**
1. 调用原始 `layoutContentView`
2. 若 `hideVoiceRedDot` 启用
3. 遍历候选 key 列表，尝试 KVC 获取红点视图 → `setHidden:YES`
4. 遍历候选 key 列表，尝试 KVC 获取转文字标签 → `setHidden:YES`

**现有关键代码（已完成）：**

```objc
static IMP _orig_VoiceMsgCell_layoutContentView = NULL;

static void hook_VoiceMsgCell_layoutContentView(id self, SEL _cmd) {
    if (_orig_VoiceMsgCell_layoutContentView) {
        ((void (*)(id, SEL))_orig_VoiceMsgCell_layoutContentView)(self, _cmd);
    }
    if (![PluginConfig shared].hideVoiceRedDot) return;

    @try {
        // 隐藏红点
        for (NSString *key in @[@"m_redDotView", @"m_voiceRedDotView", @"redDotView"]) {
            @try {
                id dotView = [self valueForKey:key];
                if (dotView && [dotView isKindOfClass:[UIView class]]) {
                    ((void (*)(id, SEL, BOOL))objc_msgSend)(dotView, @selector(setHidden:), YES);
                }
            } @catch (NSException *e) {}
        }
        // 隐藏"转文字"标签
        for (NSString *key in @[@"m_translateLabel", @"m_voiceTransLabel", @"translateLabel"]) {
            @try {
                id label = [self valueForKey:key];
                if (label && [label isKindOfClass:[UIView class]]) {
                    ((void (*)(id, SEL, BOOL))objc_msgSend)(label, @selector(setHidden:), YES);
                }
            } @catch (NSException *e) {}
        }
    } @catch (NSException *e) {}
}
```

:white_check_mark: **状态：已完成。** 多 key 尝试策略相比微信优化的单 key 方案更健壮。

#### 2.5 功能 5：隐藏聊天气泡背景

**目标微信类：** `BaseMessageCellView`（或 `CommonMessageCellView`）
**Hook 方法：** `layoutContentView`

**实现逻辑：**
1. 调用原始 `layoutContentView`
2. 若 `hideBubbleBackground` 启用
3. 遍历候选 key，通过 KVC 获取气泡背景视图 → `setAlpha:0`
4. 设置 Cell 自身 `backgroundColor` 为 `clearColor`

**现有关键代码（已完成）：**

```objc
static IMP _orig_BaseMsgCell_layoutContentView = NULL;

static void hook_BaseMsgCell_layoutContentView(id self, SEL _cmd) {
    if (_orig_BaseMsgCell_layoutContentView) {
        ((void (*)(id, SEL))_orig_BaseMsgCell_layoutContentView)(self, _cmd);
    }
    if (![PluginConfig shared].hideBubbleBackground) return;

    @try {
        for (NSString *key in @[@"m_bgImageView", @"m_bubbleImageView",
                                 @"m_backgroundImageView", @"bgImageView"]) {
            @try {
                id bgView = [self valueForKey:key];
                if (bgView && [bgView isKindOfClass:[UIView class]]) {
                    ((void (*)(id, SEL, CGFloat))objc_msgSend)(bgView,
                        sel_registerName("setAlpha:"), 0.0);
                }
            } @catch (NSException *e) {}
        }
        [self setValue:[UIColor clearColor] forKey:@"backgroundColor"];
    } @catch (NSException *e) {}
}
```

:white_check_mark: **状态：已完成。**

**改进建议（参照微信优化）：**

微信优化采用了更精细的双重验证策略：
1. Hook `YYAsyncImageView.layoutSubviews`（气泡背景的实际图片渲染类）
2. 沿 `superview` 链向上遍历找到 `CommonMessageCellView`
3. 调用 `[msgCell getBgImageView]` 获取背景图容器
4. 验证 `[self isDescendantOfView:bgImageView]`——确认 self 确实是气泡背景的子视图
5. 只有全部验证通过才 `setAlpha:0`

这种双重验证可避免误伤头像、缩略图等其他用途的 `YYAsyncImageView`。

#### 2.6 功能 6：禁用输入框听写

**目标微信类：** `BaseMsgContentViewController`
**Hook 方法：** `viewDidLoad`

**实现逻辑：**
1. 调用原始 `viewDidLoad`
2. 若 `disableDictation` 启用
3. 递归遍历 `self.view` 所有子视图
4. 找到 `UITextView` / `UITextField` → 置空 `inputAssistantItem` 的 `leadingBarButtonGroups` 和 `trailingBarButtonGroups`

**现有关键代码（已完成）：**

```objc
static void disableInputDictation(UIView *view) {
    for (UIView *subv in view.subviews) {
        if ([subv isKindOfClass:[UITextView class]] ||
            [subv isKindOfClass:[UITextField class]]) {
            @try {
                if ([subv respondsToSelector:@selector(inputAssistantItem)]) {
                    id assistant = [subv performSelector:@selector(inputAssistantItem)];
                    if ([assistant respondsToSelector:@selector(setLeadingBarButtonGroups:)]) {
                        [assistant performSelector:@selector(setLeadingBarButtonGroups:)
                                        withObject:@[]];
                    }
                    if ([assistant respondsToSelector:@selector(setTrailingBarButtonGroups:)]) {
                        [assistant performSelector:@selector(setTrailingBarButtonGroups:)
                                        withObject:@[]];
                    }
                }
            } @catch (NSException *e) {}
        }
        disableInputDictation(subv);
    }
}

static IMP _orig_BaseMsgVC_viewDidLoad = NULL;
static void hook_BaseMsgVC_viewDidLoad(id self, SEL _cmd) {
    if (_orig_BaseMsgVC_viewDidLoad) {
        ((void (*)(id, SEL))_orig_BaseMsgVC_viewDidLoad)(self, _cmd);
    }
    if ([PluginConfig shared].disableDictation) {
        @try {
            disableInputDictation([self valueForKey:@"view"]);
        } @catch (NSException *e) {}
    }
}
```

:white_check_mark: **状态：已完成。**

**改进建议（参照微信优化）：**

微信优化采用更直接的方案——Hook `MMGrowTextViewExtConfig.enableDictation` 直接返回 `NO`：

```objc
// 更简洁的方案
Class cls = objc_getClass("MMGrowTextViewExtConfig");
MSHookMessageEx(cls, sel_registerName("enableDictation"),
    (IMP)hook_enableDictation, &_orig_enableDictation);

static BOOL hook_enableDictation(id self, SEL _cmd) {
    if ([PluginConfig shared].disableDictation) return NO;
    return ((BOOL (*)(id, SEL))_orig_enableDictation)(self, _cmd);
}
```

优点：单行 Hook、确定性高、不依赖视图树遍历。可考虑追加此 Hook 作为备用。

### 编译验证步骤

```
1. 确认所有 6 个 Hook 的目标类在运行时能找到
   → 查看 Xcode 控制台日志 "[Hook] ✓" 或 "[Hook] - not found"

2. 测试每个功能开关：
   a. 隐藏分割线    → 进入聊天页，观察时间分割线是否消失
   b. 隐藏撤回消息  → 让好友撤回一条消息，观察提示是否消失
   c. 隐藏拍一拍    → 让好友拍一拍，观察提示是否消失
   d. 隐藏语音提示  → 接收语音消息，观察红点和"转文字"是否消失
   e. 气泡透明      → 进入聊天页，观察气泡背景是否变透明
   f. 禁用听写      → 在输入框长按，观察听写按钮是否消失

3. 确认开关状态正确持久化：
   → 切换开关后退出微信重进，设置应保持
```

## 五、微信优化方案升级路线图（可选）

若希望将实现提升到微信优化同等级的完成度，以下为建议的升级点：

|---|---|---|---|---|
| 中 | 撤回/拍一拍隐藏 | `updateStatus` 文本匹配 | `initWithViewModel:` 阶段拦截 + 5 重 Hook | 3-4h |
| 中 | 气泡透明 | `BaseMessageCellView` KVC | `YYAsyncImageView` 双重验证 | 2-3h |
