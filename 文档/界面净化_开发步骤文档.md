## 二、Hook 详解

### 2.1 隐藏撤回消息（5 连 Hook）

**目标：** 从 Cell 创建阶段就阻止撤回提示的显示和布局。

```
SystemMessageCellView
├── initWithViewModel:     → 调用原始，若配置启用 → hidden=YES, alpha=0, frame=CGRectZero
├── layoutInternal         → 若配置启用 → 跳过原始（不执行布局）
├── canBeReused            → 若配置启用 → 返回 YES（阻止复用）
├── shouldLayoutIfNeeded   → 若配置启用 → 返回 NO
SystemMessageViewModel
└── measure:               → 若配置启用 → 返回 CGSizeZero（跳过测量）
```

**关键代码（UIPurifyHook.m L49-85）：**
```objc
static id hook_SysCell_initWithViewModel(id self, SEL _cmd, id viewModel) {
    id result = ((id (*)(id, SEL, id))_orig_SysCell_initWithViewModel)(self, _cmd, viewModel);
    if (!result) return nil;
    if (purifyReadConfig(@"HideRevokeHint")) {
        UIView *v = (UIView *)result;
        [v setHidden:YES]; v.alpha = 0; v.frame = CGRectZero;
    }
    return result;
}

static void hook_SysCell_layoutInternal(id self, SEL _cmd) {
    if (purifyReadConfig(@"HideRevokeHint")) return;
    ((void (*)(id, SEL))_orig_SysCell_layoutInternal)(self, _cmd);
}

static BOOL hook_SysCell_canBeReused(id self, SEL _cmd) {
    if (purifyReadConfig(@"HideRevokeHint")) return YES;
    return ((BOOL (*)(id, SEL))_orig_SysCell_canBeReused)(self, _cmd);
}

static BOOL hook_SysCell_shouldLayoutIfNeeded(id self, SEL _cmd) {
    if (purifyReadConfig(@"HideRevokeHint")) return NO;
    return ((BOOL (*)(id, SEL))_orig_SysCell_shouldLayoutIfNeeded)(self, _cmd);
}

static CGSize hook_SysVM_measure(id self, SEL _cmd, CGSize size) {
    if (purifyReadConfig(@"HideRevokeHint")) return CGSizeZero;
    return ((CGSize (*)(id, SEL, CGSize))_orig_SysVM_measure)(self, _cmd, size);
}
```

### 2.4 气泡透明（1 Hook）

**目标：** `YYAsyncImageView.layoutSubviews`

```objc
static void hook_YYAsyncImage_layoutSubviews(id self, SEL _cmd) {
    ((void (*)(id, SEL))_orig_YYAsyncImage_layoutSubviews)(self, _cmd);
    if (!purifyReadConfig(@"HideBubbleBackground")) return;

    UIView *current = (UIView *)self;
    UIView *check = current;
    while (check) {
        UIView *parent = check.superview;
        if (!parent) break;
        check = parent;
        if ([check isKindOfClass:NSClassFromString(@"CommonMessageCellView")]) {
            id bgImageView = nil;
            @try { bgImageView = [check valueForKey:@"m_bgImageView"]; }
            @catch (NSException *e) {}
            if (bgImageView && [current isDescendantOfView:bgImageView]) {
                current.alpha = 0;
                return;
            }
            break;
        }
    }
}
```

**双重验证逻辑（微信优化 `FUN_00026384`）：**
1. 沿 superview 链向上查找 `CommonMessageCellView`
2. 调用 `getBgImageView`（KVC `m_bgImageView`）获取气泡背景容器
3. 调用 `isDescendantOfView:` 验证 self 确实是气泡背景的子视图
4. 验证通过才 `setAlpha:0`

**对比旧方案：** 旧方案 Hook `BaseMessageCellView.layoutContentView` + 4 个候选 key 遍历；新方案采用微信优化的 `YYAsyncImageView` + superview 链双重验证，避免误伤头像和缩略图。

### 2.6 隐藏水平分割线（1 Hook，独立安装器）

**目标：** `UIView.layoutSubviews` — 对全局所有 UIView 生效，通过智能检测识别并隐藏水平分割线。

**注意：** 这是一个独立安装器（对应微信优化 `FUN_00046248`），不在 `FUN_00025688` 内部，因为它是 `UIView` 基类的全局 Hook，影响范围远大于其他 5 个功能。

**微信优化实现：** `FUN_0004627c`（L41156-41309），约 160 行检测逻辑。

#### 完整检测流程

```
┌─ 原始 layoutSubviews 调用
│
├─ 读取 NSUserDefaults "HideSeparatorLine"
│   └─ 未启用 → return
│
├─【第1层：类名过滤】══════════════════════════════════
│   ├─ if [self isKindOfClass:FTSBrandContactCell] → return
│   ├─ if [className containsString:"Brand"]        → return
│   └─ if [className containsString:"Contact"]      → return
│
├─【第2层：获取视图属性】══════════════════════════════
│   ├─ isSep = [className isEqualToString:"_UITableViewCellSeparatorView"]
│   ├─ h = CGRectGetHeight([self frame])
│   ├─ w = CGRectGetWidth([self frame])
│   ├─ a = [self alpha]
│   ├─ bg = [self backgroundColor]
│   ├─ isLabel = [self isKindOfClass:UILabel]
│   └─ isImg = [self isKindOfClass:UIImageView]
│
├─【分支A：_UITableViewCellSeparatorView 处理】═══════
│   │
│   │ 若 h ≤ 0 → 判定需隐藏
│   │ 若 h > 1.0 → 不隐藏（非细线）
│   │
│   │ 若 isSep == NO        (不是系统分隔线类)
│   │  && h ≤ 1.0           (高度 ≤ 1px → 是细线)
│   │  && w > 100           (宽度 > 100 → 排除竖线)
│   │  && a > 0.9           (几乎不透明 → 是可见的线)
│   │  && bg != nil         (有背景色)
│   │  && !isLabel && !isImg (非文字/图片视图)
│   │  → 判定需隐藏
│   │
│   └─ if ([className isEqualToString:"UIView"]) {
│         【分支B：普通 UIView 额外检查】
│         │
│         │ if (w ≤ 100) → 不隐藏（窄视图不是分割线）
│         │
│         │ if (h ≤ 1.0          高度达标
│         │  && a > 0.9           可见
│         │  && bg != nil         有背景色
│         │  && !isLabel && !isImg  不是文字/图片
│         │  && [self subviews].count == 0)  无子视图 → 纯装饰线
│         │   → 判定需隐藏
│         │
│         │ 否则 → return
│
├─【父链排除遍历：nextResponder 链】═════════════════
│   │
│   │ 遍历1：从 self 沿 nextResponder 向上（最多11层）
│   │   if [resp isKindOfClass:WCTimeLineViewController] → return
│   │   if [className isEqualToString:"WCTimelineFooterCell"] → return
│   │
│   │ 遍历2：从 self 重新沿 nextResponder 向上（最多11层）
│   │   if [resp isKindOfClass:MPSubscriptionViewController] → return
│
└─【最终操作】════════════════════════════════════════
    [self setHidden:YES]
```

#### 关键排除类

| 类名 | 排除原因 | 检测方式 |
|---|---|---|
| `FTSBrandContactCell` | 全局搜索中品牌联系人 | `isKindOfClass:` |
| `WCTimeLineViewController` | 朋友圈页面 | `isKindOfClass:` + `nextResponder` 链遍历 |
| `WCTimelineFooterCell` | 朋友圈底部 Cell | `isEqualToString:` + `nextResponder` 链遍历 |
| `MPSubscriptionViewController` | 订阅号页面 | `isKindOfClass:` + `nextResponder` 链遍历 |
| `UILabel` / `UIImageView` | 文字和图片不可能是分割线 | `isKindOfClass:` |
| 类名含 "Brand" / "Contact" | 通讯录/品牌相关的视图 | `containsString:` |

#### 核心策略对比

| 方面 | 微信优化实现 | 说明 |
|---|---|---|
| Hook 方式 | 独立安装器 `FUN_00046248`，Hook `UIView.layoutSubviews` | 作用于全局所有视图 |
| 检测方式 | 多条件过滤（高度/宽度/透明度/背景色/类名/子视图数） | 层层递进，逐步排除 |
| 父链遍历 | `nextResponder` 响应者链（非 `superview` 视图树） | 沿 ViewController 层级检测 |
| 排除逻辑 | 4 个排除类 + 2 个排除视图类型 + 2 个排除字符匹配 | 避免误杀页面元素 |
| 隐藏方式 | `setHidden:YES` | 保留占位，仅不可见 |

#### 还原 ObjC 伪代码

```objc
// 安装器（独立于其他5个Hook，在 +install 中单独调用）
MSHookMessageEx([UIView class], @selector(layoutSubviews),
    (IMP)hook_UIView_layoutSubviews, &_orig_UIView_layoutSubviews);

// Hook 函数
static void hook_UIView_layoutSubviews(id self, SEL _cmd) {
    original(self, _cmd);
    if (!purifyReadConfig(@"HideSeparatorLine")) return;

    // 第1层：类名过滤
    if ([self isKindOfClass:NSClassFromString(@"FTSBrandContactCell")]) return;
    NSString *cn = NSStringFromClass([self class]);
    if ([cn containsString:@"Brand"]) return;
    if ([cn containsString:@"Contact"]) return;

    // 第2层：获取属性
    BOOL isSep = [cn isEqualToString:@"_UITableViewCellSeparatorView"];
    CGFloat h = CGRectGetHeight([self frame]);
    CGFloat w = CGRectGetWidth([self frame]);
    CGFloat a = [self alpha];
    id bg = [self backgroundColor];
    BOOL notLabel = ![self isKindOfClass:[UILabel class]];
    BOOL notImg   = ![self isKindOfClass:[UIImageView class]];

    BOOL shouldHide = NO;
    BOOL isThin = (h <= 1.0);

    // 分支A：非系统分隔线类的检测
    if (!isSep && isThin && w > 100 && a > 0.9) {
        shouldHide = (bg != nil) && notLabel && notImg;
    }

    // 分支B：普通 UIView 额外检查
    if (!shouldHide && [cn isEqualToString:@"UIView"]) {
        if (isThin && a > 0.9 && bg != nil && notLabel && notImg) {
            if ([[self subviews] count] == 0) shouldHide = YES;
        }
    }
    if (!shouldHide) return;

    // 父链排除：沿 nextResponder 链（非 superview）
    Class timelineVC  = NSClassFromString(@"WCTimeLineViewController");
    Class subVC        = NSClassFromString(@"MPSubscriptionViewController");
    id resp = self;
    for (int i = 0; i < 11; i++) {
        if ([resp isKindOfClass:timelineVC]) return;
        if ([NSStringFromClass([resp class]) isEqualToString:@"WCTimelineFooterCell"]) return;
        resp = [resp nextResponder];
        if (!resp) break;
    }
    resp = self;
    for (int i = 0; i < 11; i++) {
        if ([resp isKindOfClass:subVC]) return;
        resp = [resp nextResponder];
        if (!resp) break;
    }

    [self setHidden:YES];
}
```

**关键细节：** 使用 `nextResponder` 而非 `superview` 进行父级遍历。因为 ViewController 不在视图树中，而在响应者链中——分割线需要排除特定 VC 对应的页面，只有通过响应者链才能找到所属的 ViewController。遍历上限 11 层确保性能安全。

## 七、分割线功能的特殊注意事项

### 7.1 与其他功能的架构差异

| 方面 | 撤回/拍一拍/语音/气泡/听写 | 隐藏水平分割线 |
|---|---|---|
| 安装器 | `FUN_00025688` 内部 | 独立安装器 `FUN_00046248` |
| Hook 目标 | 微信特定类（9个） | `UIView`（全局基类） |
| 影响范围 | 聊天页特定消息类型 | 聊天页、通讯录、发现页……所有页面 |
| 检测方式 | 直接判断配置 → 隐藏 | 多条件智能过滤 → 确认是分割线后才隐藏 |
| 父级遍历 | `superview`（视图树） | `nextResponder`（响应者链），用于排除特定 VC |
| 开关回调 | 普通保存+同步 | 保存+同步+**弹重启提示**（微信优化中调用 `showRestartAlertInViewController:`） |

### 7.2 配置依赖（需补齐）

分割线功能需要在以下文件中补充配置读写：

| 文件 | 需补充内容 |
|---|---|
| `Config/PluginConfig.h` | `@property (nonatomic, assign) BOOL hideSeparatorLine;` 添加到界面净化区域 |
| `Config/PluginConfig.m` `loadDefaults` | `_hideSeparatorLine = [d boolForKey: ... @"HideSeparatorLine"];` |
| `Config/PluginConfig.m` `save` | `[d setBool:_hideSeparatorLine forKey: ... @"HideSeparatorLine"];` |
| `Modules/SettingEntry/WPUIPurifyVC.m` | 添加 "隐藏水平分割线" + "HideSeparatorLine" 的 Switch 行 |

### 7.3 为什么切换分割线需要重启提示？

因为分割线 Hook 的是 `UIView.layoutSubviews`，该 Hook 对所有已存在的视图在**下次 layoutSubviews 调用时**才会生效。TableView 等列表视图可能已经缓存了 Cell 的布局结果，切换后旧的 Cell 不会立即触发重新布局，需要导航层级刷新或重启才能看到效果。

### 7.4 性能考量

`UIView.layoutSubviews` 是调用频率极高的方法。Hook 函数内必须**尽可能快**地完成判断：
- 未启用时只有一次 `NSUserDefaults` 读取 → 立即返回
- 启用时先做轻量的 `isKindOfClass:` 和 `containsString:` 过滤 → 绝大多数视图在此被排除
- 只有疑似分割线的视图才执行完整的属性获取和父链遍历（遍历上限 11 层防止死循环）
