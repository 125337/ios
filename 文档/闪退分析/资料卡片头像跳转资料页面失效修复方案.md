# 资料卡片头像跳转资料页面失效修复方案

## 问题描述

在聊天顶栏弹出的资料卡片中，点击头像无法跳转到微信原生资料页面。用户点击头像无任何反应。

**涉及代码** ([CSContactInfoPopoverController.m](file:///www/wwwroot/ios/MioPlugin/Modules/ChatTopBar/CSContactInfoPopoverController.m#L290-L338)):

```objc
- (void)onAvatarTapped:(UITapGestureRecognizer *)gesture {
    [self handleProfileNavigation];
}

- (void)handleProfileNavigation {
    if (!self.wxid) return;                      // ← 检查1
    id contact = WXGetContactForWxid(self.wxid); // ← 关键：通过 wxid 重新获取 contact
    if (!contact) return;                        // ← 检查2：获取不到就静默返回
    // ... 创建 ContactInfoViewController 并 push
}
```

---

## 根因分析

### 执行链路追踪

```
用户点击头像
  → onAvatarTapped: 被调用（手势识别成功）
  → handleProfileNavigation
  → self.wxid = @"48551701903@chatroom"   ✅ 非 nil，通过检查1
  → WXGetContactForWxid(self.wxid)
    → CContactMgr.getContactByUserName:@"48551701903@chatroom"
    → 返回 nil ❌ 获取不到群聊 contact 对象
  → if (!contact) return;  ← 静默返回，无任何视觉效果
```

### 根因：`WXGetContactForWxid` 对群聊 wxid 返回 nil

`WXGetContactForWxid` 的实现 ([ServiceHelper.h](file:///www/wwwroot/ios/MioPlugin/Core/ServiceHelper.h#L13-L17)):

```objc
static inline id WXGetContactForWxid(NSString *wxid) {
    id contactMgr = WXGetService(objc_getClass("CContactMgr"));
    if (!contactMgr || ![contactMgr respondsToSelector:@selector(getContactByUserName:)]) return nil;
    return ((id (*)(id, SEL, id))objc_msgSend)(contactMgr, @selector(getContactByUserName:), wxid);
}
```

`CContactMgr.getContactByUserName:` 对 @chatroom 后缀的 wxid 可能返回 nil，原因：

1. **群聊 contact 延迟加载**：群聊 CContact 对象在聊天界面打开时可能尚未完全加载到 CContactMgr 缓存中
2. **查询方式不对**：`getContactByUserName:` 主要针对个人联系人，对群聊可能使用不同的查询方法（如 `getGroupContactByUserName:`）
3. **群聊 contact 未持久化**：群聊信息可能通过不同的数据通道加载，不在 CContactMgr 的常规缓存中

### 关键矛盾

| 状态 | 说明 |
|------|------|
| `self.contact` | 已持有群聊 CContact 对象 ✅ 可用 |
| `WXGetContactForWxid(self.wxid)` | 重新查询返回 nil ❌ 不可用 |
| `handleProfileNavigation` | 舍近求远，不使用已有的 contact |

**`self.contact` 在初始化时已被传入并强引用持有**（[CSContactInfoPopoverController.m](file:///www/wwwroot/ios/MioPlugin/Modules/ChatTopBar/CSContactInfoPopoverController.m#L52)）：

```objc
- (instancetype)initWithContact:(id)contact avatar:(UIImage *)avatar {
    self = [super init];
    if (self) {
        self.contact = contact;   // ← strong property，ARC 持有
        self.wxid = WXSafeStringGet(contact, @"m_nsUsrName");
        ...
    }
    return self;
}
```

`self.contact` 在整个控制器生命周期内都有效（通过 strong 持有），且已用于读取群主、群成员等数据。但 `handleProfileNavigation` 却选择通过 wxid 重新获取，这个重新获取对群聊场景失败。

---

## 方案对比

### 方案 A：直接使用 `self.contact`（推荐）

**改动**：将 `WXGetContactForWxid(self.wxid)` 替换为 `self.contact`

```objc
- (void)handleProfileNavigation {
    if (!self.wxid) return;
    
    // 直接使用已持有的 contact 对象（ARC strong property 安全持有）
    id contact = self.contact;
    if (!contact) return;  // 兜底
    
    // 后续逻辑不变：创建 ContactInfoViewController → setM_contact: → dismiss → push
    ...
}
```

| 优点 | 缺点 |
|------|------|
| 改动最小，1 行代码 | 依赖 contact 对象生命周期 |
| 与类内其他方法使用方式一致 | — |
| 群聊和个人都适用 | — |

### 方案 B：改用 `self.contact` + 兜底 re-fetch

**改动**：优先使用 `self.contact`，如果不行再走 re-fetch

```objc
id contact = self.contact;
if (!contact) {
    contact = WXGetContactForWxid(self.wxid);
}
if (!contact) return;
```

| 优点 | 缺点 |
|------|------|
| 兼容性好 | 改变不大，A 已足够 |

### 方案 C：修复 `WXGetContactForWxid` 对群聊的支持

**改动**：在 `WXGetContactForWxid` 中增加群聊查询逻辑

```objc
static inline id WXGetContactForWxid(NSString *wxid) {
    id contactMgr = WXGetService(objc_getClass("CContactMgr"));
    if (!contactMgr) return nil;
    
    // 群聊: 尝试 getGroupContactByUserName:
    if ([wxid containsString:@"@chatroom"]) {
        if ([contactMgr respondsToSelector:@selector(getGroupContactByUserName:)]) {
            return ((id (*)(id, SEL, id))objc_msgSend)(contactMgr, @selector(getGroupContactByUserName:), wxid);
        }
    }
    
    // 个人: 使用 getContactByUserName:
    if ([contactMgr respondsToSelector:@selector(getContactByUserName:)]) {
        return ((id (*)(id, SEL, id))objc_msgSend)(contactMgr, @selector(getContactByUserName:), wxid);
    }
    return nil;
}
```

| 优点 | 缺点 |
|------|------|
| 彻底解决问题，全局受益 | 需要确认 `getGroupContactByUserName:` 是否存在 |
| 不改变原有设计意图 | 改动范围大 |

---

## 推荐方案

**推荐方案 A**：直接使用 `self.contact`。

理由：
1. 改动最小，只改 `handleProfileNavigation` 中一行代码
2. `self.contact` 已通过 strong property 持有，生命周期与控制器一致
3. 该 contact 对象在类内其他方法（groupOwnerValue、groupMemberCountValue 等）中已正常使用
4. 无需依赖外部查询 API

---

## 验证步骤

1. 进入任意微信群聊
2. 点击聊天顶栏头像弹出资料卡片
3. 点击大图头像 → 应跳转到微信原生群聊资料页
4. 返回后进入个人聊天，同样测试头像跳转
