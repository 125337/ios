# 资料卡片头像跳转资料页面失效修复方案

## 问题描述

在聊天顶栏弹出的资料卡片中，点击头像无法跳转到微信原生资料页面。用户点击头像无任何反应。

---

## 根因分析

### 执行链路追踪

```
用户点击头像
  → onAvatarTapped: 被调用（手势识别成功）
  → handleProfileNavigation
  → self.wxid = @"48551701903@chatroom"   ✅ 非 nil
  → WXGetContactForWxid(self.wxid)          ← 通过 wxid 重新获取 contact
    → CContactMgr.getContactByUserName:@"...@chatroom"
    → 返回 nil ❌
  → if (!contact) return;                   ← 静默返回
```

**根因**：`handleProfileNavigation` 通过 `WXGetContactForWxid(self.wxid)` 重新获取 contact，但对群聊 wxid 返回 nil，方法在第 299 行静默退出。

---

## 参考实现分析（wxyh1.6.5.dylib.c）

微信优化插件的 `CSUserInfoPopoverController` 类实现了完全相同的功能，分析其对了解正确实现非常有价值。

### 参考实现的关键方法

| 方法 | 功能 |
|------|------|
| `addAvatarSection_:` | 创建头像 section，将 contact 关联到 UI 对象 |
| `addBasicInfoSection_:` | 创建基本信息 section，将 contact 以 `profileContact` 键关联到 UI 对象 |
| `handleProfileNavigation_:` | 处理头像点击，取出关联的 contact，跳转资料页 |

### 核心代码流程

#### 1. 存储 contact（`addAvatarSection_` / `addBasicInfoSection_`）

```c
// 伪代码：创建 settingItem，将 contact 关联到 item 上
CSSettingItem *item = [[CSSettingItem alloc] init];
item.title = contact.m_nsNickName;
item.icon = contact.m_nsHeadImgUrl;
objc_setAssociatedObject(item, "profileContact", contact, 1);  // ← 关键
```

#### 2. 读取 contact（`handleProfileNavigation_`）

```c
// 伪代码：从 tableView 的 cell 中取出关联的 contact
id contact = objc_getAssociatedObject(cell, "profileContact");
if (contact && [ContactInfoViewController class]) {
    ContactInfoViewController *vc = [[ContactInfoViewController alloc] init];
    [vc setValue:contact forKey:@"m_contact"];  // KVC 方式设置
    
    // dismiss 当前弹窗，在 completion 中 push
    [self dismissViewControllerAnimated:YES completion:^{
        UINavigationController *nav = self.presentingViewController.navigationController;
        if (nav) {
            [nav pushViewController:vc animated:YES];
        } else {
            [self.presentingViewController presentViewController:vc animated:YES completion:nil];
        }
    }];
}
```

### 参考实现 vs 我们的实现

| 对比项 | 参考实现（微信优化） | 我们的实现 |
|--------|-------------------|-----------|
| **contact 存储方式** | `objc_setAssociatedObject` 关联到 UI 对象 | `self.contact` strong property |
| **contact 读取方式** | 从关联对象中取（不重新查询） | `WXGetContactForWxid(self.wxid)` **重新查询** |
| **设置 contact 到 VC** | `setValue:forKey:@"m_contact"`（KVC） | `setM_contact:`（直接调用） |
| **导航方式** | `presentingViewController.navigationController` → push / present | `WPGetTopVCForPresentation()` → push / present |
| **对群聊支持** | ✅ 正常工作（不依赖重新查询） | ❌ `WXGetContactForWxid` 返回 nil |

### 关键发现

**参考实现的核心原则是：不重新查询 contact，而是复用已持有的对象。**

参考实现通过 `objc_setAssociatedObject` 将 contact 保存在 UI 对象上，点击时直接通过 `objc_getAssociatedObject` 取出 — 这和我们用 `self.contact` strong property 持有 contact 是等价的。

而我们的实现却在需要使用时通过 `WXGetContactForWxid` 重新查询，这个查询对群聊场景失败。

---

## 推荐修复方案

### 方案：直接使用 `self.contact`（基于参考实现分析）

**核心思想**：参考实现不重新查询 contact，我们也应该直接使用 `self.contact`。

#### 修改内容

将 `handleProfileNavigation` 中的 `WXGetContactForWxid(self.wxid)` 替换为 `self.contact`：

```objc
- (void)handleProfileNavigation {
    if (!self.wxid) return;
    
    // 直接使用已持有的 contact 对象（参考实现使用 associatedObject 等价方案）
    id contact = self.contact;
    if (!contact) return;
    
    // 后续不变
    Class contactInfoVCClass = objc_getClass("ContactInfoViewController");
    if (!contactInfoVCClass) return;
    
    id contactInfoVC = [[contactInfoVCClass alloc] init];
    if (!contactInfoVC) return;
    
    SEL setContactSel = NSSelectorFromString(@"setM_contact:");
    if ([contactInfoVC respondsToSelector:setContactSel]) {
        ((void (*)(id, SEL, id))objc_msgSend)(contactInfoVC, setContactSel, contact);
    }
    
    // 参考实现：dismiss 后在 completion 中通过 presentingViewController 导航
    __weak typeof(self) weakSelf = self;
    [self dismissViewControllerAnimated:YES completion:^{
        __strong typeof(weakSelf) strongSelf = weakSelf;
        if (!strongSelf) return;
        
        UIViewController *topVC = WPGetTopVCForPresentation();
        if (!topVC) {
            UIViewController *rootVC = [UIApplication sharedApplication].keyWindow.rootViewController;
            if (rootVC) {
                topVC = rootVC;
                while (topVC.presentedViewController) {
                    topVC = topVC.presentedViewController;
                }
            }
        }
        if (!topVC) return;
        
        if ([topVC isKindOfClass:[UINavigationController class]]) {
            [(UINavigationController *)topVC pushViewController:contactInfoVC animated:YES];
        } else if (topVC.navigationController) {
            [topVC.navigationController pushViewController:contactInfoVC animated:YES];
        } else {
            UINavigationController *nav = [[UINavigationController alloc] initWithRootViewController:contactInfoVC];
            [topVC presentViewController:nav animated:YES completion:nil];
        }
    }];
}
```

> 注：导航部分的 `WPGetTopVCForPresentation` 也可简化参考实现的 `self.presentingViewController.navigationController` 方式，但现有逻辑已正常工作，无需修改。

| 文件 | 修改位置 | 改动 |

#### 安全性分析

| 关注点 | 说明 |
|--------|------|
| **ARC 安全性** | `self.contact` 是 strong property，控制器生命周期内有效 |
| **野指针** | 不涉及，strong property 自动管理 |
| **线程安全** | 全部在主线程操作 |
| **兼容性** | 群聊和个人都可用，与类内其他方法一致 |

## 验证步骤

1. 进入任意微信群聊
2. 点击聊天顶栏头像弹出资料卡片
3. 点击大图头像 → 应跳转到微信原生群聊资料页
4. 返回后进入个人聊天，同样测试头像跳转
5. 确认个人聊天和群聊的头像跳转都正常
