# 资料卡片数据提取导致的崩溃修复方案

## 崩溃信息

- **时间**: 2026-06-10 08:36:09
- **设备**: iPhone 16,1 (iPhone 15 Pro), iOS 17.2.1
- **应用**: WeChat 8.0.60
- **崩溃类型**: `EXC_CRASH` / `SIGABRT`
- **异常类型**: `NSInvalidArgumentException` — unrecognized selector

## 根因分析

### 异常信息

```
-[%s (dynamic selector)]: unrecognized selector sent to instance 0x177d46520
```

`performSelector:` 向一个 CContact 实例发送了它**不响应**的 selector，导致崩溃。

### 触发流程

```
用户点击头像
  ↓
MioChatAvatarTitleView.onLeftAvatarTapped:
  ↓  [contact performSelector:NSSelectorFromString(@"GetContact")]
ChatTopBarHook.m 的 delegate 方法
  ↓  提取全部字段（新增的代码）
  ↓  [contact performSelector:NSSelectorFromString(@"m_nsChatRoomOwner")]
  ↓  ⚠️ contact 是普通联系人或公众号，没有 m_nsChatRoomOwner 方法
  ↓
❌ unrecognized selector → SIGABRT
```

### 具体原因

在 `ChatTopBarHook.m` 的 delegate 方法中提取数据时，**对所有 contact 类型无差别地调用群聊专属 selector**：

```objc
// 以下方法在普通联系人和公众号的 CContact 上不存在！
NSString *groupOwner = [contact performSelector:NSSelectorFromString(@"m_nsChatRoomOwner")];
NSString *chatRoomMemList = [contact performSelector:NSSelectorFromString(@"m_nsChatRoomMemList")];
NSString *chatRoomAdminList = [contact performSelector:NSSelectorFromString(@"m_nsChatRoomAdminList")];
```

`performSelector:` 不检查 `respondsToSelector:`，直接发送消息。当 contact 是 **普通联系人** 或 **公众号** 时，这些方法不存在，直接崩溃。

### 各字段在不同 contact 类型的可用性

| Selector | 普通联系人 | 群聊 | 公众号 |
|----------|-----------|------|--------|
| `m_nsNickName` | ✅ | ✅ | ✅ |
| `m_nsUsrName` | ✅ | ✅ | ✅ |
| `m_nsContactRemark` | ✅ | ✅ | ❌ |
| `m_nsGender` | ✅ | ❌ | ❌ |
| `m_nsLocation` | ✅ | ❌ | ✅ |
| `m_nsSignature` | ✅ | ❌ | ✅ |
| `m_nsChatRoomOwner` | ❌ | ✅ | ❌ |
| `m_nsChatRoomMemList` | ❌ | ✅ | ❌ |
| `m_nsChatRoomAdminList` | ❌ | ✅ | ❌ |

## 修复方案

**原则**：每个 `performSelector:` 调用前都要用 `respondsToSelector:` 检查，不响应的字段跳过（保持 nil）。

### 修改文件

只改 [ChatTopBarHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ChatTopBar/ChatTopBarHook.m) 中的 delegate 方法。

### 修改后的代码

将无差别提取改为有条件提取：

```objc
- (void)avatarTitleView:(MioChatAvatarTitleView *)view
didTapAvatarWithContact:(id)contact
           avatarImage:(UIImage *)avatar
            sourceView:(UIView *)sourceView
                  wxid:(NSString *)wxid {
    PluginConfig *config = [PluginConfig shared];
    if (config.avatarTapFeedback) {
        UIImpactFeedbackGenerator *generator = [[UIImpactFeedbackGenerator alloc]
            initWithStyle:UIImpactFeedbackStyleLight];
        [generator prepare];
        [generator impactOccurred];
    }

    // 在 contact 还存活时提取所有需要的数据
    NSMutableDictionary *rawData = [NSMutableDictionary dictionary];

    // nickname（所有 contact 类型都有）
    NSString *nickname = [contact performSelector:NSSelectorFromString(@"m_nsNickName")];

    // 以下字段用 respondsToSelector: 保护，防止对不支持的 contact 类型发送无法识别的 selector
    if ([contact respondsToSelector:NSSelectorFromString(@"m_nsContactRemark")]) {
        rawData[@"remark"] = [contact performSelector:NSSelectorFromString(@"m_nsContactRemark")];
    }
    if ([contact respondsToSelector:NSSelectorFromString(@"m_nsGender")]) {
        id genderObj = [contact performSelector:NSSelectorFromString(@"m_nsGender")];
        if ([genderObj respondsToSelector:@selector(integerValue)]) {
            NSInteger g = [genderObj integerValue];
            rawData[@"gender"] = (g == 1) ? @"男" : (g == 2) ? @"女" : @"未知";
        }
    }
    if ([contact respondsToSelector:NSSelectorFromString(@"m_nsLocation")]) {
        rawData[@"location"] = [contact performSelector:NSSelectorFromString(@"m_nsLocation")];
    }
    if ([contact respondsToSelector:NSSelectorFromString(@"m_nsSignature")]) {
        rawData[@"signature"] = [contact performSelector:NSSelectorFromString(@"m_nsSignature")];
    }

    // 群聊专属字段
    if ([contact respondsToSelector:NSSelectorFromString(@"m_nsChatRoomOwner")]) {
        rawData[@"groupOwner"] = [contact performSelector:NSSelectorFromString(@"m_nsChatRoomOwner")];
    }
    if ([contact respondsToSelector:NSSelectorFromString(@"m_nsChatRoomMemList")]) {
        rawData[@"chatRoomMemList"] = [contact performSelector:NSSelectorFromString(@"m_nsChatRoomMemList")];
    }
    if ([contact respondsToSelector:NSSelectorFromString(@"m_nsChatRoomAdminList")]) {
        rawData[@"chatRoomAdminList"] = [contact performSelector:NSSelectorFromString(@"m_nsChatRoomAdminList")];
    }

    CSContactInfoPopoverController *popover =
        [[CSContactInfoPopoverController alloc] initWithWxid:wxid
                                                    nickname:nickname
                                                      avatar:avatar];
    popover.remark = rawData[@"remark"];
    popover.gender = rawData[@"gender"];
    popover.location = rawData[@"location"];
    popover.signature = rawData[@"signature"];
    popover.groupOwner = rawData[@"groupOwner"];
    popover.chatRoomMemList = rawData[@"chatRoomMemList"];
    popover.chatRoomAdminList = rawData[@"chatRoomAdminList"];

    popover.modalPresentationStyle = UIModalPresentationPopover;
    popover.preferredContentSize = CGSizeMake(280, 400);

    UIPopoverPresentationController *popPC = popover.popoverPresentationController;
    popPC.sourceView = sourceView;
    popPC.sourceRect = sourceView.bounds;
    popPC.permittedArrowDirections = UIPopoverArrowDirectionAny;
    popPC.backgroundColor = [UIColor whiteColor];
    popPC.delegate = popover;

    UIViewController *presentingVC = WPGetTopVCForPresentation();
    if (!presentingVC) {
        presentingVC = (UIViewController *)view.chatController;
    }
    if (presentingVC) {
        [presentingVC presentViewController:popover animated:YES completion:nil];
    }
}
```

## 原理说明

### 为什么用了 NSDictionary 做中转？

避免在 property 赋值时传入 nil 导致 unexpected behavior。用 NSDictionary 保存提取到的数据，setter 只设给有值字段，未提取到的字段保持 property 的初始 nil 值（`valueForInfoKey:` 中遇到 nil 会显示"未设置"/"未知"等 fallback 文案）。

### 为什么不直接在 init 方法中提取？

因为 delegate 方法收到的是 `id contact`（运行时类型为 `CContact`），`CContact` 的属性和方法只能在包含头文件的编译单元中直接调用。delegate 方法所在的 `ChatTopBarHook.m` 是数据提取的现场，提取完成后把安全的值类型传给 popover。

### 为什么 `m_nsNickName` 不需要 check？

因为所有类型的 CContact（普通联系人、群聊、公众号）都一定包含 `m_nsNickName` 方法，这是 CContact 的最基础属性。同理 `m_nsUsrName`。
