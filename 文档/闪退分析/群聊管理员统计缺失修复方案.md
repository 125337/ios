# 群聊管理员统计缺失修复方案

## 问题描述

在聊天顶栏弹出的群聊信息卡片中，群成员行显示"群人员2人"，没有显示管理员数量。期望显示为"群人员2人 管理员1人"。

当前运行日志 ([plugin(81).log](file:///www/wwwroot/ios/plugin(81).log#L92-L93)):
```
[Mio-Group] groupOwner via m_nsOwner=wxid_vosn7rznf98o22
[Mio-Group] fallback m_nsChatRoomMemList=wxid_vosn7rznf98o22;wxid_el0cxp44b16m12
```

---

## 根因分析

### 问题链路追踪

从日志可以追踪到完整的执行路径：

```
groupMemberCountValue 被调用
  → contactMgr = WXGetService(CContactMgr)
  → [contactMgr respondsToSelector:@selector(getGroupMemberCountForContact:)]
  →   ↓ (方法不存在 或 返回NO)
  → if 块被跳过（无任何 CContactMgr 相关日志输出）
  → 进入 fallback 路径
  → WXSafeStringGet(contact, @"m_nsChatRoomMemList")  → 成功返回 "wxid_...;wxid_..."
  → 按 ";" 分割 → 2 个成员
  → return @"群人员2人"  ← 没有读取 m_nsChatRoomAdminList！
```

### 根因1：主路径 `getGroupMemberCountForContact:` 不存在

日志中没有出现 `CContactMgr.getGroupMemberCount=%u` 的输出，说明主路径的 if 条件不成立：

```objc
if (contactMgr && [contactMgr respondsToSelector:@selector(getGroupMemberCountForContact:)]) {
```

原因分析：
- `CContactMgr` 对象获取成功（否则后续的 fallback 路径也会失败，但 fallback 成功了）
- `getGroupMemberCountForContact:` 方法在当前 WeChat 版本中**不存在**，`respondsToSelector:` 返回 NO
- 主路径被整体跳过，意味着成员数量获取、管理员列表读取、最终格式化这三个步骤全部被跳过

参考实现对比：微信优化插件 **完全不依赖** `CContactMgr` 的 API，而是直接解析 `m_nsChatRoomMemList` 字符串。

### 根因2：Fallback 路径未读取管理员列表

fallback 路径（当前代码第 462-468 行）只做了三件事：

```objc
// fallback: 手动解析成员列表
NSString *memList = WXSafeStringGet(contact, @"m_nsChatRoomMemList");
if (memList.length) {
    NSArray *members = [memList componentsSeparatedByString:@";"];
    return [NSString stringWithFormat:@"群人员%lu人", (unsigned long)members.count];
}
```

1. 读取 `m_nsChatRoomMemList`
2. 按 `;` 分割计算成员数
3. 格式化输出"群人员X人"

**完全没有读取 `m_nsChatRoomAdminList`**，所以管理员统计永远不可能在 fallback 路径中出现。

### 根因3：`m_nsChatRoomAdminList` 可能为空

即使主路径能进入，当前代码中 `m_nsChatRoomAdminList` 也可能读取为空：

```objc
NSString *adminList = WXSafeStringGet(contact, @"m_nsChatRoomAdminList");
```

可能的原因：
1. `CContact` 对象是作为参数传入的，可能没有完整加载群聊管理员的属性数据
2. 微信内部可能延迟加载管理员列表，弹窗创建时尚未就绪
3. 该字段名在当前微信版本中可能已变更（相比参考实现的版本）

## 参考实现分析 (wxyh1.6.5.dylib.c)

微信优化插件的 `CSUserInfoPopoverController` 实现 ([wxyh1.6.5.dylib.c](file:///www/wwwroot/ios/插件/微信优化反编译最新/wxyh1.6.5.dylib.c#L120617-L120676))：

```
getGroupMemberInfoForContact:(contact)
  → safeValueForKey:@"m_nsChatRoomMemList" fromContact:contact  ← 读取成员列表
  → [memList componentsSeparatedByString:@","]                  ← 逗号分割
  → [NSString stringWithFormat:@"%ld人", count]                  ← 格式化成员数
  → safeValueForKey:@"m_nsChatRoomAdminList" fromContact:contact ← 读取管理员列表
  → [adminList componentsSeparatedByString:@","]                 ← 逗号分割
  → [NSString stringWithFormat:@"管理员%ld人", adminCount]         ← 格式化管理员数
  → [NSString stringWithFormat:@"%@ %@", memberStr, adminStr]    ← 合并输出
```

关键差异：

| 对比项 | 我们的实现 | 微信优化插件 |
|--------|-----------|-------------|
| **成员数量数据源** | `CContactMgr.getGroupMemberCountForContact:` (主路径) | `m_nsChatRoomMemList` 直接解析 |
| **管理员数据源** | 仅主路径中读取 `m_nsChatRoomAdminList` | 独立读取 `m_nsChatRoomAdminList` |
| **fallback 路径** | 只读 `m_nsChatRoomMemList`，不读管理员 | N/A（没有 fallback，一次完成） |
| **列表分隔符** | `;` (分号) | `,` (逗号) |
| **依赖关系** | 依赖 CContactMgr API 存在性 | 无依赖，直接读取 contact 属性 |
| **管理员为空** | 跳过不显示 | 拼接空字符串 |

## 修复策略

### 策略方案对比

| 方案 | 改动量 | 优点 | 缺点 |
|------|--------|------|------|
| **A. fallback 路径追加管理员读取** | 小 | 改动最小，原有结构不变 | 仍保留无效的主路径 |
| **B. 重构成单一路径：直接解析 memList + adminList** | 中 | 对齐参考实现，去除无用依赖 | 需要验证分隔符 |
| **C. 保留主路径 + fallback 统一读取 adminList** | 中 | 兼容性好，保留多条路径 | 代码冗余 |

**推荐方案 B**：移除对 `CContactMgr.getGroupMemberCountForContact:` 的依赖，统一使用 `m_nsChatRoomMemList` 和 `m_nsChatRoomAdminList` 直接解析。

### 方案 B 具体步骤

#### 步骤1：重写 `groupMemberCountValue` 方法

```objc
- (NSString *)groupMemberCountValue {
    id contact = self.contact;
    if (!contact) return @"未知";
    
    // === 成员数量 ===
    // 方案一：优先通过 CContactMgr 获取（保留但不依赖）
    NSUInteger memberCount = 0;
    id contactMgr = WXGetService(objc_getClass("CContactMgr"));
    if (contactMgr && [contactMgr respondsToSelector:@selector(getGroupMemberCountForContact:)]) {
        unsigned int count = (unsigned int)((unsigned int (*)(id, SEL, id))objc_msgSend)(
            contactMgr, @selector(getGroupMemberCountForContact:), contact);
        if (count > 0) {
            memberCount = count;
        }
    }
    
    // 方案二：手动解析 m_nsChatRoomMemList（兜底）
    if (memberCount == 0) {
        NSString *memList = WXSafeStringGet(contact, @"m_nsChatRoomMemList");
        if (memList.length) {
            memberCount = [memList componentsSeparatedByString:@";"].count;
        }
    }
    
    if (memberCount == 0) return @"未知";
    
    // === 管理员数量 ===
    NSUInteger adminCount = 0;
    NSString *adminList = WXSafeStringGet(contact, @"m_nsChatRoomAdminList");
    if (adminList.length) {
        adminCount = [adminList componentsSeparatedByString:@";"].count;
    }
    
    // === 格式化输出 ===
    if (adminCount > 0) {
        return [NSString stringWithFormat:@"群人员%lu人 管理员%lu人",
                (unsigned long)memberCount, (unsigned long)adminCount];
    }
    return [NSString stringWithFormat:@"群人员%lu人", (unsigned long)memberCount];
}
```

#### 步骤2：增加诊断日志

```objc
WPLog(@"Mio-Group", @"memberCount=%lu (from %@), adminList=%@, adminCount=%lu",
    memberCount, contactMgr ? @"CContactMgr" : @"memList",
    adminList ?: @"nil", adminCount);
```

#### 步骤3：验证分隔符

如果 `m_nsChatRoomAdminList` 也读不到，可能字段名或分隔符与当前微信版本不匹配：

- 尝试 `m_nsChatRoomAdminList` 在不同的 property 访问方式（WXSafeStringGet vs 直接 msgSend）
- 尝试不同分隔符 `;` 和 `,`
- 尝试从群聊的完整数据中查找是否有其他 admin 相关字段
