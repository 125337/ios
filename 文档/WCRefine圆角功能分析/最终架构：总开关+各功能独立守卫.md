# 最终架构：总开关 + 守护下沉到方法内部

审查日期：2026-06-06
决策：`cardBgBeautifyEnabled` 是唯一总开关，关闭时所有逻辑不生效。
每个方法内部自己守卫自己的开关，入口不再分散判断。

---

## 一、架构总纲

### 1.1 三层原则

```
第1层 → 总开关守卫: if (!cardBgBeautifyEnabled) return; ← 关闭则全部不执行

第2层 → 通用安全检查: VC/头像/高度 ← 与具体功能无关

第3层 → 内部守卫: 每个方法自己在入口处检查自己的开关/配置 ← 决定该功能是否实际执行
```

**关键规则**：入口只做总开关 + 安全检查，**不判断任何子开关**。每个方法自己对自己负责。

### 1.2 最终入口代码

```objc
+ (void)handleButtonLayout:(UIView *)button {
    PluginConfig *config = [PluginConfig shared];

    // ══════════════════════════════════════════
    // ★ 第1层：总开关守卫（唯一入口守卫）
    // ★ cardBgBeautifyEnabled 关闭时，全部不生效
    // ══════════════════════════════════════════
    if (!config.cardBgBeautifyEnabled) return;

    // ══════════════════════════════════════════
    // 第2层：通用安全检查（与具体功能无关）
    // ══════════════════════════════════════════
    UIViewController *vc = [ProfileCardBgHook findMoreViewController:button];
    if (!vc) return;
    if (![ProfileCardBgHook hasHeadImageViewInView:button]) return;
    if (button.frame.size.height <= 50.0) return;
    BOOL isDark = [ProfileCardBgHook isDarkModeForVc:vc];

    // ══════════════════════════════════════════
    // ★ 第3层：统一调用，每个方法内部自己守卫
    // ★ 入口不判断任何子开关，只负责路由
    // ══════════════════════════════════════════

    // ── 场景路由 ──
    if (config.cardBgHidden) {
        [ProfileCardBgHook handleHiddenPath:button isDark:isDark];
    } else if (config.cardBgMaterialEnabled || config.cardBgCornerEnabled) {
        [ProfileCardBgHook handleVisiblePath:button isDark:isDark];
    }

    // ── 独立功能（统一调用，内部守卫） ──
    [ProfileCardBgHook handleHeightAdjustment:button];  // 内部: targetH<=0 → return
    [ProfileCardBgHook handleMarginAdjustment:button];  // 内部: !cornerEnabled → return 🔥
    [ProfileCardBgHook handleCornerAndQR:button isDark:isDark];  // 内部: !cornerEnabled → return
}
```

### 1.3 各功能的内部守卫

| 功能 | 方法 | 内部守卫 | 守卫位置 |
|------|------|----------|---------|
| 隐藏路径 | `handleHiddenPath:` | `config.cardBgHidden` | 入口场景路由（属路由，不入内部） |
| 美化路径 | `handleVisiblePath:` | `config.cardBgMaterialEnabled \|\| config.cardBgCornerEnabled` | 入口场景路由 |
| 高度调整 | `handleHeightAdjustment:` | `config.cardBgHeight > 0` | **方法内部第1行** ✅ 已有 |
| 边距调整 | `handleMarginAdjustment:` | `!config.cardBgCornerEnabled → return` | **方法内部第1行** 🔥 需新增 |
| 圆角 | `handleCornerAndQR:` | `config.cardBgCornerEnabled` | 方法内部 ✅ 已有 |
| QR 码隐藏 | `hideQRButtonInCell:` | `config.listHideRightQRCode` | 方法内部 ✅ 已有 |

## 三、改动清单（仅 2 处）

### 改动 1：入口守卫改为总开关单守卫

**文件**：[ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L588-L594)

**当前代码**：

```objc
// ★ 入口守卫：OR 聚合
PluginConfig *config = [PluginConfig shared];
BOOL anyFeatureEnabled = config.cardBgBeautifyEnabled
                      || config.cardBgHidden
                      || config.cardBgCornerEnabled;
if (!anyFeatureEnabled) return;
```

**改为**：

```objc
// ★ 第1层：总开关守卫（唯一入口守卫）
PluginConfig *config = [PluginConfig shared];
if (!config.cardBgBeautifyEnabled) return;
```

---

### 改动 2：`handleMarginAdjustment` 内部添加开关守卫 🔥

**文件**：[ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L654)

**当前代码**：

```objc
+ (void)handleMarginAdjustment:(UIView *)button {
    PluginConfig *config = [PluginConfig shared];

    CGFloat margin = 0;
    if (config.cardBgCornerUseGlobal) {
        margin = config.listCellMargin;
    } else if (config.cardBgCornerMargin > 0) {
        margin = config.cardBgCornerMargin;
    }
    // margin=0 时，后续 margin <= 0 守卫直接跳过，不产生任何效果
```

**改为**（方法第1行加 guard）：

```objc
+ (void)handleMarginAdjustment:(UIView *)button {
    PluginConfig *config = [PluginConfig shared];

    // ★ 内部守卫：圆角未开启时不做边距调整
    if (!config.cardBgCornerEnabled) return;

    CGFloat margin = 0;
    if (config.cardBgCornerUseGlobal) {
        margin = config.listCellMargin;
    } else if (config.cardBgCornerMargin > 0) {
        margin = config.cardBgCornerMargin;
    }
```

---

### 为什么只改 2 处就够了？

| 方法 | 是否有内部守卫 | 需要改？ |
|------|--------------|---------|
| `handleHeightAdjustment` | `targetH <= 0` 已有 | ❌ 不改 |
| `handleMarginAdjustment` | 缺失核心开关守卫 | ✅ **加 `!cornerEnabled → return`** |
| `handleCornerAndQR` | `cornerEnabled` 已有 | ❌ 不改 |
| `handleHiddenPath` | 入口场景路由判断 | ❌ 不改 |
| `handleVisiblePath` | 入口场景路由判断 | ❌ 不改 |

唯一的问题是：`handleMarginAdjustment` 被无条件调用时，虽然 margin 计算已经去掉了 9.0 默认值，但 `cardBgCornerMargin` 可能因为**NSUserDefaults 持久化**保留了旧值（比如曾设过 9）。加上 `!cornerEnabled → return` 后，只要圆角没开，**无论 margin 配置是什么**，边距代码一行都不执行。

## 六、设计决策记录

### 6.1 为什么用内部守卫而不是入口判断

| 方案 | 代码 | 问题 |
|------|------|------|
| OR 聚合入口（旧） | `beautify \|\| hidden \|\| corner` | 总开关控制力不足 |
| 第2层守卫在入口（之前方案） | 入口同时判断 `height>0`、`cornerEnabled` | 调用者和被调用者职责分裂，入口需要知道每个方法的开关条件 |
| **内部守卫（本方案）** | 每个方法内部 `if (!mySwitch) return;` | **调用者和被调用者职责统一，入口永不修改** ✅ |

### 6.2 内部守卫的优势

- **职责单一**：入口只做总开关 + 安全检查，不关心子功能细节
- **防新增遗漏**：新增方法时只需在内部加守卫，入口不用改
- **防误调用**：即使从其他地方调用 `handleMarginAdjustment`，它自己会守卫
- **修复当前问题**：`handleMarginAdjustment` 不再依赖调用者来守卫，自己就能拦截

核心区别：**第2层守卫从入口移到了方法内部**，入口代码更干净，各方法更自洽。
