## 二、方法独立性逐项确认

### 2.1 入口：`handleButtonLayout:`

```objc
+ (void)handleButtonLayout:(UIView *)button {
    // OR 聚合入口守卫
    BOOL anyEnabled = beautify || hidden || corner;
    if (!anyEnabled) return;

    // 通用守卫
    vc = findMoreViewController(button);          // 辅助方法
    hasHeadImageViewInView(button);               // 辅助方法
    height > 50;                                  // 自有逻辑
    isDark = isDarkModeForVc(vc);                 // 辅助方法

    // 场景路由
    if (hidden) → handleHiddenPath                // 路径方法
    else if (material || corner) → handleVisiblePath // 路径方法

    // 独立功能（可任意交换顺序）
    handleHeightAdjustment(button);               // 独立方法
    handleCornerAndQR(button, isDark);            // 独立方法
}
```

**入口不持有状态**，只做路由分发。✅

### 2.2 路径方法

| 方法 | 自有守卫 | 递归预防 | 修改范围 | 依赖 |
|------|---------|---------|---------|------|
| `handleHiddenPath:` | 无（由入口守卫保证） | `!hasMaterial` → return | `button.frame`, `layer`, subviews hidden | 仅调用辅助方法 |
| `handleVisiblePath:` | 无（由入口守卫保证） | `hasMaterial` 分支 | `button.hidden`, 背景素材 | 仅调用辅助方法 |

**路径方法互斥**：hidden=YES 走隐藏路径，hidden=NO 走可见路径，不会同时执行。✅

### 2.3 独立功能方法

| 方法 | 自有守卫 | 递归预防 | 修改范围 | 是否被调用 |
|------|---------|---------|---------|-----------|
| `handleHeightAdjustment:` | `targetH <= 0` + `height >= targetH` | ✅ 高度判等 | `button.frame.size.height` | ✅ 第611行 |
| `handleMarginAdjustment:` | `margin <= 0` | ✅ 浮点比较 | `button.frame.origin.x` + `.size.width` | ❌ **未被调用** |
| `handleCornerAndQR:` | `cornerEnabled` + `listHideRightQRCode` | 无（不涉及 frame） | `button.layer`, subviews | ✅ 第612行 |

**关键验证：三者的修改范围不重叠**

```
handleHeightAdjustment  → 只改 frame.size.height
handleMarginAdjustment  → 只改 frame.origin.x + frame.size.width
handleCornerAndQR       → 只改 layer.cornerRadius + layer.border + subviews.hidden
```

三个方法修改的是 `button` 的不同属性，相互不冲突。**即使交换调用顺序，结果一致**。✅

## 三、发现的问题

### 问题 1：`handleMarginAdjustment:` 孤儿方法

**位置**：[.m 第653行](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L653) 定义，.h **无声明**，**无调用方**

**现状**：方法已提取为独立方法，拥有完整的守卫和递归预防逻辑，但未被 `handleButtonLayout` 入口调用。

**影响**：边距功能当前未生效。用户配置了边距大小，代码中存在处理逻辑，但没有执行入口。

**修复方案**：在 `handleButtonLayout` 的独立功能区添加调用：

```objc
// 独立功能
[ProfileCardBgHook handleHeightAdjustment:button];
[ProfileCardBgHook handleMarginAdjustment:button];  // ← 新增
[ProfileCardBgHook handleCornerAndQR:button isDark:isDark];
```

同时需要在 [ProfileCardBgHook.h](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.h) 添加声明：

```objc
+ (void)handleMarginAdjustment:(UIView *)button;
```

### 问题 2：`handleCardHiddenInButton:` 悬空声明

**位置**：[.h 第46-48行](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.h#L46-L48) 有声明，.m **无实现**

**现状**：此方法已被 `handleHiddenPath:` + `handleVisiblePath:` 替代，实现已从 .m 中删除，但 .h 中的声明仍保留。

**影响**：如果任何其他代码尝试调用此方法，会发生链接错误。当前暂无其他调用者（已搜索确认），属于代码污染。

**修复方案**：从 [ProfileCardBgHook.h](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.h) 中删除悬空声明：

```objc
// 删除以下代码
// 隐藏信息卡片（保留兼容）
+ (BOOL)handleCardHiddenInButton:(UIView *)button
                       isHidden:(BOOL)isHidden
                    hasMaterial:(BOOL)hasMaterial;
```
