# 隐藏信息卡片独立改造方案

## 现状问题

当前 `handleButtonLayout` 中，"隐藏信息卡片"（`cardBgHidden`）和"背景素材"（`cardBgMaterialEnabled`）两个功能的代码交织在一起，位于同一个 `if (needsNewCardBg)` 大块中：

```
handleButtonLayout:
  needsNewCardBg {
    Scene B (isHidden && !hasMaterial) → 早返   ← 交织 ①
    if (hasMaterial) { /* bg 生命周期 */ }          ← 素材代码
    if (isHidden) { /* 场景 A */ }                  ← 交织 ②
    else { /* 非隐藏态 */ }                          ← 交织 ③
    FIX-WHITE                                       ← 不分家
  }
```

三个交织点：

| 交织点 | 代码 | 问题 |
|--------|------|------|
| ① Scene B | `isHidden && !hasMaterial` | 隐藏代码中引用了 `hasMaterial` |
| ② 场景 A | `isHidden = YES` 分支 | 隐藏在素材段之后执行 |
| ③ 非隐藏态 | `isHidden = NO` 分支 | 和场景 A 在一个 `if/else` 里 |

---

## 改造目标

把"隐藏信息卡片"相关代码全部抽为独立方法，`handleButtonLayout` 不再直接处理隐藏逻辑。

```
改造前：handleButtonLayout 一人管全家
改造后：handleButtonLayout 管素材 + 调度
       handleCardHidden    独立管隐藏
```

---

## 新方法设计

### 方法签名

```objc
/// 处理隐藏信息卡片
/// @param button 资料卡 button
/// @param isHidden cardBgHidden 配置值
/// @param hasMaterial cardBgMaterialEnabled 配置值
/// @return YES = Scene B（完全隐藏，调用者应 return）
///         NO  = 非隐藏 或 Scene A（调用者继续执行）
+ (BOOL)handleCardHiddenInButton:(UIView *)button 
                       isHidden:(BOOL)isHidden 
                    hasMaterial:(BOOL)hasMaterial;
```

### 完整代码

```objc
+ (BOOL)handleCardHiddenInButton:(UIView *)button 
                       isHidden:(BOOL)isHidden 
                    hasMaterial:(BOOL)hasMaterial {
    
    // ══════════════════════════════════════════
    // 非隐藏态：确保可见，不干预背景
    // ══════════════════════════════════════════
    if (!isHidden) {
        button.hidden = NO;
        return NO;  // 让调用者继续处理背景和布局
    }

    // ══════════════════════════════════════════
    // 隐藏态共有清除：button 背景色 + 原生 bg
    // ══════════════════════════════════════════
    button.backgroundColor = [UIColor clearColor];
    button.layer.backgroundColor = [UIColor clearColor].CGColor;
    button.layer.masksToBounds = NO;
    button.layer.cornerRadius = 0;
    button.layer.borderWidth = 0;

    Ivar bgIvar = class_getInstanceVariable([button class], "m_bgImageView");
    if (bgIvar) {
        id bgImgView = object_getIvar(button, bgIvar);
        if (bgImgView && [bgImgView isKindOfClass:[UIImageView class]]) {
            [(UIImageView *)bgImgView setImage:nil];
            [(UIImageView *)bgImgView setBackgroundColor:[UIColor clearColor]];
            [(UIImageView *)bgImgView setHidden:YES];
        }
        object_setIvar(button, bgIvar, nil);
    }

    PluginConfig *config = [PluginConfig shared];

    // ══════════════════════════════════════════
    // Scene B：隐藏 + 无素材 → 完全隐藏
    // ══════════════════════════════════════════
    if (!hasMaterial) {
        for (UIView *sub in button.subviews) {
            sub.hidden = YES;
        }

        if (config.listHideRightQRCode) {
            [ProfileCardBgHook hideQRButtonInCell:button];
        }
        return YES;  // Scene B → 调用者应 return
    }

    // ══════════════════════════════════════════
    // Scene A：隐藏 + 有素材 → 隐藏内容，保留背景
    // ══════════════════════════════════════════
    for (UIView *sub in button.subviews) {
        if ([sub isKindOfClass:[UIImageView class]] &&
            sub.tag == kProfileCardBgImageTag) {
            continue;  // 豁免背景图
        }
        sub.hidden = YES;
    }

    if (config.listHideRightQRCode) {
        [ProfileCardBgHook hideQRButtonInCell:button];
    }
    return NO;  // Scene A → 调用者继续执行
}
```

## handleButtonLayout 改造

### 改造后结构

```
handleButtonLayout:
  needsNewCardBg {
    ├─ 背景素材（独立）
    │   if (hasMaterial) { /* bg 生命周期 + 清 button bg 让 bg 透出 + 清原生 bg */ }
    │
    ├─ 隐藏信息卡片（独立，一行调度）
    │   if ([self handleCardHiddenInButton:...]) return;
    │
    ├─ FIX-WHITE（bg 通过 tag 豁免）
    ├─ ...
    }
  └─ 方案 H 高度调整
  └─ DO_CORNER
```

| 场景 | beautify | material | hidden | 改造前行为 | 改造后行为 | 结果 |

## 边界情况说明

### 1. 原生 bg 清理归属

改造前：原生 bg 清理出现在 3 个地方：
- Scene B（L434-L443）
- 场景 A（L602-L611）
- 非隐藏态（L640-L649）

改造后：统一放在两个地方：
- `hasMaterial` 段（bg 生命周期内）→ 有素材时清理
- `handleCardHidden` 的隐藏态共有部分 → 隐藏时清理

非隐藏态 + 无素材时，原生 bg 不再主动清理（因为没必要——没有自定义 bg 需要露出来，保持微信默认即可）。

### 2. FIX-WHITE 的 bg 豁免

改造后 FIX-WHITE 仍在 `handleButtonLayout` 中，`sub.tag == kProfileCardBgImageTag` 豁免保留不变。

### 3. 代码量变化

| 文件 | 行数变化 |
|------|---------|
| ProfileCardBgHook.h | **+3**（新增方法声明）|
| ProfileCardBgHook.m | **-10**（删除 ~60 行旧代码，新增 ~50 行新方法）|

## 最终文件对比

### 改造前 `handleButtonLayout` 结构

```
needsNewCardBg {
  Scene B (13行)
  if (hasMaterial) { bg 生命周期 (130行) }
  HideCard { 场景A (35行) } else { 非隐藏态 (20行) }
  FIX-WHITE (40行)
}
```

### 改造后 `handleButtonLayout` 结构

```
needsNewCardBg {
  if (hasMaterial) { bg 生命周期 + bg 清理 (135行) }     ← 纯素材
  if ([self handleCardHidden:...]) return; (1行)          ← 调度行
  FIX-WHITE (40行)                                         ← 通用清理
}
```

### 新方法 `handleCardHiddenInButton:`

```
非隐藏态 → button.hidden = NO, return NO
隐藏态 {
  共有清除：button 背景色 + 原生 bg
  Scene B (!hasMaterial) → 全隐藏所有子视图, return YES
  Scene A (hasMaterial)  → 隐藏子视图豁免 bg tag, return NO
}
```
