# 我的页面顶栏透明问题修复文档

## 问题描述

**场景**：只开启资料卡片美化（`cardBgBeautifyEnabled = YES`），未开启背景素材（`materialEnabled = NO`），未开启隐藏信息卡片（`isHidden = NO`）。

**现象**：我的页面顶部导航栏（顶栏）变透明，微信原生应该是**白色导航栏**，现在变成**透明**，底色（微信列表深色背景）透了出来。

**旧的修复**（m_bgImageView 清理）没有解决这个问题——这是另一个独立的原因。

---

## 根因分析

### 问题定位：FIX-WHITE 在非隐藏态不应运行

当前代码中，FIX-WHITE 块无条件位于 `needsNewCardBg` 块内：

```
needsNewCardBg:
  if (hasMaterial) {
    bg 生命周期
    清 button 背景色
    清原生 m_bgImageView
  }
  handleCardHiddenInButton(...) → non-hide 清理 m_bgImageView
  FIX-WHITE  ◄── ★ 始终执行
```

**FIX-WHITE 的设计初衷**：在"隐藏信息卡片 + 有背景素材"（Scene A）时，button 上残留的白色子视图会遮盖背景图，所以需要隐藏它们。

**但 FIX-WHITE 在非隐藏态运行会出问题**：

当 `isHidden = NO`、`hasMaterial = NO` 时，FIX-WHITE 仍然遍历 button 的所有子视图，并将以下视图隐藏：

| 隐藏条件 | 说明 | 影响 |
|---------|------|------|
| 背景色是 `whiteColor` 或 `>0.95 白` | 白色视图 | 可能是头像区域、名称区域的白色衬底 |
| 背景色含 `DynamicProvider` / `UIDynamic` | 动态颜色（含系统白色） | iOS 原生白底视图 |
| 类名是 `UIView` 且有背景色 | 纯 UIView（无条件隐藏） | **极易误伤！** |
| 类名是 `UIImageView` 且 tag≠0 | 非背景的图片视图 | 可能包含重要的装饰图片 |

**关键问题**：微信原生"我的"页面的 MMUIButton（资料卡按钮）内部包含多个白色背景的 `UIView` 子视图，它们一直延伸到导航栏下方区域，为导航栏提供白色衬底。FIX-WHITE 将这些视图隐藏后，导航栏失去白色衬底，呈现透明状态。

### 为什么以前没问题？

在 `handleButtonLayout` 重构之前，FIX-WHITE 也存在，但当时代码路径更复杂：

- **旧逻辑**：FIX-WHITE 与隐藏逻辑深度耦合，实际上在非隐藏态可能因为其他判断条件跳过了执行，或是非隐藏态时按钮的正常布局抵消了 FIX-WHITE 的影响
- **新逻辑**：`handleCardHiddenInButton` 提取后，非隐藏态路径变清晰，FIX-WHITE 的副作用暴露了出来
- **m_bgImageView 修复后**：之前的 m_bgImageView 清理修复了"灰色残留"的问题，但**顶栏透明**是 FIX-WHITE 造成的新问题，两者不相关

### 代码执行流对照

```
场景：beautify=YES, hidden=NO, material=NO

needsNewCardBg = YES
├─ hasMaterial = NO → 跳过素材块
├─ handleCardHiddenInButton(button, NO, NO)
│    └─ non-hide: button.hidden = NO
│                 清理 m_bgImageView ✅ 已修复
│                 return NO
├─ FIX-WHITE  ◄── 非隐藏态也运行！
│    └─ 隐藏 button 内所有白色/动态 UIView 子视图
│        → 白色衬底被移除 → 导航栏透明
└─ 圆角 + 边框
```

---

## 修复方案

### 解决方案：FIX-WHITE 仅限隐藏态执行

**原理**：FIX-WHITE 的作用是在"隐藏内容、保留背景"（Scene A）时，防止白色子视图遮挡背景素材。在非隐藏态，白色子视图是正常 UI 的一部分，不应该被隐藏。

**改动**：给 FIX-WHITE 块加上 `if (isHidden)` 条件守卫。

**[ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m) — handleButtonLayout 方法**

```objc
        // ══════════════════════════════════════════
        // 隐藏信息卡片（独立方法）
        // ══════════════════════════════════════════
        if ([ProfileCardBgHook handleCardHiddenInButton:button
                                                isHidden:isHidden
                                             hasMaterial:hasMaterial]) {
            return;  // Scene B：完全隐藏，后面的不用执行了
        }

        // ══════════════════════════════════════════
        // 4. FIX-WHITE：隐藏白色视图
        //    ★ 仅在隐藏态执行（Scene A），非隐藏态跳过 ★
        // ══════════════════════════════════════════
        if (isHidden)  // ◄── ★ 新增条件守卫
        {
            for (NSInteger i = button.subviews.count - 1; i >= 0; i--) {
                // ... 原有 FIX-WHITE 逻辑不变 ...
            }
        }
```

**为什么 `isHidden` 时 FIX-WHITE 必须运行**：
- Scene A（`hidden=YES, hasMaterial=YES`）：button 的背景图已加载，需要隐藏白色子视图让背景图完全展示
- 此时 FIX-WHITE 是必要的，因为它隐藏在背景图之上的白色/动态子视图

**为什么非隐藏态 FIX-WHITE 不应运行**：
- 场景 1（`hidden=NO, hasMaterial=NO`）：button 没有背景图，白色子视图是正常 UI，隐藏后导致导航栏透明
- 场景 2（`hidden=NO, hasMaterial=YES`）：button 有背景图，但用户没有隐藏内容，白色子视图不会被隐藏（实际上这个场景在 hasMaterial 块中已经设置了 clearColor，但由于没有隐藏，导航栏区域应该保持白色）

## 场景验证

| 场景 | beautify | material | hidden | FIX-WHITE 执行 | 预期结果 |
|------|----------|----------|--------|----------------|---------|
| 1 | ON | OFF | OFF | **❌ 跳过** ✅ **修复** | 导航栏白色 ✅ |
| 2 | ON | ON | OFF | **❌ 跳过** ✅ | 导航栏白色 ✅ |
| 3 | ON | OFF | ON | **❌ 跳过**（Scene B 早返） | 完全隐藏 ✅ |
| 4 | ON | ON | ON | **✅ 执行**（Scene A） | 隐藏内容留背景 ✅ |

场景 1 是本次修复的目标场景。
