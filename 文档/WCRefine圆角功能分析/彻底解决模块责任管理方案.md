# 彻底解决：模块责任管理方案

> 解决列表圆角 Hook 中零散判断 VC 归属的问题，通过独立的责任管理表统一所有 VC 的模块归属查询。

---

## 一、问题重现

### 当前代码现状

`ListCornerRadiusHook.m` 的 `replaced_MMTableViewCell_layoutSubviews` 函数中，存在多种类型的跳过判断：

```objc
static void replaced_MMTableViewCell_layoutSubviews(id vc, SEL sel, MMTableViewCell *cell, ...) {
    PluginConfig *config = [PluginConfig shared];

    // 1. 总开关守卫
    if (!config.listCornerRadiusEnabled && !config.globalCornerRadiusEnabled) {
        orig(vc, sel, cell, ...);
        return;
    }

    // 2. 黑名单跳过（shouldSkipCorner 内部维护一个 NSSet）
    if (shouldSkipCorner(vc)) {
        orig; return;
    }

    // 3. ★ 如果按之前的方案加了责任划分 ★
    if ([vc isKindOfClass:NSClassFromString(@"MoreViewController")]) {
        orig; return;
    }

    // 4. 全局圆角页面开关（如果已实现 shouldApplyGlobalCorner）
    if (!shouldApplyGlobalCorner(vc)) {
        orig; return;
    }

    // 5. 获取 VC 类名，后续可能还有特殊页面判断
    NSString *className = NSStringFromClass([vc class]);

    // 6. 原来的资料卡背景色代码（300-317 行，如果还没删）
    if ([className isEqualToString:@"MoreViewController"]) {
        // 设置 MMUIButton 背景色...
    }

    // 7. 后续对 Cell 的实际处理...
}
```

### 问题

| 问题 | 说明 |
|------|------|
| **重复判断** | MoreVC 在第 3 步 return 了，但第 6 步的死代码还在（如果没删） |
| **判断分散** | `shouldSkipCorner`、`shouldApplyGlobalCorner`、`isKindOfClass:` 三种判断方式散布在函数中 |
| **语义模糊** | `shouldSkipCorner` 返回 YES 的 VC 既有"不支持圆角"的，也有"由其他模块管理"的 |
| **扩展困难** | 再来一个新模块要接管某个 VC，又得在 hook 函数中加一行 if |
| **没有测试入口** | 无法单元测试某个 VC 应该由哪个模块处理 |

## 二、设计方案

### 核心思路

新增一个独立的 `CornerResponsibility` 类，唯一的职责是回答一个问题：

> **给定一个 UIViewController，它的圆角由哪个模块负责？**

所有 VC → 模块的映射关系集中在这个类中，hook 函数只需要调用一次查询，然后根据返回值决定是否处理。

### 模块定义

定义三个模块：

| 模块 | 含义 | 做什么 |
|------|------|--------|
| `kCornerModuleList` | 列表圆角模块 | 走现有的 `replaced_MMTableViewCell_layoutSubviews` 完整逻辑 |
| `kCornerModuleProfileCard` | 资料卡片美化模块 | 不走列表圆角，由 `ProfileCardBgHook` 的 `applyProfileCardCorner` 管理 |
| `kCornerModuleNone` | 无圆角模块 | 不应用任何圆角 |

### 映射策略

```
VC 类名 → CornerResponsibility.moduleForViewController:
    ├── 在 profileCardVCs Set 中 → kCornerModuleProfileCard
    ├── 在 skipListVCs Set 中     → kCornerModuleNone
    └── 都不在                    → kCornerModuleList（默认）
```

## 三、完整代码

### 3.1 CornerResponsibility.h

```objc
//
//  CornerResponsibility.h
//  MioPlugin
//
//  功能：管理各 VC 的圆角模块归属，集中查询，避免判断分散。
//

#import <UIKit/UIKit.h>

/// 圆角模块枚举
typedef NS_ENUM(NSInteger, CornerModule) {
    /// 列表圆角模块（由 ListCornerRadiusHook 管理）
    kCornerModuleList = 0,
    /// 资料卡片美化模块（由 ProfileCardBgHook 管理）
    kCornerModuleProfileCard,
    /// 无圆角模块（当前不支持圆角的页面）
    kCornerModuleNone,
};

@interface CornerResponsibility : NSObject

/// 查询指定 VC 的圆角模块归属
/// @param vc 当前正在展示的 UIViewController 实例
/// @return CornerModule 枚举值
+ (CornerModule)moduleForViewController:(UIViewController *)vc;

/// 判断指定 VC 是否应由列表圆角模块处理
/// 等效于 moduleForViewController: == kCornerModuleList
+ (BOOL)isListCornerResponsibleFor:(UIViewController *)vc;

/// 判断指定 VC 是否应由资料卡片美化模块处理
/// 等效于 moduleForViewController: == kCornerModuleProfileCard
+ (BOOL)isProfileCardResponsibleFor:(UIViewController *)vc;

/// 判断指定 VC 是否不支持任何圆角
/// 等效于 moduleForViewController: == kCornerModuleNone
+ (BOOL)isNoCornerResponsibleFor:(UIViewController *)vc;

@end
```

### 3.2 CornerResponsibility.m

```objc
//
//  CornerResponsibility.m
//  MioPlugin
//

#import "CornerResponsibility.h"

/// ========== 配置区：在此维护各模块的 VC 归属 ==========

/// 资料卡片美化模块专属的 VC 类名列表
/// 这些 VC 的 Cell 由 ProfileCardBgHook 全权管理
static NSString *const kProfileCardVCs[] = {
    @"MoreViewController",
};

/// 列表圆角黑名单（不支持任何圆角的 VC 类名列表）
/// 这些 VC 的页面还不适配圆角
static NSString *const kSkipListVCs[] = {
    @"WCTimeLineViewController",
    @"WCContactDataSearchViewController",
    @"WCOutPhoneContactViewController",
    @"WCAddressBookSearchViewController",
    @"BrandTimelineViewController",
    @"WCBrandTimelineViewController",
    @"GameCenterViewController",
};

/// ========== 配置区结束 ==========

/// 获取静态 NSSet（profileCardVCs）
static NSSet *profileCardSet(void) {
    static NSSet *set = nil;
    static dispatch_once_t onceToken;
    dispatch_once(&onceToken, ^{
        NSMutableSet *mutableSet = [NSMutableSet set];
        NSUInteger count = sizeof(kProfileCardVCs) / sizeof(kProfileCardVCs[0]);
        for (NSUInteger i = 0; i < count; i++) {
            [mutableSet addObject:kProfileCardVCs[i]];
        }
        set = [mutableSet copy];
    });
    return set;
}

/// 获取静态 NSSet（skipListVCs）
static NSSet *skipListSet(void) {
    static NSSet *set = nil;
    static dispatch_once_t onceToken;
    dispatch_once(&onceToken, ^{
        NSMutableSet *mutableSet = [NSMutableSet set];
        NSUInteger count = sizeof(kSkipListVCs) / sizeof(kSkipListVCs[0]);
        for (NSUInteger i = 0; i < count; i++) {
            [mutableSet addObject:kSkipListVCs[i]];
        }
        set = [mutableSet copy];
    });
    return set;
}

@implementation CornerResponsibility

+ (CornerModule)moduleForViewController:(UIViewController *)vc {
    if (vc == nil) return kCornerModuleNone;

    NSString *cls = NSStringFromClass([vc class]);
    if (cls.length == 0) return kCornerModuleNone;

    // 1. 资料卡片美化专属 VC
    if ([profileCardSet() containsObject:cls]) {
        return kCornerModuleProfileCard;
    }

    // 2. 列表圆角黑名单（暂不支持圆角的页面）
    if ([skipListSet() containsObject:cls]) {
        return kCornerModuleNone;
    }

    // 3. 默认都归列表圆角
    return kCornerModuleList;
}

+ (BOOL)isListCornerResponsibleFor:(UIViewController *)vc {
    return [self moduleForViewController:vc] == kCornerModuleList;
}

+ (BOOL)isProfileCardResponsibleFor:(UIViewController *)vc {
    return [self moduleForViewController:vc] == kCornerModuleProfileCard;
}

+ (BOOL)isNoCornerResponsibleFor:(UIViewController *)vc {
    return [self moduleForViewController:vc] == kCornerModuleNone;
}

@end
```

### 3.3 改造后的 ListCornerRadiusHook.m

#### 删除的内容

将 `shouldSkipCorner` 函数整体删除（它的功能已被 `CornerResponsibility` 替代）。如果代码中其他地方还引用了 `shouldSkipCorner`，也一并改为调用 `[CornerResponsibility moduleForViewController:]`。

#### 替换 `replaced_MMTableViewCell_layoutSubviews` 入口

改前（假设已有之前的责任划分代码）：

```objc
static void replaced_MMTableViewCell_layoutSubviews(id vc, SEL sel, MMTableViewCell *cell, ...) {
    PluginConfig *config = [PluginConfig shared];

    // 1. 守卫
    if (!config.listCornerRadiusEnabled && !config.globalCornerRadiusEnabled) {
        orig(vc, sel, cell, ...);
        return;
    }

    // 2. 黑名单
    if (shouldSkipCorner(vc)) {
        orig; return;
    }

    // 3. 资料卡责任划分
    if ([NSStringFromClass([vc class]) isEqualToString:@"MoreViewController"]) {
        orig; return;
    }

    // 4. shouldApplyGlobalCorner（如果有）
    if (!shouldApplyGlobalCorner(vc)) {
        orig; return;
    }

    // ... 剩下的 Cell 处理 ...
}
```

改后：

```objc
static void replaced_MMTableViewCell_layoutSubviews(id vc, SEL sel, MMTableViewCell *cell, ...) {
    PluginConfig *config = [PluginConfig shared];

    // 1. 守卫：两个转角开关都关则跳过
    if (!config.listCornerRadiusEnabled && !config.globalCornerRadiusEnabled) {
        orig(vc, sel, cell, ...);
        return;
    }

    // ★ 2. 模块责任查询：不属于列表圆角则跳过 ★
    if (![CornerResponsibility isListCornerResponsibleFor:vc]) {
        orig(vc, sel, cell, ...);
        return;
    }

    // ★ 3. 全局圆角页面开关（如果已实现） ★
    // ★ 这里只查页面开关，不再查 VC 归属 ★
    if (!shouldApplyGlobalCorner(vc)) {
        orig; return;
    }

    // ... 剩下的 Cell 处理（margin / corner / border / background） ...
}
```

### 3.4 改造后的 ProfileCardBgHook.m（可选）

如果 ProfileCardBgHook 也需要在自己的入口确认是否是自己的 VC，可以加一个断言或守卫：

```objc
// 在 handleButtonLayout 入口
if (![CornerResponsibility isProfileCardResponsibleFor:self.vc]) {
    // 不是自己的 VC，理论上不应执行到这里
    return;
}
```

不过这一步不是必须的——ProfileCardBgHook 的 MMUIButton Hook 只对 MoreVC 页面中的按钮生效，它不需要做 VC 判断。

## 四、改造步骤（操作手册）

### 第 1 步：新建文件

将 `CornerResponsibility.h` 和 `CornerResponsibility.m` 放入项目中建议的位置：

### 第 2 步：填充黑名单

将 `shouldSkipCorner` 函数中 `skipSet` 里的所有类名，复制到 `CornerResponsibility.m` 的 `kSkipListVCs[]` 数组中。

原 `shouldSkipCorner` 代码：

```objc
static BOOL shouldSkipCorner(id vc) {
    static NSSet *skipSet = nil;
    static dispatch_once_t onceToken;
    dispatch_once(&onceToken, ^{
        skipSet = [NSSet setWithObjects:
            @"WCTimeLineViewController",
            @"WCContactDataSearchViewController",
            // ... 其他黑名单 VC
            nil];
    });
    NSString *cls = NSStringFromClass([vc class]);
    return [skipSet containsObject:cls];
}
```

复制到 `kSkipListVCs[]`：

```objc
static NSString *const kSkipListVCs[] = {
    @"WCTimeLineViewController",
    @"WCContactDataSearchViewController",
    // ... 全部复制过来，保持与原来一致
};
```

### 第 3 步：填充资料卡片 VC

当前只有 `MoreViewController`：

```objc
static NSString *const kProfileCardVCs[] = {
```

## 五、预期的最终代码结构

### ListCornerRadiusHook.m 的完整入口

```objc
static void replaced_MMTableViewCell_layoutSubviews(id vc, SEL sel, MMTableViewCell *cell, ...) {
    PluginConfig *config = [PluginConfig shared];

    // [Step 1] 总开关守卫
    if (!config.listCornerRadiusEnabled && !config.globalCornerRadiusEnabled) {
        orig(vc, sel, cell, isHighlighted, animated);
        return;
    }

    // [Step 2] 模块责任查询（取代了 shouldSkipCorner + MoreVC 判断）
    if (![CornerResponsibility isListCornerResponsibleFor:vc]) {
        orig(vc, sel, cell, isHighlighted, animated);
        return;
    }

    // [Step 3] 全局圆角页面开关（四个页面的控制）
    if (!shouldApplyGlobalCorner(vc)) {
        orig; return;
    }

    // [Step 4 ~] 以下全是 Cell 的实际处理逻辑，不再有任何 VC 判断
    NSString *className = NSStringFromClass([vc class]);
    BOOL isDark = ...;

    // 4a. 计算边距、调整 frame
    // 4b. 设置圆角
    // 4c. 设置背景色
    // 4d. 设置边框
    // 4e. masksToBounds

    orig(vc, sel, cell, isHighlighted, animated);
}
```

### 判断链可视化

```
replaced_MMTableViewCell_layoutSubviews 进入
    │
    ├─ 总开关关? → orig; return
    │
    ├─ CornerResponsibility 查询
    │   ├─ kCornerModuleProfileCard → orig; return
    │   ├─ kCornerModuleNone       → orig; return
    │   └─ kCornerModuleList       → 继续
    │
    ├─ shouldApplyGlobalCorner 页面开关
    │   ├─ NO → orig; return
    │   └─ YES → 继续
    │
    └─ 正常处理 Cell
```

## 七、后续扩展方式

### 新增一个由"资料卡片美化"接管的 VC

在 `kProfileCardVCs[]` 追加类名：

```objc
static NSString *const kProfileCardVCs[] = {
    @"MoreViewController",
    @"NewProfileViewController",  // ← 新增
};
```

### 新增一个不支持圆角的 VC

在 `kSkipListVCs[]` 追加类名：

```objc
static NSString *const kSkipListVCs[] = {
    ...
    @"NewNotSupportedViewController",  // ← 新增
};
```

### 新增一个圆角模块（如"消息页圆角"）

1. 在 `CornerResponsibility.h` 增加枚举：

```objc
typedef NS_ENUM(NSInteger, CornerModule) {
    kCornerModuleList = 0,
    kCornerModuleProfileCard,
    kCornerModuleMessagePage,     // ← 新增
    kCornerModuleNone,
};
```

2. 在 `CornerResponsibility.m` 增加对应的 VC Set 和判断

3. 在 `replaced_MMTableViewCell_layoutSubviews` 中的判断改为：

```objc
CornerModule module = [CornerResponsibility moduleForViewController:vc];
if (module == kCornerModuleProfileCard || module == kCornerModuleMessagePage) {
    orig; return;
}
```

> 如果模块越来越多，可以将 `replaced_MMTableViewCell_layoutSubviews` 中的判断改为对 `[CornerResponsibility shouldListCornerHandleModule:module]` 的查询。
