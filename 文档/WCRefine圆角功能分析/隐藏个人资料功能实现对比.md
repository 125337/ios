# 隐藏个人资料/信息卡片功能实现对比分析

## WCRefine vs MioPlugin

> 分析基于：WCRefine 1.4-5 反编译代码 & MioPlugin 当前项目代码

---

## 一、功能概念对比

| 维度 | WCRefine | MioPlugin |
|------|----------|-----------|
| **功能名称** | 隐藏个人资料（profileHide） | 隐藏信息卡片（cardBgHidden） |
| **定位** | 独立功能，有独立总开关 | 附属功能，在"资料卡片美化"总开关下 |
| **UI 位置** | 个人资料卡片设置 → 独立 section | 资料卡片美化 → 平铺开关行 |
| **精细度** | **细粒度**：可分别控制总开关、状态按钮、箭头二维码 | **粗粒度**：一个开关隐藏全部非背景内容 |
| **额外功能** | 可隐藏好友个人信息、好友微信号 | 可单独隐藏右侧二维码（listHideRightQRCode） |

---

## 二、配置属性对比

### WCRefine 配置属性

| 属性 | 类型 | 用途 |
|------|------|------|
| `profileHideEnabled` | BOOL | 隐藏个人资料总开关 |
| `profileHideStateButtonsEnabled` | BOOL | 隐藏状态按钮（如"状态"、"朋友圈"等） |
| `profileHideArrowQREnabled` | BOOL | 隐藏箭头二维码 |
| `hideFriendProfileInfoEnabled` | BOOL | 隐藏好友个人资料信息 |
| `hideFriendWeChatIDEnabled` | BOOL | 隐藏好友微信号 |
| `chatAvatarProfileCardWechatIDHiddenByDefault` | BOOL | 默认隐藏微信号 |

### MioPlugin 配置属性

| 属性 | 类型 | 用途 |
|------|------|------|
| `cardBgHidden` | BOOL | 隐藏信息卡片开关 |
| `listHideRightQRCode` | BOOL | 隐藏列表右侧二维码 |

### 差异总结

WCRefine 将隐藏功能拆分为 **3 个独立开关**（总隐藏 + 状态按钮 + 箭头二维码），外加好友维度的 2 个独立开关。MioPlugin 只有 **1 个总开关** + 1 个二维码隐藏开关，粒度较粗。

## 三、Hook 实现对比

### 3.1 入口守卫条件

| 条件 | WCRefine (FUN_0032b0d0) | MioPlugin (handleButtonLayout) |
|------|------------------------|-------------------------------|
| **总开关** | 多重检查：profileCornerEnabled / profileLayoutEnabled / profileHideStateButtonsEnabled / profileHideArrowQREnabled / profileBgBeautifyEnabled / profileHideEnabled 任一开启即进入 | `cardBgBeautifyEnabled` 必须为 ON |
| **VC 类型** | `MoreViewController` | `MoreViewController` |
| **子视图检查** | MMUIButton（遍历 subviews 找到第一个 button） | MMHeadImageView 存在 |
| **高度过滤** | 无显式过滤 | `selfHeight > 50.0` |

### 3.2 隐藏逻辑对比

| 操作 | WCRefine | MioPlugin |
|------|----------|-----------|
| **清空背景色** | 由 profileBgBeautifyEnabled 分支处理 | ✅ clearColor + 清除 layer backgroundColor |
| **清除 m_bgImageView** | 由 profileBgBeautifyEnabled 分支处理 | ✅ 通过 class_getInstanceVariable 找到并置 nil |
| **隐藏子视图** | `profileHideStateButtonsEnabled` → **选择性**隐藏状态按钮类视图 | ✅ 隐藏所有子视图（排除 background image tag） |
| **隐藏二维码** | `profileHideArrowQREnabled` → 独立隐藏 | `listHideRightQRCode` → 通过 hideQRButtonInCell 隐藏右侧按钮 |
| **白色背景清理** | 未发现独立逻辑 | ✅ FIX-WHITE 段：隐藏白色/dynamic provider 背景视图 |
| **隐藏后继续处理** | 是（继续背景美化等后续处理） | ✅ 是（继续到 FIX-WHITE / corner 处理） |

### 3.3 代码结构对比

```
WCRefine FUN_0032b0d0（约 500+ 行）
├── 快速拒绝链（检查多个 feature toggle）
├── VC 类型检查 → MoreViewController
├── 遍历 subviews 找到 MMUIButton
├── 关联对象标记处理状态
├── 调用 FUN_0032d818 / FUN_0032dba0 / FUN_0032e1d0 / FUN_0032e4e0 (背景美化)
├── profileHideArrowQREnabled → FUN_0032e7f0 (隐藏箭头二维码)
├── profileHideStateButtonsEnabled → FUN_0032eb3c (隐藏状态按钮)
├── FUN_0032ecac (其他处理)
└── FUN_00320000+ (边框/圆角等)

MioPlugin handleButtonLayout（约 300 行）
├── 快速拒绝链（cardBgBeautifyEnabled / VC / MMHeadImageView / 高度）
├── 卡片背景处理（添加/更新 UIImageView）
│   ├── 填充模式、对齐方式、偏移、层级
│   └── 异步加载图片
├── HideCard 分支 (cardBgHidden)
│   ├── clearColor + 清除 m_bgImageView
│   ├── 隐藏全部子视图（排除 bg tag）
│   └── 可选隐藏右侧二维码
├── 非 HideCard 分支（清除原生背景）
├── FIX-WHITE 段（隐藏白色背景层）
├── 高度调整
└── 圆角处理
```

## 四、隐藏效果细节对比

### WCRefine 隐藏的内容

| 隐藏开关 | 隐藏目标 | 方式 |
|---------|---------|------|
| `profileHideEnabled` | 整体资料卡片内容 | 通过关联对象标记后调用子函数处理 |
| `profileHideStateButtonsEnabled` | 状态按钮区域（如"状态"、"朋友圈"等入口） | 通过 FUN_0032eb3c 处理 |
| `profileHideArrowQREnabled` | 右侧箭头和二维码 | 通过 FUN_0032e7f0 处理 |

### MioPlugin 隐藏的内容

| 开关 | 隐藏目标 | 方式 |
|------|---------|------|
| `cardBgHidden` | **全部**子视图（头像/昵称/签名等），但**保留**背景图片 | subview.hidden = YES（排除 kProfileCardBgImageTag） |
| `listHideRightQRCode` | 右侧二维码按钮 | 通过 hideQRButtonInCell 按位置（x > 0.7*width）隐藏 |
| FIX-WHITE（无条件） | 白色背景层、DynamicProvider 背景 | 根据背景色判断并隐藏 |

## 五、优缺点分析

### WCRefine 方案

**优点：**
- 更精细的隐藏控制（总开关、状态按钮、二维码独立开关）
- 好友维度隐藏（hideFriendProfileInfoEnabled / hideFriendWeChatIDEnabled）
- 功能拆分明细，用户可精准控制

**缺点：**
- 实现复杂度高（多个开关的组合逻辑）
- 反编译代码中功能耦合严重（一个函数处理多个 feature toggle）

### MioPlugin 方案

**优点：**
- 简洁：一个隐藏开关搞定，代码清晰易维护
- FIX-WHITE 机制完善，能自动清理微信原生白色背景层
- 与背景美化功能深度集成，背景图不受隐藏影响
- 不 return，继续执行后续处理（圆角、高度调整等）

**缺点：**
- 粒度较粗，无法单独控制隐藏哪些元素
- 缺少好友维度的隐藏控制
- 二维码隐藏需要通过额外开关（listHideRightQRCode）实现

## 八、总结

| 维度 | WCRefine | MioPlugin |
|------|----------|-----------|
| 功能粒度 | 精细（5 个开关） | 粗略（1 个开关） |
| 实现复杂度 | 高（多开关组合） | 低（单开关 + FIX-WHITE） |
| 可维护性 | 低（反编译代码无法直接维护） | 高（原生项目代码） |
| 隐藏后背景保留 | 依赖 profileBgBeautifyEnabled 处理 | ✅ 内置支持（kProfileCardBgImageTag 豁免） |
| 白色背景清理 | ❌ 未发现 | ✅ FIX-WHITE 机制 |
| 隐藏后继续处理 | ✅ 继续 | ✅ 继续 |
| 适用场景 | 需要精细控制的用户 | 简单隐藏，以背景美化为主 |
