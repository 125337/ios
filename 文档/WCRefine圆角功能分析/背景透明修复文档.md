# handleCardHidden 提取后背景透明修复文档

## 问题描述

**场景**：只开启资料卡片美化（`cardBgBeautifyEnabled = YES`），未开启背景素材（`materialEnabled = NO`），未开启隐藏信息卡片（`isHidden = NO`）

**现象**：资料卡上方区域变为透明，可以看到微信底层背景透出

---

## 根因分析

### 代码执行路径对比

对 `beautifyEnabled=YES, material=NO, hidden=NO` 场景：

| 步骤 | 旧代码（refactoring 前） | 新代码（handleCardHidden 提取后） |
|------|------------------------|----------------------------------|
| ① bg 生命周期 | 跳过（有 `if (hasMaterial)` 守卫） | 跳过（同样有守卫） |
| ② button.backgroundColor | 不修改 | 不修改 |
| ③ **清理原生 m_bgImageView** | **执行**（在 non-hide else 分支） | **不执行**（只清 `if (hasMaterial)` 内） |
| ④ FIX-WHITE | 执行（隐藏白色子视图） | 执行（相同） |

**关键差异在第③步**：

```objc
// 旧代码：non-hide branch（位于 else 块）
} else {
    button.hidden = NO;
    if (hasMaterial) {              // hasMaterial=NO → 跳过
        button.backgroundColor = [UIColor clearColor];
    }
    // ★ 无条件执行：清除原生 m_bgImageView ★
    Ivar bgIvar = class_getInstanceVariable([button class], "m_bgImageView");
    ...
}

// 新代码：handleCardHiddenInButton（non-hide 路径）
+ (BOOL)handleCardHiddenInButton:(UIView *)button
                       isHidden:(BOOL)isHidden
                    hasMaterial:(BOOL)hasMaterial {
    if (!isHidden) {
        button.hidden = NO;
        return NO;      // ← 没有任何 bg 清理
    }
    // ... 隐藏态的清理 ...
}
```

### 为什么原生 m_bgImageView 不清理会导致透明？

`m_bgImageView` 是微信 MMUIButton 的原生背景图片视图。分析认为有两种可能机制：

**机制 A**（最可能）：`m_bgImageView` 自身有透明背景 + 内容半透明，叠加在 button.backgroundColor 上制造了视觉上的透明效果。旧代码清除了它，卡面是纯色的；新代码没清除，它的透明部分导致整体变透。

**机制 B**：`m_bgImageView` 在 FIX-WHITE 运行前影响 button.subviews 的布局，导致 FIX-WHITE 误判某些视图不应该隐藏。

无论哪种机制，**修复方向都是：确保 `material=NO` 时也清理原生 m_bgImageView**。

---

## 修复方案

### 方案 A：handleCardHiddenInButton 的 non-hide 路径追加原生 bg 清理（推荐）

```objc
+ (BOOL)handleCardHiddenInButton:(UIView *)button
                       isHidden:(BOOL)isHidden
                    hasMaterial:(BOOL)hasMaterial {
    
    // ══════════════════════════════════════════
    // 非隐藏态：确保可见，清理原生 bg
    // ══════════════════════════════════════════
    if (!isHidden) {
        button.hidden = NO;
        
        // ★ 追加：清理原生 m_bgImageView ★
        // 防止 m_bgImageView 的透明效果透出
        [self clearNativeBgForButton:button];
        
        return NO;
    }
    // ...
```

追加的 `clearNativeBgForButton:` 方法（或内联代码）：

```objc
+ (void)clearNativeBgForButton:(UIView *)button {
    Ivar bgIvar = class_getInstanceVariable([button class], "m_bgImageView");
    if (bgIvar) {
        id bgImgView = object_getIvar(button, bgIvar);
        if (bgImgView && [bgImgView isKindOfClass:[UIImageView class]]) {
            [(UIImageView *)bgImgView setImage:nil];
            [(UIImageView *)bgImgView setBackgroundColor:[UIColor clearColor]];
            [(UIImageView *)bgImgView setHidden:YES];
        }
        object_setIvar(button, bgIvar, nil);
    }
}
```

### 方案 B：在 hasMaterial 块外部也清理原生 bg（更简单）

在 `if (hasMaterial) { }` 块之后、`handleCardHidden` 调用之前，加一段无条件清理原生 bg：

```objc
        }  // if (hasMaterial)

        // ══════════════════════════════════════════
        // ★ 通用清理：无论有无素材，都清除原生 bg
        // ══════════════════════════════════════════
        Ivar bgIvar = class_getInstanceVariable([button class], "m_bgImageView");
        if (bgIvar) {
            id bgImgView = object_getIvar(button, bgIvar);
            if (bgImgView && [bgImgView isKindOfClass:[UIImageView class]]) {
                [(UIImageView *)bgImgView setImage:nil];
                [(UIImageView *)bgImgView setBackgroundColor:[UIColor clearColor]];
                [(UIImageView *)bgImgView setHidden:YES];
            }
            object_setIvar(button, bgIvar, nil);
        }

        // ══════════════════════════════════════════
        // 隐藏信息卡片（独立方法）
        // ══════════════════════════════════════════
        if ([ProfileCardBgHook handleCardHiddenInButton:...]) {
            return;
        }
```

## 方案对比

| 维度 | 方案 A（推荐） | 方案 B |
|------|---------------|--------|
| 改动位置 | `handleCardHiddenInButton` non-hide 分支 | `handleButtonLayout` 主流程 |
| 职责归属 | 清理原生 bg 是隐藏功能的附带职责 | bg 清理放在通用段 |
| 重复代码 | 内置 `clearNativeBgForButton:` 避免重复 | 会和 `if (hasMaterial)` 内代码重复 |
| 代码量 | +10 行（方法 + 调用） | +10 行（内联） |
| 风险 | 低 | 低 |

**推荐方案 A**，因为 `handleCardHiddenInButton` 承担了"非隐藏态"的视觉恢复职责，清理原生 bg 是其中合理的一部分。

修复后，3 个场景都应正确：

| 场景 | beautify | material | hidden | 预期行为 | 验证 |
|------|----------|----------|--------|---------|------|
| 1 | ON | OFF | OFF | 卡面正常显示，上方区域不透明 | **之前出问题，修复后应恢复** |
| 2 | ON | ON | OFF | 背景图正常显示 | 不受影响（`if (hasMaterial)` 内白有清理） |
| 3 | ON | OFF | ON | Scene B 全隐藏 | `handleCardHidden` 隐藏态中自有清理 |
| 4 | ON | ON | ON | Scene A 隐藏内容保留 bg | 同上 |
