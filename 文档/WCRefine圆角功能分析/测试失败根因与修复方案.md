## 二、根因分析

### 2.1 当前入口代码（有问题的代码）

**文件**：[ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L588-L594)

```objc
+ (void)handleButtonLayout:(UIView *)button {
    // ★ 入口守卫：OR 聚合  ← 这是旧的！没改！
    PluginConfig *config = [PluginConfig shared];
    BOOL anyFeatureEnabled = config.cardBgBeautifyEnabled
                          || config.cardBgHidden
                          || config.cardBgCornerEnabled;
    if (!anyFeatureEnabled) return;

    // ... 后续代码 ...
    [ProfileCardBgHook handleHeightAdjustment:button];
    [ProfileCardBgHook handleMarginAdjustment:button];
    [ProfileCardBgHook handleCornerAndQR:button isDark:isDark];
}
```

**这条 OR 守卫是老的，没有被改为总开关单守卫**。对比最终架构文档要求的代码：

```objc
// ★ 应该改为：总开关单守卫
if (!config.cardBgBeautifyEnabled) return;
```

### 2.2 逐测试分析

#### 测试2 失败原因：OR 守卫放行了 corner=ON

**测试2 条件**：`beautify=OFF, hidden=OFF, corner=ON, material=OFF, height=0`

**执行路径**：

```
OR 守卫: beautify=OFF || hidden=OFF || corner=ON = YES → 通过！❌ 不应该通过
  ├─ 场景路由: hidden=NO, material=OFF, corner=ON → handleVisiblePath 被调用
  │   └─ 内部 hasMaterial=OFF → 什么都不做
  ├─ handleHeightAdjustment: targetH=0 → 跳过 ✅
  ├─ handleMarginAdjustment: 内部 !corner=NO → 不跳过（因为 corner=ON）
  │   └─ cardBgCornerMargin 有持久化旧值（如 9）→ margin=9 → 边距生效！❌
  └─ handleCornerAndQR: 内部 corner=ON → 圆角生效
```

**结论**：`beautify=OFF` 时，OR 守卫仍然因为 `corner=ON` 放行了所有代码。`handleMarginAdjustment` 虽然已有 `!cornerEnabled` 内部守卫，但在 `corner=ON` 时这个守卫不拦截，加上 `cardBgCornerMargin` 有持久化旧值，边距最终生效。

#### 测试3 失败原因：OR 守卫放行了 beautify=ON

**测试3 条件**：用户描述"资料卡高度 200 但卡片背景已关闭"

这里需要区分两种情况：

**情况 A**：`cardBgBeautifyEnabled=OFF, height=200`

```
OR 守卫: beautify=OFF || hidden=OFF || corner=OFF = NO → return！
高度不应当生效。
```

如果此时高度仍生效，说明有**其他代码路径**绕过了 `handleButtonLayout`。

**情况 B**：`cardBgBeautifyEnabled=ON, height=200`（用户误解"卡片背景已关闭"）

```
OR 守卫: beautify=ON → 通过
├─ handleHeightAdjustment: targetH=200 → 高度生效 ✅ （这是正确行为）
```

从测试5结果来看，用户确认"总开关开启后高度 300 正常"，说明高度功能本身正常。测试3的"卡片背景已关闭"可能是用户描述歧义。

**如果确认是情况 A**（beautify=OFF 但高度仍生效），则存在严重安全问题——需要排查是否有其他 hook 直接调用了 `handleHeightAdjustment`。

经过代码全量搜索，确认 `handleHeightAdjustment` **仅在** `handleButtonLayout` 中被调用（第 611 行），外部无调用者。所以如无其他路径，`cardBgBeautifyEnabled=OFF` 时高度不应生效。

#### 测试6 失败原因：背景图不显示

**测试6 条件**：`beautify=ON, material=ON, corner=OFF, height=OFF`

```
OR 守卫: beautify=ON → 通过
├─ 场景路由: hidden=NO, material=ON → handleVisiblePath 被调用
│   └─ 内部 hasMaterial=ON → setupBackgroundMaterialInButton 被调用
│       ├─ findBackgroundImageViewInButton → 没有已有 bg（首次）
│       ├─ createBackgroundImageViewInButton → 创建新 bg
│       ├─ loadImageAsyncForImageView → 异步加载图片
│       │   └─ 如果图片加载失败 → 走 fallback 设置背景色
│       └─ cleanNativeBgImageView → 清理原生背景
```

背景图不显示的问题独立于本次架构改动，可能有 3 个原因：

| 原因 | 检查方法 |
|------|---------|
| 图片路径 `cardBgImagePath` 无效或文件不存在 | 检查 NSUserDefaults 中保存的路径 |
| 异步加载失败 `loadImageAsyncForImageView` | 检查日志或模拟器沙盒文件 |
| `createBackgroundImageViewInButton` 图层顺序错（`cardBgLayer`） | 检查 bg 是否被其他 subview 遮挡 |

## 三、修复方案

### 3.1 唯一必须的改动：入口守卫改为总开关单守卫

**文件**：[ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L588-L594)

**当前代码**（旧 OR 守卫）：

```objc
// ★ 入口守卫：OR 聚合
PluginConfig *config = [PluginConfig shared];
BOOL anyFeatureEnabled = config.cardBgBeautifyEnabled
                      || config.cardBgHidden
                      || config.cardBgCornerEnabled;
if (!anyFeatureEnabled) return;
```

**改为**（总开关单守卫）：

```objc
// ★ 第1层：总开关守卫
PluginConfig *config = [PluginConfig shared];
if (!config.cardBgBeautifyEnabled) return;
```

### 3.2 改动后各测试的预期行为

| 测试 | 条件 | OR 守卫（旧） | 单守卫（新） | 结果 |
|------|------|--------------|-------------|------|
| 测试2 | beautify=OFF, corner=ON | beauty=OFF, corner=ON → **放行** ❌ | beautify=OFF → **return** ✅ | 全部不生效 |
| 测试3 | beautify=OFF, height=200 | beauty=OFF, hidden=OFF, corner=OFF → **return** ✅（已正常） | beautify=OFF → **return** ✅ | 一致 |
| 测试1 | beautify=ON, 全OFF | beautify=ON → 场景路由跳过, height/margin 无条件执行 → 部分方法跳过 | beautify=ON → 场景路由跳过, height/margin 无条件执行 | 行为一致 |
| 测试4/5/7 | beautify=ON, 子功能ON | beautify=ON → 全部通过 | beautify=ON → 全部通过 | 行为一致 |

### 3.3 改动后的完整执行路径对比

#### 测试2 修复后（beautify=OFF, corner=ON）

```
旧 OR 守卫: beautify=OFF || hidden=OFF || corner=ON = YES → 放行
  → marginAdjustment 被调用, corner=ON, 持久化 margin=9 → 边距生效 ❌

新单守卫: beautify=OFF → return
  → 整个 handleButtonLayout 不执行, 所有子功能不生效 ✅
```

#### 测试1 修复后（beautify=ON, 全 OFF）

```
旧 OR 守卫: beautify=ON → 放行
  → heightAdjustment: targetH=0 → 跳过
  → marginAdjustment: !corner=OFF → 不跳过... corner=OFF 怎么办？
     → 等一下, 内部守卫是 !cornerEnabled → return, corner=OFF → return ✅ 正确
     
新单守卫: beautify=ON → 放行
  → 后续行为完全一致 ✅
```

其实测试1在两种守卫下行为一致，因为 `handleMarginAdjustment` 已经有 `!cornerEnabled → return` 的内部守卫。

### 3.4 仅改动这一处即可修复测试2和测试3

| 当前问题 | 根因 | 修复方式 | 改动量 |
|---------|------|---------|--------|
| 测试2 总开关OFF, 子功能生效 | OR 守卫未拦截 | 改为单守卫 | **1 行** |
| 测试3 总开关OFF, 高度生效 | OR 守卫未拦截 | 同上（同一行） | **0 行额外改动** |

## 五、常见错误总结

### 错误 1：入口 OR 守卫没有改为单守卫（当前实际存在的错误）

```objc
// ❌ 错：OR 聚合
if (!config.cardBgBeautifyEnabled || !config.cardBgHidden || !config.cardBgCornerEnabled) return;
// 注意 OR 的取反是 De Morgan 定律：!(A || B) = !A && !B
// 上面这行等价于 "只有三个都 OFF 才拦截"——这是错的

// ❌ 错：还是 OR
if (!(config.cardBgBeautifyEnabled || config.cardBgHidden || config.cardBgCornerEnabled)) return;

// ✅ 对：总开关单守卫
if (!config.cardBgBeautifyEnabled) return;
```

### 错误 2：误以为 `handleButtonLayout` 之外还有入口

经搜索确认，`handleButtonLayout` 仅在 `ListCornerRadiusHook.m:125` 被调用，此外没有其他调用者。所有子功能方法（`handleHeightAdjustment`、`handleMarginAdjustment` 等）也仅在此被调用。所以**只要入口守卫正确，所有子功能都会被正确地拦截或放行**。

## 六、测试6补充说明：背景图不显示

背景图不显示**不是本次架构改动导致的问题**，而是独立的功能 bug。建议在入口守卫修复并验证通过后，单独排查：

1. 检查 `cardBgImagePath` 是否保存了正确的文件路径
2. 检查 `loadBackgroundImageSync` 是否返回 nil
3. 检查 `createBackgroundImageViewInButton` 中 `cardBgLayer` 的图层顺序
