# 隐藏信息卡片联合背景素材改造文档

## 问题回顾

当前「隐藏信息卡片」（`cardBgHidden = YES`）时，背景图因 `kProfileCardBgImageTag` 豁免而始终残留。且 `needsNewCardBg` 在 HideCard 分支之前运行，导致背景图已被创建，然后又因为豁免而不被隐藏。

## 改造目标

根据是否开启了「使用背景素材」（`cardBgMaterialEnabled`），区分两种行为：

| 场景 | 隐藏信息卡片 | 使用背景素材 | 期望行为 |
|------|------------|------------|---------|
| A | ON | ON | 隐藏内容（头像、昵称、按钮等），**保留背景图** |
| B | ON | OFF | 隐藏所有内容，**连背景图也隐藏** |

---

## 执行顺序改造

### 改造前（当前）

```
① needsNewCardBg（始终创建 bg，只要 cardBgBeautifyEnabled = YES）
    ├─ 分支 A：bg 已存在 → 更新 frame
    └─ 分支 B：bg 不存在 → 创建新 bg + 异步加载图片
② HideCard（隐藏内容，但通过 tag 豁免 bg）
   └─ bg 被豁免 → 残留
③ FIX-WHITE（清理白色视图，也豁免 bg）
```

### 改造后

```
① 判断是否需要创建 bg
   条件：cardBgBeautifyEnabled && !(cardBgHidden && !cardBgMaterialEnabled)
   即：开启了美化，且（没开启隐藏 / 或者开启了隐藏但开启了素材）
   ↓
② needsNewCardBg（仅在①为 YES 时执行）
   ├─ 分支 A：bg 已存在 → 更新 frame
   └─ 分支 B：bg 不存在 → 创建新 bg + 异步加载图片
   ↓
③ HideCard（隐藏内容）
   ├─ 场景 A（hidden=YES, material=YES）→ 保留 bg（当前行为不变）
   └─ 场景 B（hidden=YES, material=NO）→ bg 已在①被跳过，无需处理
   ↓
④ FIX-WHITE（清理白色视图）
   ├─ 场景 A → 跳过 bg（当前行为不变）
   └─ 场景 B → bg 不存在，无需特殊处理
```

## 改动清单

### 改动 1：needsNewCardBg 守卫条件

**[ProfileCardBgHook.m:411](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L411)**

```objc
// 改前：
BOOL needsNewCardBg = config.cardBgBeautifyEnabled;

// 改后：
BOOL needsNewCardBg = config.cardBgBeautifyEnabled
    && !(config.cardBgHidden && !config.cardBgMaterialEnabled);
```

**条件表：**

| cardBgBeautifyEnabled | cardBgHidden | cardBgMaterialEnabled | needsNewCardBg | 场景 |
|----------------------|-------------|----------------------|----------------|------|
| NO | — | — | NO | 无效 |
| YES | NO | NO | YES | 正常使用 bg |
| YES | NO | YES | YES | 正常使用 bg |
| YES | YES | NO | NO | 场景 B：跳过 bg 创建 |
| YES | YES | YES | YES | 场景 A：创建 bg（用于隐藏时保留） |

---

### 改动 2：HideCard 分支 — 删除 bg 豁免

**[ProfileCardBgHook.m:572-579](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L572-L579)**

```objc
// 改前：
// ★ 选择性隐藏子视图（bg 通过 tag 豁免）
for (UIView *sub in button.subviews) {
    if ([sub isKindOfClass:[UIImageView class]] &&
        sub.tag == kProfileCardBgImageTag) {
        continue;
    }
    sub.hidden = YES;
}

// 改后：
// ★ 隐藏全部子视图（场景 A 中 bg 已在 needsNewCardBg 阶段创建好，不隐藏）
// ★ 场景 B 中 bg 未被创建，不需要额外处理
for (UIView *sub in button.subviews) {
    if ([sub isKindOfClass:[UIImageView class]] &&
        sub.tag == kProfileCardBgImageTag) {
        if (config.cardBgMaterialEnabled) {
            continue;  // 场景 A：有背景素材 → 保留背景图
        }
        // 场景 B：无背景素材 → bg 不存在（needsNewCardBg 已跳过），不会走到这里
    }
    sub.hidden = YES;
}
```

> 实际上在场景 B 中，needsNewCardBg 已被跳过，子视图中不存在 `kProfileCardBgImageTag` 的 view，所以 HideCard 分支中的 bg 豁免逻辑永远不会触发。但保留 `cardBgMaterialEnabled` 判断作为**防御性编程**，防止未来代码顺序变化导致问题。

## 与 WCRefine 方案对比

```
WCRefine 策略：
  HideCard ON → 跳过背景美化函数执行（不加载背景图）
  → 在源头阻止背景图创建

MioPlugin 改造后策略：
  HideCard ON + Material OFF → needsNewCardBg 为 NO（不创建背景图）
  HideCard ON + Material ON  → needsNewCardBg 为 YES（创建背景图，但不隐藏）
  → 通过守卫条件在源头控制背景图创建
```

两种方案本质相同：**隐藏卡片时，从源头阻止无意义的背景图创建**。MioPlugin 改造后多了一层素材开关的判断，在用户有背景素材时保留背景图展示。

## 不做方案

不考虑的方案及原因：

| 方案 | 放弃原因 |
|------|---------|
| 在 HideCard 中 `removeFromSuperview` bg | 每次 layout 都会重新创建→移除，浪费性能 |
| 新增单独配置属性控制隐藏 bg | 增加复杂度，用户体验不直观 |
| 统一设计为隐藏时始终保留 bg | 场景 B 中无意义的背景图残留不符合预期 |
