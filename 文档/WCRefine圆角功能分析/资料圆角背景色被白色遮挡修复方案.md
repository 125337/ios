# 资料圆角 + 卡片背景颜色被原生白色遮挡 修复方案

## 问题描述

开启「开启资料圆角」（`cardBgCornerEnabled=YES`）并设置了「卡片背景颜色」（`cardBgCornerBgColor`），但用户看到的仍然是白色背景，设置的背景色没生效。

## 根因分析

### 执行链路

当 `cardBgCornerEnabled=YES`、`cardBgMaterialEnabled=NO` 时，执行顺序如下：

```
handleButtonLayout: (L664)
  └─ handleVisiblePath: (L815)  ← hasMaterial=NO → else 分支
       └─ 什么也不做
           保持原生状态
  └─ handleCornerAndQR: → applyProfileCardCorner: (L48)
       └─ cell.backgroundColor = cardBgCornerBgColor  ← 设背景色
       └─ cell.layer.cornerRadius = radius
       └─ cell.layer.masksToBounds = YES
```

### 问题位置

**问题文件**：[ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m)

**问题 1** — `handleVisiblePath:` 无素材分支（L858-L864）：

```objc
} else {
    // ══════════════════════════════════════════
    // 无素材：不做任何背景操作
    // 不动 button.backgroundColor，保持原生导航栏白色
    // 不动 m_bgImageView，避免破坏昵称显示导致"微信用户"
    // ══════════════════════════════════════════
}
```

当没有背景素材时，微信原生的白色 `m_bgImageView` 没有被清理。

**问题 2** — `applyProfileCardCorner:`（L48）虽然设置了 `cell.backgroundColor = cardBgCornerBgColor`，但这个颜色是设在 **button 自身**上的。而 button 内部的子视图 `m_bgImageView`（微信原生的白色背景 UIImageView）**覆盖在 button 背景色之上**，导致用户看到的还是白色。

### 视觉层次

```
┌─ MMUIButton (backgroundColor = 用户设置的颜色) ─┐
│                                                 │
│  ┌─ m_bgImageView (backgroundColor = 白色) ──┐  │  ← 这层盖住了 button 背景色
│  │                                            │  │
│  │  ┌─ 头像/昵称/状态等 ─────────────────┐   │  │
│  │  │                                    │   │  │
│  │  └────────────────────────────────────┘   │  │
│  └────────────────────────────────────────────┘  │
│                                                 │
└─────────────────────────────────────────────────┘
```

### 为什么有素材路径没这个问题？

有素材路径（`hasMaterial=YES`）在 [L840-L842](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L840-L842) 调用了 `cleanNativeBgImageView:`：

```objc
if (hasImagePath) {
    [ProfileCardBgHook cleanNativeBgImageView:button];
}
```

该方法将 `m_bgImageView` 的 image 置 nil、backgroundColor 设 clearColor、hidden 设 YES，从而移除了白色遮挡。

---

## 修复方案

### 改动 1：`handleVisiblePath:` 无素材分支 — 清理原生背景

在 `handleVisiblePath:` 的 else 分支中，当 `cardBgCornerEnabled=YES` 时调用 `cleanNativeBgImageView:`：

```objc
// 改前（L858-L864）：
} else {
    // ══════════════════════════════════════════
    // 无素材：不做任何背景操作
    // 不动 button.backgroundColor，保持原生导航栏白色
    // 不动 m_bgImageView，避免破坏昵称显示导致"微信用户"
    // ══════════════════════════════════════════
}

// 改后：
} else {
    // ══════════════════════════════════════════
    // 无素材 + 有圆角：清理原生白色背景，让 applyProfileCardCorner 设置的背景色透出
    // ══════════════════════════════════════════
    if (config.cardBgCornerEnabled) {
        [ProfileCardBgHook cleanNativeBgImageView:button];
    }
}
```

### 改动 2（可选）：`applyProfileCardCorner:` 中加强背景色设置

确保在设置 `cell.backgroundColor` 之前先清除 `m_bgImageView`，防止时序问题。

在 [applyProfileCardCorner:](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L48) 中，设置 cell.backgroundColor 之前添加清理：

```objc
// 改前（在设置 backgroundColor 之前，约 L60/L86）：
// （无清理）

// 改后：
// ★ 清理原生白色背景，让设置的背景色透出
[ProfileCardBgHook cleanNativeBgImageView:cell];
// 继续现有逻辑...
cell.layer.cornerRadius = radius;
cell.layer.masksToBounds = YES;
cell.backgroundColor = bgColor;
```

> 方案对比：
> - **改动 1（推荐）**：只改一处，与现有代码风格一致，改动最小
> - **改动 2**：在 `applyProfileCardCorner:` 中统一清理，覆盖路径更全（包括 `handleHiddenPath:` 中已清理，此处重复清理无副作用）

## 安全性说明

`cleanNativeBgImageView:` 的内部实现（L441-L452）：

```objc
+ (void)cleanNativeBgImageView:(UIView *)button {
    Ivar bgIvar = class_getInstanceVariable([button class], "m_bgImageView");
    if (!bgIvar) return;
    id bgImgView = object_getIvar(button, bgIvar);
    if (bgImgView && [bgImgView isKindOfClass:[UIImageView class]]) {
        [(UIImageView *)bgImgView setImage:nil];
        [(UIImageView *)bgImgView setBackgroundColor:[UIColor clearColor]];
        [(UIImageView *)bgImgView setHidden:YES];
    }
    // ★ 保留 ivar：不清 nil，只清内容（防止"微信用户"bug）
}
```

该方法：
- **不会**将 ivar 置 nil（已通过注释确认不会引发"微信用户"bug）
- 只清内容（image、backgroundColor、hidden），不释放对象
- 在素材路径（`hasMaterial=YES && hasImagePath=YES`）已经使用，无已知问题
