# 隐藏信息卡片时消除残留背景图 实现文档

## 问题描述

当开启「隐藏信息卡片」（`cardBgHidden = YES`）时，MioPlugin 添加的背景图片仍然显示在资料卡片上，未被隐藏。

**预期行为**：隐藏信息卡片应隐藏所有装饰性内容（包括背景图），只保留必要 UI 或呈现完全空白的效果。

---

## 根因分析

### 问题位置 1：HideCard 分支（显式豁免）

[ProfileCardBgHook.m:572-579](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L572-L579)

```objc
// ★ 选择性隐藏子视图（bg 通过 tag 豁免）
for (UIView *sub in button.subviews) {
    if ([sub isKindOfClass:[UIImageView class]] &&
        sub.tag == kProfileCardBgImageTag) {
        continue;  // ← 背景图被跳过，不会被隐藏
    }
    sub.hidden = YES;
}
```

### 问题位置 2：FIX-WHITE 段（同样豁免）

[ProfileCardBgHook.m:614](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L614)

```objc
if (sub.tag == kProfileCardBgImageTag) continue;  // ← FIX-WHITE 也跳过背景图
```

### 执行时序

```
needsNewCardBg 块（行 416-548）
  └─ 创建/更新背景图（tag = kProfileCardBgImageTag = 999902）
      ↓
HideCard 分支（行 554-586）
  └─ 隐藏全部子视图 ... 但 ⚠️ 跳过背景图
      ↓
FIX-WHITE 段（行 610-650）
  └─ 隐藏白色视图 ... 但 ⚠️ 也跳过背景图
```

背景图在 `needsNewCardBg` 块中创建后，后续两个隐藏逻辑都将其豁免，导致背景图始终可见。

## WCRefine 的处理方式

WCRefine 的反编译代码（FUN_0032b0d0）采用不同的架构：

| 维度 | WCRefine | MioPlugin |
|------|----------|-----------|
| **背景美化与隐藏的关系** | **独立**：profileBgBeautifyEnabled 和 profileHideEnabled 是平级的 feature toggle | **耦合**：cardBgHidden 嵌套在 cardBgBeautifyEnabled 内部 |
| **背景图豁免** | **无豁免机制**：背景美化走独立函数路径，隐藏不干预 | **有豁免**：通过 kProfileCardBgImageTag 显式跳过 |
| **隐藏范围** | 通过 profileHideStateButtonsEnabled / profileHideArrowQREnabled 分别控制 | 一个 cardBgHidden 控制全局 |

WCRefine 没有"隐藏时保留背景图"的设计意图，其隐藏功能和背景美化是完全独立的两个功能模块。

## 改动方案

### 方案 A（推荐）：HideCard 时移除背景图

在 HideCard 分支中，除了隐藏子视图，同时移除背景图 imageView。

#### 改动 1：HideCard 分支 — 移除背景图

**[ProfileCardBgHook.m:572-579](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L572-L579)**

```objc
// 改前：
// ★ 选择性隐藏子视图（bg 通过 tag 豁免）
for (UIView *sub in button.subviews) {
    if ([sub isKindOfClass:[UIImageView class]] &&
        sub.tag == kProfileCardBgImageTag) {
        continue;
    }
    sub.hidden = YES;
}

// 改后：
// ★ 隐藏全部子视图（包括背景图）
// ★ 背景图需要从父视图移除而非仅 hidden，否则下次 layout 会重新显示
for (UIView *sub in button.subviews) {
    if (sub.tag == kProfileCardBgImageTag) {
        [sub removeFromSuperview];  // 彻底移除背景图
        continue;
    }
    sub.hidden = YES;
}
```

#### 改动 2：FIX-WHITE 段 — 同样移除背景图

**[ProfileCardBgHook.m:614](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m#L614)**

```objc
// 改前：
if (sub.tag == kProfileCardBgImageTag) continue;  // 跳过 bg

// 改后：
if (sub.tag == kProfileCardBgImageTag) {
    [sub removeFromSuperview];  // 从父视图移除
    continue;
}
```

> **为什么用 removeFromSuperview 而不是 sub.hidden = YES？**
>
> 因为 `needsNewCardBg` 块（行 416-548）**在** HideCard 分支之前执行。如果仅设 hidden=YES，下次 `handleButtonLayout` 触发时，`needsNewCardBg` 块会找到已有 bg（分支 A），更新它的 frame 并将它设为不隐藏。只有彻底 removeFromSuperview 才能让下次 `needsNewCardBg` 块走分支 B（重新创建），这样当用户关闭 hide 后背景图也能正确恢复。

---

### 方案 B（可选）：添加独立开关控制

如果希望保留"隐藏卡片时保留背景图"的选项，可以新增一个配置属性：

```objc
// PluginConfig.h
@property (nonatomic, assign) BOOL cardBgHiddenKeepBg;  // 隐藏时保留背景图
```

```objc
// ProfileCardBgHook.m HideCard 分支
for (UIView *sub in button.subviews) {
    if ([sub isKindOfClass:[UIImageView class]] &&
        sub.tag == kProfileCardBgImageTag) {
        if (config.cardBgHiddenKeepBg) continue;  // 用户选择保留
        [sub removeFromSuperview];                 // 否则移除
        continue;
    }
    sub.hidden = YES;
}
```

> 此方案增加复杂度，除非有明确需求，否则推荐方案 A。

## 执行效果

| 操作 | 改前 | 改后 |
|------|------|------|
| 开启隐藏信息卡片 | 背景图残留可见 | 背景图完全消失 |
| 关闭隐藏信息卡片 | 背景图显示（正常） | 背景图自动重建显示（因 removeFromSuperview 后走分支 B） |
| 关闭资料卡片美化总开关 | 不生效 | 不生效（行为不变） |
| 重新打开后台再进入 | 背景图可能重新出现（依赖布局触发） | 正确根据 cardBgHidden 状态隐藏/显示 |

## 恢复逻辑说明

因为 `handleButtonLayout` 每次触发时都会执行：

```
1. needsNewCardBg → 尝试查找或创建背景图
   - 如果 bg 已被 removeFromSuperview → 走分支 B（创建新的）
2. HideCard 分支 → 如果 cardBgHidden=NO → 走 else 分支（保留背景图）
3. FIX-WHITE → 不处理背景图
```

所以当用户关闭 `cardBgHidden` 后，背景图会在下一次 `handleButtonLayout` 触发时自动重建，无需额外逻辑。

## 与 WCRefine 方案对比

```
WCRefine 方案：
  profileBgBeautifyEnabled ─→ 背景美化（独立路径）
  profileHideEnabled       ─→ 隐藏处理（独立路径，不干预背景）
  → 背景和隐藏互不干扰，隐藏时不涉及"豁免"概念

MioPlugin 方案（改后）：
  cardBgBeautifyEnabled → needsNewCardBg（创建背景图）
                         → cardBgHidden ? hide all（含背景图）: show all
  → 背景图随隐藏开关联动，更符合"隐藏信息卡片"的用户预期
```

方案 A 改动后，MioPlugin 的行为更接近用户对"隐藏"的直观理解：隐藏所有装饰性内容，包括背景图。
