# 隐藏信息卡片功能迁移

> 将「隐藏信息卡片」的实际效果从旧 UI 的 `cardBgEnabled` 总开关下，迁移到新 UI 的 `cardBgBeautifyEnabled` 总开关下。

---

## 一、现状分析

### UI 层（SettingCardBackgroundController.m）

| 旧 UI | 新 UI |
|-------|-------|
| `cardBgEnabled → subBuilder → 14 项（含 cardBgHidden）` | `cardBgBeautifyEnabled → subBuilder → 3 项（含 cardBgHidden）` |
| cardBgHidden 藏在旧主开关内 | cardBgHidden 在新主开关内平铺 |

**两个 UI 的 cardBgHidden 共用同一个 Config key**，存取值一致，不存在数据不同步的问题。

### Hook 层（ProfileCardBgHook.m）

```
handleButtonLayout:
  │
  ├── 364: 守卫 → cardBgEnabled 为 NO 就 return ← 问题在这
  │
  └── if (cardBgEnabled) {         ← 旧 UI 总开关
        ├── 背景图加载
        ├── if (cardBgHidden) {    ← 隐藏信息卡片
        │     clearColor、隐藏子视图...
        │   }
        └── FIX-WHITE
      }
```

**问题**：新 UI 开启 `cardBgBeautifyEnabled` + `cardBgHidden` 时，Hook 的守卫（364 行）会直接 return，根本走不到 `cardBgHidden` 的判断。

---

## 二、改动方案

### 改动 1：Hook 守卫 — 允许新总开关进入

**文件**：`ProfileCardBgHook.m:364`

```diff
-    if (!config.cardBgEnabled && !config.globalCornerRadiusEnabled) return;
+    if (!config.cardBgEnabled && !config.cardBgBeautifyEnabled && !config.globalCornerRadiusEnabled) return;
```

这样新总开关开启时，`handleButtonLayout` 也能执行后续逻辑。

### 改动 2：Hook — 新增「新 UI 隐藏信息卡片」代码块

**文件**：`ProfileCardBgHook.m`，在 `} // end needsFullCardBg`（第 642 行）之后，高度调整代码（第 644 行）**之前**插入。

```objc
    // ══════════════════════════════════════════
    // ★ 新 UI：隐藏信息卡片（旧 UI 不开时才执行，避免重复）
    // ══════════════════════════════════════════
    if (config.cardBgBeautifyEnabled && !config.cardBgEnabled) {
        if (config.cardBgHidden) {
            button.backgroundColor = [UIColor clearColor];
            button.layer.backgroundColor = [UIColor clearColor].CGColor;
            button.layer.masksToBounds = NO;
            button.layer.cornerRadius = 0;
            button.layer.borderWidth = 0;

            Ivar bgIvar = class_getInstanceVariable([button class], "m_bgImageView");
            if (bgIvar) {
                id bgImgView = object_getIvar(button, bgIvar);
                if (bgImgView && [bgImgView isKindOfClass:[UIImageView class]]) {
                    [(UIImageView *)bgImgView setImage:nil];
                    [(UIImageView *)bgImgView setBackgroundColor:[UIColor clearColor]];
                    [(UIImageView *)bgImgView setHidden:YES];
                }
                object_setIvar(button, bgIvar, nil);
            }

            for (UIView *sub in button.subviews) {
                if ([sub isKindOfClass:[UIImageView class]] &&
                    sub.tag == kProfileCardBgImageTag) {
                    continue;
                }
                sub.hidden = YES;
            }
        }
    }
```

> `!config.cardBgEnabled` 确保与旧 UI 不冲突。旧 UI 开着时，还是走旧的 `needsFullCardBg` 里的隐藏逻辑；旧 UI 关着时，才走这个新块。

### 改动 3：UI — switchChanged 触发 buildUI（可选，推荐加）

**文件**：`SettingCardBackgroundController.m`

在已有 switchChanged 中（或新增），加上新 UI 开关的 buildUI 触发，让手风琴正确折叠/展开：

```objc
// 在 switchChanged 或 viewWillAppear 中
// 如果基类已自动 handle 了手风琴折叠，则不需加
// 如果发现新 UI 的子手风琴展开/折叠不灵，加这句：
[self buildUI];
```

> 实际上 `addMasterSwitchRowInGroup:subBuilder:` 的基类实现已自动处理折叠展开，一般不需要额外加 buildUI。但如果测试发现问题再补。
