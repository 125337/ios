# 全局圆角与资料卡圆角责任划分修复文档

> **现象**：开启全局圆角所有页面开关后，其他三个页面（主页、联系人、发现）的普通 Cell 有效果，但"我的页面"（MoreViewController）的普通 Cell 无圆角，资料卡反而有圆角。
>
> **根因**：`CornerResponsibility` 将 `MoreViewController` 全部分配给 `kCornerModuleProfileCard`，导致两个问题同时出现。

---

## 一、问题分析

### 1.1 两段独立执行路径

```
全局圆角开启后，MoreViewController 中有两条独立的代码路径：

路径 A: MMTableViewCell::layoutSubviews → replaced_MMTableViewCell_layoutSubviews
  用于给所有列表 Cell 应用圆角 + 边距
  → CornerResponsibility 判断 → MoreVC = kCornerModuleProfileCard → 跳过 ❌
  → 普通 Cell 无圆角

路径 B: MMUIButton::layoutSubviews → replaced_MMUIButton_layoutSubviews
  → ProfileCardBgHook handleButtonLayout:
  → 入口守卫: !cardBgBeautifyEnabled && !globalCornerRadiusEnabled
  → globalCornerRadiusEnabled = YES → 放行 ✅
  → DO_CORNER → 对资料卡应用圆角（即使 cardBgCornerEnabled = NO）
  → 资料卡有圆角 ❌（不应有）
```

### 1.2 根因 1：CornerResponsibility 归责过粗

[CornerResponsibility.m](file:///www/wwwroot/ios/MioPlugin/Modules/CornerResponsibility/CornerResponsibility.m) 第12-14行：

```objc
static NSString *const kProfileCardVCs[] = {
    @"MoreViewController",
};
```

`moduleForViewController:` 对 MoreViewController 返回 `kCornerModuleProfileCard`。

然后在 [ListCornerRadiusHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ListCornerRadius/ListCornerRadiusHook.m) 第163行：

```objc
if (![CornerResponsibility isListCornerResponsibleFor:vc]) {
    // ... 直接 return
    return;
}
```

**后果**：MoreViewController 下的 **所有 MMTableViewCell**（包括普通列表 Cell）都被跳过，全局圆角对它们不生效。

### 1.3 根因 2：handleButtonLayout 入口守卫不当

[ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m) 第385行：

```objc
if (!config.cardBgBeautifyEnabled && !config.globalCornerRadiusEnabled) return;
```

这个守卫是 **或逻辑**，`cardBgBeautifyEnabled` 或 `globalCornerRadiusEnabled` 任一为 YES 就放行。

当 `globalCornerRadiusEnabled = YES` 时：
- 函数进入 → 检查 VC 类型 → 检查 MMHeadImageView → 高度过滤 → **全部通过**
- `needsNewCardBg = NO`（因为 `cardBgBeautifyEnabled = NO`）→ 跳过背景图段高度调整段
- `targetH(=0) <= 0` → `goto DO_CORNER`
- `DO_CORNER` → 调用 `applyProfileCardCorner:` → 即使 `cardBgCornerEnabled = NO`，函数也走到了这里

虽然 `applyProfileCardCorner:` 内部会检查 `cardBgCornerEnabled` 并清除圆角，但**从责任划分角度**，`handleButtonLayout:` 根本不应该在 `cardBgBeautifyEnabled = NO` 时进入资料卡圆角处理逻辑。

### 1.4 责任划分问题总结

| 代码位置 | 现有行为 | 问题 |
|---------|---------|------|
| CornerResponsibility | MoreVC → `kCornerModuleProfileCard` | 列表 Cell 全部被跳过的根源 |
| handleButtonLayout 入口守卫 | `!A && !B` → A 或 B 任一开启就放行 | 全局圆角错误地触发了资料卡处理 |
| DO_CORNER | 无前置条件，直接调用 | 应仅在 `cardBgCornerEnabled` 时执行 |

---

## 二、修复方案

### 2.1 修复 CornerResponsibility

**目标**：MoreViewController 的列表 Cell 应该能正常接收全局圆角，不应被归为 `kCornerModuleProfileCard`。

修改 [CornerResponsibility.m](file:///www/wwwroot/ios/MioPlugin/Modules/CornerResponsibility/CornerResponsibility.m) 第12-14行：

```objc
// 改前：
static NSString *const kProfileCardVCs[] = {
    @"MoreViewController",
};

// 改后：
static NSString *const kProfileCardVCs[] = {
    // ★ MoreViewController 不再归为资料卡模块，
    //   它的列表 Cell 应由列表圆角模块处理。
    //   资料卡的识别在 handleButtonLayout 中通过
    //   MMHeadImageView 子视图检查 + VC 类型检查完成。
};
```

**移除后**：
- MoreViewController 走 `moduleForViewController:` 的默认分支 → `kCornerModuleList`
- `isListCornerResponsibleFor:` 返回 YES
- `replaced_MMTableViewCell_layoutSubviews` 不再跳过 MoreVC 的 Cell
- 普通 Cell 正确获得全局圆角 ✅

**注意**：此处不需要担心列表圆角代码"误伤"资料卡，因为列表圆角代码作用于 `MMTableViewCell`，而资料卡是 `MMUIButton`，两者不同。

### 2.2 修复 handleButtonLayout 入口守卫

**目标**：资料卡的处理应只由 `cardBgBeautifyEnabled` 控制，不应由全局圆角触发。

修改 [ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m) 第384-385行：

```objc
// 改前：
PluginConfig *config = [PluginConfig shared];
// ★ 极速拒绝链 ★
if (!config.cardBgBeautifyEnabled && !config.globalCornerRadiusEnabled) return;

// 改后：
PluginConfig *config = [PluginConfig shared];
// ★ 极速拒绝链 ★
if (!config.cardBgBeautifyEnabled) return;
```

**改动效果**：
- `cardBgBeautifyEnabled = NO` 时：整个函数直接返回，不处理任何资料卡相关内容 ✅
- `cardBgBeautifyEnabled = YES` 时：进入函数，正常处理背景图、圆角、边距等 ✅
- 全局圆角不再能触发资料卡处理 ✅

### 2.3 修复 DO_CORNER 段（双重保险）

**目标**：即使入口守卫有遗漏，DO_CORNER 也只应在 `cardBgCornerEnabled` 时执行。

修改 [ProfileCardBgHook.m](file:///www/wwwroot/ios/MioPlugin/Modules/ProfileCardBg/ProfileCardBgHook.m) 第723-732行：

```objc
// 改前：
DO_CORNER:

    // ── 圆角 + 边框 + QR码隐藏 ──
    {
        [ProfileCardBgHook applyProfileCardCorner:button isDark:isDark];

        if (config.listHideRightQRCode) {
            [ProfileCardBgHook hideQRButtonInCell:button];
        }
    }

// 改后：
DO_CORNER:

    // ── 圆角 + 边框 + QR码隐藏 ──
    {
        // ★ 仅在"开启资料圆角"时才处理资料卡圆角和边距 ★
        if (config.cardBgCornerEnabled) {
            [ProfileCardBgHook applyProfileCardCorner:button isDark:isDark];
        }

        if (config.listHideRightQRCode) {
            [ProfileCardBgHook hideQRButtonInCell:button];
        }
    }
```

## 四、修复后的执行路径

### 场景：全局圆角 ON，资料卡片美化 OFF，资料圆角 OFF

```
全局圆角开启（globalCornerRadiusEnabled=YES, cardBgBeautifyEnabled=NO, cardBgCornerEnabled=NO）

路径 A（列表 Cell）:
  → MMTableViewCell::layoutSubviews
  → shouldApplyGlobalCorner(MoreVC) → YES
  → CornerResponsibility: MoreVC → kCornerModuleList ✅（修复后）
  → 应用全局圆角 + 边距
  → 普通 Cell 有圆角 ✅

路径 B（资料卡）:
  → MMUIButton::layoutSubviews
  → handleButtonLayout:
  → 入口守卫: cardBgBeautifyEnabled = NO → 直接 return ✅（修复后）
  → 不处理资料卡任何内容
  → 资料卡无圆角 ✅
```

### 场景：全局圆角 OFF，资料卡片美化 ON，资料圆角 ON

```
资料卡美化开启（globalCornerRadiusEnabled=NO, cardBgBeautifyEnabled=YES, cardBgCornerEnabled=YES）

路径 A（列表 Cell）:
  → MMTableViewCell::layoutSubviews
  → globalCornerRadiusEnabled = NO → 直接 return
  → 列表 Cell 无圆角 ✅

路径 B（资料卡）:
  → MMUIButton::layoutSubviews
  → handleButtonLayout:
  → 入口守卫: cardBgBeautifyEnabled = YES → 通过
  → 处理背景图、高度调整等
  → DO_CORNER: cardBgCornerEnabled = YES → 应用圆角 + 边距
  → 资料卡有圆角 ✅
```

### 场景：全局圆角 ON，资料卡片美化 ON，资料圆角 OFF

```
都开启但资料圆角关闭（globalCornerRadiusEnabled=YES, cardBgBeautifyEnabled=YES, cardBgCornerEnabled=NO）

路径 A（列表 Cell）:
  → MMTableViewCell::layoutSubviews
  → 应用全局圆角 ✅

路径 B（资料卡）:
  → MMUIButton::layoutSubviews
  → handleButtonLayout: 入口通过
  → 处理背景图（cardBgBeautifyEnabled = YES）
  → DO_CORNER: cardBgCornerEnabled = NO → 不应用圆角
  → 资料卡无圆角 ✅
```

## 五、原则总结

| 原则 | 说明 |
|------|------|
| **全局圆角 → 仅列表 Cell** | 全局圆角的四个开关（主页/我的/联系人/发现）只控制对应页面的列表 Cell 圆角，不涉及资料卡 |
| **资料卡圆角 → 仅卡片背景** | 资料卡的圆角和边距仅由"卡片背景"设置页面的"开启资料圆角"控制 |
| **CornerResponsibility 只管入口分发** | MoreViewController 应被分发到列表圆角模块，资料卡的区分通过 MMHeadImageView 子视图检测完成 |
| **功能独立性** | 卡片背景美化（背景图）和资料卡圆角可以独立开启，互不依赖 |
