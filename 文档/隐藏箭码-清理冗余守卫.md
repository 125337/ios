# 隐藏箭码 — 清理冗余守卫操作文档

> **背景：** `handleArrowQRHiding:` 内的 3 道守卫与 `handleButtonLayout:` 内的 3 道守卫**完全重复**。清理后不影响功能，减少冗余判断。

---

## 确认重复

### 当前执行顺序

```
replaced_MMUIButton_layoutSubviews (ListCornerRadiusHook L118)
  ├── ① 原始 layoutSubviews
  ├── ② handleArrowQRHiding:        ← L125 独立调用
  │   ├── findMoreViewController:  ← 第 1 次
  │   ├── hasHeadImageViewInView:  ← 第 1 次
  │   └── height <= 50.0 check     ← 第 1 次
  └── ③ handleButtonLayout:        ← L128
      ├── hideStateElementsInCell:
      ├── cardBgBeautifyEnabled guard
      ├── findMoreViewController:  ← 第 2 次（重复）
      ├── hasHeadImageViewInView:  ← 第 2 次（重复）
      └── height <= 50.0 check     ← 第 2 次（重复）
```

### 三份代码完全相同

**handleArrowQRHiding 内（L757-760）：**
```objc
UIViewController *vc = [self findMoreViewController:button];
if (!vc) return;
if (![self hasHeadImageViewInView:button]) return;
if (button.frame.size.height <= 50.0) return;
```

**handleButtonLayout 内（L664-667）：**
```objc
UIViewController *vc = [ProfileCardBgHook findMoreViewController:button];
if (!vc) return;
if (![ProfileCardBgHook hasHeadImageViewInView:button]) return;
if (button.frame.size.height <= 50.0) return;
```

**结论：** 完全重复，代码一模一样。`handleArrowQRHiding` 跑的守卫，接下来 `handleButtonLayout` 还要再跑一遍一模一样的。是**100% 冗余**。

## 为什么是冗余

| 问题 | 答案 |
|------|------|
| 不删会怎么样？ | 多做 3 次判断，浪费约 0.006μs，不影响功能，只是代码冗余 |
| 删了会怎么样？ | `handleButtonLayout` 会做一遍同样的守卫，完全不影响功能 |
| 会不会漏判？ | 不会。不满足守卫条件时，`handleButtonLayout` 直接 `return`，代码路径正常终止 |
