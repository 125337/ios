## 二、架构设计

### 2.1 数据流

```
┌─────────────────────────────────┐
│  WPUISimplifyVC (编辑入口)       │
│  onEditRowTap: → UIAlertController│
│  "确定" → valueLabel.text 更新   │
│         → NSUserDefaults 持久化  │
└───────────┬─────────────────────┘
            │ NSUserDefaults
            │ SimplifyEnabled (BOOL)
            │ Simplify_MainTitle (NSString)
            │ Simplify_ContactsTitle (NSString)
            │ Simplify_DiscoverTitle (NSString)
            │ Simplify_FriendsCount (NSString)
            │ Simplify_MenuNames (NSDictionary)
            │ Simplify_Tab_Names (NSDictionary)
            ▼
┌─────────────────────────────────┐
│  UISimplifyHook +install         │
│  ① UISimplify_ReloadConfig()    │  ← 启动时从 NSUserDefaults 读入静态变量
│  ② 检测老版本插件               │  ← objc_getClass("CSWCEnhanceViewController")
│  ③ MSHookMessageEx ×9 (或×6)   │  ← 老版本存在时跳过策略B的3个Hook
└───────────┬─────────────────────┘
            │
     ┌──────┼──────┐
     ▼      ▼      ▼
  策略A ×6      策略B ×3
  字典查表      上下文匹配
  (始终安装)    (条件安装)
```

### 2.2 两层缓存避免热路径 IO

Hook 方法高频调用（如 `setText:` 每次标签渲染都会触发），直接从 `NSUserDefaults` 读会导致 IO 阻塞。

```
+install 时:  UISimplify_ReloadConfig()
              NSUserDefaults → 静态变量 (_simplifyEnabled, _menuNames, ...)
              
Hook 内:     直接读静态变量，零 IO
```

### 2.3 老版本共存检测

设备上可能同时加载 `微信优化1.6.5.dylib`，两个 dylib Hook 相同方法会导致 `objc_retain(0x3)` 崩溃。

```objc
// UISimplifyHook.m L380-383
if (objc_getClass("CSWCEnhanceViewController")) {
    _oldPluginLoaded = YES;  // 老版本存在 → 跳过策略B的3个Hook
}
```

| 状态 | 策略A (6个) | 策略B (3个) | 总计 |
|------|:----------:|:----------:|:----:|
| 老版本不存在 | 安装 | 安装 | 9 |
| 老版本存在 | 安装 | **跳过** | 6 |

### 3.4 策略A: 字典查找替换 (6个Hook, L112-182)

所有 6 个 Hook 遵循同一模式：`_menuNames[原文]` 或 `_tabNames[原文]` → 替换。

| Hook | 被Hook方法 | 类型 |
|------|-----------|------|
| `hook_WCTitle` (L112) | `WCTableViewCellLeftConfig.title` | 返回值替换 + `\n`后缀处理 |
| `hook_MMTabbarItem_init` (L141) | `MMTabbarItem.initWithTitle:normalImage:selectedImage:` | 参数替换 |
| `hook_MMTabbarItem_setNormalTitle` (L146) | `MMTabbarItem.setNormalTitle:` | 参数替换 |
| `hook_MMTabBarItemView_setTitle` (L151) | `MMTabBarItemView.setTitle:` | 参数替换 |
| `hook_MMTabBarController_setTabBarItemTitle` (L156) | `MMTabBarController.setTabBarItemTitle:forIndex:` | 参数替换 |
| `hook_MMTableViewInfo_getTitle` (L165) | `MMTableViewInfo.getTitle:` | 返回值替换 + `\n`后缀处理 |

关键实现细节:
- 签名均为精确匹配，无多余参数
- `MMTableViewInfo.getTitle:` 签名为 `(id, SEL)` — **无额外参数**（避免了 ARM64 X2 寄存器污染）
- `\n` 后缀处理：`"服务\n支付"` → 取 `\n` 后 `"支付"` 查字典

### 3.5 策略B: 上下文匹配 (3个Hook, L188-367)

#### 3.5.1 MMUILabel.setText: (L188-262) ⭐核心

4 层守卫 + 4 层匹配决策树：

```
入口: hook_MMUILabel_setText(self, _cmd, text)

Guard 0: _orig 非 NULL
Guard 1: _simplifyEnabled 关闭 → 原始
Guard 2: text == nil → 原始
Guard 3: text hasPrefix "[" (badge数字) → 原始
Guard 4: self isKindOfClass UIResponder → 否则原始

层1: _mainTitle 有值 + NavigationBar 在响应者链中 → setText(_mainTitle)
层2: _contactsTitle 有值 + text含"通讯录" + Contact 在响应者链中 → setText(_contactsTitle)
层3: _discoverTitle 有值 + text含"发现" → setText(_discoverTitle)
层4: _friendsCount 有值 + 正则\d+ + text含"位"+"联系人" → stringWithFormat
默认: 原始
```

每层都检查 `!_oldPluginLoaded`，老版本存在时跳过所有匹配逻辑。

#### 3.5.2 MMUILabel.setAttributedText: (L279-329)

同 setText 的决策树结构，但替换时保留富文本属性：

```objc
NSDictionary *attrs = [orig attributesAtIndex:0 effectiveRange:NULL];
[[NSAttributedString alloc] initWithString:newText attributes:attrs];
```

#### 3.5.3 MFTitleView.updateTitleView:title: (L335-367)

同 setText 的层1-3决策树（无好友数匹配层），替换 title 参数后调用原始方法。

### 3.6 install 入口 (L375-441)

```objc
+ (void)install {
    UISimplify_ReloadConfig();

    // 检测老版本
    if (objc_getClass("CSWCEnhanceViewController")) {
        _oldPluginLoaded = YES;
    }

    // 策略A (6个): 始终安装，每个 class 先用 SafeGetClass 检查
    MSHookMessageEx(SafeGetClass("WCTableViewCellLeftConfig"), @selector(title), ...);
    MSHookMessageEx(SafeGetClass("MMTabbarItem"), @selector(initWithTitle:...), ...);
    // ... 共6个

    // 策略B (3个): 仅老版本不存在时安装
    if (!_oldPluginLoaded) {
        MSHookMessageEx(SafeGetClass("MMUILabel"), @selector(setText:), ...);
        MSHookMessageEx(SafeGetClass("MMUILabel"), @selector(setAttributedText:), ...);
        MSHookMessageEx(SafeGetClass("MFTitleView"), @selector(updateTitleView:title:), ...);
    }
}
```

### 4.2 数据持久化 (L47-96)

`onEditRowTap:` 点击任一行 → `UIAlertController` 弹框 → 输入 → "确定"：

1. 更新 UI: `valueLabel.text = newText`
2. 持久化到 NSUserDefaults:
   - **字符串项** (标题/好友数): 直接 `setObject:forKey:`
   - **字典项** (菜单/Tab): 读取字典 → `mutableCopy` → 更新对应 key → `setObject:forKey:`

每行通过 `objc_setAssociatedObject` 绑定两个关键属性：
- `editNSKey` → NSUserDefaults 键名（如 `@"Simplify_MenuNames"`）
- `editDictKey` → 字典内的 key（如 `@"服务"`），仅字典项需要

### 4.3 Swift Toggle 联动 (L11-23)

`SimplifySwitchTarget.toggleSwitch:` 响应 UISwitch：
- 控制下方 4 个 section 的 `hidden` 属性
- 更新 scrollView `contentSize`
- 写入 `SimplifyEnabled` 到 NSUserDefaults

### 4.4 动态子类创建 (L316-333)

`WPUISimplifyVCHelper.makeVC`：

```objc
// ⚠️ class_addMethod 必须在 objc_registerClassPair 之前
```

## 七、避坑记录

| 崩溃 | 原因 | 修复 |
|------|------|------|
| `objc_retain(0x3)` SIGSEGV | `MMTableViewInfo.getTitle:` 多了 `id param` 参数 → ARM64 X2 寄存器污染 | 签名改为 `(id, SEL)` 无额外参数 |
| `objc_retain(0x3)` (第二次) | 老版本 `微信优化1.6.5.dylib` 同时 Hook 相同方法 | 检测 `objc_getClass("CSWCEnhanceViewController")` → 跳过策略B的3个Hook |
| 点进微信就闪退 (第三次) | `objc_registerClassPair` 先于 `class_addMethod` → `method_setImplementation` 覆盖了父类 `MMUIViewController.viewDidLoad` | 先 `class_addMethod` 再 `objc_registerClassPair` |
| 响应者链遍历崩溃 | `nextResponder` 返回已被释放的对象 | `isKindOfClass:[UIResponder class]` 守卫 + 深度限制 10 层 + `@try` |
| Hook 热路径 IO | 每次 `setText:` 都读 `NSUserDefaults` | 改为静态变量缓存，启动时一次性加载 |
