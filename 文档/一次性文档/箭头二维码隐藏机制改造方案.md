# 箭头/二维码隐藏机制改造方案

---

## 一、现状与目标

### 1.1 当前实现（MioPlugin）

```objc
+ (void)hideQRButtonInCell:(UIView *)cell {
    for (UIView *sub in cell.subviews) {
        // 识别：类名含 "Button" + 位置 > 70% 宽度
        if ([sub.className containsString:@"Button"]) {
            if (sub.frame.origin.x > sub.superview.width * 0.7) {
                sub.hidden = YES;  // 仅 hidden，无 alpha/opacity 处理
            }
        }
        [self hideQRButtonInSubviews:sub.subviews];  // 递归遍历
    }
}
```

### 1.2 目标实现（参考 WCRefine）

```objc
+ (void)hideArrowQRInCell:(UIView *)cell shouldHide:(BOOL)shouldHide {
    for (UIView *sub in cell.subviews) {  // 单层遍历，不递归
        // 双层识别策略（OR）：
        if ([self isArrowQRByAccessibilityLabel:sub] ||
            [self isArrowQRByFrameHeuristic:sub]) {
            [self applyHiddenWithCache:sub shouldHide:shouldHide];
        }
    }
}
```

---

## 二、改造点详解

### 改造 1：识别方式 — 双层策略

**问题：** 当前仅靠 "类名含 Button + x>70% 宽度" 判断，可能误判其他右侧按钮，也无法区分箭头和二维码。

**改造：** 参考 WCRefine 的 `FUN_00336e4c + FUN_00337128` 双层 OR 策略：

#### 策略 A：accessibilityLabel 匹配（推荐主力）

```objc
+ (BOOL)isArrowQRByAccessibilityLabel:(UIView *)view {
    NSString *label = view.accessibilityLabel;
    if (!label) return NO;

    // WCRefine 反编译目标 label:
    //   @"More_CardInfo"  — 箭码
    //   @"•"              — 单点箭码
    //   @"• N"            — 带数字的箭码
    NSArray *targetLabels = @[
        @"More_CardInfo",
        @"•",
    ];

    for (NSString *target in targetLabels) {
        if ([label isEqualToString:target] ||
            [label hasPrefix:target]) {
            return YES;
        }
    }
    return NO;
}
```

> 说明：`@"•"` 本身就是 Unicode 字符，微信用这个作为 accessibilityLabel 来标识箭码按钮。`@"• N"`（带数字）可用 `hasPrefix:@"•"` 覆盖。

#### 策略 B：UIImageView + frame 启发式（兜底）

```objc
+ (BOOL)isArrowQRByFrameHeuristic:(UIView *)view {
    // WCRefine FUN_00337128 反编译帧判断：
    //   1. 是 UIImageView
    //   2. 宽度 10-18pt
    //   3. 高度 8-40pt
    //   4. X 坐标 > 父视图宽度 - 40pt（右侧区域）
    if (![view isKindOfClass:[UIImageView class]]) return NO;

    CGFloat w = view.frame.size.width;
    CGFloat h = view.frame.size.height;
    CGFloat x = view.frame.origin.x;
    CGFloat parentW = view.superview.bounds.size.width;

    return (w >= 10 && w <= 18) &&
           (h >= 8 && h <= 40) &&
           (x > parentW - 40);
}
```

#### 最终识别入口

```objc
+ (BOOL)isArrowQRView:(UIView *)view {
    return [self isArrowQRByAccessibilityLabel:view] ||
           [self isArrowQRByFrameHeuristic:view];
}
```

> 策略 A 优先（accessibilityLabel 匹配精准），策略 B 兜底（应对微信版本更新后 label 变化的情况）。

---

### 改造 2：遍历方式 — 单层，去递归

**问题：** `hideQRButtonInSubviews` 递归遍历所有层级。箭码/二维码始终是 button（资料卡容器 MMUIButton）的直接子视图，递归无必要。

**改造：** 只遍历直接子视图，不递归。

```objc
+ (void)hideArrowQRInCell:(UIView *)cell shouldHide:(BOOL)shouldHide {
    // 单层快速枚举，不递归
    for (UIView *sub in cell.subviews) {
        if ([self isArrowQRView:sub]) {
            [self applyHiddenWithCache:sub shouldHide:shouldHide];
        }
    }
}
```

**优势：**
- 消除无限递归风险
- 减少不必要的遍历次数（O(n) vs O(n^depth)）
- 与 WCRefine 的 `NSFastEnumeration` 一致，性能对齐

## 四、改动后完整代码

```objc
#pragma mark - 箭码/二维码隐藏

+ (BOOL)isArrowQRByAccessibilityLabel:(UIView *)view {
    NSString *label = view.accessibilityLabel;
    if (!label) return NO;
    // WCRefine 反编译目标 label: @"More_CardInfo", @"•", @"• N"
    return [label isEqualToString:@"More_CardInfo"] ||
           [label hasPrefix:@"•"];
}

+ (BOOL)isArrowQRByFrameHeuristic:(UIView *)view {
    if (![view isKindOfClass:[UIImageView class]]) return NO;
    CGFloat w = view.frame.size.width;
    CGFloat h = view.frame.size.height;
    CGFloat x = view.frame.origin.x;
    CGFloat parentW = view.superview.bounds.size.width;
    return (w >= 10 && w <= 18) &&
           (h >= 8 && h <= 40) &&
           (x > parentW - 40);
}

+ (BOOL)isArrowQRView:(UIView *)view {
    return [self isArrowQRByAccessibilityLabel:view] ||
           [self isArrowQRByFrameHeuristic:view];
}

+ (void)hideArrowQRInCell:(UIView *)cell {
    for (UIView *sub in cell.subviews) {
        if ([self isArrowQRView:sub]) {
            sub.hidden = YES;
        }
    }
}
```

## 五、对比总结

| 维度 | 改前（MioPlugin） | 改后（参考 WCRefine） |
|:-----|:----------------|:---------------------|
| **识别策略** | 类名 "Button" + x>70% 宽度（单策略启发式） | accessibilityLabel 匹配 + UIImageView 帧启发式（双策略 OR 组合） |
| **识别精度** | 中（可能误判其他右侧按钮） | 高（accessibilityLabel 精准匹配，帧启发式兜底） |
| **遍历方式** | 递归（深度遍历所有层级） | 单层直接遍历 |
| **递归风险** | 有（深度过大可能栈溢出） | 无 |
| **隐藏操作** | 仅 `hidden=YES` | 仅 `hidden=YES`（不变） |
| **透明度残留** | 无风险 | 同左 |
| **可逆性** | — | —（无恢复场景，保持不可逆） |
| **函数签名** | `hideQRButtonInCell:` | `hideArrowQRInCell:` |
| **冗余代码** | hideQRButtonInSubviews 拆分两个方法 | 合并为一个方法 |

## 六、安全性分析

| 风险 | 等级 | 说明 | 应对 |
|:-----|:----:|:------|:------|
| **accessibilityLabel 匹配失败** | 🟡 | 微信版本更新可能改变 label | 策略 B（帧启发式）作为兜底，不影响功能 |
| **帧启发式误判** | 🟡 | 右侧可能有其他小 UIImageView | 限制严格（w 10-18, h 8-40, x>父宽-40），微信资料卡右侧只有箭头和二维码 |
| **call 3 处没改全** | 🟡 | handleCornerAndQR + 2 处 handleHiddenPath | 编译后检查无 `hideQRButtonInCell` 残留 |
