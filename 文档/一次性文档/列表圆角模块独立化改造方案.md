# 列表圆角模块独立化改造方案

---

## 一、现状分析

### 1.1 目录结构

```
Modules/ListCornerRadius/
├── ListCornerRadiusHook.h        (2 个公开方法)
├── ListCornerRadiusHook.m        (~620 行)
├── WPAuxiliaryHooks.h            (1 个 C 函数声明)
├── WPAuxiliaryHooks.m            (~209 行)
├── WPSessionSpacingHook.h        (1 个 C 函数声明)
└── WPSessionSpacingHook.m        (?)

Modules/ProfileCardBg/            (对比目标)
├── ProfileCardBgHook.h           (17 个公开方法)
└── ProfileCardBgHook.m           (~790 行)
```

### 1.2 初始化方式对比

| 模块 | 注册方式 | 调用位置 |
|:-----|:---------|:---------|
| **资料卡背景** (ProfileCardBgHook) | 由 ListCornerRadiusHook 的 MMUIButton Hook 内分发调用，**不直接注册** | `Tweak.m` 无直接调用 |
| **列表圆角** (ListCornerRadiusHook) | 由 `Tweak.m` 直接调用 `initListCornerRadiusHook` | `Tweak.m` L20 |
| **WPAuxiliaryHooks** | 由 `Tweak.m` 直接调用 `WPInstallAuxiliaryHooks()` | `Tweak.m` L22 |
| **WPSessionSpacingHook** | 由 `Tweak.m` 直接调用 `WPInstallSessionSpacingHooks()` | `Tweak.m` L21 |

**问题：** 同一个模块 3 个 C 函数在 `Tweak.m` 中分别初始化，散落在不同文件。

### 1.3 文件间调用关系

```
Tweak.m
  ├──→ [ListCornerRadiusHook initListCornerRadiusHook]   ← 注册 3 个 MSHook
  │         │

  │         │               │     └── wp_applyBorderAndBg:
  │         │               └── 懒注册 MMUIButton Hook (if !_orig)
  │         │                     └──→ [ProfileCardBgHook handleButtonLayout:]
  │         │
  │         ├──→ MSHook WCSearchBar::layoutSubviews
  │         │
  │         └──→ MSHook MMUIButton::layoutSubviews
  │                 └──→ [ProfileCardBgHook handleButtonLayout:]   ← ★ 跨模块分发
  │
  ├──→ WPInstallSessionSpacingHooks()
  │
  └──→ WPInstallAuxiliaryHooks()
          ├──→ MSHook MFWebMMBtn::layoutSubviews
          ├──→ MSHook MFBannerBtn::layoutSubviews
          ├──→ MSHook MainFrameSectionFoldView::layoutSubviews
```

### 1.4 耦合问题汇总

| # | 问题 | 位置 | 说明 |
|:-:|:-----|:-----|:------|
| 1 | **MMUIButton 重复 Hook** | `initListCornerRadiusHook`(L310) + `replaced_MMTableViewCell_layoutSubviews`(L131) + `WPAuxiliaryHooks`(L195) | 同一个 hook 在 3 处注册，存在重复和冲突风险 |
| 2 | **跨模块方法调用** | ListCornerRadiusHook.m L125 | `[ProfileCardBgHook handleButtonLayout:]` 属于职责错位 |
| 3 | **初始化散落** | Tweak.m L20-22 | 3 个 C 函数分别初始化，应合并 |
| 4 | **FeatureModuleRegistry 未注册** | `hookInstallerClasses: @[]` | 列表圆角未使用标准注册流程 |
| 5 | **WPAuxiliaryHooks 归属不清** | 放在 ListCornerRadius 目录下，逻辑上属于它但物理上分散 | 应合并 |
| 6 | **WPSessionSpacingHook 归属不清** | 同上 | 应合并 |
| 7 | **公开接口过多** | `ListCornerRadiusHook.h` 只暴露 2 个方法 | 过多内部方法通过私有接口暴露，实际不需要 |

## 二、改造目标

```
改前：                                         改后：
Tweak.m                                        Tweak.m
  ├── [ListCornerRadiusHook initListCorner]      └── [ListCornerRadiusHook initListCorner]
  ├── WPInstallSessionSpacingHooks()
  └── WPInstallAuxiliaryHooks()                 ListCornerRadiusHook.m (合并全部)

ProfileCardBgHook.m                              ProfileCardBgHook.m
  ← 被 ListCorner 的 MMUIButton Hook 调用         ← 自我注册 MMUIButton Hook
                                                  ← 独立初始化，不依赖 ListCorner
```

### 核心原则

1. **MMUIButton Hook 归属给 ProfileCardBgHook** — 它是唯一使用方，由它自己注册
2. **WPAuxiliaryHooks + WPSessionSpacingHook 合并进 ListCornerRadiusHook** — 同一模块不分散
3. **列表圆角通过 FeatureModuleRegistry 注册** — 与其他模块一致
4. **`Tweak.m` 中只留一行初始化**

---

## 三、详细改造步骤

### 步骤 1：将 MMUIButton Hook 迁移到 ProfileCardBgHook

**当前状态：** `ListCornerRadiusHook.m` 中注册的 `replaced_MMUIButton_layoutSubviews` 只做一件事——调用 `[ProfileCardBgHook handleButtonLayout:]`。

**改造：**

#### 1a. 删除 ListCornerRadiusHook.m 中的 MMUIButton 相关代码

删除 L117-L126 的 `replaced_MMUIButton_layoutSubviews` 函数体。

```objc
// 整段删除（L117-L126）：
static void replaced_MMUIButton_layoutSubviews(id self, SEL _cmd) {
    if (_orig_MMUIButton_layoutSubviews) {
        ((void (*)(id, SEL))_orig_MMUIButton_layoutSubviews)(self, _cmd);
    }
    [ProfileCardBgHook handleButtonLayout:(UIView *)self];
}
```

删除 L130-L141 的懒注册逻辑：

```objc
// 整段删除（L130-L141）：
if (!_orig_MMUIButton_layoutSubviews) {
    Class MMUIButtonClass = objc_getClass("MMUIButton");
    if (MMUIButtonClass) {
        MSHookMessageEx(MMUIButtonClass, @selector(layoutSubviews),
            (IMP)replaced_MMUIButton_layoutSubviews, &_orig_MMUIButton_layoutSubviews);
    }
}
```

删除 L309-L334 的正式注册逻辑：

```objc
// 整段删除（L309-L334）：
WPLog(...);
Class MMUIButtonClass = objc_getClass("MMUIButton");
if (MMUIButtonClass) {
    MSHookMessageEx(MMUIButtonClass, @selector(layoutSubviews),
        (IMP)replaced_MMUIButton_layoutSubviews, &_orig_MMUIButton_layoutSubviews);
} else {
    // objc_lookUpClass 重试...
}
```

删除 L3 的 `#import "../ProfileCardBg/ProfileCardBgHook.h"`（如果只剩这个 import 被引用）。

#### 1b. 在 ProfileCardBgHook.m 中新增 MMUIButton Hook

在 `ProfileCardBgHook.m` 的 `@implementation` 中新增初始化方法：

```objc
static IMP _orig_MMUIButton_layoutSubviews = NULL;
static void replaced_MMUIButton_layoutSubviews(id self, SEL _cmd) {
    if (_orig_MMUIButton_layoutSubviews) {
        ((void (*)(id, SEL))_orig_MMUIButton_layoutSubviews)(self, _cmd);
    }
    [ProfileCardBgHook handleButtonLayout:(UIView *)self];
}

// 新增入口（供 Tweak.m / FeatureModuleRegistry 调用）
+ (void)initProfileCardHook {
    Class cls = objc_getClass("MMUIButton");
    if (cls) {
        MSHookMessageEx(cls, @selector(layoutSubviews),
            (IMP)replaced_MMUIButton_layoutSubviews, &_orig_MMUIButton_layoutSubviews);
    }
}
```

在 `ProfileCardBgHook.h` 中声明 `initProfileCardHook`。

#### 1c. 删除懒注册逻辑中残留的 `_orig_MMUIButton_layoutSubviews` 静态变量

删除 L11 的 `static IMP _orig_MMUIButton_layoutSubviews = NULL;`

### 步骤 2：合并 WPAuxiliaryHooks 进 ListCornerRadiusHook

**当前状态：** WPAuxiliaryHooks 对 4 个 Class 进行 Hook，其中 `_hooked_MMUIButton_layoutSubviews` 实际上是列表圆角的能力（`listHideRightQRCode`, `listDisableLabelWidthAdjustment`, `listMediaCornerEnabled`）。

**改造：**

#### 2a. 将 WPAuxiliaryHooks.m 的内容合并进 ListCornerRadiusHook.m

将以下 4 个 Hook 函数从 WPAuxiliaryHooks.m **全部搬入** ListCornerRadiusHook.m，放在 `@implementation` 之前作为 static C 函数：

| Hook 函数 | 目标 Class | 归属判断 |
|:----------|:-----------|:---------|
| `_hooked_MFWebMMBtn_layoutSubviews` | MFWebMMBtn | ✅ 列表圆角能力（设置背景色） |
| `_hooked_MFBannerBtn_layoutSubviews` | MFBannerBtn | ✅ 列表圆角能力（设置背景色） |
| `_hooked_FoldView_layoutSubviews` | MainFrameSectionFoldView | ✅ 列表圆角能力（布局+边框+背景） |
| `_hooked_MMUIButton_layoutSubviews` | MMUIButton | ⚠️ 这部分逻辑移到 ProfileCardBgHook（步骤 1 已处理） |

合并后在 `ListCornerRadiusHook.m` 中注册：

```objc
+ (void)initListCornerRadiusHook {
    // 原来就有的
    MSHookMessageEx(MMTableViewCellClass, @selector(layoutSubviews), ...);
    MSHookMessageEx(WCSearchBarClass, @selector(layoutSubviews), ...);

    // 新增（原 WPAuxiliaryHooks 中的）
    Class c1 = objc_getClass("MFWebMMBtn");
    if (c1) MSHookMessageEx(c1, @selector(layoutSubviews), ...);

    Class c2 = objc_getClass("MFBannerBtn");
    if (c2) MSHookMessageEx(c2, @selector(layoutSubviews), ...);

    Class c3 = objc_getClass("MainFrameSectionFoldView");
    if (c3) MSHookMessageEx(c3, @selector(layoutSubviews), ...);

    // 不再注册 MMUIButton Hook，已移至 ProfileCardBgHook

    [ProfileCardBgHook initCellHeightHook];  // 保留
}
```

#### 2b. 删除 WPAuxiliaryHooks.h/.m 文件

合并完成后，删除这两个文件。从 `Tweak.m` 中删除 `#import "WPAuxiliaryHooks.h"` 和 `WPInstallAuxiliaryHooks()` 调用。

#### 2c. 将 WPAuxiliaryHooks 中的辅助函数内联

`wp_findViewController`（WPAuxiliaryHooks.m L8-17）与 `ListCornerRadiusHook.m` 中的 `findParentViewController`（L14-23）功能重复，**合并为一个**，保留 `findParentViewController` 即可。

### 步骤 3：合并 WPSessionSpacingHook 进 ListCornerRadiusHook

**改造：**

#### 3a. 读取 WPSessionSpacingHook.m 的完整内容

查看其 Hook 的函数和逻辑，将 `WPInstallSessionSpacingHooks()` 体搬到 `initListCornerRadiusHook` 末尾。

#### 3b. 删除 WPSessionSpacingHook.h/.m

合并后删除，从 `Tweak.m` 中删除调用。

### 步骤 4：将 `Tweak.m` 简化为一行

**改前（Tweak.m L20-22）：**
```objc
[ListCornerRadiusHook initListCornerRadiusHook];
WPInstallSessionSpacingHooks();
WPInstallAuxiliaryHooks();
```

**改后：**
```objc
[ListCornerRadiusHook initListCornerRadiusHook];
[ProfileCardBgHook initProfileCardHook];
```

> 注：`[ProfileCardBgHook initProfileCardHook]` 是步骤 1 新增的方法。如果 ProfileCardBgHook 也想遵循 FeatureModuleRegistry 模式，后续可以将其放入 `hookInstallerClasses`。

### 步骤 5：从 FeatureModuleRegistry 中启用标准注册（可选）

**当前：** `hookInstallerClasses: @[]`（ListCornerRadius 的空数组）

**方式一（不改）：** 保留 `Tweak.m` 的直接调用，跳过 registry。简单但不够统一。

**方式二（推荐）：** 在 ListCornerRadiusHook 实现 `+install` 方法：

```objc
// ListCornerRadiusHook.m
+ (void)install {
    [self initListCornerRadiusHook];
}
```

然后将 `FeatureModuleRegistry.m` L67 改为：
```objc
hookInstallerClasses:@[[ListCornerRadiusHook class]]
```

同时从 `Tweak.m` 删除 `[ListCornerRadiusHook initListCornerRadiusHook]` 调用。

这样 `Tweak.m` 只需调用 `[HookRegistry installAllHooks]`（已有），不再需要任何直接初始化。

### 步骤 6：清理 import

完成上述步骤后：

| 文件 | 增减 |
|:-----|:-----|
| `ListCornerRadiusHook.m` | 删除 `#import "ProfileCardBgHook.h"`（如不再需要） |
| `ListCornerRadiusHook.m` | 删除 `#import "CornerResponsibility.h"`（如不再需要）→ 需先确认是否还有引用 |
| `Tweak.m` | 仅保留 `#import "ListCornerRadiusHook.h"` + `#import "ProfileCardBgHook.h"` |

## 六、安全性分析

| 风险 | 影响 | 等级 | 应对 |
|:-----|:-----|:----:|:-----|
| **MMUIButton Hook 重复** | 两处注册同一 Hook 导致先执行的被覆盖或 crash | 🔴 | 删除 ListCorner 侧的 3 处注册，只保留 ProfileCardBg 侧 1 处 |
| **WPAuxiliaryHooks 合并遗漏** | FoldView / MFWebMMBtn / MFBannerBtn 圆角失效 | 🟡 | 逐函数确认合并完整性，对照源码一一搬入 |
| **WPSessionSpacingHook 合并遗漏** | session 间距失效 | 🟡 | 读取原文件，逐行搬入 |
| **`wp_findViewController` / `findParentViewController` 重复** | 两个同名函数存在，行为不一致 | 🟡 | 合并为一个 |
| **`Tweak.m` 删除后注册顺序** | 如有其他模块依赖 init 顺序 | 🟢 | `HookRegistry` 以数组顺序注册，可控制 |
| **MMUIButton Hook 注册时机** | 原 ListCorner 在 initListCornerRadiusHook 时就注册了，迁移后不应变晚 | 🟢 | `initProfileCardHook` 在 `Tweak.m` 中紧跟在 initListCorner 后调用，时序一样 |

## 九、与 ProfileCardBgHook 的结构对标

| 维度 | ProfileCardBgHook (目标模式) | 改造后 ListCornerRadiusHook |
|:-----|:---------------------------|:---------------------------|
| 文件数 | 2 个（.h + .m） | 2 个（.h + .m，合并没有的） |
| 初始化方式 | 外部调用一个入口方法 | 外部调用一个入口方法 |
| 外部直接调用的方法 | 仅 `handleButtonLayout:` 供 MMUIButton 分发 | 仅 `initListCornerRadiusHook`（或 `+install`）供注册 |
| 是否注册在 FeatureModuleRegistry | 否（可后续加上） | 是（标准注册） |
| 是否依赖其他模块的 Hook | 否（但被 ListCorner 调用） | 否（不依赖任何 Hook） |
| 职责范围 | 资料卡 button 的美化全部 | 列表 Cell 的圆角/边框/背景/间距全部 |
