# 列表圆角模块独立化改造方案

> 基于当前代码实际状态重写，反映真实的文件结构、Hook 注册关系和耦合问题。

---

## 一、现状分析

### 1.1 目录结构

```
Modules/ListCornerRadius/
├── ListCornerRadiusHook.h          (2 个公开方法)
├── ListCornerRadiusHook.m          (~620 行)
├── WPAuxiliaryHooks.h              (1 个 C 函数声明)
├── WPAuxiliaryHooks.m              (~199 行)
├── WPSessionSpacingHook.h          (1 个 C 函数声明)

```

### 1.2 初始化方式现状

当前 [Tweak.m](file:///www/wwwroot/ios/MioPlugin/Tweak.m) L20-22 的初始化代码：

```objc
[ListCornerRadiusHook initListCornerRadiusHook];
WPInstallSessionSpacingHooks();
WPInstallAuxiliaryHooks();
```

同时，[HookRegistry](file:///www/wwwroot/ios/MioPlugin/Registry/HookRegistry.m) 通过 [FeatureModuleRegistry](file:///www/wwwroot/ios/MioPlugin/Registry/FeatureModuleRegistry.m) 扫描模块并调用 `+install` 方法，但**列表圆角模块的 `hookInstallerClasses` 为空数组**。

| 模块 | 注册方式 | 调用位置 |
|:-----|:---------|:---------|
| **ListCornerRadiusHook（列表圆角）** | `Tweak.m` 直接调用 `initListCornerRadiusHook` | `Tweak.m` L20 |
| **WPAuxiliaryHooks（辅助钩子）** | `Tweak.m` 直接调用 `WPInstallAuxiliaryHooks()` | `Tweak.m` L22 |
| **WPSessionSpacingHook（会话间距）** | `Tweak.m` 直接调用 `WPInstallSessionSpacingHooks()` | `Tweak.m` L21 |
| **其他模块（RevokeHook 等）** | 通过 `FeatureModuleRegistry` + `HookRegistry` 的 `+install` 机制 | 自动注册 |

> **问题：** 列表圆角模块 3 个文件在 Tweak.m 中分别初始化，同一模块逻辑散落在不同文件中，未使用统一的注册流程。

### 1.4 耦合问题汇总

| # | 问题 | 位置 | 严重性 | 说明 |
|:-:|:-----|:-----|:------:|:------|
| 1 | **MMUIButton 重复 Hook** | `initListCornerRadiusHook` L310 + `replaced_MMTableViewCell_layoutSubviews` L131 + `WPAuxiliaryHooks（辅助钩子）` L194 | 🔴 | 同一个 `MMUIButton（微信按钮）::layoutSubviews` 在 3 处注册，其中两处实现不同（资料卡分发 vs 列表媒体圆角），按 MSHookMessageEx 链式调用顺序，后注册的会覆盖前者，导致其中一方功能失效 |
| 2 | **MMUIButton Hook 归属错位** | `ListCornerRadiusHook.m（列表圆角）` L118-126 | 🔴 | 列表圆角模块代资料卡背景模块注册 `MMUIButton（微信按钮）` Hook，职责错位 |

| 5 | **FeatureModuleRegistry（模块注册表）未利用** | `FeatureModuleRegistry.m（模块注册表）` L67: `@[]` | 🟡 | 列表圆角已注册在 `FeatureModuleRegistry（模块注册表）` 中但 `hookInstallerClasses` 为空，没有利用标准注册流程 |

| 9 | **WPSessionSpacingHook（会话间距）归属不清** | 同上 | 🟢 | 同上 |

### 核心原则

1. **MMUIButton Hook 拆分** — 资料卡分发的 Hook 归属给 ProfileCardBgHook 自行注册；列表媒体圆角的 Hook 保留在 ListCornerRadiusHook
2. **WPAuxiliaryHooks + WPSessionSpacingHook 合并进 ListCornerRadiusHook** — 同一模块不分散
3. **列表圆角通过 FeatureModuleRegistry 注册 `+install`** — 与其他模块保持一致
4. **`Tweak.m` 只保留 `[HookRegistry installAllHooks]`**

## 三、详细改造步骤

### 步骤 1：拆分 MMUIButton Hook

当前 MMUIButton::layoutSubviews 被 Hook 了**两套实现**：

| 注册位置 | 实现函数 | 功能 |
|:---------|:---------|:------|
| `ListCornerRadiusHook.m（列表圆角）` L118-126 | `replaced_MMUIButton_layoutSubviews` | 调用 `[ProfileCardBgHook（资料卡背景） handleButtonLayout:]` → 资料卡背景/圆角/隐藏 |
| `WPAuxiliaryHooks.m（辅助钩子）` L145-173 | `_hooked_MMUIButton_layoutSubviews` | 列表媒体圆角 `listMediaCornerEnabled` + 标签宽度调整 `listDisableLabelWidthAdjustment` |

两套实现必须**分开注册**，不能由同一模块管理。

## 六、安全性分析

| 风险 | 影响 | 等级 | 应对 |
|:-----|:-----|:----:|:-----|
| **MMUIButton Hook 拆分后顺序错误** | 列表媒体圆角或资料卡背景功能失效 | 🔴 | `WPAuxiliaryHooks（辅助钩子）` 的 `_hooked_MMUIButton_layoutSubviews` 留在步骤 2 统一搬入 `ListCornerRadiusHook.m（列表圆角）`，**不随资料卡迁移**；资料卡分发 Hook 由 `ProfileCardBgHook（资料卡背景）` 自行注册，两套 Hook 各自独立 |
| **Hook 注册时序变化** | 先注册的 Hook 被后注册的覆盖或行为异常 | 🟡 | MSHookMessageEx 链式调用，注册顺序影响调用链顺序。需确保 `Tweak.m` 中 `initListCornerRadiusHook` 在 `initProfileCardHook` 之前，保证列表媒体圆角先注册（作为外层），资料卡分发后注册（在原实现之上叠加） |
| **WPAuxiliaryHooks（辅助钩子）合并遗漏** | FoldView / MFWebMMBtn / MFBannerBtn 功能失效 | 🟡 | 逐函数对照 `WPAuxiliaryHooks.m（辅助钩子）` 源码，确认 4 个 `_hooked_*` 函数全部搬入 |
| **WPSessionSpacingHook（会话间距）合并遗漏** | Session 间距、Section Header 背景、UIView 透明化失效 | 🟡 | 逐函数对照 `WPSessionSpacingHook.m（会话间距）` 源码，确认全部搬入 |
| **`findParentViewController` 合并遗漏** | 某些 VC 过滤条件不一致 | 🟢 | 统一保留 `ListCornerRadiusHook.m（列表圆角）` 中的实现，其余两处删除 |
| **`+install` 调用时机** | 如果在模块构造函数中 initListCornerRadiusHook 还没准备好 | 🟢 | `HookRegistry（钩子注册器）` 的 `installAllHooks` 在 `@try` 中执行，且有异常捕获 |
| **FeatureModuleRegistry（模块注册表）配置错误** | 列表圆角所有功能不加载 | 🟢 | 配置为 `@[[ListCornerRadiusHook class]]`，确保 `+install` 方法存在 |
| **ProfileCardBgHook（资料卡背景）未实现 initProfileCardHook** | MMUIButton 资料卡分发无 Hook，资料卡所有功能失效 | 🔴 | 在步骤 1c 中必须完成该方法的实现，并在 `Tweak.m` 或 `FeatureModuleRegistry（模块注册表）` 中注册调用 |
