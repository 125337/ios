# 颜色配置去深浅化改造文档

---

## 一、改造清单

将以下 4 组深浅色配置合并为单一颜色配置：

| 分组 | 旧属性（删） | 新属性（增） | 默认值 |
|:-----|:------------|:------------|:------|
| **Cell背景色** | `listCellLightBgColor` / `listCellDarkBgColor` | `listCellBgColor` | `#FFFFFF` |
| **边框颜色** | `listCellBorderLightColor` / `listCellBorderDarkColor` | `listCellBorderColor` | `#E5E5E5` |
| **卡片背景色** | `listCardLightBgColor` / `listCardDarkBgColor` | `listCardBgColor` | `#FFFFFF` |
| **资料卡边框颜色** | `listProfileCardBorderLightColor` / `listProfileCardBorderDarkColor` | `listProfileCardBorderColor` | `#E5E5E5` |

> 新默认值取原浅色模式值。`listProfileCardBorderColor` 原深/浅的 default 为 `#E5E5E5` / `#3A3A3C`，选浅色默认值 `#E5E5E5`。

## 四、改造模式总结

每一处改动的模式完全相同：

```
改前：isDark ? config.xxxDarkColor : config.xxxLightColor

```

涉及的 `isDark` 局部变量**全部有剩余用途，必须保留**。详见 [第八节](#八isdark-残留分析)。

## 八、isDark 残留分析

所有涉及颜色改造的文件中，`isDark` **在每处都有剩余用途，必须保留**。逐文件验证如下：

### 8.1 ListCornerRadiusHook.m

**函数 `replaced_MMTableViewCell_layoutSubviews`（L222-229）：**
```objc
// isDark 还有剩余用途 ↓
((UIView *)self).backgroundColor = customBg ?: wp_cellDefaultBgColor(isDark);
//                                                     ↑ 函数参数仍需 isDark
```
`wp_cellDefaultBgColor(isDark)` 仍需要传 `isDark` 来决定兜底背景色。**必须保留。**

**函数 `wp_applyBorderAndBg`（L457-468）：**
```objc
if (!borderColor) {
    borderColor = isDark
        ? [UIColor colorWithRed:0.25 green:0.25 blue:0.25 alpha:1.0]
        : [UIColor colorWithRed:0.9 green:0.9 blue:0.9 alpha:1.0];
//               ↑ isDark 仍有剩余用途：区分深浅的兜底色
}
```
`colorFromHex` 返回 nil 时的 fallback 仍区分深/浅。**必须保留。**

### 8.2 ProfileCardBgHook.m

**函数 `applyProfileCardCorner:isDark:`（L40-97）— 参数 `isDark`：**
```objc
} else {
    // ── 使用单独配置 ──
    ...
    UIColor *bgColor = [config colorFromHex:isDark
        ? config.cardBgCornerDarkBgColor : config.cardBgCornerBgColor];
    //       ↑ 这组颜色不在本次改造范围内，isDark 仍是需要的
}
```
`cardBgCornerDarkBgColor` / `cardBgCornerBgColor` 是"资料卡圆角背景色"的深浅色对，**不在本次改造的 4 组颜色之内**。**必须保留。**

**函数 `handleButtonLayout`（L627）：**
```objc
BOOL isDark = [ProfileCardBgHook isDarkModeForVc:vc];
[ProfileCardBgHook handleHiddenPath:button isDark:isDark];
[ProfileCardBgHook handleVisiblePath:button isDark:isDark];
[ProfileCardBgHook handleCornerAndQR:button isDark:isDark];
```
`isDark` 作为参数传入多个子函数，最终流入 `applyProfileCardCorner`。**必须保留。**

**类方法 `isDarkModeForVc:`（L387-392）：**
```objc
+ (BOOL)isDarkModeForVc:(UIViewController *)vc {
    if (@available(iOS 13.0, *)) {
        return vc.traitCollection.userInterfaceStyle == UIUserInterfaceStyleDark;
    }
    return NO;
}
```
此为 `isDark` 的提供者方法，被多处调用。**必须保留。**

### 8.3 WPAuxiliaryHooks.m

三个函数（`_hooked_MFWebMMBtn_layoutSubviews`、`_hooked_MFBannerBtn_layoutSubviews`、`_hooked_FoldView_layoutSubviews`）均为同一模式：

```objc
UIColor *targetBg = [config colorFromHex:config.listCellBgColor];  // ← 改造后不再用 isDark
if (!targetBg) {
    targetBg = isDark                                              // ← isDark 仍有剩余用途
        ? [UIColor colorWithRed:0.125 green:0.125 blue:0.125 alpha:1.0]
        : [UIColor whiteColor];
}
```
`colorFromHex` 返回 nil 时的 fallback 仍区分深/浅。**必须保留。**
