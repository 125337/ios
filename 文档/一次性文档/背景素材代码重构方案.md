# 背景素材代码重构方案 — 消除分支A/分支B的配置重复

---

## 一、现状分析

### 1.1 重复的配置代码

当前有三份逻辑做**同一件事**——决定 imageView 的 `clipsToBounds`、`contentMode`、frame（含对齐偏移）：

| # | 代码位置 | 行号 | 用途 | `clipsToBounds` | `contentMode` | frame 含偏移 | 层级 |
|:-:|:---------|:----:|:----|:---------------:|:-------------:|:-----------:|:----:|
| ① | `createBackgroundImageViewInButton` | L474-495 | 新建 | `NO` | ✅ | ❌ | ✅ |
| ② | `setupBackgroundMaterialInButton` 分支A | L554-571 | 已存在更新 | `NO` | ✅ | ✅ | ✅ |
| ③ | `loadImageAsyncForImageView` 回调 | L519-528 | 异步加载完 | ❌ | ❌ | ✅ | ❌ |

### 1.2 风险

1. **改一处漏一处**：之前 `clipsToBounds=YES` 的 bug 就是改②忘了①导致的
2. **不一致的隐患**：①设frame不带偏移，③单独算偏移但只改 `origin.y`、不改 `contentMode`
3. **维护成本**：改对齐算法要改②和③两处，改 contentMode 要改①和②两处

---

## 二、重构方案

### 2.1 核心思路

**提取统一配置方法 `configureBackgroundImageView:inButton:`，让所有场景都走它。**

```
                      ┌──────────────────────────────┐
                      │  configureBackgroundImageView │
                      │  :inButton:                    │
                      │                                │
                      │  • clipsToBounds = NO          │
                      │  • contentMode (fillMode)      │
                      │  • frame (ox, oy+offset, W, H) │
                      │  • bringSubviewToFront (layer) │
                      └──────────┬─────────────────────┘
                                 │
              ┌──────────────────┼──────────────────┐
              ▼                  ▼                  ▼
      ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
      │  分支A       │  │  异步回调     │  │  将来新增场景 │
      │  (已存在)    │  │  (图片加载完)  │  │              │
      └──────────────┘  └──────────────┘  └──────────────┘
```

### 2.2 各方法新职责

| 方法 | 重构前 | 重构后 |
|:----|:-------|:-------|
| `createBackgroundImageViewInButton:` | 创建 + 设 contentMode + 设 frame | **只创建 + 加 subview**，不做任何配置 |
| **`configureBackgroundImageView:inButton:`** | **不存在** | **统一配置**，单点修改 |
| `loadImageAsyncForImageView:button:isDark:` | 加载 + 设 image + **算偏移** + **改 frame** | 加载 + 设 image → **调 configure** |
| `setupBackgroundMaterialInButton:isDark:` | 分支A **内联配置** / 分支B 调 create+load | 分支A → **调 configure** / 分支B → create+load（不变） |

### 2.3 不变的部分

以下代码**完全不动**：

- `calcImageAlignmentOffsetWithImageSize:inView:` → 偏移算法不变
- `setupBackgroundMaterialInButton` 的 fillMode=1 适应模式逻辑 → 继续内联
- `button.backgroundColor`, `cleanNativeBgImageView`, `button.layer.masksToBounds` → 继续放在末尾
- `.h` 文件接口声明 → 只需新增一个方法声明，其余不变

## 三、详细改造步骤

### 步骤1：新增 `configureBackgroundImageView:inButton:`

**位置：** 放在 `createBackgroundImageViewInButton:` 之后（L498 之后）

**方法来源：** 从分支A（L554-571）提取通用逻辑 + 补充异步回调需要的部分

```objc
/// 统一配置 imageView：clipsToBounds、contentMode、frame（含对齐偏移）、层级
/// 无论新建还是复用都走这里，保证行为一致
/// imageView 必须已添加到 button 上
+ (void)configureBackgroundImageView:(UIImageView *)imageView
                            inButton:(UIView *)button {
    PluginConfig *config = [PluginConfig shared];

    // ── 裁剪：让 aspectFill 渲染超界部分透出，对齐偏移才能生效 ──
    imageView.clipsToBounds = NO;

    // ── 填充模式 ──
    NSInteger fillMode = config.cardBgFillMode;
    switch (fillMode) {
        case 1: imageView.contentMode = UIViewContentModeScaleAspectFill; break;
        case 2: imageView.contentMode = UIViewContentModeScaleToFill; break;
        default: imageView.contentMode = UIViewContentModeScaleAspectFill; break;
    }

    // ── 计算对齐偏移（无图片时偏移为 0）──
    CGFloat alignOffset = 0;
    if (imageView.image && imageView.image.size.width > 0) {
        alignOffset = [self calcImageAlignmentOffsetWithImageSize:imageView.image.size
                                                          inView:button];
    }

    // ── frame（含偏移）──
    CGFloat ox = config.cardBgOffsetX;
    CGFloat oy = config.cardBgOffsetY;
    imageView.frame = CGRectMake(ox, oy + alignOffset,
                                 button.bounds.size.width,
                                 button.bounds.size.height);

    // ── 层级 ──
    if (config.cardBgLayer == 1) {
        [button bringSubviewToFront:imageView];
    }
}
```

> **为什么这个方法安全？**
> - `clipsToBounds=NO` 总是对的 → 分支A 已经这么做，修复后的分支B 也是这么做
> - `contentMode` 只读 config，不依赖 imageView 状态 → 总是正确的
> - 对齐偏移有 `image` 守卫 → 无图时不计算，不会出错
> - frame 完整覆盖所有属性（ox, oy, W, H）→ 不会残留旧值

### 4.3 `loadImageAsyncForImageView:button:isDark:`（简化后）

```objc
+ (void)loadImageAsyncForImageView:(UIImageView *)imageView
                            button:(UIView *)button
                            isDark:(BOOL)isDark {
    __weak UIImageView *weakBg = imageView;
    __weak UIView *weakButton = button;

    dispatch_async(dispatch_get_global_queue(DISPATCH_QUEUE_PRIORITY_DEFAULT, 0), ^{
        UIImage *resultImage = [ProfileCardBgHook loadBackgroundImageSync];

        dispatch_async(dispatch_get_main_queue(), ^{
            __strong UIImageView *strongBg = weakBg;
            __strong UIView *strongButton = weakButton;
            if (!strongBg || !strongButton) return;

            if (resultImage) {
                strongBg.image = resultImage;
                strongBg.alpha = 1.0;
                strongBg.hidden = NO;
                [ProfileCardBgHook configureBackgroundImageView:strongBg
                                                      inButton:strongButton];
            } else {
                PluginConfig *cfg = [PluginConfig shared];
                UIColor *cardBg = [cfg colorFromHex:isDark
                    ? cfg.listCardDarkBgColor : cfg.listCardLightBgColor];
                if (cardBg) strongButton.backgroundColor = cardBg;
            }
        });
    });
}
```

### 4.4 `setupBackgroundMaterialInButton:isDark:`（分支A简化后）

```objc
+ (void)setupBackgroundMaterialInButton:(UIView *)button
                                 isDark:(BOOL)isDark {
    PluginConfig *config = [PluginConfig shared];

    UIImageView *bgImgView = [ProfileCardBgHook findBackgroundImageViewInButton:button];

    if (bgImgView) {
        // ── 分支 A：已存在 → 统一配置 ──
        [ProfileCardBgHook configureBackgroundImageView:bgImgView inButton:button];
    } else {
        // ── 分支 B：不存在 → 创建（初始 frame 无偏移）→ 异步加载 → configure ──
        bgImgView = [ProfileCardBgHook createBackgroundImageViewInButton:button];
        [ProfileCardBgHook loadImageAsyncForImageView:bgImgView
                                               button:button
                                               isDark:isDark];
    }

    // ★ 适应模式（fillMode=1）— 不变
    NSInteger fillMode = config.cardBgFillMode;
    if (fillMode == 1) {
        UIImage *img = [ProfileCardBgHook loadBackgroundImageSync];
        if (img && img.size.width > 0 && img.size.height > 0) {
            CGFloat btnW = button.bounds.size.width;
            CGFloat imgRatio = img.size.height / img.size.width;
            CGFloat targetH = btnW * imgRatio;
            if (targetH > button.bounds.size.height) {
                CGRect bf = button.frame;
                bf.size.height = targetH;
                button.frame = bf;
                if (bgImgView) {
                    CGRect bgf = bgImgView.frame;
                    bgf.size.height = targetH;
                    bgImgView.frame = bgf;
                }
                UIView *tableView = button.superview;
                if (tableView && [tableView isKindOfClass:[UIScrollView class]]) {
                    if (((UITableView *)tableView).tableHeaderView == button) {
                        [((UITableView *)tableView) setTableHeaderView:button];
                    }
                }
            }
        }
    }

    button.backgroundColor = [UIColor clearColor];
    [ProfileCardBgHook cleanNativeBgImageView:button];
    button.layer.masksToBounds = YES;
}
```

## 六、执行时序推演

### 场景 A：第一次加载（分支B → 异步）

```
时间线
│
├─ handleButtonLayout → setupBackgroundMaterialInButton
│   │
│   ├─ create:  alloc/init, tag, frame(ox, oy, W, H), addSubview
│   │           └─ imageView 存在但无图、无 contentMode、clipsToBounds=YES（默认）
│   │
│   ├─ loadImageAsync: 开始后台加载 ...
│   │
│   └─ button.masksToBounds = YES
│
│   （短暂间隙：imageView 无图，不可见）
│
└─ 异步回调完成
    │
    ├─ imageView.image = resultImage
    ├─ alpha=1, hidden=NO
    └─ configure:
        ├─ clipsToBounds = NO
        ├─ contentMode = aspectFill
        ├─ 算偏移 (有图 → 正确)
        └─ frame = (ox, oy+offset, W, H) ← 最终正确位置 ✅
```

与重构前的区别：configure 同时设了 contentMode、clipsToBounds，而重构前这些值在 create 时已设好。结果完全一致。

### 场景 B：后续刷新（分支A → 同步）

```
handleButtonLayout → setupBackgroundMaterialInButton
    │
    ├─ 找到已有 bgImgView
    └─ configure:
        ├─ clipsToBounds = NO
        ├─ contentMode = aspectFill
        ├─ 算偏移 (有图 → 正确)
        └─ frame = (ox, oy+offset, W, H) ✅
```

与重构前完全等价，只是把内联代码移到独立方法中。

## 七、安全性分析

### 7.1 行为等价性证明

| 配置项 | 重构前 ①（create） | 重构前 ②（分支A） | 重构前 ③（回调） | 重构后（configure） | 结论 |
|:------:|:-----------------:|:----------------:|:---------------:|:------------------:|:----:|
| `clipsToBounds=NO` | 创建时设 | 每次更新设 | 没设（沿用创建值） | 每次都设 | ✅ 一致 |
| `contentMode` | 创建时设 | 每次更新设 | 没设（沿用创建值） | 每次都设 | ✅ 一致 |
| frame 含偏移 | ❌ 无偏移 | ✅ 含偏移 | ✅ 含偏移 | ✅ 含偏移 | ✅ 分支A/回调→一致，创建时偏移=0（因为无图） |
| 层级（layer==1） | 创建时 | 更新时 | 没设 | 每次都设 | ✅ 一致 |

### 7.2 回归风险矩阵

| 场景 | 风险等级 | 说明 |
|:----|:--------:|:-----|
| fillMode=0 + 三种对齐 | 🟢 无 | configure 中的偏移算法与原分支A/回调完全一致 |
| fillMode=1（适应模式） | 🟢 无 | 适应模式逻辑在 configure 之外，完全不动 |
| fillMode=2（拉伸） | 🟢 无 | contentMode 与之前一致 |
| 无素材（仅圆角） | 🟢 无 | 不经过任何修改的方法 |
| 隐藏路径 + 素材 | 🟢 无 | 隐藏路径也调 setupBackgroundMaterialInButton，覆盖到 |
| 创建后异步加载前短暂间隙 | 🟢 安全 | imageView 无图不可见，配置由回调一次性完成 |

### 7.3 特别注意点

| 关注点 | 分析 | 结论 |
|:-------|:-----|:----:|
| `create` 不再设 contentMode | 异步回调中 configure 会设，间隙极短且 imageView 无图不可见 | ✅ 安全 |
| `create` 不再 `bringSubviewToFront` | 新建时 layer=1 场景：configure 在回调中执行 bringSubviewToFront，稍晚但正确 | ✅ 安全 |
| `create` 统一 `insertSubview:atIndex:0` | layer=0 场景行为不变；layer=1 场景从"创建时 bringToFront"变为"回调中 bringToFront"，结果一致 | ✅ 安全 |
| 分支A 删除的 `ox/oy/bgW/bgH` 变量 | 检查 fillMode=1 段是否引用；如果引用则保留变量声明，不引用则删除 | ⚠️ 注意 |
