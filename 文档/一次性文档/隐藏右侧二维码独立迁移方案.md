# 隐藏右侧二维码功能独立迁移方案

---

## 一、功能现状

### 1.1 调用链路

```
SettingListCornerRadiusController.m        ← UI 开关（非卡片背景页面）
    ↓
PluginConfig.listHideRightQRCode            ← 配置属性（list 前缀，位置不合理）
    ↓
ProfileCardBgHook.m (L701-761)              ← 资料卡内二维码隐藏（3 处调用）
    ↓
WPAuxiliaryHooks.m (L164-172)               ← ★ 同一功能的冗余实现！
```

### 1.2 当前引用分布

| 文件 | 行号 | 用途 |
|:-----|:----:|:------|
| `PluginConfig.h` | L156 | `@property (nonatomic, assign) BOOL listHideRightQRCode` |
| `PluginConfig.m` | L416 | 加载: `_listHideRightQRCode = [d boolForKey:...]` |
| `PluginConfig.m` | L672 | 保存: `[d setBool:_listHideRightQRCode forKey:...]` |
| `SettingListCornerRadiusController.m` | L79-80 | UI 开关 + key 绑定 |
| `SettingListCornerRadiusController.m` | L230 | reloadBlock 的 key 判断 |
| `ProfileCardBgHook.m` | L706 | `handleCornerAndQR:` → `hideQRButtonInCell:` |
| `ProfileCardBgHook.m` | L734 | handleHiddenPath（隐藏+无素材场景） |
| `ProfileCardBgHook.m` | L759 | handleHiddenPath（隐藏+有素材场景） |
| `WPAuxiliaryHooks.m` | L164 | MMUIButton Hook 中同一功能的冗余实现 |

### 1.3 两个 QR 隐藏机制（冗余）

这个功能实际上有 **两套实现**，都在隐藏同一个"我的页面"资料卡二维码：

| 实现 | 位置 | 所属 Hook | 机制 |
|:-----|:------|:----------|:-----|
| **ProfileCardBgHook（主力）** | ProfileCardBgHook.m L99-123 | MMTableViewCell → handleButtonLayout | 遍历 button subviews, 隐藏 x > 0.7*width 的按钮 |
| **WPAuxiliaryHooks（冗余）** | WPAuxiliaryHooks.m L164-172 | MMUIButton → _hooked_MMUIButton_layoutSubviews | 按 class 名包含 "QRCode" 直接隐藏按钮本身 |

两者都在 Hook **NewMainFrameViewController**（我的页面）中的 MMUIButton，针对同一个二维码按钮。WPAuxiliaryHooks 版本是早期实现，ProfileCardBgHook 版本是后续更完善的实现。

**迁移时应直接删除 WPAuxiliaryHooks 的冗余代码，不需要移到 ProfileCardBgHook。**

```

    ↓
PluginConfig.cardBgHideRightQRCode          ← 属性重命名（cardBg 前缀）
    ↓

WPAuxiliaryHooks.m → 删除冗余的 QR 隐藏代码  ← 同一功能有两套实现，删冗余
```

**改 3 个文件：**

```

#### 1b. PluginConfig.m — 加载（L416）

```objc

// 改后
_cardBgHideRightQRCode = [d boolForKey:[kPluginPrefix stringByAppendingString:@"CardBgHideRightQRCode"]];
```

#### 1c. PluginConfig.m — 保存（L672）

```objc

```

> 用户明确说不兼容旧数据，旧 NSUserDefaults key `PluginListHideRightQRCode` 不再读取。

### 步骤 4：删除 WPAuxiliaryHooks.m 的冗余 QR 隐藏代码

WPAuxiliaryHooks.m L164-172 中的 QR 隐藏代码与 ProfileCardBgHook 的 `hideQRButtonInCell:` 功能重复，是同一功能的早期实现。

**直接删除 L164-L172：**

```objc
// 整段删除（L164-L172）：
if (config.listHideRightQRCode) {
    UIView *view = (UIView *)self;
    Class cls = [view class];
    NSString *className = NSStringFromClass(cls);
    if ([className containsString:@"QRCode"] || [className containsString:@"Qrcode"]) {
        view.hidden = YES;
        view.alpha = 0;
    }
}
```

> 这段删除可以等未来合并 WPAuxiliaryHooks 到 ListCornerRadiusHook 时一起做（参考《列表圆角模块独立化改造方案》），也可以现在就删。
>
> 现在就删的前提：ProfileCardBgHook 的 `hideQRButtonInCell:` 已经覆盖了所有场景。由于 `hideQRButtonInCell:` 是遍历 button.subviews 隐藏右侧按钮，而 WPAuxiliaryHooks 版本是直接根据 class name 隐藏按钮本身，理论上前者全覆盖后者，删除安全。

---

## 六、安全性分析

| 风险 | 影响 | 等级 | 应对 |
|:-----|:------|:----:|:------|
| **旧配置不兼容** | 已升级用户的开关状态丢失 | 🟢 | 用户明确要求不需要兼容旧数据 |
| **UI key 绑定错误** | 开关无法控制功能 | 🟡 | key 名 `cardBgHideRightQRCode` 必须与 PluginConfig 属性名一致 |
| **冗余代码残留** | WPAuxiliaryHooks 和 ProfileCardBgHook 同时执行，功能正常但代码重复 | 🟢 | 延迟到合并 WPAuxiliaryHooks 时清理即可，当前无实际影响 |
| **reloadBlock 遗漏** | 开关变化时 UI 不刷新 | 🟡 | SettingCardBackgroundController 的 reloadBlock 必须添加 key 判断 |
| **属性名误改漏改** | 编译不过 | 🟢 | 编译器会报错，无隐藏风险 |
