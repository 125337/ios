# 二维码未隐藏 — 根因分析与修复方案

## 问题现象

开启「隐藏箭码」开关后：
- ✅ **箭头**被成功隐藏
- ❌ **二维码**仍然显示

已在 `isArrowQRView:` 中新增 `isQRCodeByClassName:` 策略（检查 "QRCode"/"Qrcode"），但测试仍然无效。

---

## 根因分析

### 问题一：第三种策略的 className 检查是错的

当前的 `isQRCodeByClassName:`：

```objc
+ (BOOL)isQRCodeByClassName:(UIView *)view {
    NSString *cn = NSStringFromClass([view class]);
    return [cn containsString:@"QRCode"] || [cn containsString:@"Qrcode"];
}
```

错误的假设：认为二维码视图的类名包含 `"QRCode"` 或 `"Qrcode"`。

**实际证据**（来自旧版代码，该版本能成功隐藏二维码）：

```objc
// 旧版有效代码：[cn containsString:@"Button"] 匹配了二维码
NSString *cn = NSStringFromClass([sub class]);
if ([cn containsString:@"Button"]) {            // ← 匹配 "MMUIButton"
    CGFloat x = sub.frame.origin.x;
    if (x > sub.superview.bounds.size.width * 0.7) {  // ← 右侧 30% 区域
        sub.hidden = YES;
    }
}
```

**结论**：二维码视图的类名包含 **"Button"**（应为 `MMUIButton`），不包含 "QRCode"。

### 问题二：单层遍历 vs 递归遍历

旧版使用**递归遍历**，可以找到嵌套深层的子视图：

```objc
// 旧版：递归遍历
+ (void)hideQRButtonInCell:(UIView *)cell {
    for (UIView *sub in cell.subviews) {
        // ... 检查并隐藏 ...
        [self hideQRButtonInSubviews:sub.subviews];  // ← 递归深入
    }
}
```

新版 `hideArrowQRInCell:` 只用**单层遍历**：

```objc
+ (void)hideArrowQRInCell:(UIView *)cell {
    for (UIView *sub in cell.subviews) {  // ← 只遍历直接子视图
        if ([self isArrowQRView:sub]) {
            sub.hidden = YES;
        }
    }
}
```

如果二维码不是 `button` 的直接子视图，单层遍历找不到它。

## 修复方案

### 改动一：删除 `isQRCodeByClassName:`，替换为正确的二维码识别方法

在 `ProfileCardBgHook.m` 中：

**删除：**
```objc
+ (BOOL)isQRCodeByClassName:(UIView *)view {
    NSString *cn = NSStringFromClass([view class]);
    return [cn containsString:@"QRCode"] || [cn containsString:@"Qrcode"];
}
```

**新增：**
```objc
/// 识别资料卡右侧的二维码按钮
/// 旧版已验证：二维码是一个 MMUIButton（类名含"Button"），位于父视图右侧
+ (BOOL)isQRCodeButton:(UIView *)view {
    NSString *cn = NSStringFromClass([view class]);
    if (![cn containsString:@"Button"]) return NO;
    // 位于右侧区域（距右边界 60pt 以内）
    CGFloat x = view.frame.origin.x;
    CGFloat parentW = view.superview.bounds.size.width;
    return x >= parentW - 60;
}
```

### 改动二：更新 `isArrowQRView:` 引用新方法

```objc
+ (BOOL)isArrowQRView:(UIView *)view {
    return [self isArrowQRByAccessibilityLabel:view] ||   // → 箭头
           [self isArrowQRByFrameHeuristic:view] ||       // → 箭头（UIImageView）
           [self isQRCodeButton:view];                    // → 二维码（MMUIButton）
}
```

### 改动三：将 `hideArrowQRInCell:` 改为递归遍历

确保能发现嵌套深层的二维码视图：

```objc
+ (void)hideArrowQRInCell:(UIView *)cell {
    for (UIView *sub in cell.subviews) {
        if ([self isArrowQRView:sub]) {
            sub.hidden = YES;
        }
        // ★ 递归遍历子视图的子视图，兼容嵌套布局
        if (sub.subviews.count > 0) {
            [self hideArrowQRInCell:sub];
        }
    }
}
```

### 改动四（可选）：修复 `handleHiddenPath:` 中的冗余调用

当前 `handleHiddenPath:` 中已经在 Scene B 和 Scene A 先隐藏了所有子视图，然后才调用 `hideArrowQRInCell:`。第二次调用是多余的。

但考虑到代码可读性，可以保留第二次调用作为保障。无需改动。

| 检查项 | 预期结果 |
|---|---|
| 开启「隐藏箭码」，不开启卡片隐藏 | 箭头隐藏、二维码隐藏 |
| 开启「隐藏箭码」+ 开启卡片隐藏 | 箭头隐藏、二维码隐藏、卡片背景隐藏 |
| 开启「隐藏箭码」+ 素材 | 箭头隐藏、二维码隐藏、素材正常显示 |
| 关闭「隐藏箭码」 | 箭头显示、二维码显示 |
| 切换深浅模式 | 两种模式行为一致 |
