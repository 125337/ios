## 1. 功能概述

「开发者工具」是「其他功能」(WPOtherVC) 中的一个导航入口，点击后进入 `SettingDevToolsController`，包含以下子功能：

| 子功能 | 说明 |
|--------|------|
| **NSLog 日志监控** | 拦截 stderr 输出，捕获 NSLog 日志到内存/文件 |
| **导航监控 (VC 抓取)** | Hook UIViewController 生命周期方法 + UINavigationController 方法，记录 VC 导航日志 |
| **日志查看器** | 查看 NSLog 日志、导航日志、VC 层级树的三个只读页面 |
| **关键词过滤** | 对捕获的日志按关键词过滤 |
| **本地保存** | 将日志写入文件 `MioPlugin_NSLogs/` 目录 |
| **清空所有日志** | 清空内存中的日志缓存 |

## 6. 风险点与注意事项

### 6.1 ⚠️ 最高风险：MioNavMonitor 的 Hook 影响全局

`MioNavMonitor.m` 通过 `MSHookMessageEx` Hook 了 `UIViewController` 和 `UINavigationController` 的 **13 个方法**（viewDidLoad、viewWillAppear:、viewDidAppear:、viewWillDisappear:、viewDidDisappear:、viewWillLayoutSubviews、viewDidLayoutSubviews、pushViewController:animated:、popViewControllerAnimated:、popToViewController:animated:、popToRootViewControllerAnimated:、presentViewController:animated:completion:、dismissViewControllerAnimated:completion:）。

**删除后这些 Hook 不再安装**，不会对微信原生 VC 产生任何影响。但需要注意：这个风险是**正面的**——删除会移除这些全局 Hook，是一种改进。

### 6.2 DevToolsHook 未安装任何全局 Hook（深度分析）

`DevToolsHook.install` 的核心代码极其简单，只做了两件事：

```objc
+ (void)install {
    [MioLogMonitor sharedInstance];  // → alloc/init，仅创建空数组，无副作用
    [MioNavMonitor sharedInstance];  // → alloc/init，仅创建空数组+名称映射，无副作用
}
```

**关键点：MioLogMonitor 和 MioNavMonitor 的 init 方法不会安装任何 Hook 或重定向 stderr。** 真正的 Hook 安装需要用户手动调用 `startMonitoring` 才会触发。这个调用路径是：

```
SettingDevToolsController UI 开关 → DevToolsConfig 配置变更 → startMonitoring → 安装 Hook
```

删除开发者工具后，**没有任何代码会调用 startMonitoring**，因此：
- MioNavMonitor 的 13 个 MethodHook **永远不会被安装**
- MioLogMonitor 的 stderr 重定向 **永远不会被执行**

### 6.3 HookRegistry 的遍历机制

`HookRegistry.installAllHooks` 遍历 `FeatureModuleRegistry.allModules` 返回的数组，每个模块的 `hookInstallerClasses` 是**独立的 Class 数组**：

```
遍历模块数组 →
  general      → [RevokeHook, ClearUnreadHook, JokerHook, GroupExitHook, MessageTimeHook]
  redenvelop   → [RedEnvelopHook, AutoTransferHook]
  listcorner   → [ListCornerRadiusHook]
  layout       → [UIPurifyHook, HideAvatarHook, UIAttachLayoutHook, PlaceholderTextHook, ChatTopBarHook]
  about        → []
  devtools     → [DevToolsHook]   ← 删除后这一整项消失，不影响前后
  settingentry → [SettingEntryHook]
```

删除 devtools 模块只是减少数组中的一个元素，**其他 6 个模块的遍历和执行完全不受影响**。

### 6.4 其他模块不受影响

| 模块 | 与开发者功能的关系 | 影响评估 |
|------|-------------------|---------|
| RevokeHook（防撤回） | 无依赖 | 不受影响 |
| ClearUnreadHook（一键已读） | 无依赖 | 不受影响 |
| RedEnvelopHook（抢红包） | 无依赖 | 不受影响 |
| SettingEntryHook（插件入口） | 无依赖 | 不受影响 |
| UIPurifyHook（界面布局） | 无依赖 | 不受影响 |
| 其他所有模块 | 无依赖 | 不受影响 |

### 6.5 编译注意事项

- 这是一个 Theos 项目（通过 GitHub Actions CI 构建），Makefile 在 CI 中自动生成
- 删除文件后，CI 不会尝试编译已删除的文件，**无需修改 Makefile 或 project.pbxproj**
- Theos 的编译规则是在运行时扫描目录，删除物理文件即可
