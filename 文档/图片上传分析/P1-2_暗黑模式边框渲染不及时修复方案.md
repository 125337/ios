# P1-2 修复方案：暗黑模式边框渲染不及时

## 问题概述

用户在 iOS 系统切换浅色/深色模式后，聊天列表 Cell 的**边框颜色**和**背景颜色**不会实时更新，需要退出页面重新进入（有时需要多次）才能正确渲染。

---

## 根因分析

### 问题链路追踪

```
系统切换深浅模式
    ↓
UITraitCollection.currentTraitCollection.userInterfaceStyle 变化
    ↓
系统调用 UIView 的 traitCollectionDidChange:
    ↓
   ┌─ MMTableViewCell: ❌ 未 Hook traitCollectionDidChange: → 无反应
   │
   ├─ MainFrameSectionFoldView: ❌ 未 Hook traitCollectionDidChange: → 无反应
   │
   └─ 其他 Cell: ❌ 同上
    ↓
layoutSubviews （不会自动触发）
    ↓
wp_applyBorderAndBg: （不会被调用）
    ↓
border 颜色保持旧模式 → 边框渲染不及时 ✅ 确认问题
```

### 三个独立但叠加的 Bug

| 编号 | 问题 | 所在代码位置 | 严重程度 |
|------|------|-------------|---------|
| **B1** | 没有 Hook `traitCollectionDidChange:`，模式切换时不会触发重绘 | `ListCornerRadiusHook.m` 缺少 | 致命 — 不修复此条，其余修复无效 |
| **B2** | 边框缓存 key 不包含暗黑模式状态，即使重绘也会被缓存命中跳过 | `wp_applyBorderAndBg:` 第604行 | 严重 — 即使 layoutSubviews 被调用，缓存也会阻止重绘 |
| **B3** | 使用了 `UITraitCollection.currentTraitCollection` **全局单例**判断模式，而非当前 Cell 所在 VC 的 `traitCollection` | `wp_applyBorderAndBg:` 第625行 | 中 — 当前场景下与 B1+B2 叠加，但单独不触发 |

### 详细分析

#### B1：缺少 traitCollectionDidChange Hook

当 iOS 系统切换深浅模式时，对**已经显示在屏幕上的 Cell**，系统会调用：

```objc
- (void)traitCollectionDidChange:(UITraitCollection *)previousTraitCollection;
```

但 `ListCornerRadiusHook.m` 只 Hook 了 `layoutSubviews`，没有 Hook `traitCollectionDidChange:`。而 `layoutSubviews` **不会被系统自动调用** — 它只在 frame 变化、addSubview、滚动复用等场景触发。

**结果**：模式切换后，已显示在屏幕上的 Cell 完全没有任何代码去更新边框和背景。

#### B2：缓存 Key 遗漏暗黑模式

`wp_applyBorderAndBg:` 第604-607行：

```objc
NSString *cacheKey = [NSString stringWithFormat:@"r%ld-p%ld-f%d-b%.1f",
                      (long)radius, (long)position, isFTSHome,
                      config.listCellBorderWidth];
```

当前 key 只考虑：radius、position、isFTSHome、borderWidth。

**缺少 `isDark`**。这意味着：

- 浅色模式下首次绘制 → cacheKey = `r18-p0-f0-b1.0`
- 切换到深色 → 即使偶然触发重新调用 `wp_applyBorderAndBg:`，cacheKey 仍然是 `r18-p0-f0-b1.0`
- 第607行 `if ([existingCacheKey isEqualToString:cacheKey]) return;` → **缓存命中，跳过绘制**
- 边框颜色保持不变

结果：**即使修复了 B1，B2 也会阻止边框正确更新**。必须同时修复。

#### B3：全局 isDarkMode vs 局部 isDarkModeForViewController

`wp_applyBorderAndBg:` 第625行：

```objc
BOOL isDark = [WPUtility isDarkMode];
```

`[WPUtility isDarkMode]` 内部使用：

```objc
UITraitCollection.currentTraitCollection.userInterfaceStyle
```

这是一个**全局单例**。在 `layoutSubviews` 被调用时（例如 Cell 滚动复用），`currentTraitCollection` 的值是正确的。但作为规范来说，更推荐使用当前 VC 的 `traitCollection`。

**影响评估**：当前场景下 B3 本身不触发问题（因为 `currentTraitCollection` 在 layoutSubviews 执行时通常已经是更新后的值）。但修复 B1+B2 后，建议一并修正，使逻辑更规范。

### 为什么退出重进就正常？

```
退出页面 → Cell 被回收 dealloc
重新进入 → 创建新 Cell → layoutSubviews 被调用
    → 此时 `[WPUtility isDarkMode]` 返回新模式的值
    → 边框和背景正确渲染 ✅
```

### 为什么有时候需要多次？

```
如果 TableView 的 Cell 被重用了：
  第一次退出 → 部分 Cell 进入 reuse pool（未 dealloc）
  重新进入 → 从 reuse pool 取出（layoutSubviews 可能不被调用）
  第二次退出 → reuse pool 的 Cell 被 dealloc
  第二次进入 → 全新创建 → 正常 ✅
```

## 修复方案

### 总体改动

| 文件 | 操作 | 说明 |
|------|------|------|
| `ListCornerRadiusHook.m` | 新增 + 修改 | 新增 `traitCollectionDidChange:` Hook；修改缓存 key；优化 isDark 判断 |

### Step 1：新增 `traitCollectionDidChange:` Hook

**文件**：`Modules/ListCornerRadius/ListCornerRadiusHook.m`

在 `replaced_MMTableViewCell_layoutSubviews` 函数定义之后（或之前），新增一个独立的 C 函数：

```objc
// ★★★ 暗黑模式切换：重新应用边框和背景 ★★★
static void (*orig_MMTableViewCell_traitCollectionDidChange)(id, SEL, UITraitCollection *);
static void replaced_MMTableViewCell_traitCollectionDidChange(id self, SEL _cmd, UITraitCollection *previousTraitCollection) {
    // 先调用原始实现（必须）
    if (orig_MMTableViewCell_traitCollectionDidChange) {
        orig_MMTableViewCell_traitCollectionDidChange(self, _cmd, previousTraitCollection);
    }

    // 检查是否是 appearance 变化（浅色↔深色）
    if (@available(iOS 13.0, *)) {
        if (![((UIView *)self).traitCollection hasDifferentColorAppearanceComparedToTraitCollection:previousTraitCollection]) {
            return; // 不是深浅切换，忽略
        }
    } else {
        return; // iOS 12 以下不支持
    }

    // 验证开关
    ListCornerRadiusConfig *config = [ListCornerRadiusConfig shared];
    if (!config.globalCornerRadiusEnabled) return;

    // 验证所属 VC
    UIViewController *vc = [WPUtility findParentViewController:(UIView *)self];
    if (!vc) return;
    if (![CornerResponsibility isListCornerResponsibleFor:vc]) return;

    // 强制清除边框缓存：删除已有 border layer
    UIView *cellView = (UIView *)self;
    NSArray *oldSublayers = [cellView.layer.sublayers copy];
    for (CALayer *sub in oldSublayers) {
        if ([sub.name isEqualToString:@"com.mio.cornerBorder"]) {
            [sub removeFromSuperlayer];
        }
    }
    // 清除关联的缓存 key（关键！让下次调用 wp_applyBorderAndBg 不命中缓存）
    static NSString *kBorderCacheKey = @"com.mio.cornerBorderCache";
    objc_setAssociatedObject(cellView, (__bridge const void *)kBorderCacheKey, nil, OBJC_ASSOCIATION_RETAIN_NONATOMIC);

    // 强制重新设置背景色
    NSString *className = NSStringFromClass([vc class]);
    static NSSet *bgColorSkipList = nil;
    static dispatch_once_t onceBgToken;
    dispatch_once(&onceBgToken, ^{
        bgColorSkipList = [NSSet setWithObjects:
            @"WCTimeLineViewController", @"WCAccountLoginUsersViewController",
            @"SessionSelectController", @"WCListViewController",
            @"BrandNotificationListViewController", @"BrandNewSessionViewController",
            @"BaseMsgContentViewController", @"BraceletRankProfileViewController",
            @"BraceletRankViewController", @"WCRedEnvelopesRedEnvelopesDetailViewController",
            @"MsgRecordDetailViewController", @"ChatRoomInfoViewController",
            @"ContactInfoViewController", @"AddFriendEntryViewController",
            @"AddContactToChatRoomViewController", @"SayHelloViewController",
            @"FTSHomeViewController", @"MMFinderPivotLiveViewController",
            @"WCSearchController", nil];
    });
    if (![bgColorSkipList containsObject:className]) {
        BOOL isDark = [WPUtility isDarkModeForViewController:vc];
        UIColor *customBg = isDark
            ? [WPColorUtil colorFromHexString:config.listCellDarkBgColor]
            : [WPColorUtil colorFromHexString:config.listCellLightBgColor];
        cellView.backgroundColor = customBg ?: (isDark
            ? [UIColor colorWithRed:0.125 green:0.125 blue:0.125 alpha:1.0]
            : [UIColor whiteColor]);
    }

    // 强制重新设置边框
    // ★ 复用 layoutSubviews 中已有的 corner/position 计算逻辑
    // ★ 但 layoutSubviews 不能直接调用，因为原逻辑中包含 orig_layoutSubviews（frame 计算等）
    // ★ 改用 setNeedsLayout，让系统在下一帧调用 layoutSubviews
    [cellView setNeedsLayout];
}
```

> **注意**：为什么最后用 `setNeedsLayout` 而不是直接调用边框设置方法？
>
> 因为 `replaced_MMTableViewCell_layoutSubviews` 中包含以下步骤：
> 1. margin 计算（frame 调整）
> 2. `orig_MMTableViewCell_layoutSubviews`（原始实现）
> 3. backgroundColor 设置
> 4. corner 圆角计算（需要 indexPath、tableView 等上下文）
> 5. `wp_applyBorderAndBg:` 调用
>
> 这些逻辑散布在 layoutSubviews 中，难以从中独立抽取出「仅更新颜色」的部分。使用 `setNeedsLayout` 是最安全的方式 — 系统会在下一帧调用 layoutSubviews，此时：
> - `UITraitCollection.currentTraitCollection` 已更新 ✅
> - 第604行缓存 key 因为加了 `isDark` 会 miss ✅
> - 所有颜色将按新模式重新设置 ✅

### Step 2：修复边框缓存 Key，加入暗黑模式

**文件**：`Modules/ListCornerRadius/ListCornerRadiusHook.m`

**修改前**（第604-607行）：

```objc
NSString *cacheKey = [NSString stringWithFormat:@"r%ld-p%ld-f%d-b%.1f",
                      (long)radius, (long)position, isFTSHome,
                      config.listCellBorderWidth];
```

**修改后**：

```objc
BOOL isDark = [WPUtility isDarkMode];
NSString *cacheKey = [NSString stringWithFormat:@"r%ld-p%ld-f%d-b%.1f-d%d",
                      (long)radius, (long)position, isFTSHome,
                      config.listCellBorderWidth, isDark];
```

改动点：在 key 末尾添加 `-d%d`（isDark 的缩写 d），使浅色/深色模式产生不同的缓存 key。

**注意**：`isDark` 必须使用 `[WPUtility isDarkMode]`（全局单例）而非 `isDarkModeForViewController:`，因为 `wp_applyBorderAndBg:` 是 C 函数而非方法，没有 VC 上下文。

### Step 3：在 install 方法中注册新的 Hook

**文件**：`Modules/ListCornerRadius/ListCornerRadiusHook.m`

在 `install` 方法的 `HookTableItem` 数组中新增一项：

```objc
+ (void)install {
    HookTableItem items[] = {
        // ... 现有条目保持不变 ...
        {@"MMTableViewCell", @"layoutSubviews",
            (IMP)replaced_MMTableViewCell_layoutSubviews, &orig_MMTableViewCell_layoutSubviews},
        // ★★★ 新增：暗黑模式切换监听 ★★★
        {@"MMTableViewCell", @"traitCollectionDidChange:",
            (IMP)replaced_MMTableViewCell_traitCollectionDidChange,
            (IMP *)&orig_MMTableViewCell_traitCollectionDidChange},
        // ... 其他现有条目 ...
    };

    [HookEngine installHookTable:@"ListCorner" items:items
                           count:sizeof(items) / sizeof(items[0])];
}
```

### Step 4：MainFrameSectionFoldView 同样问题修复（可选但推荐）

**文件**：`Modules/ListCornerRadius/ListCornerRadiusHook.m`

`MainFrameSectionFoldView` 的 `_hooked_FoldView_layoutSubviews`（第295行）中也设置了边框和背景色，同样缺少深浅切换监听。按相同方式修复：

在 `replaced_MMTableViewCell_traitCollectionDidChange` 函数附近新增：

```objc
// ★★★ 暗黑模式切换：FoldView 重新应用边框和背景 ★★★
static void (*orig_FoldView_traitCollectionDidChange)(id, SEL, UITraitCollection *);
static void replaced_FoldView_traitCollectionDidChange(id self, SEL _cmd, UITraitCollection *previousTraitCollection) {
    if (orig_FoldView_traitCollectionDidChange) {
        orig_FoldView_traitCollectionDidChange(self, _cmd, previousTraitCollection);
    }

    if (@available(iOS 13.0, *)) {
        if (![((UIView *)self).traitCollection hasDifferentColorAppearanceComparedToTraitCollection:previousTraitCollection]) {
            return;
        }
    } else {
        return;
    }

    ListCornerRadiusConfig *config = [ListCornerRadiusConfig shared];
    if (!config.globalCornerRadiusEnabled) return;

    // 清除旧 border layer
    UIView *foldView = (UIView *)self;
    NSArray *oldSublayers = [foldView.layer.sublayers copy];
    for (CALayer *sub in oldSublayers) {
        if ([sub.name isEqualToString:@"com.mio.cornerBorder"]) {
            [sub removeFromSuperlayer];
        }
    }
    static NSString *kBorderCacheKey = @"com.mio.cornerBorderCache";
    objc_setAssociatedObject(foldView, (__bridge const void *)kBorderCacheKey, nil, OBJC_ASSOCIATION_RETAIN_NONATOMIC);

    [foldView setNeedsLayout];
}
```

在 `install` 方法的数组中也新增一项：

```objc
{@"MainFrameSectionFoldView", @"traitCollectionDidChange:",
    (IMP)replaced_FoldView_traitCollectionDidChange,
    (IMP *)&orig_FoldView_traitCollectionDidChange},
```

### Step 5：修复 wp_applyBorderAndBg 中的 isDark 判断方式（可选）

**文件**：`Modules/ListCornerRadius/ListCornerRadiusHook.m`

当前（第625行）：

```objc
BOOL isDark = [WPUtility isDarkMode];
```

这个调用出现在 `wp_applyBorderAndBg:` 方法内部。该方法是一个类方法，被 `wp_applyStandardCorner:` 和 `wp_applyCornerForContacts:` 调用，这些调用者**确实没有 VC 上下文**。

但我们可以利用 `cell` 参数来推断 VC：

```objc
// 使用 cell 推断所属 VC，获取更精确的 traitCollection
UIViewController *vc = [WPUtility findParentViewController:cell];
BOOL isDark = vc
    ? [WPUtility isDarkModeForViewController:vc]
    : [WPUtility isDarkMode];
```

**注意**：这个改动不是必须的（`currentTraitCollection` 在 layoutSubviews 中通常已更新），只是一个代码质量优化。如果希望改动最小化，可以只做 Step 1-3。

## 附录：关键代码片段对照

### 修改前（Bug 状态）

```
layoutSubviews 被调用 → 边框颜色 = isDark ? 深色 : 浅色

系统切换模式
    ↓
traitCollectionDidChange → 无 Hook → 无反应
    ↓
layoutSubviews 不触发 → 边框不更新
    ↓
缓存 key = r18-p0-f0-b1.0（不区分深浅）
```

### 修改后（修复状态）

```
layoutSubviews 被调用 → 边框颜色 = isDark ? 深色 : 浅色

系统切换模式
    ↓
traitCollectionDidChange: → Hook 捕获
    ↓
判断 hasDifferentColorAppearanceComparedToTraitCollection:
    ↓
是深浅切换 → ① 清除旧 border layer
             ② 清除关联缓存 key
             ③ 更新 backgroundColor
             ④ setNeedsLayout
    ↓
下一帧 layoutSubviews 被调用
    ↓
wp_applyBorderAndBg: 执行
    ↓
缓存 key = r18-p0-f0-b1.0-d1（深色） ≠ 旧缓存 r18-p0-f0-b1.0-d0（浅色）
    ↓
缓存 miss → 绘制新颜色的边框 ✅
```
