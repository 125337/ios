# P1-1 修复方案：统一暗黑模式判断

## 问题概述

当前项目存在 **3 套不同的暗黑模式判断实现**，且其中一套（`isWeChatDarkMode`）在微信 8.0.55 头文件中已找不到对应类，存在兼容性风险。

### 现状

| 实现 | 文件 | 行号 | 方式 | 状态 |
|------|------|------|------|------|
| `wp_isDarkMode()` / `wp_isDarkModeForVC` | `ListCornerRadiusHook.m` | 12-24 | `UITraitCollection.currentTraitCollection` | ✅ 可用 |
| `wp_isDarkModeForVC` | `ProfileCardBgHook.m` | 10-15 | `UITraitCollection.currentTraitCollection` | ✅ 可用 |
| `isWeChatDarkMode()`（通过 WCThemeMgr） | `MessageTimeHook.m` | 27-41 | **通过微信私有类 `WCThemeMgr`** | **⚠️ 微信头文件中已找不到 `WCThemeMgr`，可能在新版微信中失效** |

### 已存在的统一方法

`WPUtility` 中已提供：

```objc
// WPUtility.h 第23行
+ (BOOL)isDarkModeForViewController:(UIViewController *)vc;
```

已有多处代码在使用（`ListCornerRadiusHook.m` 第200/268/293/355行），说明该方法正常工作。

但 `WPUtility` **缺少一个无参数的 `isDarkMode` 类方法**用于不需要 VC 上下文的场景。

---

## 目标

- 删除 3 处重复实现（共 ~30 行）
- 所有模块统一调用 `[WPUtility isDarkModeForViewController:vc]` 或 `[WPUtility isDarkMode]`
- 消除 `isWeChatDarkMode()` 的兼容性风险

---

## 详细修改步骤

### Step 1：在 WPUtility 中补充 `isDarkMode` 方法

**文件**: `Core/WPUtility.h`

在现有 `isDarkModeForViewController:` 声明之后添加：

```objc
/// 检测当前是否为暗黑模式（不需要 VC 上下文时使用）
/// 基于 UITraitCollection.currentTraitCollection
/// @return YES 表示暗黑模式，NO 表示普通模式
+ (BOOL)isDarkMode;
```

**文件**: `Core/WPUtility.m`

在 `@implementation WPUtility` 中添加实现：

```objc
+ (BOOL)isDarkMode {
    if (@available(iOS 13.0, *)) {
        return UITraitCollection.currentTraitCollection.userInterfaceStyle == UIUserInterfaceStyleDark;
    }
    return NO;
}
```

---

### Step 2：删除 ListCornerRadiusHook.m 的重复实现

**文件**: `Modules/ListCornerRadius/ListCornerRadiusHook.m`

#### 2.1 删除 wp_isDarkMode 和 wp_isDarkModeForVC

**删除第12-24行**（`wp_isDarkMode()` 和 `wp_isDarkModeForVC()` 完整定义）。

#### 2.2 检查调用处

该文件已有多处使用 `[WPUtility isDarkModeForViewController:vc]`：

```objc
// 第200行
BOOL isDark = [WPUtility isDarkModeForViewController:vc];
// 第268行
BOOL isDark = [WPUtility isDarkModeForViewController:vc];
// 第293行
BOOL isDark = [WPUtility isDarkModeForViewController:vc];
// 第355行
BOOL isDark = [WPUtility isDarkModeForViewController:vc];
```

搜索是否有仍使用 `wp_isDarkMode()` 或 `wp_isDarkModeForVC()` 的残留调用：

```bash
grep -n "wp_isDarkMode\|wp_isDarkModeForVC" ListCornerRadiusHook.m
```

如果找到，替换为对应的 `[WPUtility isDarkMode]` 或 `[WPUtility isDarkModeForViewController:vc]`。

---

### Step 3：删除 ProfileCardBgHook.m 的重复实现

**文件**: `Modules/ProfileCardBg/ProfileCardBgHook.m`

#### 3.1 删除 wp_isDarkModeForVC

**删除第10-15行**（`wp_isDarkModeForVC` 定义）。

#### 3.2 替换调用处

搜索使用 `wp_isDarkModeForVC` 的代码，全部改为 `[WPUtility isDarkModeForViewController:vc]`。

---

### Step 4：迁移 MessageTimeHook.m 的 isWeChatDarkMode

**文件**: `Modules/MessageTime/MessageTimeHook.m`

#### 4.1 删除 isWeChatDarkMode

**删除第27-41行**（`isWeChatDarkMode()` 完整定义，通过 `WCThemeMgr` 的方式已无法在头文件中确认）。

#### 4.2 替换所有调用

| 原代码 | 行号 | 替换为 |
|--------|------|--------|
| `isWeChatDarkMode()` | 56 | `[WPUtility isDarkModeForViewController:nil]` 或 `[WPUtility isDarkMode]` |
| 其他使用了 `isWeChatDarkMode()` 的位置 | — | 同上 |

**关于 VC 参数的说明**:

如果调用处没有 VC 上下文（在 C 函数中），使用 `[WPUtility isDarkMode]`。如果在 Objective-C 方法中且有 `self` 可获取 VC，优先使用 `[WPUtility isDarkModeForViewController:vc]`。

`MessageTimeHook.m` 中 `isWeChatDarkMode()` 的调用在第56行的 `autoDarkColor` 函数中，这是一个不接收 VC 参数的 C 函数，所以使用 `[WPUtility isDarkMode]` 即可。

---

### Step 5：编译验证

1. 确认 `ListCornerRadiusHook.m` 不再引用 `wp_isDarkMode` / `wp_isDarkModeForVC`
2. 确认 `ProfileCardBgHook.m` 不再引用 `wp_isDarkModeForVC`
3. 确认 `MessageTimeHook.m` 不再引用 `isWeChatDarkMode` / `WCThemeMgr`
4. 编译项目，确认无警告、无错误
