# 布局功能实现后插件入口消失 — 诊断与修复

## 一、现象

| 现象 | 说明 |
|------|------|
| 微信内插件设置入口消失 | 原来界面底部的"Mio助手"整个页面不见了 |
| 日志仅有一条 | `[2026-06-12 13:27:02][GroupExit] [GroupExitHook] startMonitoring` |
| 没有 MioModuleRegistry 日志 | 看不到任何 `[MioPlugin][ModuleRegistry] ...` 输出 |

MioModuleRegistry 正常情况下会在日志中输出约 20 行，包括：

```
[MioPlugin][ModuleRegistry] registerAll start
[MioPlugin][ModuleRegistry] ✓ config registered: FontLayoutConfig
...
[MioPlugin][ModuleRegistry] ✓ hook installed: SettingEntryHook
...
[MioPlugin][ModuleRegistry] registerAll complete: ...
```

这些日志全部消失，说明 `registerAll` 没有执行完毕。

---

## 二、根因分析

### 2.1 流程图解

```
dylib 被 Substrate 注入到微信进程
    │
    ├── Tweak.m constructor
    │      └── MioModuleRegistry.registerAll()
    │             │
    │             ├── 第 1 步: 注册 Config 模块     ✓ 成功
    │             │      (只是把 class 添加到数组中)
    │             │
    │             ├── 第 2 步: loadAll 加载配置     ★ 崩溃
    │             │      ├── 处理 FontLayoutConfig 时
    │             │      └── [instance setValue:@(16) forKey:@"globalFontSize"]
    │             │              │
    │             │              └── KVC 崩溃: NSUnknownKeyException
    │             │                     原因: @dynamic → 没有 ivar → 没有 setter
    │             │
    │             └── 第 3 步: 安装 Hook(含SettingEntry)  ← 永远走不到
    │                    └── SettingEntryHook 不执行
    │                           └── MioPluginEntryVC 不创建
    │                                  └── 插件入口消失
    │
    └── GroupExit 15秒后 dispatch_after 执行
           └── startMonitoring 日志出现
```

### 2.2 直接原因 — @dynamic 导致 KVC 崩溃

**崩溃点**在 `ConfigManager.loadAll`：

```objc
// ConfigManager.m line 18-54
+ (void)loadAll {
    for (Class<ConfigModule> cls in s_registeredModules) {
        id instance = [cls shared];
        for (ConfigDescriptor *desc in [cls descriptors]) {
            ...
            [instance setValue:desc.defaultValue forKey:desc.key];  // ← 崩溃
        }
    }
}
```

当处理到 `FontLayoutConfig` 时，`desc.key = @"globalFontSize"`，`desc.defaultValue = @(16.0f)`，代码执行 `[instance setValue:@(16) forKey:@"globalFontSize"]`。

**崩溃链**：

```
setValue:forKey:@"globalFontSize"
    → 找 setGlobalFontSize: 方法    → @dynamic 无合成 → 不存在
    → 找 _globalFontSize ivar       → @dynamic 无合成 → 不存在
    → 找 globalFontSize ivar        → @dynamic 无合成 → 不存在
    → setValue:forUndefinedKey:      → 抛出 NSUnknownKeyException
        
    *** Terminating app due to uncaught exception 'NSUnknownKeyException',
    reason: '[<FontLayoutConfig 0x...> setValue:forUndefinedKey:]:
    this class is not key value coding-compliant for the key globalFontSize.'
```

`ConfigManager.loadAll` **没有**被 `@try/@catch` 包裹，这个异常未被捕获，直接导致 `registerAll` 中断。

### 2.3 为什么 GroupExit 日志出现了？

GroupExitHook 的 `startMonitoring` 是在一个 `dispatch_after(15秒)` 中执行的（在 GroupExitHook.install 中注册）。但这次日志出现不代表 Hook 被安装了？

**实际上**：这次的日志文件可能是**上一次运行（未改代码前）**残留的。或者说，用户看到的日志来自同一个 dylib 的不同加载阶段。更可能的情况是：

1. 用户编译前的旧版本 Dylib 中，GroupExit 正常工作
2. 用户编译发布了新版本 Dylib（包含 FontLayout）
3. 微信杀死后重启，Substrate 注入新 Dylib
4. `registerAll` → `loadAll` → **崩溃** → 进程可能立即崩溃/挂起
5. 微信检测到异常，重新启动
6. 再次注入，再次崩溃... 循环
7. 最终微信禁用该 dylib（Substrate 安全机制），或进程不再加载它
8. 用户看到的日志是某次加载后 15 秒才执行了 GroupExit 的 dispatch，而此时 registerAll 已崩溃

或者更简单：该日志来自 **未修改前的旧 dylib**，用户改完后编译安装，新 dylib 的崩溃导致整个插件功能消失。

### 2.4 对比：其他 Config 为什么没这个问题

查看项目中其他 Config 的实现：

```objc
// UIPurifyConfig.m (正确做法)
@implementation UIPurifyConfig
// ... 没有 @dynamic，也没有 @synthesize
// 编译器自动合成 ivar + getter + setter
```

```objc
// FontLayoutConfig.m (错误做法)
@dynamic globalLayoutEnabled;   // ← 告诉编译器"别合成，运行时再提供"
@dynamic globalFontSize;        //    但运行时也没提供 → KVC 崩溃
@dynamic chatLayoutEnabled;
@dynamic chatFontSize;
```

项目中所有其他 Config 类的属性都没有使用 `@dynamic`，都依赖编译器的自动合成。

## 三、修复方案

### 3.1 修复 #1（关键）：删除 @dynamic（5 秒修复）

**文件**：`/www/wwwroot/ios/MioPlugin/Modules/FontLayout/FontLayoutConfig.m`

**操作**：删除第 31-34 行的 `@dynamic` 语句

```objc
// ──── 删除以下 4 行 ────
@dynamic globalLayoutEnabled;
@dynamic globalFontSize;
@dynamic chatLayoutEnabled;
@dynamic chatFontSize;
```

**原理**：在 Modern Objective-C（64-bit, iOS）中，`@property` 不加 `@dynamic`/`@synthesize` 时，编译器会自动：
1. 创建 ivar `_globalFontSize`（`CGFloat` 类型）
2. 创建 getter `- (CGFloat)globalFontSize`
3. 创建 setter `- (void)setGlobalFontSize:(CGFloat)fontSize`

这样 `ConfigManager.loadAll` 调用 `[instance setValue:@(16) forKey:@"globalFontSize"]` 时，KVC 能找到 `_globalFontSize` ivar，正常赋值。

**修复后代码**：

```objc
// FontLayoutConfig.m
#import "FontLayoutConfig.h"

@implementation FontLayoutConfig

+ (instancetype)shared {
    static FontLayoutConfig *instance = nil;
    static dispatch_once_t onceToken;
    dispatch_once(&onceToken, ^{
        instance = [[FontLayoutConfig alloc] init];
    });
    return instance;
}

+ (NSString *)modulePrefix {
    return @"FontLayout_";
}

+ (NSArray<ConfigDescriptor *> *)descriptors {
    return @[
        [ConfigDescriptor itemWithKey:@"globalLayoutEnabled" type:ConfigValueTypeBool default:@(NO)],
        [ConfigDescriptor itemWithKey:@"globalFontSize"      type:ConfigValueTypeFloat default:@(16.0f)],
        [ConfigDescriptor itemWithKey:@"chatLayoutEnabled"   type:ConfigValueTypeBool default:@(NO)],
        [ConfigDescriptor itemWithKey:@"chatFontSize"        type:ConfigValueTypeFloat default:@(16.0f)],
    ];
}

// ★ 删除 @dynamic，让编译器自动合成 ivar + getter + setter

@end
```

### 3.2 修复 #2（增强防御）：给 loadAll 加 @try/@catch

为了避免未来其他 Config 也出现类似问题导致整个插件崩溃，建议给 `loadAll` 增加异常保护。

**文件**：`/www/wwwroot/ios/MioPlugin/Core/ConfigManager.m`

**修改**：将第 18-54 行的 `loadAll` 方法用 `@try/@catch` 包裹

```objc
+ (void)loadAll {
    for (Class<ConfigModule> cls in s_registeredModules) {
        @try {  // ★ 添加 try/catch 保护单个模块
            id instance = [cls shared];
            for (ConfigDescriptor *desc in [cls descriptors]) {
                NSString *fullKey = [kPluginPrefix stringByAppendingFormat:@"%@%@", [cls modulePrefix], desc.key];
                NSUserDefaults *d = [NSUserDefaults standardUserDefaults];
                id raw = [d objectForKey:fullKey];

                if (raw) {
                    switch (desc.type) {
                        case ConfigValueTypeBool:
                            [instance setValue:@([raw boolValue]) forKey:desc.key];
                            break;
                        case ConfigValueTypeInteger:
                            [instance setValue:@([raw integerValue]) forKey:desc.key];
                            break;
                        case ConfigValueTypeFloat:
                            [instance setValue:@([raw floatValue]) forKey:desc.key];
                            break;
                        case ConfigValueTypeString:
                            [instance setValue:([(NSString *)raw length] > 0 ? raw : desc.defaultValue) forKey:desc.key];
                            break;
                        case ConfigValueTypeArray:
                            [instance setValue:(raw ?: desc.defaultValue) forKey:desc.key];
                            break;
                    }
                } else {
                    [instance setValue:desc.defaultValue forKey:desc.key];
                }
            }

            if ([cls respondsToSelector:@selector(loadArchivedData)]) {
                [cls loadArchivedData];
            }
        } @catch (NSException *e) {
            NSLog(@"[MioPlugin][ConfigManager] ✗ loadAll failed for %@: %@ - %@",
                  cls, e.name, e.reason);
        }
    }
}
```

### 3.3 修复 #3（可选）：从文档中移除 @dynamic 说明

**文件**：`/www/wwwroot/ios/文档/布局功能/2-项目布局功能适配实现方案.md`

找到"`@dynamic` 让 `ConfigManager` 自动合成 getter/setter"这段说明并删除。这个说法本身就是错误的：
- `@dynamic` 不是"让 ConfigManager 自动合成"，而是"不让编译器合成" 
- ConfigManager 使用 KVC（`setValue:forKey:`）来赋值的
- KVC 依赖于 ivar 或 setter 的存在，`@dynamic` 恰恰阻止了这一切

## 六、根本原因总结

```
┌──────────────────────────────────────────────────┐
│  根因：@dynamic 在 FontLayoutConfig 中的误用     │
├──────────────────────────────────────────────────┤
│                                                    │
│  @dynamic                                          │
│     ↓                                              │
│  编译器不合成 ivar                                  │
│     ↓                                              │
│  KVC setValue:forKey: 找不到存储                    │
│     ↓                                              │
│  NSUnknownKeyException 抛出                         │
│     ↓                                              │
│  ConfigManager.loadAll 无 @try/@catch 保护           │
│     ↓                                              │
│  registerAll 中断，第 3 步永远不执行                 │
│     ↓                                              │
│  SettingEntryHook 从未安装                          │
│     ↓                                              │
│  MioPluginEntryVC 不创建                            │
│     ↓                                              │
│  微信设置中 Mio助手 入口消失                         │
└──────────────────────────────────────────────────┘
```

**一句话修复**：删除 `FontLayoutConfig.m` 中的 `@dynamic` 行即可。
