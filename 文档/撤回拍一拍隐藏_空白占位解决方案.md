## 一、微信优化为什么不会污染父类

### 1.1 MSHookMessageEx 的工作方式

```
MSHookMessageEx(ClassX, @selector(foo), replacement, &orig)
```

- 如果 ClassX **重写了** `foo`（有自己的 IMP，与父类不同）：
  → 修改 ClassX 方法表中的 `foo` 条目
  → 只影响 ClassX 及其子类中**未重写** `foo` 的类
  → 父类不受影响 ✓

- 如果 ClassX **继承了** `foo`（与父类 IMP 相同）：
  → MSHookMessageEx 会在 ClassX 方法表中**新增** `foo` 条目
  → 但新增的条目可能错误地引用/修改了父类的方法表
  → **父类和所有兄弟类都被污染** ✗
```

### 1.2 微信优化能正常工作的原因

在微信优化所针对的微信版本中：

```
BaseMessageCellView           ← 定义了 measure:、shouldLayoutIfNeeded
├── CommonMessageCellView     ← 重写了这些方法（有自己的 IMP）
├── SystemMessageCellView     ← 重写了这些方法（有自己的 IMP）✓ 可安全 Hook
└── AppPatMessageCellView     ← 重写了这些方法（有自己的 IMP）✓ 可安全 Hook
```

而在**你的微信版本中**：

```
BaseMessageCellView           ← 定义了 measure:、shouldLayoutIfNeeded
├── CommonMessageCellView     ← 可能继承或重写
├── SystemMessageCellView     ← 继承了（未重写）！← 直接 Hook 污染父类
└── AppPatMessageCellView     ← 继承了（未重写）！← 直接 Hook 污染父类
```

**结论：** 微信版本差异导致 `SystemMessageCellView` 在你版本中没有重写 `measure:` 和 `shouldLayoutIfNeeded`，直接 `MSHookMessageEx` 向上污染了父类 `BaseMessageCellView`，进而影响 `CommonMessageCellView` 等所有普通消息 Cell。

## 二、为什么会产生空白占位

隐藏 Cell 但不起效的原因是 **高度仍然为非零**：

```
┌──────────────────────────────────────────┐
│  TableView 的消息 Cell 显示流程            │
├──────────────────────────────────────────┤
│                                          │
│  1. heightForRowAtIndexPath:             │
│       │                                  │
│       ▼                                  │
│  2. ViewModel.measure: → 返回 CGSize     │
│       │                                  │
│       ├─ 未 hook → 原始高度 (如 44pt)     │
│       │    → TableView 分配 44pt 空间     │
│       │    → Cell 被 setHidden:YES        │
│       │    → 视觉不可见但空间仍在 → 空白！  │
│       │                                  │
│       └─ hook 成功 → CGSizeZero          │
│            → TableView 分配 0pt 空间      │
│            → Cell 完全不存在 → 无空白 ✓    │
│                                          │
└──────────────────────────────────────────┘
```

当前 `measure:` 被跳过 → Cell 保持原始高度 → `setHidden:YES` 只隐藏视觉，不释放空间。

## 三、最佳解决方案：`class_addMethod` + `MSHookMessageEx`

### 3.1 核心思路

```
┌──────────────────────────────────────────────────┐
│  对 inherited（继承）方法的安全 Hook 流程            │
├──────────────────────────────────────────────────┤
│                                                  │
│  1. purifyIsOverridden(cls, sel) → NO            │
│     → 方法继承自父类，不能直接 Hook                 │
│                                                  │
│  2. class_addMethod(cls, sel,                    │
│        父类的 IMP, 类型编码)                       │
│     → 在 SystemMessageViewModel 方法表中          │
│       创建一份独立的副本（指向父类 IMP）              │
│     → 此时 SystemMessageViewModel 拥有了自己的      │
│       measure: 实现，不再是继承                    │
│                                                  │
│  3. MSHookMessageEx(cls, sel,                    │
│        replacement, &orig)                       │
│     → Hook 的是 SystemMessageViewModel 的副本     │
│     → 父类方法表完全未动                          │
│     → CommonMessageCellView 不受影响 ✓            │
│                                                  │
└──────────────────────────────────────────────────┘
```

### 3.2 代码实现

新增一个安全的 Hook 辅助函数：

```objc
/// 安全 Hook：如果方法被继承（未重写），先用 class_addMethod 创建本地副本隔离父类，再 Hook
/// @return YES 表示 Hook 成功，NO 表示跳过（类不存在等）
static BOOL purifySafeHook(Class cls, SEL sel, IMP replacement, IMP *orig) {
    if (!cls) return NO;

    // 获取类型编码（从父类方法中提取）
    Method parentMethod = class_getInstanceMethod(class_getSuperclass(cls), sel);
    if (!parentMethod) {
        // 没有父类方法，调用 MSHookMessageEx 由 substrate 处理
        MSHookMessageEx(cls, sel, replacement, orig);
        return YES;
    }

    const char *types = method_getTypeEncoding(parentMethod);

    if (purifyIsOverridden(cls, sel)) {
        // 类已重写 → 直接 Hook，安全（参考微信优化）
        MSHookMessageEx(cls, sel, replacement, orig);
    } else {
        // 类继承了父类方法 → 先用 class_addMethod 创建本地副本隔离
        IMP parentIMP = method_getImplementation(parentMethod);
        if (!class_addMethod(cls, sel, parentIMP, types)) {
            // class_addMethod 失败（方法已存在但 IMP 相同？）
            // 回退：仍然尝试 Hook（由 MSHookMessageEx 处理边界情况）
            MSHookMessageEx(cls, sel, replacement, orig);
        } else {
            // 本地副本创建成功 → Hook 这个本地副本，父类不受影响
            MSHookMessageEx(cls, sel, replacement, orig);
        }
    }
    return YES;
}
```

### 3.3 在 install 中应用

```objc
// ——— 隐藏撤回消息：SystemMessageCellView + SystemMessageViewModel ———
{
    Class cls = objc_getClass("SystemMessageCellView");
    if (cls) {
        // 这两个是 init 方法，通常一定被重写，直接 Hook
        MSHookMessageEx(cls, sel_registerName("initWithViewModel:"),
            (IMP)hook_SysCell_initWithViewModel, &_orig_SysCell_initWithViewModel);
        MSHookMessageEx(cls, sel_registerName("layoutInternal"),
            (IMP)hook_SysCell_layoutInternal, &_orig_SysCell_layoutInternal);

        if (purifyIsOverridden(cls, sel_registerName("canBeReused"))) {
            MSHookMessageEx(cls, sel_registerName("canBeReused"),
                (IMP)hook_SysCell_canBeReused, &_orig_SysCell_canBeReused);
        } else {
            WPLog(@"UIPurify", @"[Hook] - SysCell.canBeReused inherited, skip");
        }

        // ★ 关键修复：shouldLayoutIfNeeded 可能被继承，使用 purifySafeHook
        if (purifySafeHook(cls, sel_registerName("shouldLayoutIfNeeded"),
                (IMP)hook_SysCell_shouldLayoutIfNeeded, &_orig_SysCell_shouldLayoutIfNeeded)) {
            WPLog(@"UIPurify", @"[Hook] ✓ SysCell.shouldLayoutIfNeeded (safe)");
        }
        WPLog(@"UIPurify", @"[Hook] ✓ SystemMessageCellView (hide revoke)");
    }

    // ★ 关键修复：ViewModel.measure: 可能被继承，使用 purifySafeHook
    Class vmCls = objc_getClass("SystemMessageViewModel");
    if (vmCls) {
        if (purifySafeHook(vmCls, sel_registerName("measure:"),
                (IMP)hook_SysVM_measure, &_orig_SysVM_measure)) {
            WPLog(@"UIPurify", @"[Hook] ✓ SysVM.measure: (safe, 消除空白占位)");
        }
    }
}
```

修复后重新编译运行，日志应显示：

3. 拍一拍提示完全消失，无空白占位 ✓

## 四、class_addMethod 为什么安全

### 4.1 Objective-C 方法查找链

```
[instance someMethod]
        │
        ▼
  objc_msgSend(instance, @selector(someMethod))
        │
        ▼
  查找 instance 所属 Class 的方法表
        │
        ├─ 找到 → 调用该 IMP
        │
        └─ 未找到 → 查找父类方法表
                │
                ├─ 找到 → 调用该 IMP
                │
                └─ 未找到 → 继续向上一级父类查找
                        (一直找到 NSObject 或 nil)
```

### 4.2 class_addMethod 的效果

```
操作前：
┌─────────────────────────────────┐
│ SystemMessageViewModel 方法表    │
│  (没有 measure: 条目)            │  ← 查找时会向上找父类
│                                 │
│ BaseMessageCellView 方法表       │
│  measure: → IMP_A               │  ← 父类的实现
│  └─ 被 CommonMessageViewModel,  │
│     SystemMessageViewModel 等    │
│     所有子类共享                  │
└─────────────────────────────────┘

class_addMethod(SystemMessageVM, measure:, IMP_A, types) 之后：
┌─────────────────────────────────┐
│ SystemMessageViewModel 方法表    │
│  measure: → IMP_A (副本)         │  ← 现在有了自己的条目！
│                                 │
│ BaseMessageCellView 方法表       │
│  measure: → IMP_A               │  ← 未被修改！
│  └─ CommonMessageViewModel      │
│     仍然使用这个，不受影响 ✓      │
└─────────────────────────────────┘

MSHookMessageEx(SystemMessageVM, measure:, hook, &orig) 之后：
┌─────────────────────────────────┐
│ SystemMessageViewModel 方法表    │
│  measure: → hook_SysVM_measure  │  ← 只 Hook 这个副本
│  orig     → IMP_A (父类)        │
│                                 │
│ BaseMessageCellView 方法表       │
│  measure: → IMP_A               │  ← 完全未动！
│  └─ CommonMessageViewModel      │
│     → IMP_A → 正常返回高度 ✓     │
└─────────────────────────────────┘
```

## 五、技术总结

### 5.1 三个问题的根本原因

```
                    ┌──────────────────────┐
                    │  measure: 继承自父类    │
                    │  shouldLayout...继承    │
                    └──────────┬───────────┘
                               │
                               │ 直接 MSHookMessageEx
                               ▼
          ┌────────────────────────────────────┐
          │  修改了父类方法表                     │
          │  BaseMessageCellView.measure:       │
          │  → 被替换为 hook_SysVM_measure       │
          └──────────────┬─────────────────────┘
                         │
                         │ 所有继承该方法的子类
                         │ 都会受影响
                         ▼
     ┌──────────────────────────────────────────┐
     │  问题 1: 所有消息消失                       │
     │  CommonMessageCellView 等收到 CGSizeZero   │
     │  → 所有 Cell 高度变为 0                     │
     │                                           │
     │  跳过 inherited 方法后（当前状态）:          │
     │  问题 2: 空白占位                           │
     │  SystemMessageCellView 仍保持原始高度        │
     │  → 视觉隐藏但空间未释放                      │
     └──────────────────────────────────────────┘
```

### 5.2 修复对照

| 方法 | 当前行为 | 修复行为 | 原理 |
|---|---|---|---|
| `measure:` | `purifyIsOverridden` → NO → **跳过** | `purifySafeHook` → `class_addMethod` → 本地副本 → Hook | 隔离父类后安全 Hook |
| `shouldLayoutIfNeeded` | `purifyIsOverridden` → NO → **跳过** | `purifySafeHook` → `class_addMethod` → 本地副本 → Hook | 同上 |
